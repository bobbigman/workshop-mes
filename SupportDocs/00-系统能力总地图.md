# 系统能力总地图（源码盘点版）

> 这份文档是**按源码（后端 Controller / 前端路由与菜单 / 授权档）逐项盘点**出来的全系统能力清单，用于：① 帮 AI 在操作手册没覆盖到时仍能答出"系统到底有哪些功能、在哪、谁能用"；② 当维护台账，源码或文档有变化时在此登记。
>
> **怎么用**：先看【一、能力总览】判断某项能力存在与否、当前状态；要看具体怎么操作，跳对应编号手册；要查是哪个指令做的，看"对应指令"列。
> **维护口径**：新增/下线功能时，同步改本表"状态"，并在末尾【维护日志】记一笔；纯技术内部项（诊断、MCP 暗语、部署脚本）不属于客服知识，不在本表展开。

## AI 兜底协议（检索命中本文时必读）

本篇是**能力/入口/状态**兜底，不是第二本操作手册。回答前按问法选深度，并遵守 `17-AI应答行为规则.md`（能不能 vs 怎么用、先简后详）。

| 客户问的是 | 用本文哪里 | 怎么答 |
|---|---|---|
| 有没有 / 系统有哪些 / 做没做 | 【一、能力总览】【七、明确未做】 | 只答有/没有/占位未做 + 入口 + 谁能用 + 授权档；未做项禁止答成已上线 |
| 在哪、谁能用、要哪档 | 【一】【二】【三】 | 菜单路径、角色、license 档；低档看不到属正常限制 |
| 新功能一句话 / 手册可能没成篇 | 【六、新功能速查】 | 只念表里「一句话回答口径」，不发挥 |
| 怎么用 / 演示 / 怎么点 / 哪个菜单按钮 | 仅当本文有「××怎么用」专节（如「派工智能推荐怎么用」） | **只念该专节**；不要说知识库没步骤，不要自己编点击路径 |
| 怎么用，但本文只有总览表一行、无「××怎么用」专节 | 看该行「详细文档」列（如 `04 #补报`） | **不要用本表教逐步操作**。若本次检索已带回对应分册（01～08 / 10 等）→ 按分册答；若只有本表 → 如实说「有这功能，入口是…；详细步骤请再问具体操作（或我按手册章节再查）」，**禁止编造菜单点击顺序** |

**禁止**：

- 把【四、后端接口地图】的 Controller / 路由名念给客户（内部定位用，客服不讲技术接口名）。
- 把「详细文档」列的编号指针当成已读完分册；指针不会自动打开 01～07，没拿到分册正文就不要假装有步骤。
- 用【七】里的未做/占位项教操作，或把「完全无人自动派工」与已上线的「派工智能推荐」混答。

**与分册关系**：操作步骤以 `01`～`08`、`10` 等为准；本文只补「有没有、在哪、谁用、做没做」以及已写明的「××怎么用」专节。

## 二、授权档（license_tier）功能矩阵

一套代码按工厂分 **入门款 / 企业版 / 旗舰版** 三档，前端按档位显隐菜单、后端按档位放行接口。

| 功能 | 最低档 |
|---|---|
| 下工单、派工、报工、车间看板、基础资料、异常上报、执行监控、生产/不良品/色码报表 | 入门款（全档） |
| 工资与工价、扫码报工、报工复核、交期预警/企微推送、打印标签 | 企业版 |
| 多账套（MultiWorkshop）、建议报价（接金蝶 MCP）、车间数据大屏 | 旗舰版 |

判定口径：前端 `licenseTier.js` 与后端 `LicenseTierPolicy` 对齐（见 docs/88）。低档登录后看不到对应菜单/按钮，属正常授权限制，不是故障。

## 派工智能推荐怎么用

客户问「演示 / 怎么用 / 具体怎么点 / 哪个菜单 / 哪个按钮」时，**只念下面这段**。不要说知识库没有步骤，不要自己编「进派工页面会自动弹出」。

**电脑**：生产管理 → 工单 → 打开这张工单。每道工序旁边有「推荐派给谁」，写着「近30天 N 次 · 良品 X」，第一名高亮。点一个人名，就派给他。

**手机**：报工页点【派工】，选个人。工人名单上面同样是「推荐派给谁」。点人名只是勾上，再点【保存派工】才派出去。选班组时不显示推荐。

这道工序近 30 天有效报工不足 3 次，两边都不显示推荐，改用原来的选人即可。推荐不是自动派工，要点下去才生效。
