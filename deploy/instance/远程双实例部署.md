# 远程服务器双实例部署（对用户就是两个入口）

> 本质与本机相同：**两个库 + 两份程序目录 + 两个网址**。  
> 不是在一个站点里“开账套”。用户各自打开自己的网址登录即可。

## 1. 目标形态

| 用户看到的 | 服务器上 | 数据库 |
|---|---|---|
| `https://a.你的域名.com` 或 `http://服务器IP:8080` | `D:\MesTrials\client-a\app` | 如 `WorkshopMes` / `Mes_A` |
| `https://b.你的域名.com` 或 `http://服务器IP:8081` | `D:\MesTrials\client-b\app` | 如 `WorkshopMesB` / `Mes_B` |

同一台 SQL Server 可以，**库必须两个**；Jwt Secret / Issuer / Audience **必须两套不同**。

## 2. 服务器先装好

1. .NET 8 ASP.NET Core Hosting Bundle  
2. IIS（或你已在用的反向代理）  
3. SQL Server（本机或同网另一台）  
4. 防火墙只放行 80/443（或你定的网站端口）；**不要**把 SQL 1433 对公网开放  

## 3. 做标准发布包（只做一次）

在开发机：

```powershell
cd backend
dotnet publish -c Release -o ..\publish\mes-release
cd ..\frontend
npm run build
# 把 frontend\dist\* 拷进 publish\mes-release\wwwroot\
```

把整个 `mes-release` 拷到服务器，**同一份包复制两份**到两个目录，不要从甲目录整盘复制后再改一半（容易把配置/密钥带错）。

## 4. 服务器目录

```
D:\MesTrials\client-a\app      ← 发布包 + 甲的 appsettings.json
D:\MesTrials\client-a\data
D:\MesTrials\client-a\logs
D:\MesTrials\client-b\app
D:\MesTrials\client-b\data
D:\MesTrials\client-b\logs
```

## 5. 两个库

- 已有还原库：直接用（例如 `WorkshopMes`、`WorkshopMesB`）  
- 新客户空库：建库后，对应实例配置里设 `BootstrapOnStartup=true` 启动一次，再改回 `false`  
- **不要**把甲库备份直接当乙库用后对外交付（账号密码会相同且数据串味）

每个库建一个 SQL 登录，只授本库权限；应用连接串用该账号，不用 sa。

## 6. 两份配置（关键）

从 `deploy/instance/appsettings.Trial.template.json` 各复制一份到：

- `client-a\app\appsettings.json`
- `client-b\app\appsettings.json`

甲示例要点：

```json
"ConnectionStrings": { "Default": "Server=本机或SQLIP;Database=WorkshopMes;..." },
"Instance": {
  "Code": "client-a",
  "DisplayName": "甲公司试用",
  "FactoryCode": "F001",
  "PublicBaseUrl": "https://a.你的域名.com",
  "SeedDemoData": false,
  "EnableMcp": false,
  "EnableSwagger": false,
  "BootstrapOnStartup": false
},
"Jwt": {
  "Secret": "甲自己的≥32位随机串",
  "Issuer": "mes-client-a",
  "Audience": "mes-client-a-app"
}
```

乙把 `Code/DisplayName/数据库/PublicBaseUrl/Jwt` 全部换成乙的；`Issuer=mes-client-b`，`Audience=mes-client-b-app`。

库里若已有 `admin`（还原库），**不要**再开 `BootstrapOnStartup`，直接用库里账号；交付前改密码。

## 7. IIS：两个站点 + 两个应用池

对每个客户：

1. 新建应用程序池（无托管代码 / No Managed Code，启用）  
2. 新建网站 → 物理路径指向该客户 `app`  
3. 绑定：
   - **推荐**：主机名 `a.域名.com` / `b.域名.com` + HTTPS  
   - **临时**：同一 IP 不同端口，如 `:8080` / `:8081`（用户记端口即可，适合内测）  
4. 站点「应用程序池」选各自的池  
5. 确认站点工作目录就是该 `app`（不会读到另一份 appsettings）

装好 Hosting Bundle 后，对 `app` 目录给应用池标识读权限。

## 8. 用户怎么用

把对应网址发给用户即可，例如：

- 甲：`https://a.你的域名.com` → 账号密码（该库管理员）  
- 乙：`https://b.你的域名.com` → 账号密码（另一库管理员）  

登录页会显示各自的 `DisplayName`。同一浏览器开两个域名不会抢 token。

## 9. 验收（远程必做）

- [ ] 甲网址标题是甲；乙是乙  
- [ ] 甲登录后下单，乙库数据不变  
- [ ] 甲的 token 调乙的 `/api/...` → 401  
- [ ] 停甲应用池，乙仍可登录  
- [ ] 手机/PDA 能打开对应网址（若用公网，确认 HTTPS）

## 10. 和本机双开的对应关系

| 本机 | 远程 |
|---|---|
| 8080 + `appsettings.json` → WorkshopMes | IIS 站点 A + 甲配置 → 甲库 |
| 8081 + `appsettings.WorkshopMesB.json` | IIS 站点 B + 乙配置 → 乙库 |
| `npm run dev` / `dev:b` | 前端已打进 `wwwroot`，用户只开网址 |

远程**不必**再跑 Vite；发布包里的静态页即可。

## 11. 你还缺的外部信息

把下面三项定下来就能开通：

1. 服务器 IP / 是否已有域名  
2. 两个入口用「双域名」还是「同 IP 双端口」  
3. SQL 是装在远程本机还是另一台  

定好后可按本清单开第一家，第二家复制目录与配置改名字即可。
