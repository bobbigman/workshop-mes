# 车间小工单助手 · 陌拜演示指南（微信机器人）

> 目标：客户用**微信扫码绑定机器人**，当场问「查工单 / 查排产」，几分钟抓住眼球。
> 定位：**陌拜抓眼球用**，不是正式商用。
> 技术路径以 `docs/47` 为准（唯一事实来源）；本文只管**怎么讲、怎么演示**。
> 前置：`docs/47` 全流程已通（Agent 调试能调 `query_work_order` + 微信渠道已授权）。

---

## 0. 演示前 30 秒自检

| 项 | 必须 |
|---|---|
| 本机 .NET MCP 后端 | 开着，`DemoSkipAuth=true` |
| cpolar | `online`，窗口别关 |
| Agent「车间小工单助手v2」 | 工具列表能看到 5 个工具 |
| 微信渠道 | 已扫码授权，自己手机已能「查工单」 |

> 电脑关机 / 隧道断 → 微信端立刻全挂。陌拜出门前再发一句「查工单」自测。
> 人设须含「只问查工单就只调 query_work_order」约束，全文见 `docs/45` 第 1 节；改后人设要**新开对话**再测。

## 1. 陌拜怎么给客户用（不是发网页链接）

新版扣子 Agent **没有公开 H5 / 分享链接**。做法是：

1. 打开你手机上已绑定的「车间小工单助手」微信机器人会话（或按扣子渠道页的绑定方式，让客户扫**授权/添加机器人**二维码）。
2. 让客户（或你代问）直接发：「查工单」或「今天先做哪个单」。
3. 看机器人回真实工单表 → 演示成功。

> ❌ 不要再找「网页版 / 分享链接」，找不到是正常的。  
> ❌ 不要让对话里的 AI「帮你做看板网页再发布」——那是跑偏。

---

## 2. 陌拜口播脚本

**开场一句：**  
老板你微信扫一下（绑这个机器人），直接问一句「今天先做哪个单」，就能看到工单进度。

**当场三连问（按顺序）：**

1. **查工单**：问「查工单」→ 看它列出产品、状态、交期（有逾期更好看）。
2. **查排产**：问「现在先做哪个单、为什么」→ 看优先级理由。
3. **收尾一句**：不用装软件、不用学后台，跟微信聊天一样。

---

## 3. 三句保命话（被问住了就这么说）

- 「能直接报工吗？」→ 现在演示版是「查」，写入报工要接真实账号权限，下一步接。
- 「工资能查吗？」→ 能，但敏感数据要财务授权才看得见（顺势演示「查工资要先授权」，反而显专业）。
- 「发个网页链接点开行不行？」→ 当前渠道是微信机器人；点开就能聊，效果一样。豆包 App 那条路官方已关。

---

## 4. 和系统能力对齐（别夸大）

- 工具只有「查」：`query_work_order` / `query_report` / `calc_schedule_priority` / `query_salary` / `start_auth`。
- **没有**「提交报工」写接口。陌拜别承诺「当场报一单」。
- 数据来自你本机车间库；演示机必须保持联网 + MCP + cpolar。
