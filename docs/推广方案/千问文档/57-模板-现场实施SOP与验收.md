# 57-模板：现场实施 SOP 与阶段验收

> 更新日期：2026-09-22
> 用途：把"上门实施"从个人发挥变成可复制清单，供 `docs/55` 第 1～3 家复用，未来供伙伴自助交付。
> 定位：实施/推广模板，不是开发指令。
> 上游依据：部署开通见 `docs/1E` §6、§8；业务操作口径见 `docs/30`（电脑端）、`docs/31`（手机端）、`docs/52`（手册与验收清单）。**本文不重复这些内容，只规定"哪天干什么、怎么算过"。**
> 硬约束：单家累计上门 **≤4 次**、陪跑 **≤6 人日**（`docs/55` §6）。超线必须收钱或按协议第 6.4 条终止。

---

## 0. 时间轴总览

| 阶段 | 你到场吗 | 目标 | 通过标志 |
|---|---|---|---|
| D0 上门前 | 否 | 准备与自测 | §1 全勾 |
| D1 第 1 天 | 是（约 4 小时） | 系统跑起来 + 第一批真实数据能扫出来 | §2 全勾 |
| D3 第 3 天 | 是（约 2 小时） | 现场自己会建单、会报工、会看进度 | §3 全勾 |
| W2 第 2 周 | 否（远程） | 系统真的在用，没被绕开 | §4 全勾 |
| W4 第 4 周 | 视情况 | 月底真出工资单 = 跑通 | §5 全勾 |

---

## 1. D0 上门前（在自家电脑完成，不到现场）

### 1.1 演示与部署自测

- [ ] 后端能起、登录正常、前端包与后端版本一致。
- [ ] 手机/平板与电脑在**同一网段**，能打开报工页并成功提交。
- [ ] PDA 扫码头实测：扫码后能自动回车进入下一步（**不允许到现场第一次试**）。
- [ ] 按 `docs/1E` §6 的 8 步，在本机把该客户的独立实例配置模板准备齐：客户显示名、内部代码、独立端口、独立 JWT 密钥与 iss/aud、独立附件与日志目录、限定到本库的数据库账号。
- [ ] 试用机与子域名/证书先锁定，再批量开通（`docs/1E` §6 第 1 条加粗项）。
- [ ] 关闭固定验证码手机号登录、去掉登录页演示账号密码预填、隐藏工厂代码输入、默认关闭 MCP 与配对授权入口（`docs/1E` §5、§7 的 P0 项）。

### 1.2 基础数据预填（省现场 1～2 小时）

- [ ] 按 §2.2 的行业模板，预建部门、工序、工艺路线骨架，产品编号留空待现场填。
- [ ] 打印测试：真实流转卡用**甲方同款打印机、同款纸张**至少提前确认纸张尺寸。若拿不到甲方打印机型号，D1 第一件事就是这项，见 §2.3。

### 1.3 谈判材料

- [ ] `docs/56` 协议打印 2 份，第 4.1 条数字留空待现场填。
- [ ] 报价口径按 `docs/55` §3 定死，写在自己本子上，**不在功能演示中途报价**（`docs/37` 坑 5）。
- [ ] 派工等未上线功能的口播话术背熟（`docs/37` 坑 1）。

## 2. D1 第 1 天（到场约 4 小时）

### 2.1 第 1 小时：环境落地

- [ ] 确认甲方服务器/电脑：固定局域网地址、自动启动、不休眠、有备份位置。
- [ ] 部署标准发布包 + 该客户配置，建库并按权威结构初始化（`docs/02`，不凭记忆建表）。
- [ ] 建客户管理员账号，初始密码每客户不同，**当场要求修改**并记录"已改"（密码不写进任何文档）。
- [ ] 验证隔离：该实例凭证不能登其他实例，也不读写其他库（`docs/1E` §6 第 7 步）。
- [ ] 记下备份方法并实际做一次备份 + 一次恢复演练。没验证过的备份等于没有备份。

### 2.2 第 2 小时：基础数据（老板/厂长 + 车间主任在场）

按此顺序录，**顺序不能颠倒**（与删除依赖倒序对应，`docs/55` 依据 AGENTS.md 硬规则 3）：

- [ ] 单位 → 部门 → 不良品项 → 工序 → 工艺路线 → 产品定义 → 工单相关配置。
- [ ] 产品编号逐一核对唯一性（硬规则 1：编号即身份证，名称可重复）。
- [ ] **工序报工权限按部门配置**（硬规则 2：权限是部门不是人），配完当场让一个工人试扫，验证"不该报的工序报不了"。
- [ ] 工价表：先配 2～3 条最常用的，不求全。
- [ ] 让甲方指认：他们最容易报错数的工序是哪道，专门看一眼。

### 2.3 第 3 小时：打印与扫码（含 `docs/52` 遗留项）

- [ ] **真实打印机纸张尺寸与流转卡模板**：用甲方打印机实际打出来，贴到实物料框/机台上，走一遍。这是 `docs/52` 验收标准里至今未勾的现场项，本 SOP 起在每一家都必须勾掉。
- [ ] **PDA 扫码头回车与标签内容**：实测扫标签能进报工页、能自动提交下一步；不行则现场确定改用"手动输工单号"备选路径。同为 `docs/52` 未勾现场项。
- [ ] 若甲方要求手机摄像头扫码：现场验证 HTTPS 与内网可达；不满足就明确写"本期用 PDA/手动路径"，不留模糊承诺。

### 2.4 第 4 小时：培训（拆两场）

- [ ] 电脑端：只教**建单 → 打印流转卡 → 看进度**三个动作。管理侧其余功能（补报、改数、复核）留到 D3，一次灌满必然忘。
- [ ] 手机端：只教**扫码 → 选工序 → 填良品数 → 提交**。**必须让工人自己操作一遍，你在旁边不许动手**。
- [ ] 留一页纸给车间主任：三个最常用界面入口 + 遇到问题找谁（你的微信）。

### 2.5 D1 收工条件

- [ ] 当天真实生产的一张单，已在系统里建单、打印、并被工人扫过一次。
- [ ] 老板当场看过看板，进度条动过。
- [ ] 协议第 4.1 条数字已现场填实。
- [ ] 台账记录：本次上门【　】小时，累计【　】/4 次。

> 当天没扫出那一次，就不要宣布 D1 成功。宁可延长，也不要把"部署完成"当成"跑起来了"。

## 3. D3 第 3 天（到场约 2 小时）

- [ ] **首次使用者独立操作验收**（`docs/52` 第三项遗留）：找一个没用过系统的班组长或工人，让他照内置手册独立完成"建单 → 打印 → 扫码 → 看结果"，**全程你不说话、不指屏幕**。做不到，记下卡在第几步，这就是产品或手册的真问题。
- [ ] 补教管理侧：复核与改数规则（已通过先退回再改；已结算不能退回改数）、批量补报（`docs/17`）、工单结束/取消的边界。
- [ ] 查数据质量：有没有集中补录的痕迹（一次报多道工序、时间戳挤在一起）。有就当场问车间主任为什么，这是使用强度的早期信号。
- [ ] 确认排班：谁每天负责看临期与超期提醒。没人负责的系统必躺平。

---

## 4. W2 第 2 周（远程）

- [ ] 拉数据看：最近 14 天里，报工天数 ≥6 天？（协议 3.1 的"每周 3 个真实生产日"）
- [ ] 扫码报工条数日均趋势是在涨还是在掉。**在掉就是危险信号**，必须上门一次查原因。
- [ ] 有没有出现"管理员补报占比过高"——说明工人端没真在用，管理端在替现场编数据。
- [ ] 打一次电话给车间主任，只问三句：现在还有没有绕开系统的纸质单？工人有没有抱怨哪一步太麻烦？月底工资打算用系统出还是另算？
- [ ] 记台账：累计上门【　】/4 次，累计陪跑【　】/6 人日。

---

## 5. W4 第 4 周（跑通判定，唯一硬标准）

- [ ] 甲方**真的用系统出了工资单**，并与自己手工核算对过账。差异有则逐笔查明，不许"差得不多就算了"。
- [ ] 连续 4 周、每周 ≥3 个真实生产日有报工记录。
- [ ] 老板/厂长自己打开过看板（不是只看你发的截图）。
- [ ] 上述三条全中 → 该家在 `docs/55` §7.1 意义上**跑通**，可以启动素材采集（`docs/58`），并启动第 2 家。
- [ ] 有任一条不中 → 不算跑通，先回 `docs/55` §2 审选客条件，尤其"是否有正在疼的事件""是否计件工资""有没有人天天喂数据"三条。

---

## 6. 成交后从试用机迁到甲方本地（第 2、3 家会用到）

按 `docs/1E` §8 执行，本 SOP 只加三条检查：

- [ ] 含公网网址的二维码全部作废并重新生成，纯工单号二维码在对应本地工厂内解析。
- [ ] 迁移后核对：工单数量、报工汇总、工资结果、附件四项逐项对得上，签字留档。
- [ ] 原试用实例保持停用，**不允许云端与本地同时写入**。

---

## 7. 三家之间的复用纪律（防第 2 家变成第 1 家延长赛）

- [ ] 第 1 家做完当天，把本 SOP 中被证明多余或不够的步骤直接改在本文里，并更新版本号。**第 2 家用改过的第 2 版，不许凭记忆再讲一遍。**
- [ ] 复制的是干净发布包，**绝不复制上一客户的数据库、密码配置或附件**（`docs/1E` §6）。
- [ ] 第 3 家必须付全价，且目标是你到场次数 ≤2 次。做不到，说明可复制性还没成立，不要扩第 4 家。
- [ ] 升级逐实例执行，不能假设"改一次代码全客户自动覆盖"（`docs/1E` §9）。
