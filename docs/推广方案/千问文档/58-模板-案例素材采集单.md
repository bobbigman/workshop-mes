# 58-模板：案例素材采集单

> 更新日期：2026-09-22
> 用途：把"客户跑通"变成能转出去的证据。配合 `docs/55` §0 证据 2、§4 协议第 3、4 条使用。
> 定位：推广素材模板，不是开发指令。
> 核心原则：**数字必须是现场看到的，不是事后回忆的；素材必须是粗糙真实的，不是精致合成的。**
> 脱敏边界一律以 `docs/56` 协议第 4 条为准，本单未列明的数字一律不对外。

---

## 0. 为什么这张纸必须在场填

早期最容易犯的错，是回去凭印象写案例："效率提升明显""管理更规范"。这类话一句都不值钱——同行一看就是编的。

**只有当场拍下的照片、当场抄下的原话、当场从系统里导出的数字，才能让别人信。**

规则：**去之前填 §1，回来当天补齐 §2～§4，一周内出 §5 案例稿。过了当天就补不回来了。**

---

## 1. 去之前填（现场核实，不许猜）

| 项 | 内容 | 说明 |
|---|---|---|
| 1.1 车间人数 | 【　】人 | 只报人数区间也可（如"20 人上下"） |
| 1.2 工序数 | 【　】道 | 从他们工艺路线里数，不是从你系统里数 |
| 1.3 现在的报工方式 | 【纸质单 / Excel / 微信群口头 / 白板 / 其他】 | 一句话写清，别抽象成"传统方式" |
| 1.4 现在算一次工资要多久 | 约【　】小时，谁算【　】 | 必须问到人，"财务算"比"人工算"可信 |
| 1.5 最近一次相关事故 | 【　】 | 例如"6 月有一单延期 4 天，因为漏了后道没发现"。**这一栏是案例的心脏，必须问到具体事件** |
| 1.6 老板原话一句话 | 【　】 | 现场直接抄他的说法，一个字都别改（方言也保留） |
| 1.7 可披露数字清单 | 勾选：□人数 □工序数 □日均扫码条数 □超期单数变化 □工资核算耗时 | 其余全部保密，按 `docs/56` 第 4.3 条兜底 |

> 1.5 问不出来怎么办：换个问法——"上个月有没有哪张单让你多跑了趟车间？"这类具体问题才答得出。答不出具体事件的客户，说明痛点还没疼，也不适合当灯塔（回 `docs/55` §2.1 第 6 条）。

## 2. 现场拍（手机直拍，一次拍够）

**画质要求：清楚即可，不要滤镜、不要稳定器、不要配乐。** 车间里的东西太干净反而没人信。

必拍清单：

- [ ] **改造前的证据**：他们现在那张纸质报工单/Excel 截屏/白板照片。**这张最值钱，也最容易忘**——一旦上线就再也拍不到了。
- [ ] 墙上/机台/料框上贴着的二维码流转卡（拍到环境，露出车间杂乱感没关系）。
- [ ] 工人**正在扫码**的手部特写（不拍脸，或事后打码）。
- [ ] 电脑看板的实拍屏幕（现场拍的，不是截图）。
- [ ] 老板/厂长本人 30～60 秒口播：只念三句——以前怎样、现在怎样、帮到哪一下。
      - 让他用自己的话说，不要念你的稿。
      - 说不流利更好，重拍控制在 2 条以内，别让他难堪。
      - 不愿露脸就只出声，配他的车间画面。
- [ ] 一张"人机同框"：老板站在看板前，手指屏幕某一处。这张做微信转发封面最合适。

素材落盘：当天存入按客户建目录（客户内部代号，**不用公司全名做目录名**），原始文件不删不裁，副本再处理。

---

## 3. 现场从系统里导（数字只认这里）

- [ ] 近 14 天报工记录条数、日均条数 → 系统导出，不手抄。
- [ ] 超期工单数量：上线前【　】单 / 上线后【　】单。
- [ ] 一次工资核算的实际耗时：上线后老板/财务口述并计时一次，记【　】分钟。
- [ ] 管理员补报占比（用于自我判断"是否真在用"，**这条不对外**，见 `docs/57` §4）。

> 铁律：**对外数字一律能追溯到导出文件或现场计时**。追不到的数字不用。宁可写"报工从每天手写十几张单，变成扫一下"，也不写"效率提升 300%"。

## 4. 回来当天填

| 项 | 内容 |
|---|---|
| 4.1 一句话结论 | 用老板的口吻写，不用你的口吻。示例句式：【"以前月底算工资要两天，现在半小时对完。"】 |
| 4.2 卡住的地方 | 现场工人抱怨最多的那一步【　】 |
| 4.3 是否入 backlog | 4.2 的问题是否对**全部客户通用**？是 → 记入 `docs/16`（或按 `docs/27`/`docs/29` 一类另立指令）；否 → 只做现场配置，**不为单家改代码**（`docs/55` §6 定制红线） |
| 4.4 素材完备度 | □改造前证据 □二维码实拍 □扫码特写 □看板实拍 □口播 □人机同框 |

## 5. 一周内出的三份产出

同一套素材，出三个版本，用途不同，**不要一稿多用**。

### 5.1 一页纸案例（给意向客户看）

结构固定，控制在 400 字内：

1. 这厂多大：人数、行业、几道工序。
2. 以前的三个麻烦：进度靠问、工资靠算、交期靠记（对齐 `docs/37` 开场三问）。
3. 现在哪一步变了：扫码 → 看板 → 工资单。
4. 一个具体数字（可披露范围内）。
5. 老板原话一句（带引号）。
6. 一张照片。

> 不写功能清单，不写"赋能/闭环/数字化转型升级"。老板看这种词就划走。

### 5.2 口播视频（首选发微信视频号）

- 60 秒以内，前 3 秒必须是**车间画面或老板那句话**，不是你的 logo。
- 字幕手写体风格即可，不做片头片尾。
- 一条只讲一个麻烦（工资 / 交期 / 进度），别塞三条。
- 平台优先级：视频号 > 抖音 > 小红书。

### 5.3 谈判用一页（给伙伴/渠道看）

三行就够：

1. 这个厂的条件：人数、工序、是否计件——让伙伴判断他手里有没有同类客户。
2. 交付成本：上门【　】次、陪跑【　】人日（数据取自 `docs/57` 台账）。
3. 客单与返点口径：首年【　】元，返点【　】%，实施由【乙方/伙伴】承担。

> 伙伴真正要看的是第 2 行。你交付越省人，他越敢卖。

---

## 6. 三条禁忌

1. **不 AI 生成车间画面或口播。** 这个客群对"没有车间味"的内容天然免疫，一旦被识破，本地圈子全知道。AI 可以用在你自己的文案初稿、字幕整理上，不能用在"冒充现场"上。
2. **未签字不发布。** 没有 `docs/56` 协议第 3.2 条授权，任何照片视频不外传，哪怕打码。
3. **不用未跑通的客户。** `docs/57` §5 三条硬标准没全中，就不算跑通，不采集、不发布。用"部署了但不用的厂"做案例，第一个电话被打来问"你们这厂现在还用吗"就崩了。
