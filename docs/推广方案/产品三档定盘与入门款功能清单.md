## 一、一句话总纲

**一套代码，档位开关，升级不重录。** 不做三套系统（solo 维护灾难），同一系统按"授权档位"开放功能子集，一个客户一个档。

## 四、入门款专项决策

### 4.1 报工交互（定死）
- **不做电脑扫码、不打印**：打印条码 = 打印机/耗材/驱动/维护，solo 的硬件泥潭，入门款绝不碰。
- **手机手工报工，走"派工到人"**：工人手机登录，只看到**派给他自己的工单**，点开、填数量就报。
- **不是"打开所有工单选自己的"**，而是"开'派给我的'选一张"——更简单、更不易错（防报错单 = 防数据污染 = 防算错工资）。
- **扫码留作企业版及以上（含打印）**，配打印标签/PDA、现场扫；企业版要扫码打印再另配。
- **不做"屏幕扫码"加分项**：扫码前要走到电脑前、先在电脑上找到工单再显示码——"找单"已完成，再扫是多余动作，比手机派工列表点选还麻烦，无增量价值。入门款报工统一走手机派工列表点选。

### 4.2 老板自然语言查工单进度 / 做法（钩子）
- **查做法（工艺）**：微信 → 扣子 → MCP 知识库问答，**已通**（docs/48），零开发。
- **查进度**：PC 端已实现，**补手机微信接入** = 新增 MCP 工具（docs/87），复用已验证进度口径，开发量小，不重造引擎。
- **边界（对外口径）**：查进度/问做法 = **联网增值**（微信服务器需够到客户服务器）；报工/看板 = **断网核心**，断外网照用。两者不混为一个卖点。

### 4.3 数据口径（对外）
- 一句话卖点：**"数据不交给别人"**——核心账本锁在客户自己电脑里；AI/推送只发必要字段（进度、交期、答疑文本），**不吐工资/单价/路径/密钥**。
- 不纠结"本地 vs 云端"：只要数据**不交给第三方/竞品**就行。
- 客户不问不展开；真较真一句"核心账本在您自己电脑里，AI 只帮答疑"兜住。

### 4.4 AI 钩子三条边界
1. **别让客户自己配 token**（小厂老板不会配，违背入门款"简单"核心）——您统一接入。
2. **不碰核心业务数据出厂**——AI 只发必要查询字段/答疑文本。
3. **不做每月倒贴口子**——token 费要算清，AI 做限次/限量，或只放企业版旗舰版当加分。

## 五、升级逻辑（红线）

- 入门款 → 企业版：后台改档位即可，**数据无缝继承、不重录**。
