## 一、一句话定位

面向**中小工厂/车间**的轻量级 MES（生产执行系统），对标黑湖小工单。主链路：

> **电脑下单出二维码 → 工人扫码报工 → 班组长复核 → 老板大屏看进度**

与黑湖/简道云的本质区别：**本地部署、断外网也能用、数据不出厂**；且**能接金蝶**（车间执行层 + 金蝶集成），不拼旗舰版功能宽度。

- 技术栈：后端 .NET 8 Web API + EF Core + SQL Server；前端 Vue3（PC 后台 Element Plus / 手机报工 Vant / 大屏看板 ECharts）；鉴权 JWT + BCrypt
- 部署：客户自己电脑/服务器局域网跑；支持**多账套**（一个系统管多个工厂/车间，数据互相隔离）

## 二、当前功能全景（核心部分）

### 1. 系统与多账套 ✅
- 登录支持**账套/工厂下拉选择**（≥2 个账套时显示）；登录后各端显示当前工厂名；数据按厂隔离
- 一键新建账套：服务器上双击 bat（填厂代码+厂名）即建好带演示数据的账套（管理界面版规划中）
- 已制作演示账套：厨具五金厂（含产品、工价、工人、带交期工单、作业指导书）

### 2. 基础数据 ✅
- 用户管理（三角色：管理员/班组长/生产人员；可填手机号、微信号并可按微信号搜人）
- 部门管理、单位、不良品项、工序（工序可配**报工权限部门** + 可选不良品项）、工艺路线（工序顺序）、产品定义（编号唯一、名称可重复）
- **自定义字段**：工单/产品/工序可加字段（单选/文本/数字）；工单字段可选「在工单列表显示 + 筛选」；报工自定义字段（设备、模具等）随报工保存
- **批量导入**：用户/不良品项/工序/工艺路线/产品均支持 Excel 下载母版→上传导入，失败逐行提示
- **制造知识库**：产品/工序可挂作业指导书、图纸、图片（pdf/docx/xlsx/jpg/png/webp，≤20MB，带版本号）；工人手机报工页可直接查看

### 3. 工单管理 ✅
- 创建工单（工单号可自动生成 A0001→Z9999，或自填如销售单号；可设**计划交期**；含自定义字段）
- 工单状态流转：未开始/执行中/已结束/已取消 + 恢复/撤回/复制
- **打印二维码流转卡**：支持 30×40 / 80×60 标签、二维码内容可选（工单号 PDA / 报工页链接手机）、字段勾选
- **派工到人** 🟢：管理员/班组长在工单详情把每道工序派给具体工人；工人手机「我的任务」看到今天要干的活（任务提醒/优先级 🔜，正式期接企业微信）
- **改数**：已通过报工先退回→修改→重新复核（已结算冻结不能改）

### 4. 报工 ✅
- 四种方式：**手机摄像头扫码 / PDA 扫码枪 / 手动输工单号 / 电脑报工**；手机支持工单列表点选报工
- 报工内容：良品数 + 不良品数（关联该工序不良原因）+ 时长（小时+分钟）+ 报工自定义字段
- **防超额报工**：良品累计不得超过工序计划数，超限拦截（不良不占上限）
- **一键补报未完工序**（仅管理员/PC）：对未报满工序统一补数，可按工序拆分到人
- **报工复核双轨** ✅：提交后进度**实时**更新；班组长/管理员复核通过后才进入生产报表与工资（班组长只能复核本组）
- 进度口径统一：现场进度=各工序良品最小值；工序达成进度=已报/计划的最小值；零计划工序不参与

### 5. 工人异常上报 ✅
- 手机一键上报：设备故障 / 物料短缺 / 质量异常（官方三类），可填描述+选工单+拍照
- 看板红色高亮 + 滚动播报；PC「异常处理」标记恢复
- （通知到对应负责人：试用期靠看板/列表，正式期接企业微信 🔜）

### 6. 看板与执行监控 ✅
- **车间看板**：全厂工单进度大屏，含状态卡、临期/超期统计、待处理异常、滚动播报
- **交期三态**：正常 / 预警（临期≤3天）/ 延期（超期），超期置顶
- **PC 执行监控**：状态统计卡、关键词/状态/交期筛选、工序进度链、超期工单、待复核与未派工待办（按角色）、约 10 秒自动刷新

### 7. 报表 ✅
- 报工记录查询（按工单/产品/报工人/复核状态）
- 生产报表（今日/本月/上月，按报工人汇总良品/不良/次数）
- **工资报表**（见下）
- **建议报价（相似件）** ✅：选本厂做过的老产品当相似件 +（可选）填金蝶物料号 → 材料（金蝶 BOM/成本价）+ 人工（相似产品**已复核报工的真实时长**估工）+ 毛利/不良预留 → 建议总价，可导出 Excel。只算不存、不写回金蝶
- **排产评分** ✅：任务+交期，填客户等级/金额/换型/齐套性分数，调整权重重算，可导出（金蝶 MCP 口径见下）

### 8. 工资计算 ✅（重点卖点）
- **工价表**：按产品/工序/部门/人员四维配置计价规则（均可留空=不限），三种计价：计件（元/件）、计时（元/小时）、固定（单笔）；可设不良扣款、生效/失效时间、优先级；支持 Excel 批量导入；失效行变色
- **工资单**：按月/周生成（如 2026-09 / 2026-W37），生成后出计件合计；**草稿**可填 5 列手工数（底薪/餐补/其他补贴/社保个税/其他扣款）并自动重算应发合计
- **确认/冻结**：核对无误后【确认】；有红色【未匹配】（没匹配到工价）会被**阻断**；确认后该批报工冻结禁改；可**导出 CSV**
- **撤回重算** ✅：已确认工资单可撤回→改/重算→重新确认（已发放不可撤）
- 应发合计公式：计件合计 + 底薪 + 餐补 + 其他补贴 − 社保个税 − 其他扣款
- **设计边界（32）**：主系统只做「底座+计价口子」，特殊客户的计价算法走**外挂**（默认 Excel+VBA：系统导出事实→客户算→上传→系统对总数兜底），不复制主系统。**不自动算社保费率、不负责银行代发**

### 9. 交期预警与推送 ✅🟢
- 看板三态预警（默认即用）
- **企业微信预警** 🟢：配置 CorpID/Secret/AgentId 后可推送临期/超期工单；**自动定时推送已做**（服务器计划任务调 cron-push，一天一批一条、当日不重推）；默认关闭，试用期不推
- 边界：通道只做企业微信，不承诺钉钉/短信

### 10. AI 能力 ✅🟢（差异化加分项）

## 三、关键业务规则与数据口径（防 AI 答错的硬约束）

1. **产品编号唯一**（=身份证号），名称可重复
2. **工序报工权限=部门**（不是人）：报工校验用户部门∈工序报权部门，管理员不受限
3. **删除依赖倒序**：工单→产品→工艺路线→工序→不良品项→单位→部门；有下级禁止删
4. **复核双轨**：进度实时可见（0+1 态），报表与工资只算已通过（1 态）
5. **防超额**：良品累计≤工序计划数；不良不占上限
6. **进度口径**：完成数/工序达成进度=各正计划工序良品最小值（非跨工序求和、非成品产出率）
7. **工资口径**：以已通过报工为底；计件=良品×单价、计时=时长×单价、固定=单价一次、不良按扣款；`base_product.price` 是扩展属性不是工价，工价一律走工价表；金额以工资单明细固化为准，重算不动历史事实
8. **交期三态**：正常/预警(≤3天)/延期；空交期不参与

## 六、已知短板与边界（劣势素材，别让 AI 吹过头）

### 不碰（❌ 明确不做，一问穿帮）
- 库存/扫码出入库、采购、销售、财务、进销存
- 全流程质检追溯（IQC/IPQC/OQC）、料批次追溯
- 社保/个税/银行代发（工资只管计件绩效算清楚、可对账可重算）
- "工序停滞预警"（系统按无报工时长猜卡住——黑湖也没有，靠人主动上报）

### 未做（🔜 排队中）
- 派工后的任务提醒/优先级调级（正式期接企业微信）

- 客户独立部署试用脚本/傻瓜化交付（23-未做）
- 官网/外部获客页；侧边菜单折叠；登录页改版

- 多账套的「管理中心」管理界面（现在是双击 bat 建账套）

### 已知风险/坑（演示时注意）

- 微信机器人链路约 10 秒（微信→扣子→隧道→本机），陌拜别现场干等；电脑关机/隧道断即全挂
