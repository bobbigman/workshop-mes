# 获客建议：本地陌拜小范围验证与交付边界

> 整理日期：2026-09-30
> 状态：讨论建议稿，不是已验证的获客方法，也不自动替代已有定价、退款及版本规则。
> 对象：单人开发、少资金、无工厂联系人、此前主要与金蝶代理合作的车间小工单开发者。
> 本文整理本次讨论及对豆包方案的点评，不涉及开发改动。

## 1. 当前只做一件事

在同一个本地工业园，用两个下午做一次小范围陌拜试验，验证能否接触负责人、找到真实问题、约到下一次演示。

先不把“每天6家、21天126个负责人”当成任务。两个下午只是控制投入的试验安排，不是行业标准或成交保证。目标是找到一家愿意配合、现有产品能交付的工厂，不是凑拜访数量。

选择本地，是为了减少后续调查、演示、部署和回访的负担；不能因此认定线下必然比线上成交率高。

## 2. 对豆包方案的点评

| 原说法 | 判断及修正 |
|---|---|
| 本地工业园线下陌拜是唯一主线 | 可以作为当前唯一的小试验，效果尚未验证。 |
| 只找10—80人、用金蝶的钣金/五金厂 | 可先以附近五金加工厂作观察范围；人数、软件、工艺要接触后核实，不假定进门前已知道。金蝶只有在对接能兑现时才是优势。 |
| 每天下午6家，每家10分钟 | 到访不等于见到负责人；路程、门卫、等人都耗时。有兴趣的沟通也不一定10分钟结束。 |
| 手写单据、用金蝶、问价格，满足两条就深耕 | 不足以证明购买或实施意愿。必须看真实麻烦、客户配合人、正式预算和下一步行动。 |
| 21天126个负责人不成交才止损 | 太晚且混淆不同问题。见不到人、没需求、报价不接受、试用跑不动，要分别处理。 |
| 失败后找代理免费搭伙 | 免费不等于代理有动力；介绍、实施、售后由谁承担的问题仍未解决，不作为默认退路。 |
| 零成本、单人全程搞定 | 交通、售前、配置、培训、维护及占用开发时间都是成本。先记录实际工时。 |
| 当面信任远高于线上、转介绍成交率最高 | 缺少适用于本项目的数据。现场运行证据、服务范围和兑现能力也影响信任。 |
| 晚上拍视频、转介绍送3个月 | 第一家尚未跑通，先不增加固定任务或许诺赠送政策。 |

## 3. 出门前准备

- 选交通方便、工厂相对集中的一个园区，不跨区域奔波。
- 带现有可运行演示；另备一段短录屏，现场网络或设备不适合时可以展示。
- 只演示一条流程：电脑下单 → 出二维码 → 扫码报数量 → 看进度。功能和版本必须与实际交付相符。
- 准备一页价格及服务范围说明，不做官网、不买流量、不招聘。
- 准备简单拜访记录表，不开发新的获客系统。

### 开场白

> 老板您好，我做车间工单和报工软件。想问一下，你们客户催交货时，办公室能直接查到订单做到哪道工序，还是得去车间问？
>
> 如果这件事经常耽误你，我可以拿一个例子演示两分钟，看看是不是你们需要的。

接待人不是负责人时，如实说明来意，询问负责生产安排的人是否方便交流。不冒充采购客户，不强行进入生产区域。

先听问题，再展示。不要一开口堆“PDA、看板、500元、全程我一人维护”。单人服务情况如实说明，并讲清可提供的服务范围，不把它当作必然增加信任的卖点。

## 4. 哪些客户值得继续跟

需要同时看到以下三个条件：

1. **有具体麻烦：** 能说出近期一次进度不清、漏报数量等实际问题，以及造成的影响；仅仅“还在用纸”不够。
2. **有配合行动：** 老板支持，愿意指定负责人，拿真实工单、安排一个班组试跑。
3. **有购买可能：** 听清适用版本的正式价格、体验范围后，仍愿意约下一步。

下一步要有“谁、什么时候、做什么”。只说“发资料看看”先轻量跟进一次，没有明确行动就暂时放下；这不等于永久判定客户无价值。

首轮暂不承接必须新增大量功能、复杂ERP对接或长时间驻厂才能开始的客户。用金蝶是背景信息，不等于有需求；主动问多少钱，也不等于愿意投入人力实施。

## 5. 两个下午如何记录与复盘

| 日期/工厂 | 是否见到负责人 | 客户原话和具体问题 | 当前软件/报工方式 | 是否愿意提供真实单据及配合人 | 价格反馈 | 下一步及时间 | 本次总耗时 |
|---|---|---|---|---|---|---|---|
| 待填写 | | | | | | | |

分别统计到访数、负责人沟通数、明确痛点数、约定演示数。不要把加微信、收下资料算作成交进展。

| 观察到的情况 | 下一步 |
|---|---|
| 大多进不了门或负责人不在 | 先调整预约方式和时段，不用相同方式盲目扩大园区数量。 |
| 能聊，但对方不觉得问题值得解决 | 检查目标工厂和问题是否匹配，不先靠降价硬推。 |
| 说有需要，但不愿意提供工单或安排人 | 暂不配置体验账套，先确认谁负责推进。 |
| 愿意演示、配合并接受正式预算 | 优先推进这一家，首轮同时只带一家真实试用。 |
| 试用没有持续报工 | 查数据准备、操作负担、网络设备、负责人推动等原因，不能把收了500元当成功。 |

两个下午结束就复盘。若没有明确下一步，先暂停同样的跑法；不要等到126个负责人，更不要直接得出“产品没市场”。是否扩大投入，要由实际沟通和交付工时决定。

## 6. 500元体验与交付边界

本次用户提供的价格背景：500元体验7天；SaaS年费3500/8800/11800元；私有买断16800/26800元。500元是体验账套费用，不是正式软件售价，也不代表全套实施只收500元。

现有《未来落地总规划》还约定了抵扣、退款、存储、各档服务等内容。本文不修改这些政策。收款前给客户明确说明适用规则，不临场随意承诺。

建议首轮用一个班组、一张真实工单验证流程。若现有对外承诺包含更广的资料配置，先在报价单里与客户约定本次范围，不收款后再缩减服务。

需要写清的内容：

- 客户提供哪些资料、谁整理、谁录入，以及产品和工序的数量范围。
- 体验使用SaaS还是本地部署，是否包含上门、网络配置和设备调试。
- 谁培训、培训方式、问题反馈时间及额外工作的处理方式。
- 现有功能配置与新增代码开发的区别；新增功能和复杂接口不能混进500元无限承诺。
- 体验起止时间、到期资料处理及转正式的安排。现有PRD注明体验到期会清理业务资料和附件、禁用登录，不能承诺到期后数据仍一直保留。

试用观察建议：开始时跑通一单，中途检查是否实际使用，结束前与负责人核对结果和正式购买意愿。不要把完整ERP实施周期硬压成7天，7天只验证约定的小范围流程。

## 7. 对外表述要特别核对

### 金蝶对接

“金蝶配套”“不用换系统”容易被理解成无需重复录入、已完成数据互通。报价前核实金蝶产品版本、接口条件、数据对象、同步方向及实施范围。有演示不等于对所有金蝶客户都能直接交付。

若当前是独立运行，就直接说明独立运行及是否需要重复录入。不要把拟开发的接口说成现成能力。

### 3500元起与现场演示

现有《未来落地总规划》写明3500元档无工单打印、无ERP对接；8800元档包含工单打印和基础上门实施。因此，展示“打印流转卡＋扫码”的完整流程时，要说明对应档位，不能只说“3500元起”让客户误以为演示内容全部包含。

### 上门与驻厂

现有规划有“基础上门实施陪跑”“深度驻厂梳理工艺”等描述，尚需在具体报价中明确次数、时长、地域及客户配合条件。单人交付不能只按软件售价估算，还要记录往返、整理数据、培训和售后工时。

## 9. 与旧文档的关系

- 《推广定盘备忘录》存在“1000元三个月”等早期口径，本次讨论采用用户给出的500元7天背景；实际报价前统一核对，不混用旧话术。
- 本文的“先问问题、再报价”是对开场顺序的建议，不擅自改写原文“500元流量钩子”的营销政策。
- 本文不自动新增转介绍赠送、免费渠道合作或无限上门服务政策。
- 线上可以带来咨询，现场或远程人工交付帮助客户跑起来；两者并不冲突。当前只验证一个小范围陌拜入口，不同时铺开短视频、官网和代理招募。

**本轮完成标准：取得真实拜访记录，判断能否推进一家范围明确、客户愿意配合的试用。不能把“写完方案”“跑满数量”当成获客已验证。**
