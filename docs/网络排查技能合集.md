# 网络排查技能合集

> 两个可独立复用、也可组合使用的网络排查技能，均来自真实故障复盘（2026-10-23）。
> 共同主题：**国内 Windows 环境下，代理 / 直连 / hosts 三者的坑。**

---

## 通用方法论（两个技能共用）

1. **分层取证，一层一条命令钉死一个方向**，别跳步、别猜。
2. **先排除「本机配置」再怀疑「被墙」**：hosts、代理、config 键的位置，往往才是真凶。
3. **别一看到 TLS/连接报错就去改证书、修 schannel 缓存、换代理**——大多白费。
4. 判断"是否被墙"的最快方法：`curl`（或浏览器）直连目标，200 就基本排除被墙。

---

# 技能一：ChatGPT 桌面版连不上 /「正在重新连接」

> 适用：Windows 上 ChatGPT 桌面版（OpenAI.Codex）能开界面，但发消息提示「正在重新连接 1/5 → 5/5」。
> 一句话：**桌面版默认不读系统代理，必须 `[features] respect_system_proxy = true` 让它吃系统代理；
> 且这个键只能放 `[features]` 段，放顶层会被静默忽略。**

## 背景模型
- 桌面版 = 商店应用 `OpenAI.Codex`，底层是 Codex Rust 后端（`codex.exe`）。
- 两类连接：**HTTPS**（`chatgpt.com/backend-api/*`）与 **Responses WebSocket**（`wss://chatgpt.com/backend-api/...`）。
- 「正在重新连接」= WebSocket（实时通道）连不上。

## 三个关键坑
1. **默认不读代理**：忽略 Windows 系统代理，也忽略 `HTTP_PROXY`/`HTTPS_PROXY`。
2. **键的位置**：`respect_system_proxy` 是 feature flag，必须写在 `[features]` 段；放顶层会打印
   `` `respect_system_proxy` is ignored `` 且症状依旧。
3. **浏览器扩展管不了桌面版**：如「谷歌上网助手(Ghelper)」只代理浏览器流量，管不到桌面版进程。

## 诊断
```powershell
$codex = "C:\Users\bob\AppData\Local\OpenAI\Codex\bin\a96ca4c1eee0cf35\codex.exe"
& $codex doctor                                    # 看 reachability / websocket / handshake
& $codex exec "只回复两个字：收到"                  # 端到端：真发一条消息
```
`doctor` 解读：`✗ reachability`=HTTPS 不通；`✓ reachability`=HTTPS 通；`⚠ websocket handshake timed out`=实时通道挂；
`✓ websocket connected (HTTP 101)`=全链路 OK；`` `respect_system_proxy` is ignored ``=键写错位置。

## 修复（无 TUN 本地代理 + 系统代理 + 正确 config）
1. **本地代理**（mihomo/Clash 内核），**不开 TUN**，`mixed-port: 7890`，规则只把目标域名走节点、`MATCH,DIRECT`。
   注意机场节点可能是 `tls: true` 的 CDN 混淆 HTTPS 代理（`curl -x http://` 会失败，交给 mihomo 或用 `-x https://`）。
2. **系统代理**：`ProxyEnable=1`、`ProxyServer=127.0.0.1:7890`（WinINET）。
3. **桌面版 config**（`C:\Users\bob\.codex\config.toml`，先备份）：
   ```toml
   [features]
   respect_system_proxy = true
   suppress_unstable_features_warning = true   # 可选，压掉"实验特性"提示
   ```
   错误写法（顶层 `respect_system_proxy = true`）会被忽略。改完完全退出桌面版重开。

## 验证清单
1. `doctor` → `✓ websocket connected (HTTP 101)`。
2. `doctor` → `✓ reachability ... reachable over HTTP`。
3. `codex exec "只回复两个字：收到"` 能返回「收到」。
4. 代理日志：`chatgpt.com → PROXY[节点]`、`国内 → DIRECT`。
5. 百度能打开（证明没被 TUN 劫持）。

## 回退
停代理 + 系统代理 `ProxyEnable=0`；删掉 config 里的 `[features] respect_system_proxy`。

# 技能二：git push 到 GitHub 失败 / GitHub 突然连不上（hosts 过期 IP）

> 适用：`git push/pull/clone` 报 `unable to access`、`Could not connect to server`、`Connection reset`、
> `unexpected eof`；或「之前一直好好的，突然推不动了」。
> 一句话：**先别急着下「github 被墙」的结论——十有八九是 `hosts` 里的 GitHub 加速条目（GitHub520 等）
> 把 github.com 指到了已失效的 IP。改回可达 IP 即可，与代理/VPN 无关。**

## 背景
- 很多人用 **GitHub520** 在 `hosts` 写死 github 域名 IP 来绕过 DNS 污染；这些 IP 会**随时间失效**。
- 真实可达 github.com IP：`140.82.112.3`、`140.82.113.3`、`140.82.114.3`（`.3` 尾缀=主站）。
- 常见失效 IP：`20.205.243.166`（Azure 东亚）、`140.82.121.3` 等。

## 分层（和 HTTP/2 是两码事）
| 层 | 报错 | 根因 | 处理 |
|---|---|---|---|
| 网络/TCP | `Could not connect to server`、`Connection reset` | hosts 过期 IP / 真被墙 | 查 hosts、换 IP、走代理 |
| TLS/HTTP2 | `unexpected eof`、`schannel: failed to receive handshake` | git 的 HTTP/2 被重置 | `git config --global http.version HTTP/1.1` |
| 代理 | 走代理也不通 | 节点/规则 | 换节点/全局 |

## 诊断
```powershell
Select-String -Path C:\Windows\System32\drivers\etc\hosts -Pattern github   # 1) hosts 指向哪个 IP
ping -n 1 github.com                                                         # 2) 实际解析(ping 走 hosts)
foreach ($ip in '140.82.112.3','140.82.113.3','140.82.114.3','20.205.243.166') {
  "$ip : $((Test-NetConnection $ip -Port 443 -WarningAction SilentlyContinue).TcpTestSucceeded)"  # 3) 逐个测 TCP
}
git ls-remote https://github.com/<user>/<repo>.git HEAD                       # 4) 直连
git -c http.proxy=http://127.0.0.1:7890 ls-remote https://github.com/<user>/<repo>.git HEAD  # 走代理
```
判定：hosts 指到测不通的 IP 而其它 IP 通 → hosts 过期；全不通+走代理通 → 真被墙；TCP 通但 `unexpected eof` → HTTP/2 层。

## 修复（hosts 过期时）
```powershell
$h = "C:\Windows\System32\drivers\etc\hosts"
Copy-Item $h "$h.bak" -Force
$c = (Get-Content $h -Raw) -replace '20\.205\.243\.166\s+github\.com', '140.82.112.3        github.com'
Set-Content $h $c -NoNewline -Encoding ASCII
ipconfig /flushdns
```
> 普通 PowerShell 写 hosts 会「访问被拒绝」，需提权：存成 `.ps1` 再 `Start-Process powershell -Verb RunAs -ArgumentList '-File','脚本.ps1'`（UAC 点确定）。

## 兜底（直连不可靠时）
- 走本地代理：`git -c http.proxy=http://127.0.0.1:7890 push origin master`。
- 只给 github 配代理：`git config --global http.https://github.com.proxy http://127.0.0.1:7890`。

## 速查避坑表（两技能通用）

| 坑 | 表现 | 正解 |
|---|---|---|
| 一看到失败就说「被墙」 | 误判、白折腾 | 先查本机（hosts/代理/config 位置） |
| `respect_system_proxy` 放顶层 | `` is ignored `` + 仍重连 | 放 `[features]` 段 |
| 浏览器扩展当代理 | 网页版能、桌面版不能 | 桌面版要系统代理或 TUN |
| 开 TUN | 百度打不开 / 要关 IPv6 | 系统代理模式，别开 TUN |
| `tls:true` 混淆节点直连 | `curl -x http://` 失败 | 交给 mihomo 或 `-x https://` |
| hosts 有 GitHub520 条目 | 之前通、突然不通 | 条目过期，更新 IP |
| 用 `Resolve-DnsName` 查 hosts | 看不到 hosts 结果 | 用 `ping` 或 `[Net.Dns]::GetHostAddresses()` |
| 写 hosts「访问被拒绝」 | 权限不够 | RunAs 提权 |
| TCP 通但 TLS 挂 | `unexpected eof` | HTTP/2 层，别当 hosts 问题 |

## 真实案例（2026-10-23, workshop-mes）
1. **ChatGPT 桌面版「正在重新连接」**：`respect_system_proxy` 误写顶层被忽略 → 改到 `[features]` 段，WebSocket 即刻 101 连通。
2. **git push GitHub 失败**：hosts 里 GitHub520 把 `github.com → 20.205.243.166`（已失效）→ 改回 `140.82.112.3` + flushdns，git 直连即通。
