# 60 · 登录界面分析与改造建议

> 日期：2026-09-24  
> 受众：工厂老板、车间报工人员（非开发演示受众）  
> 配套执行指令：[已做指令/60-Cursor执行指令-登录页中文与可读性改造.md](已做指令/60-Cursor执行指令-登录页中文与可读性改造.md)（**已实现** 2026-09-24）

## 1. 结论（一句话）

把登录页从「英文临时名 + 偏散的信息」收成：**中文厂名眉标 +「车间小工单系统」+ 大字号账号密码表单**；稳重、好认、好点，不要厂房大图和科技光效。

## 2. 现状（实现后）

| 项 | 现状 |
|---|---|
| 产品名 | 登录页固定「车间小工单系统」 |
| 厂名眉标 | `Instance:DisplayName`；`WorkShop`/`WorkshopB` 等英文占位会被清洗，不显示眉标 |
| 仓库默认 DisplayName | `车间小工单系统`（B 实例模板为「演示工厂B」） |
| 副标题 | PC「生产进度 · 工单管理 · 报工统计」；窄屏「扫码报工，查看生产任务」 |
| 密码显隐 | Element Plus `show-password` |
| 登录后跳转 | 支持 `?redirect=/h5/...`；无 redirect 进 `/order` |
| 部署铁律 | 客户机 appsettings **禁止覆盖**；DisplayName 需手工改中文厂名 |

## 3. 问题归纳

1. **业务辨识度差**：`WorkShop` 像开发代号，老板和工人第一眼不知道是「自家车间系统」。
2. **副标题浪费**：「账号 + 密码登录」不提供新信息。
3. **字号与对比偏弱**：副标题/版本用浅灰小字，现场灯光与年纪稍大的使用者不友好。
4. **视觉重心松散**：标题居中、标签偏左、手册与版本挤在卡片内底部，层次不清。

## 4. 对标借鉴（公开产品定位，不照搬登录页布局）

- **黑湖小工单**：围绕工单、报工、进度讲产品——登录副文案可用「生产进度 · 工单管理 · 报工统计」。
- **金蝶智慧工厂**：强调生产进度、异常、质量等管理内容——文案要具体、中文、一看就懂。

原则：借「业务表达」，不借「炫酷视觉」。车间交付软件优先清楚、稳重、好操作。

## 5. 改造建议（拍板）

| 项 | 建议 |
|---|---|
| 产品名 | 固定中文：**车间小工单系统**（与项目定位、`index.html` title 一致） |
| 企业标识 | `Instance:DisplayName` 作**厂名/实例名眉标**；若为空、为 `WorkShop`/`Workshop`、或与产品名相同，则不单独显示眉标，只留产品名 |
| 副标题（PC） | `生产进度 · 工单管理 · 报工统计` |
| 副标题（窄屏/H5 登录同页） | 可用同一句，或改为 `扫码报工，查看生产任务`（CSS/宽度判断即可，不必拆两套页面） |
| 表单 | 「账号」「密码」**标签在输入框上方**（`label-position="top"`），左对齐 |
| 控件尺度 | 输入与主按钮高度约 48–52px；主要文字 ≥16px |
| 配色 | 沿用现有主题令牌：浅灰底、白卡片、深蓝主色（`--app-primary`），不新开紫/科技风 |
| 密码 | 验收现有显隐即可 |
| 帮助 | 表单下：「账号或密码有问题，请联系管理员」；「操作手册」作次要链接 |
| 版本号 | 移到**卡片外**底部，小字但可读 |
| 布局 | 保留居中卡片；PC 宽约 400px；手机接近满宽 |
| 角色选择 | **不做**登录前「老板/员工」分流；登录后按 role 进页 |

### 配置口径（与 docs/23 一致）

- `Instance:DisplayName`：客户现场应填**中文厂名或客户认可名称**（如「××制造」），不要英文开发代号。
- 仓库开发默认值改为「车间小工单系统」，避免本机一打开就是 WorkShop。
- **已部署客户机**：在服务器上**手工**改 `DisplayName`，不得靠覆盖整个 `appsettings.json` 更新。

## 6. 明确不做

- 厂房大图、粒子光效、英文 slogan、登录前角色选择页。
- 改登录接口契约、改表结构、改 JWT。
- 覆盖客户机 `appsettings*.json` / `start.bat`。

## 7. 验收观感（目标）

顶部（可选）厂名 → 中间「车间小工单系统」→ 业务向副标题 → 大号账号密码 → 登录按钮 → 管理员提示 + 手册链接；版本号在卡片外。中文明确、字号够大、蓝白稳重，像正式交付软件。
