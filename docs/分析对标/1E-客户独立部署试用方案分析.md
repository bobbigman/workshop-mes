## 1. 已确定的方向

眼下两三家客户试用，每客户单独部署一份程序、一个数据库、一个专属网址。
客户拿到网址、用户名、密码即可使用；成交后把其程序配置、数据库及附件迁到客户电脑。

程序来自同一套源代码、同一标准发布包；各实例只在配置、运行进程、端口、数据和密钥上独立。不得复制出各自长期修改的代码分支。

## 2. 部署关系

| 客户 | 入口示例（待配置，非现有地址） | 程序 | 数据 |
|---|---|---|---|
| 甲 | https://a.example.com | 独立目录、IIS 站点/池与内部端口 | 甲数据库、甲附件目录 |
| 乙 | https://b.example.com | 独立目录、IIS 站点/池与内部端口 | 乙数据库、乙附件目录 |
| 丙 | https://c.example.com | 独立目录、IIS 站点/池与内部端口 | 丙数据库、丙附件目录 |

这些实例可以放在同一台试用服务器上。域名由反向代理分发到对应程序，数据库也可以位于同一个 SQL Server 实例内。
同机部署仍共享 CPU、内存、磁盘和故障风险，不等同于每客户独立服务器。
共用同一 SQL Server 时，磁盘满、误删库、整机备份失败会影响全部试用客户——台账须注明资源与备份责任，不能误以为「库名不同 = 运维爆炸半径独立」。

每份程序始终连接自己配置的数据库；不根据登录输入动态换库。
数据库账号各自限制到本客户库，不能让所有应用共用 sa。
JWT 密钥与 Issuer/Audience 各实例独立（约定见 23 §3），使甲客户登录凭证不能在乙实例使用。

## 3. 相比管理中心方案，省掉什么

本期不需要管理库、平台管理员、TenantContext、请求级动态连接、租户字段改造、统一试用期限引擎。
沿用现有固定连接、工厂表和账号体系。原有产品唯一、部门报工权限、删除依赖等业务规则保持。

账套的开通、到期停用和续期先由你人工管理，使用简单部署台账。未建立计费或自动停用能力。
以后开通/维护实例明显费力时，再评估管理中心；独立数据库仍能作为后续基础，但不能承诺届时零改造。

## 4. 客户体验

客户打开自己的网址，登录页显示公司名称或“某公司试用环境”，仅需填写账号和密码。
工厂代码由本实例服务端配置提供；请求可空（走配置）或与配置一致；非空且不匹配必须拒绝，不得让客户通过修改它切换目标工厂或数据库。
后台页头也显示公司名称，便于你同时检查多个实例。

采用独立主机名优先于同域名的不同路径。不同路径仍共用浏览器 origin 和 localStorage，容易造成现有 token 相互覆盖；不同主机名可沿用现有登录存储，减少前端改造。
网址只是入口，数据访问仍依赖服务端身份验证。

## 5. 最小必要改造

| 内容 | 优先级 | 处理 |
|---|---|---|
| 客户名称、默认工厂 | P0 | 增加实例配置及最小公开展示接口 |
| 登录页 | P0 | 显示本客户名称，去掉演示账号密码预填，隐藏工厂代码 |
| 身份隔离 | P0 | 每实例独立强密钥与 iss/aud，验证跨实例 token 被拒绝 |
| 演示入口 | P0 | 关闭固定验证码手机号登录；默认关闭 MCP 及配对授权入口 |
| 初始化 | P0 | 首次按本客户配置初始化，禁止每次启动重设密码或补入演示数据 |
| 部署 | P0 | 标准发布包、每实例配置模板、IIS 独立站点/池、端口及日志目录 |
| 维护 | P0 | 独立备份、升级、停用、恢复；一份脱敏部署台账 |
| 登录限流 / 追踪号 / 权威文档全文同步 | P1 | 见 23；不挡发放试用 |

工单、报工、工资、看板等业务尽量不动。已有数据库升级和启动补丁需在副本验证，不能因实例少就省略。

## 6. 开通流程

1. 为客户确定内部代码、显示名称、独立网址及内部端口（**先锁死试用机与子域名/证书，再批量开通**）。
2. 创建独立数据库与限定权限的运行账号，按权威结构初始化。
3. 建立独立发布目录，放入相同版本发布包及该客户配置。
4. 设置独立 JWT 密钥与 iss/aud、日志与附件目录。
5. 创建客户管理员，使用每客户不同的初始密码，要求交付后修改。
6. 配置 HTTPS 和反向代理 / IIS 主机名绑定，验证电脑、手机/PDA及看板。
7. 验证甲乙实例不能互用凭证、不会读写对方数据。
8. 记录备份和停用方法后发放网址与账号密码。

第一家做成模板，第二家复用并验证隔离，第三家再按清单复制。
复制的是干净发布包，不是上一客户的数据库、密码配置或附件。

## 7. 公开试用的实际限制

当前代码存在固定验证码手机号登录、预填演示密码、默认初始化及 MCP 演示入口。公开试用前需要按开发指令处理。
试用服务器必须能稳定访问，配置 HTTPS；登录频率限制属 P1，可用代理层顶住。
试用期满可以停对应 IIS 应用池或阻断该实例入口；不可只隐藏登录按钮。
MCP/AI/金蝶集成如确需演示，另行逐实例配置并检查凭据和权限，不能共用万能凭据。

这里只处理与公开试用直接相关的必要事项，不建设大型平台安全或计费系统。

## 8. 成交后迁到客户电脑

先停止该客户试用服务并确认无在途写入，再备份数据库、附件和必要配置。
在客户电脑部署匹配版本程序及兼容 SQL Server（仍按 IIS），恢复数据，设置本地地址和新的身份密钥。
本地实例直接连接本地库，不依赖你公网服务；核心车间业务可离线于公网运行。
核对工单数量、报工汇总、工资结果及附件，验证 PDA/手机局域网访问。
确认后原试用实例保持停用，按约定保留备份，不能云端本地同时写入。

客户电脑需固定局域网地址、自动启动、防休眠和定期备份。含公网网址的二维码需更新，纯工单号二维码在对应本地工厂内解析。
外部 AI/金蝶等服务是否可用，取决于其网络与配置，不属于核心业务离线承诺。

## 9. 工作量判断

与多账套管理中心相比，改动明显缩小，以配置化、部署整理、演示入口收口和隔离验证为主。
每增加客户会增加一个 IIS 站点/池及一套数据库的资源与维护成本；两三家阶段接受人工维护通常更合适。
升级须逐实例执行，不是改一次代码就自动覆盖全部客户。
不预估未经验证的固定天数。完成标准是两套实例能并行独立使用，且一套数据能恢复到本地电脑独立运行（以 23 的 P0 验收为准）。
