# 车间小工单：预警、查看与复核 Use Case 分析文档

**版本：** v1.1  
**变更记录：** v1.1 修正 UC-05 参与者为「工人/班组长」；第四节补「用例关系（include / extend）」。  
**分析观点：** 以使用案例驱动、物件导向分析。使用案例不是功能清单，而是参与者与系统之间为达成可观察结果的一次交互契约。  
**适用范围：** 试用期系统内预警；正式期企业微信应用消息推送。  
**参考：** 1A「把查看做成管理动作」、1B「微信预警推送（企业微信版）落地文档」。

---

## 一、系统边界与上下文

**系统内部：** 工单、工序、报工、看板、待办、预警规则、推送配置、聚合、审计。  
**外部系统：** 企业微信应用消息 API。  
**外部时间参与者：** 调度器，负责定时触发超期、停滞、每日汇总检查。  
**终端：** 电脑浏览器、工人手机 H5、PDA 扫码枪。

**核心原则：**
1. 查看不是报表，而是管理动作：看板 → 待办 → 复核 → 数据生效。
2. 企业微信是外部系统参与者，不是内部功能。
3. 试用期默认关闭微信推送，先做系统内预警。
4. 正式启用企业微信推送，需工厂注册企业微信并完成认证；认证按次收费（小型企业 300 元/次，有效期一年、到期需重新认证），费用腾讯收取、由工厂承担。

## 二、参与者

| 参与者 | 类型 | 主要利益 |
|---|---|---|
| 工人 | 主要 | 快速报工，少填表，工资数据准确 |
| 班组长 | 主要 | 掌握本组进度，复核报工，处理异常 |
| 厂长/老板 | 主要 | 看全厂进度，接收关键预警，不用跑车间追问 |
| 系统管理员 | 主要 | 配置规则、管理推送、控制启用范围 |
| 企业微信应用 | 外部系统 | 接收并投递企业微信应用消息 |
| 调度器 | 外部时间参与者 | 定时触发超期、停滞、汇总推送 |

- 调度器 → UC-04 工单超期预警、UC-06 工序停滞预警、UC-10 发送企业微信聚合预警。
- 企业微信应用 → UC-10 发送企业微信聚合预警。

### 用例关系（include / extend）

- **extend（扩展，可选分支）**
  - UC-01 扫码报工 ← 扩展 UC-05 报工异常预警：仅当报工提交校验异常（良品超剩余计划数，或良品+报废>投入）时才触发 UC-05；正常报工不经过它。
  - UC-04 工单超期、UC-05 报工异常、UC-06 工序停滞 ← 扩展 UC-10 发送企业微信聚合预警：仅正式期已启用企业微信时，预警才走聚合推送；否则只停在本系统内待办。
- **展示出口（看板呈现预警）**
  - UC-04、UC-06 的预警结果在 UC-03 看板上以红标高亮呈现；UC-03 的逾期数字 / 异常待办可点击，跳转 UC-11 处理预警待办。
- **收敛到待办（预警 → 处理）**
  - UC-04/05/06 生成的预警事件，统一进入 UC-11 处理预警待办，UC-11 是三类预警的处理出口，处理必须留痕。
  - UC-02 复核报工发现异常时（扩展场景 3b），转 UC-11 处理。

## 五、详细用例

### UC-01 扫码报工

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 工人
- **涉众与利益：** 工人希望 10 秒内完成报工；班组长希望数据可复核；老板希望数据最终进入工资与进度。
- **前置条件：** 工人已登录；工单已下发；工序已配置；二维码可扫描。
- **触发事件：** 工人扫描流转卡二维码，或搜索工单。
- **主成功场景：**
  1. 工人扫码进入报工页。
  2. 系统显示工单、工序、剩余计划数。
  3. 工人输入良品数、不良品数、工时。
  4. 系统校验良品数 ≤ 该工序剩余计划数。
  5. 系统保存报工记录，状态为“待复核”。
  6. 系统刷新本组看板与全厂看板。
- **扩展场景：**
  - 4a 良品数超过剩余计划数：系统拦截，提示“超过剩余计划数”，要求修改或申请主管授权。
  - 4b 良品 + 报废 > 投入：系统标记“数据异常”，转 UC-05。
  - 4c 网络中断：暂存本机，恢复后重传。
- **后置条件：** 报工记录已保存，状态“待复核”，未进入工资计算。
- **业务规则：** BR-07 报工异常不进工资计算；BR-08 班组长复核后数据才生效。
- **非功能需求：** 报工提交响应 < 2 秒；手机页面适配。
- **BCE 物件：**
  - 边界：报工页、扫码入口。
  - 控制：报工控制器、异常校验器。
  - 实体：工单、工序、报工记录、用户。

### UC-02 班组长复核报工

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 班组长
- **涉众与利益：** 班组长履行审批职责；工人工资数据准确；老板放心数据质量。
- **前置条件：** 存在“待复核”报工记录。
- **触发事件：** 班组长打开待办列表，或系统提示有待复核记录。
- **主成功场景：**
  1. 班组长进入待复核列表。
  2. 系统按工单、工人、工序列出待复核记录。
  3. 班组长逐条查看数量、工时、异常标记。
  4. 班组长确认无误，点击“复核通过”。
  5. 系统将报工记录状态改为“已生效”。
  6. 系统更新看板、工资计算、预警状态。
- **扩展场景：**
  - 3a 班组长发现数量错误：点击“退回修改”，填写原因。
  - 3b 班组长发现异常：转 UC-11 处理预警待办。
  - 4a 批量复核：支持勾选多条一次通过，但异常记录必须逐条确认。
- **后置条件：** 报工记录生效，进入工资计算与进度统计。
- **业务规则：** 复核是管理动作，不是可选操作；未复核数据不进入工资。
- **非功能需求：** 待复核列表加载 < 3 秒；支持手机与电脑。
- **BCE 物件：**
  - 边界：待复核列表页、复核详情页。
  - 控制：复核控制器、状态流转器。
  - 实体：报工记录、复核日志、用户。

### UC-03 分角色查看生产看板

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 工人、班组长、厂长/老板
- **涉众与利益：** 不同角色只看自己关心的数据，避免信息过载。
- **前置条件：** 用户已登录，角色已配置。
- **触发事件：** 用户打开首页或看板。
- **主成功场景：**
  1. 工人登录：看到自己负责的工单进度、待报工工序。
  2. 班组长登录：看到本组所有人实时报工进度、待复核数量、异常待办。
  3. 厂长登录：看到全厂今日投产量、完工量、不良率、逾期预警工单数。
  4. 系统按角色过滤数据，刷新页面。
- **扩展场景：**
  - 2a 班组长发现某工人长时间未报工：转 UC-06 工序停滞预警。
  - 3a 厂长点击逾期预警数字：跳转 UC-11 预警待办。
- **后置条件：** 用户获得可行动信息，而非单纯数据。
- **业务规则：** 查看即管理动作；看板必须能跳转到待办或详情。
- **非功能需求：** 看板首屏 < 3 秒；手机端适配。
- **BCE 物件：**
  - 边界：看板页、角色视窗。
  - 控制：看板控制器、权限过滤器。
  - 实体：用户、部门、工单、报工记录、预警事件。

### UC-04 工单超期预警

- **范围：** 车间小工单
- **层级：** 子功能级
- **主要参与者：** 调度器、班组长、厂长
- **前置条件：** 工单有“计划完成时间”；工单状态为“进行中”。
- **触发事件：** 调度器定时检查，或用户打开看板时实时计算。
- **主成功场景：**
  1. 调度器检查所有进行中工单。
  2. 若当前时间 > 计划完成时间，生成“工单超期”预警事件。
  3. 系统在看板红色高亮，并进入班组长、厂长待办。
  4. 正式期若已启用企业微信，按聚合规则推送。
- **扩展场景：**
  - 2a 工单已结束：不生成预警。
  - 2b 工单已取消：不生成预警。
  - 4a 推送失败：降级为系统内待办，不重复轰炸。
- **后置条件：** 预警事件已生成，待办可见，必要时已推送。
- **业务规则：** 同一工单同一超期异常，当天只推一次；一般异常每日傍晚汇总。
- **非功能需求：** 定时检查不阻塞报工；预警生成 < 1 秒。
- **BCE 物件：**
  - 边界：看板红标、待办列表。
  - 控制：预警规则引擎、调度器、聚合器。
  - 实体：工单、预警事件、推送配置。

---

### UC-05 报工异常预警

- **范围：** 车间小工单
- **层级：** 子功能级
- **主要参与者：** 工人、班组长
- **前置条件：** 工人提交报工。
- **触发事件：** 报工提交时校验不通过，或后端审计发现异常。
- **主成功场景：**
  1. 系统校验良品数、报废数、投入数。
  2. 若良品数超过剩余计划数，或良品 + 报废 > 投入，生成“报工异常”预警。
  3. 系统拦截提交或标记“待复核”。
  4. 异常记录进入班组长待办，并暂停工资计算。
  5. 班组长处理：授权通过、退回修改、或标记异常。
- **扩展场景：**
  - 2a 单次报工数量远超历史平均产能：弹窗警告，需主管授权。
  - 5a 班组长授权通过：记录授权人、时间、原因。
  - 5b 班组长退回：工人重新报工。
- **后置条件：** 异常记录被处理，数据要么生效，要么退回。
- **业务规则：** 异常数据不进工资；授权必须留痕。
- **非功能需求：** 校验 < 1 秒；授权记录不可删除。
- **BCE 物件：**
  - 边界：报工页弹窗、待办列表。
  - 控制：异常校验器、授权控制器。
  - 实体：报工记录、预警事件、授权日志。

---

### UC-06 工序停滞预警

- **范围：** 车间小工单
- **层级：** 子功能级
- **主要参与者：** 调度器、班组长
- **前置条件：** 工单已开始；工序已配置；有停滞时长阈值。
- **触发事件：** 调度器定时检查。
- **主成功场景：**
  1. 调度器检查各工单当前工序。
  2. 若某工序超过设定时长无报工记录，生成“工序停滞”预警。
  3. 系统在看板高亮，并进入班组长待办。
  4. 正式期按聚合规则推送企业微信。
- **扩展场景：**
  - 2a 工单已暂停：不生成预警。
  - 2b 已报工但未复核：仍算有报工，不生成停滞。
- **后置条件：** 班组长知道哪道工序卡住。
- **业务规则：** 停滞阈值可按工序配置。
- **非功能需求：** 定时检查频率可配置，建议每小时一次。
- **BCE 物件：**
  - 边界：看板、待办。
  - 控制：停滞检查器、调度器。
  - 实体：工单、工序、报工记录、预警事件。

### UC-07 配置预警规则

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 系统管理员
- **前置条件：** 管理员已登录。
- **触发事件：** 管理员进入预警设置。
- **主成功场景：**
  1. 管理员设置工单超期阈值、报工异常规则、停滞时长。
  2. 管理员设置聚合时间窗口、每日推送上限。
  3. 系统保存规则并生效。
- **扩展场景：**
  - 1a 规则冲突：系统提示并阻止保存。
  - 3a 修改规则：记录修改人、时间、前后值。
- **后置条件：** 预警规则已更新。
- **业务规则：** 规则变更需留审计日志。
- **非功能需求：** 保存 < 1 秒。
- **BCE 物件：**
  - 边界：预警设置页。
  - 控制：规则控制器。
  - 实体：预警规则、审计日志。

### UC-08 管理微信推送设置

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 系统管理员
- **前置条件：** 管理员已登录。
- **触发事件：** 管理员点击“微信预警推送”。
- **主成功场景：**
  1. 试用期：显示静态说明页。
  2. 说明页写明：正式启用需工厂注册企业微信并完成认证；认证按次收费（小型企业 300 元/次，有效期一年、到期需重新认证），费用腾讯收取。
  3. 说明页建议：先让工人熟悉扫码报工，再开启微信推送。
  4. 管理员可手动开启或关闭推送。
- **扩展场景：**
  - 1a 第一次点入弹说明，之后不再弹。
  - 4a 关闭推送：系统内预警继续工作。
- **后置条件：** 管理员了解门槛与建议，推送状态明确。
- **业务规则：** 试用期默认关闭微信推送；是否开启由管理员手动决定。
- **非功能需求：** 说明页静态加载 < 1 秒。
- **BCE 物件：**
  - 边界：推送设置页、说明弹窗。
  - 控制：推送设置控制器。
  - 实体：推送配置、审计日志。

### UC-09 启用企业微信推送

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 系统管理员
- **前置条件：** 工厂已注册企业微信并完成认证；已创建自建应用。
- **触发事件：** 管理员填写 CorpID、Secret、AgentID。
- **主成功场景：**
  1. 管理员输入企业微信配置。
  2. 系统校验配置连通性。
  3. 管理员配置接收人映射。
  4. 系统保存配置，启用企业微信推送通道。
  5. 上层 `sendWechatAlert` 内部替换为企业微信 API 调用。
- **扩展场景：**
  - 2a 配置错误：提示具体错误，不启用。
  - 3a 接收人未映射：该用户只收系统内预警。
- **后置条件：** 企业微信推送通道可用。
- **业务规则：** 认证费由工厂承担；配置加密保存。
- **非功能需求：** 配置校验 < 5 秒。
- **BCE 物件：**
  - 边界：企业微信配置页。
  - 控制：企业微信适配器、配置校验器。
  - 实体：推送配置、接收人映射。

---

### UC-10 发送企业微信聚合预警

- **范围：** 车间小工单
- **层级：** 子功能级
- **主要参与者：** 调度器、企业微信应用
- **前置条件：** 企业微信推送已启用；存在待推送预警事件。
- **触发事件：** 调度器到达聚合时间窗口，或严重异常实时触发。
- **主成功场景：**
  1. 聚合器收集待推送预警事件。
  2. 按接收人、工单、异常类型去重。
  3. 生成聚合消息：如“今日有 3 个工单超期，点击查看”。
  4. 调用 `sendWechatAlert`。
  5. 企业微信应用投递消息。
  6. 记录推送结果。
- **扩展场景：**
  - 3a 同一工单同一异常当天已推：跳过。
  - 5a 推送失败：重试不超过 3 次，仍失败则降级系统内待办。
  - 5b 链接手机打不开：消息只提示“请打开车间系统查看”。
- **后置条件：** 消息已投递或已降级。
- **业务规则：** 严重异常可实时推；一般异常每日汇总；所有推送可一键关闭。
- **非功能需求：** 推送不阻塞主流程；失败可追踪。
- **BCE 物件：**
  - 边界：企业微信消息。
  - 控制：聚合器、推送调度器、企业微信适配器。
  - 实体：预警事件、推送日志、接收人映射。

### UC-11 处理预警待办

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 班组长、厂长
- **前置条件：** 存在预警待办。
- **触发事件：** 用户打开待办列表，或点击微信消息链接。
- **主成功场景：**
  1. 用户看到待办列表，按严重程度排序。
  2. 用户点击某条预警，进入详情。
  3. 用户处理：确认、授权、退回、标记已处理。
  4. 系统更新预警状态，记录处理人与时间。
- **扩展场景：**
  - 3a 用户无法处理：转交他人。
  - 3b 误报：标记“误报”，记录原因。
- **后置条件：** 预警关闭或转交。
- **业务规则：** 处理必须留痕。
- **非功能需求：** 待办加载 < 3 秒。
- **BCE 物件：**
  - 边界：待办列表、预警详情。
  - 控制：待办控制器、状态流转器。
  - 实体：预警事件、处理日志。

### UC-12 查看预警历史与审计

- **范围：** 车间小工单
- **层级：** 用户目标级
- **主要参与者：** 厂长、系统管理员
- **前置条件：** 用户有权限。
- **触发事件：** 用户进入预警历史。
- **主成功场景：**
  1. 用户按时间、工单、类型、处理人筛选。
  2. 系统显示预警事件、处理过程、推送记录。
  3. 用户可导出。
- **扩展场景：**
  - 3a 无权限：拒绝访问。
- **后置条件：** 用户获得审计视图。
- **业务规则：** 审计日志不可删除。
- **非功能需求：** 查询 < 5 秒。
- **BCE 物件：**
  - 边界：预警历史页。
  - 控制：审计查询控制器。
  - 实体：预警事件、推送日志、处理日志。

## 六、业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-01 | 试用期默认关闭微信推送。 |
| BR-02 | 企业微信认证按次收费（小型企业 300 元/次，有效期一年、到期需重新认证），费用腾讯收取、由工厂承担。 |
| BR-03 | 同一工单同一异常，当天只推一次。 |
| BR-04 | 严重异常可实时推，一般异常每日傍晚汇总。 |
| BR-05 | 推送失败自动降级为系统内待办。 |
| BR-06 | 所有推送可一键关闭。 |
| BR-07 | 报工异常不进工资计算。 |
| BR-08 | 班组长复核后数据才生效。 |
| BR-09 | 所有预警处理与授权必须留痕。 |

## 七、非功能需求

1. 系统内预警响应 < 2 秒。
2. 企业微信配置加密保存。
3. 推送失败重试不超过 3 次。
4. 手机链接必须可达，否则只提示打开系统。
5. 审计日志保留，不可删除。
6. 看板首屏 < 3 秒。
7. 所有推送可关闭。

## 八、物件导向分析摘要

**边界物件：** 报工页、看板页、待办页、预警设置页、企业微信配置页、说明弹窗。  
**控制物件：** 报工控制器、复核控制器、预警规则引擎、调度器、聚合器、企业微信适配器、推送设置控制器。  
**实体物件：** 用户、部门、工单、工序、报工记录、预警事件、预警规则、推送配置、接收人映射、推送日志、审计日志。

## 九、最小落地清单

1. 试用期：系统内预警 + 静态说明页，微信推送关闭。
2. 先做三类预警：工单超期、报工异常、工序停滞。
3. 班组长复核报工作为必经管理动作。
4. 封装 `sendWechatAlert`，试用期空实现。
5. 正式期：工厂注册企业微信并认证，费用工厂承担。
6. 启用企业微信应用消息，聚合限频、可关闭、失败降级。
7. 所有处理留痕，审计不可删。

**一句话总结：试用期先把“查看—待办—复核—生效”做成管理闭环，正式期再以企业微信应用消息作为微信推送通道，费用工厂承担，聚合限频、可关闭、可审计。**
