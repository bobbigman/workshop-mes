# MCP 连接器接入避坑指南

> 基于 `workshop-laoShen`（WorkshopMes v1.1.118.0）实战测试总结
> 整理时间：2026-09-29

---

## 一、一句话结论

**连接器服务端没问题，坑全在「客户端加载」这一层。**

本次案例中，服务端直连一次握手成功（0.4s，8 个工具全部可用），但客户端会话里始终看不到 `query_work_order` 等工具——**问题 100% 出在配置读取环节，不在你的代码。**

---

## 二、最快的验证路径：直接贴配置给我

### ✅ 推荐做法

遇到连接器连不上，**第一件事就是把 MCP 配置原文贴给我**：

```json
{
  "mcpServers": {
    "workshop-laoShen": {
      "type": "streamable-http",
      "url": "https://410df73d.r18.cpolar.top/mcp",
      "headers": {
        "Authorization": "Bearer laohu-demo-2026-server"
      },
      "disabled": false
    }
  }
}
```

**为什么这样做有效**

| 优势 | 说明 |
|---|---|
| **绕过客户端加载层** | 我从沙箱直连你的端点，测的是连接器本身，不受客户端配置是否生效影响 |
| **一次定位问题层** | 直连能通 → 问题在客户端；直连不通 → 问题在服务端。一步砍掉一半排查范围 |
| **可复现、可量化** | 能拿到具体状态码、握手耗时、工具清单、字段内容 |
| **不依赖会话状态** | 中途改配置、会话级缓存这类问题全部绕开 |

### ⚠️ 注意事项

- **贴配置时说明这是不是生产 token** —— demo token 可以贴；生产环境的 key 建议先脱敏或临时换成 demo 值
- **只贴必要字段** —— `type` / `url` / `headers` 就够，其他无关配置不用带
- **贴完明确你要测什么** —— 比如"取工单"、"查进度"，我好直接跑对应工具

## 三、客户端加载层：四个高频坑

### 坑 1：配置是会话级加载的，中途加不生效

MCP 服务列表通常在**客户端启动时**读取一次。

```
❌ 错误做法：开着会话 → 改配置 → 指望它热更新
✅ 正确做法：改配置 → 完全退出客户端进程 → 重新启动
```

**注意区分**：
- ❌ 刷新页面 —— 不生效
- ❌ 新开一个会话 —— 不一定生效
- ✅ **退出进程再启动** —— 这才是真正重启

**判断方法**：改完重启后，让我列一下可用工具，看有没有你的工具名（如 `query_work_order`）。有 = 加载成功。

---

### 坑 2：配置写在了别的客户端文件里

`mcpServers` 是 **Claude Desktop / Cursor 风格**的配置格式，各客户端读的文件**不是同一个**。

| 你可能写到 | 实际读取方 | 结果 |
|---|---|---|
| Claude Desktop 的 `claude_desktop_config.json` | Claude Desktop | WorkBuddy 读不到 |
| Cursor 的 MCP 配置 | Cursor | WorkBuddy 读不到 |
| 项目目录下随手建的 json | 没人读 | 静默失效 |

**排查动作**：
1. 先确认 **WorkBuddy 的 MCP 配置文件在哪**（通常在用户配置目录，**不是项目目录**）
2. 确认 `workshop-laoShen` 确实写进了那个文件
3. 改完重启

---

### 坑 3：`disabled: false` 字段不被识别

不同客户端对字段名要求不一：

```json
// 部分客户端用这个
{ "disabled": false }

// 另一些客户端用这个
{ "enabled": true }
```

**如果配置写对了、路径也对，但服务还是不加载，先试把 `disabled: false` 换成 `enabled: true`。**

这个坑的特点是**静默失效**——不报错、不提示，服务就是不出现，最难查。

---

### 坑 4：「连接器」和「MCP 服务」是两个独立入口

这是本次踩过的一个弯路，值得单独记：

| 概念 | 查什么 | 对应接口 |
|---|---|---|
| **项目连接器** | 项目配置面板里的「连接器」 | `automation_list_connectors`（OAuth 授权类，如工蜂、Figma） |
| **MCP 服务** | MCP 配置文件里的 `mcpServers` | MCP 协议加载，独立机制 |

**关键**：这两个是**完全独立的两套体系**。

- 如果你把 MCP 配到了「连接器」面板 → 格式对不上，**永远不会以 MCP 形式加载**
- 反过来，用 MCP 格式的服务，**去查连接器列表永远是空的**，这不是故障

**本次现象就是这样**：`automation_list_connectors` 返回 `{"connectors": []}`，但这**不代表 MCP 有问题**，只是两套体系各查各的。

## 四、标准排查流程（照着做）

```
1. 贴配置给我 → 沙箱直连验证
        │
        ├─ 直连失败 → 服务端问题（域名/隧道/token/服务没起）
        │            检查：curl -I 端点，看 HTTP 状态码和 remote_ip
        │
        └─ 直连成功 → 问题在客户端，往下走
                 │
2. 确认配置文件路径对不对（是不是 WorkBuddy 读的那个）
                 │
3. 完全重启客户端进程（不是刷新、不是新开会话）
                 │
4. 列可用工具 → 看目标工具出现没
                 │
5. 还没出现 → 试 enabled: true 替换 disabled: false → 再重启
                 │
6. 仍然不行 → 看客户端启动日志，搜 mcp / 服务名
             正常应有 "connected"，失败会有 failed 或干脆没这行
```

## 五、本次实战证据链（供对照）

| 时间 | 动作 | 结果 | 说明 |
|---|---|---|---|
| 11:20 | 查项目连接器列表 | `{"connectors": []}` | 空的——但这是**连接器**接口，与 MCP 无关 |
| 11:20 | 全盘搜索服务名 | 0 命中 | 沙箱与项目里都没有该文件 |
| 11:23 | 沙箱直连 `initialize` | HTTP 200，握手成功 | 服务端活着 |
| 11:23 | `tools/list` | 8 个工具 | 服务正常 |
| 11:23 | `query_work_order` | `code:0, total:8` | 取工单功能正常 |

**推论**：服务端 100% 正常，客户端加载 100% 失败。方向应指向**配置读取环节**，不要改服务端代码。

## 七、顺手提的三个改进建议

### 1. 需授权工具的错误信息被吞掉

`calc_schedule_priority`、`query_salary` 在缺 `authToken` 时只回一句：

```
An error occurred invoking 'calc_schedule_priority'.
```

调用方拿不到原因（应该提示"请先走 start_auth 授权"）。**建议返回结构化错误**，把真实原因带出来。

### 2. 工艺知识库文件未挂载

`query_production_guide` 查 YX-001 时返回 `files: []`——路线能查到（首道/装配/包装），但**工艺文件是空的**。

这个工具的核心价值就是"把工艺文件读成文字"，文件没挂 = 功能实际未生效。建议确认文件是否已上传到产品或各工序上。

### 3. 临时穿透域名不持久

```
https://410df73d.r18.cpolar.top
```

这是 **cpolar 内网穿透临时域名**，域名一换配置就整体失效。作为 demo 够用，**长期使用建议换固定域名或内网直连地址**。

## 八、速查表

| 现象 | 最可能原因 | 动作 |
|---|---|---|
| 客户端看不到工具 | 配置未重启 / 路径错 / 字段名错 | 完全重启 → 查路径 → 试 `enabled: true` |
| 连接器列表为空 | 查错接口了 | 那是连接器体系，与 MCP 无关，正常现象 |
| 直连 401 | token 错或缺失 | 检查 `Authorization` 头 |
| 直连超时/连不上 | 隧道没起 / 域名变了 | `curl -I` 端点确认可达性 |
| 参数错误但提示笼统 | 服务端错误信息被吞 | 建议服务端返回结构化错误 |
| 查询成功但内容空 | 数据未配置 | 检查业务侧数据（如工艺文件是否上传） |

---

**核心记住一条**：**连不上时，先把配置贴给我，从沙箱直连。**这一步能立刻判定「服务端问题」还是「客户端问题」，省掉大量来回试探。
