# 73-编码级规格-H5系统自测（L1 E2E spec 细分 + L2 请求构造）

> 上游：`72-执行指令`。本文把每个 spec 拆到「路径 / 步骤 / 元素 / 断言」，L2 给到请求体构造，**Cursor 照此直接编码**。
> 元素定位给「建议」，可按下述 placeholder/文本/class 调整；Vant Toast 渲染到 `body > .van-toast`，断言用 `page.locator('.van-toast').textContent()`。

---

## 0. 公共约定（所有 spec 复用）

- 基地址 `https://localhost:5173`；登录复用 helper：`login(page, 'admin','Admin123')` / `loginWorker`。
- 登录成功的标志：URL 到 `/order`（管理员）或 `/h5/orders`（工人）+ 顶部出现工厂名（`FactoryBadge`）。
- **账号分工**：`admin`（管理员，免报权校验）→ 走界面正常流；`zhangchu`（工人）→ 走权限/任务/我的工单。
- Toast 断言统一 helper：`expectToast(page, '文案')`。
- 每 spec 结束清理：不删数据，只保证不污染（报工只落在自造/演示工单）。

## 1. login.spec.js

| 步骤 | 操作 | 元素/定位 | 断言 |
|---|---|---|---|
| 1 | 打开 `/login` | 见登录表单 | 出现账号、密码输入框（单账套无账套下拉） |
| 2 | 输错密码点登录 | 密码框填错，点【登录】 | toast 报错；仍在 `/login` |

| 6 | 无切账套 | 登录后页面 | 无"账套/工厂"切换控件 |
| — | 多账套下拉（H5-03/04） | 需双账套环境 | 默认 `test.skip` 并注明 |

> 路由守卫：未登录访问 `/h5/*` → `redirect` 到 login（router `isSafeH5Redirect`）。步骤 4/5 验证此逻辑。

## 5. report.spec.js（核心，报工对象=自造/演示工单）

> 前置：L2 或手工造一张**未开始/执行中**工单，含至少 2 道工序、1 道已配不良品项；记下 `orderNo`。
> 工序下拉 option 文本 = `${seq} ${operationName}`；`select` 用 `selectOption({ label })` 或按 index。

| 步骤 | 操作 | 元素/定位 | 断言 |
|---|---|---|---|
| 1 | 打开 `/h5/report?order=<单号>` | — | 顶部见工单号+产品；下方有 计划/已完成/剩余 |
| 2 | 不选工序点【提交报工】 | 按钮文本「提交报工」 | toast「请选择工序」 |
| 3 | 选工序 | 工序 `select` 选第 1 道 | 剩余可报随工序变化（不等于"—"） |
| 4 | 步进 | 点 `+10`→`-1`→`+1`→`-10`（`.stepper button`） | 良品数按档增减；`+`不超剩余、`-`不为负 |
| 5 | 报全部剩余 | 点按钮文本「报全部剩余」 | 良品数=当前剩余 |
| 6 | 不良不选原因 | 良品 5、不良 3、不选原因 | toast「有不良品时必须选择不良品原因」 |
| 7 | 时长分钟超界 | 分钟填 60 | toast「时长填写不正确」 |
| 8 | 时长超 24h | 小时 24 + 分钟 1（或 1441 分钟） | toast「单次报工时长不能超过24小时」 |
| 9 | 正常提交 | 良品 1、不良 0、选工序 | toast「报工成功」→ 回 `/h5/scan` |
| 10 | 进度减少 | 重开该单选同工序 | 已完成 = 上次+1，剩余 = 上次-1 |
| 11 | 继续报工 | 回该单点【继续报工】 | toast「报工成功」，留在原页，数量清空 |
| 12 | 报满锁定 | 对该工序连续报到剩余 0 | 出现「该工序已报满，不可继续报工」，提交/继续禁用 |

> 步骤 9-12 会写真实进度，建议用**独立测试工单**（`AUTOTEST-*`），别用生产单。

## 8. L2 后端规则自测（请求构造）

> 直连 `http://localhost:8080`；登录取 token。单账套 body 参考：`POST /auth/login  { account, password }`（以 `auth.js` 为准；多账套才加 `factoryCode`）。

### 8.1 通用 helper
- `login(admin|worker)` → 返回 `Authorization: Bearer <token>`。
- `newReport(orderId, operationId, {good, defect, defectId, minutes})` → `POST /Report` body `{ orderId, operationId, goodQty, defectQty, defectId, durationMinutes }`（对齐 report.vue buildPayload）。
- `newAbnormal(formData)` → `POST /Abnormal`，FormData `{ type, description, workOrderId?, image? }`。

### 8.2 用例断言表
| # | 请求 | 期望 |
|---|---|---|
| A1 | admin 调 `GET /ReportStat/board` | 200 |
| A2 | 无 token 调 `GET /ReportStat/board` | 401 |
| A3 | goodQty 超工序剩余提交 | 4xx，文案含「剩余可报」 |
| A4 | defectQty>0 不传 defectId | 4xx，文案含「有不良品时必须选择不良品原因」 |
| A5 | durationMinutes=1441 | 4xx，文案含「单次报工时长不能超过24小时」 |
| A6 | goodQty=-1 或 defectQty=-1 | 4xx，文案含「良品/不良品数不能为负」 |
| A7 | zhangchu 对无权部门工序提交 | 4xx，文案含「无报工权限」 |
| A8 | 同批重复提交 2 次 | 进度只计入 1 次（复核通过前不重复计数）或第二次报满锁定 |
| A9 | `POST /Abnormal` 关联不存在工单 | 4xx 工单不存在 |
| A10 | `POST /Abnormal` 合法 | 200/成功 |
| A11 | 造单→报工→查进度→删单 | 全程走通，`DELETE /WorkOrder/{id}` 200 |

### 8.3 数据生命周期
1. 用 admin `POST /WorkOrder` 造 `AUTOTEST-<ts>` 单（产品/工艺复用 F001）。
2. 跑 A3~A8（报工都落在这张单）。
3. 末尾 `DELETE /WorkOrder/{id}` 清理；删除失败则标注遗留。
4. A7 用 `zhangchu`（需其部门不在该工序报权内；否则脚本先断言其有权，再切换工序）。

## 9. 一键命令顺序（建议）

```json
"test:h5": "npm run test:api && npm run test:e2e"
```
理由：L2 API 快、先暴露规则问题；L2 造的测试工单可被 L1 report.spec 复用（如按固定前缀取单号）。若需隔离，L1 自行再造。

## 10. 通过标准与反馈口径
- 全绿：`test:api` A1~A11 + `test:e2e` 1~7 全部通过。
- 失败处理：先核对文案/状态码是否与后端一致；不一致优先**改实现**，勿降级跳过；真机 4 项不纳入自动，单列清单。
- 输出：Playwright 报告 + 控制台 A 用例结果表 + 遗留真机项。
