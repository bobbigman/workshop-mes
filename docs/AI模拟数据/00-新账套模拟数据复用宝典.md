## 0. 一句话总览

**换新厂模拟数据 = 纯 API 灌数 + 脚本复用，不动代码、不改表结构、不手改库。** 流程是一条可复制的流水线：
`建账套 → 清种子旧数据 → 配基础数据(部门/单位/不良/工序/路线/产品) → 建工单+启动 → 工价 → 报工 → 复核 → 工资 → 图纸/作业指导书 → 操作手册 → 验收`。

## 1. 架构基线（先记住，决定全流程怎么走）

- **账套 = 工厂（`sys_factory` 一行）**。所有业务表带 `factory_id`，唯一索引含工厂，单库内天然隔离，**表结构一个不用改**。
- **多账套走单库多租户**，`factory_id` 隔离；**不走多库**（`WorkshopMesB` 已冻结不扩展，见 `docs/51`）。
- **升级机制不变**：加表/加字段只改 `backend/Data/DbCompat.cs`（幂等）+ `docs/02`；不另建 EF Migrations，不手改生产表。
- 建厂（`POST /api/factories`）自动灌**种子骨架**：3 用户（admin/banzhang/gongren，密码 `Admin123`）+ 3 部门（冲压/打磨/质检）+ 2 单位（件/套）+ 3 不良品项 + 4 工序（XC/CY/DM/ZJ）+ 1 路线（RT-WJ）+ 2 产品（WJ-001/002）+ 1 演示工单（DEMO001）+ 2 自定义字段（批次/材质）。
- **删除依赖倒序（红线）**：工单 → 产品 → 工艺路线 → 工序 → 不良品项 → 单位 → 部门；有下级的对象禁止直接删。
- **产品编号唯一**（身份证），名称可重复；**工序报工权限 = 部门**（不是人），报工前校验用户所在部门是否属该工序报工权限部门。

## 3. 关键技能点（每阶段的核心操作）

### 3.1 认证与通用请求
- 登录：`POST /api/auth/login {FactoryCode,Account,Password}` → `data.token`，后续所有请求带 `Authorization: Bearer {token}`。
- 统一返回：`{code:0,msg:"ok",data:...}`；`code≠0` 为业务错误，`msg` 带原因。
- 分页接口用 `?pageSize=N` 控制返回条数。
- **路由命名：PascalCase 单数**（`/api/WorkOrder`，不是 `/api/workorders`）→ 写错就 404。

### 3.2 建账套（阶段1）
- `POST /api/factories` 需管理员 token（`[Authorize]`），**先登录任一已有账套**拿 token。
- 建厂自动灌种子骨架 + admin 账号。厂代码全局唯一，重复报「账套代码已存在」。
- 建完 `GET /api/factories` 确认在列表，刷新登录页下拉即出现新厂，用 `admin/Admin123` 登录。

### 3.3 清种子旧数据（阶段2，最易踩外键坑）
- **必须按 工单→产品→路线 的倒序删**，否则外键约束报「该产品下有关联工单」。
- 自定义字段「批次」「材质」清理后仍在（不关联具体记录即可），**直接复用**。

### 3.4 配基础数据（阶段3）
- 所有新建 ID 由库自增，**脚本动态获取、不硬编码**（`GET` 后按 code/name 反查）。
- 新建工序：`POST /api/Operation {Code,Name,DeptIds,DefectIds}` —— **DeptIds = 报工权限部门**（硬规则），DefectIds = 该工序可登记的不良品项。部门不存在报「报工权限部门不存在」。
- 一个通用新厂补建模板（打蛋器样板）：新建「组装组」部门 + 补「组装」「包装」工序 + 对应不良品项 + 6 道工序的路线。

### 3.5 工单（阶段5）
- **不传 OrderNo** → 系统自动生成 `GD{日期}{三位序号}`，看不出模拟痕迹。
- `Ext` 的 **key 是自定义字段 ID 的字符串**（`"7"` 不是 `7`），value 是选项 label（如「第一批」「304不锈钢」）。
- 状态机：`start`(0→1执行中) / `finish`(1→2) / `withdraw`(2→1,1→0) / `cancel`(0/1→3) / `restore`(3→0)。

### 3.6 工价（阶段6）
- `POST /api/PriceRule {ProductId,OperationId,PriceType,UnitPrice,DeductPrice,EffectiveFrom,DepartmentId:null,UserId:null}`。
- PriceType：1=计件 / 2=计时 / 3=固定。DeductPrice 为不良扣款（NULL=不扣）。
- 每个产品每道工序配一条；`EffectiveFrom` 填当天。

### 3.7 报工（阶段7）
- 工人报工前**必须先加入该工序的报工权限部门**，否则 403（报工权限=部门硬规则）。
- 种子工人只在冲压组，要报全工序须 `GET /api/Department/{id}` → 追加 MemberIds → `PUT` 写回（打磨/质检/组装等）。
- **良品/不良逻辑要自洽**（打蛋器样板：下料5全良→冲压4良1毛刺→打磨再1划伤→后面全良收尾，最终良品4件），演示才可信。
- 管理员报工 → `review_status=1`（自动通过）；工人/班组长报工 → `review_status=0`（待复核）。

### 3.8 复核（阶段8）
- 班组长 token 查 `GET /api/Review/pending` → 批量 `POST /api/Review/batch-approve {ids}` 或逐条 `approve` / `reject {reason}`。
- **驳回必填 reason**（1~256字）；驳回后 `review_status=2`，进度不含该条、不计工资。
- 可刻意留一笔驳回，验证「通过才计钱、驳回不算钱」。

### 3.9 工资（阶段9）
- `POST /api/Salary/generate {PeriodType:1,PeriodValue:"2026-09",UserId}` → 拉取 `review_status=1 AND settled_flag=0` 报工，逐条匹配工价 → amount/deduct → 汇总 totalAmount。
- PeriodType：1=月（"2026-09"），2=周（"2026-W37"）。
- **确认即冻结**：`POST /{id}/confirm` → status=1、报工 `settled_flag=1` 不可再改。
- **已确认单不可删、无撤回接口**（`DELETE` 报「仅草稿可删除」）→ 报工/复核顺序错了金额就永久定错（见 §7 坑 8）。

### 3.10 图纸/作业指导书（阶段10）
- 数据模型：表 `base_knowledge_file`（元数据）+ 磁盘 `KnowledgeBase:RootPath/<factoryId>/<guid>.<ext>`（本体）；**一律走上传接口**，不手改库、不手动拷文件。
- `POST /api/knowledgefile`（multipart：`refType` + `refId` + `version` + `file`），refType=`product`（产品级）或 `operation`（工序级），refId 用**当前厂的新 id**。
- 工人端 `GET /api/knowledgefile/by-order/{orderId}` 按工单列出（产品级 + 各工序级）；`GET /{fileId}/raw` 预览/下载。
- 支持 pdf/docx/xlsx/jpg/png/webp，单文件 ≤20MB；远程须先配 `KnowledgeBase:RootPath` 否则报「未配置」。
- **中文文件名必须原名上传**：UTF-8 控制台 + curl `-F filename=中文原名`；`filename*` 语法 curl 不识别会被忽略。
- 回滚：`DELETE /api/knowledgefile/{fileId}` 删登记（磁盘保留可再传）。

### 3.11 操作手册（阶段11）
- 四篇正文：`docs/manual/第一次使用.md`、`docs/manual/遇到问题.md`、`docs/30-使用手册-管理员（电脑端）.md`、`docs/31-使用手册-工人（手机端）.md`。
- 图片放 `frontend/public/manual`，正文写 `![位置说明](/manual/文件名.png)`。
- 改版本要同步三处：正文页首、`frontend/src/help/manual.js`（manualVersion）、`frontend/scripts/sync-manual.mjs`（version + systemVersion）。
- 构建：`npm run manual:sync`（生成 SupportDocs 和 docs/ai-support）→ `manual:check`（37章节/12图/11篇一致）→ `npm run build`；**部署带完整 `frontend/dist`**（含 dist/manual 图片），否则帮助页裂图。
- 去技术味/AI味：H5→手机端、localhost→「只有本机能打开的地址」、模型服务→AI服务；业务红线/按钮名/字段名不改。

## 7. 坑大全（按根因分类，全部为真实踩过的）

### 7.1 编码 / 脚本工具
1. **PS5.1 发中文会乱码**：`ConvertTo-Json` 对非 ASCII 转 `\uXXXX`，DB 存乱码 → **一律用 Python `requests` 发 UTF-8**。
2. **一键新建账套连不上后端**三大根因：协议错（`http` 应为 `https`）、自签名证书未被信任、PS5.1 用 `{ $true }` 脚本块作证书回调在后台线程报「无运行空间」（改 Add-Type 编译 .NET 委托解决）——见 `docs/未做指令/51` 相关执行记录与 `docs/78`。
3. **上传中文文件名**：PS5.1 `HttpClient` 连远程失败（证书/异步）；curl `--config` 读本地文件 exit 26；`filename*` 被 curl 忽略导致文件名变临时 ascii 名。**唯一稳法**：控制台代码页 65001（UTF-8）+ curl `-F "file=@<ascii临时路径>;filename=<中文原名>"`。

### 7.2 API 契约
4. **路由 PascalCase 单数**：`/api/WorkOrder` 不是 `/api/workorders`，写错 404。
5. **建厂需管理员 token**：`POST /api/factories` 带 `[Authorize]`，先登录已有账套。
6. **`Ext` 的 key 是字符串**：`"7"` 不是 `7`（JSON 传输必须字符串）。
7. **全小写/复数/少参数都 404 或业务报错**；分页接口记得 `?pageSize`。

### 7.3 数据一致性 / 外键
8. **删除必须倒序**：工单→产品→路线，否则「该产品下有关联工单」外键报错。
9. **工资单确认即冻结、不可逆**：报工/复核顺序错了 → 工资永久定错且 API 无法改（赵江陵样板：包装漏通过，工资 19.60 永久定格，缺 2.40）。**这是最大坑**——生成工资前务必先核对所有报工 `review_status=1`。
10. **驳回必填 reason**（1~256字）；驳回不计工资、进度不含该条。
11. **报工权限=部门硬规则**：新工人不在任何组就 403，须先加齐相关部门成员。

### 7.4 演示真实感
12. **工单号不传 OrderNo**，由系统生成 `GD{日期}{序号}`，避免 DEMO 痕迹。
13. **清种子演示工单 DEMO001、WJ-001/002、RT-WJ**，否则新厂混进旧数据。
14. **齐套/未接金蝶等口子**：演示前接真数据或改中性文案，不可把「未接」写脸上；不吹版本对比、不编造现网事实（见 `docs/63/64` 注意事项与 `docs/推广方案/黑湖对标速记.md`）。

## 8. 交付与分工（换新厂时的动作边界）

- **分工**：豆包=程序分析员，**只做分析、写指令与规划，不写代码**；代码由 Cursor 编写执行。本宝典的 `tools/*.py` 是历史执行脚本（豆包曾按 API 逐调），如要新写/改脚本，写成指令交 Cursor。
- **新写的分析/指令类 md** → `docs\未做指令\`；本宝典及其后续产物放 `docs\AI模拟数据\`（黑帽大人指定目录）。
- **起草开发/执行指令**遵循 `docs/102-指令起草模板-给豆包（精简版V3）.md`：性质+一句话目标+取舍表+范围落点+行为与口径（分叉「当X则A、当Y则B」）+止步线+验收≤5条+交付终点；验证随风险走；PC=Element Plus、H5=Vant；不编造现网事实。
- **上线部署更新**：只用增量包，绝不覆盖服务器 `appsettings*.json` / `start.bat`（见根目录 `DEPLOYMENT_NOTES.md`、`docs/59`）。
- **命名空间**统一 `ahu.MicrosoftMes`；异常不吞、必须抛带上下文（`Common/ThrowHelper.cs`）。

## 9. 换新厂 checklist（开工即用）

1. 定厂代码（唯一、字母+数字）+ 厂名 + 客户行业（五金/服装/厨具…）。
2. 想好产品线：产品编号/名称/单位/工艺路线（几道工序、每道挂哪个部门、哪些不良品项）。
3. 想好工价表：每工序 计件价 + 不良扣款。
4. 想好演示剧本：几人报工、谁复核、留不留驳回、工单数量/良品逻辑自洽。
5. 确定要不要图纸/作业指导书（产品级+工序级共几份）。
6. 决定操作手册是否新做（复用模板正文，只改厂/产品名词）。
7. 按 §2 全景流程跑一遍，逐阶段 §6 验收。
8. 全程复用 §4 资产、避开 §7 坑。
