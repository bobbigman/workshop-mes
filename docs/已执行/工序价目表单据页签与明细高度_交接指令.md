## 1. 已完成（勿重做价目表主路径）

### A. 退出误关列表 / 报「链接无效」

**现象：** 价目表开单 → 改/编辑 → 点「退出」→ 报「价目表链接无效，请从列表重新打开」→ **列表页签也被关掉**。

**根因：** `leaveToList` 先 `closePcTab`（bump keep-alive epoch）再 `router.push`。仍停在单据 path 时 key 变 → 表单重挂载 → 异步 `onMounted`/`loadBill` 跑完时路由已是列表 → `id` 无效 → 再 `leaveToList` 把**列表签**关掉。

**已改文件：**

| 文件 | 改动 |
|---|---|
| `frontend/src/composables/usePcTabs.js` | 新增 `closePcTabAndNavigate`：**先跳转，离开后再 splice+bump** |
| `frontend/src/views/operation-price-list/form.vue` | `leaveToList` 改用上述 API；`loadBill` 若已不在单据路由则直接 return |
| `frontend/src/views/order/form.vue` | 同样改 `leaveToList` + `loadBill` 防护（工单已顺带防同坑） |
| `frontend/src/components/PcTabs.vue` | 页签 × 关闭也走 `closePcTabAndNavigate` |

### B. 明细只显示 1～2 行（对标金蝶约 8 行）

**现象：** 开价目表单据，明细可视行极少；中间一度改完更少（试算区抢高）。

**根因（叠两层）：**

1. 全局列表定高 CSS（`theme.css` 里 `:has(.toolbar)`）误套到单据页：根 flex + overflow hidden，表又不在根下直挂 → 被挤扁；`MesTable` 再锁死矮 height。  
2. 自研「bill-top / bill-detail / bill-foot」后，**取价试算一直展开**约占 244px，表头又高 → 明细只剩约 1 行。

**已改（价目表）：**

| 点 | 做法 |
|---|---|
| 列表 CSS | `theme.css`：列表规则加 `:not(:has(.pc-bill-page))`；单据另写 `.pc-bill-page` 布局 |
| 结构 | `form.vue` 根加 `pc-bill-page price-bill`：`bill-top` / `bill-detail` / `bill-foot` |
| 明细高度 | `mes-table` 显式 `:height="detailTableHeight"`（`syncDetailHeight`，约 ≥400，对标一屏多行） |
| 试算 | 默认 **折叠**（「取价试算（点开再用）」），不抢明细高度 |
| 行文案 | 去掉行上「已确认/待确认」；性质改独立列「性质」 |
| 启用提示 | 去掉灰条：「启用中不能直接编辑。改结构请先停用或复制…」 |
| 浏览提示 | 去掉灰条：「当前是浏览模式，可复制内容；要修改请点左上角「编辑」」 |
| 列表头 | 「行号」：显式 `column-key="rowNo"` + `width/min-width=72`（避免旧 localStorage 列宽把 th 挤成「行…」） |
| 工具条 | 压过 theme 列表工具条 `padding:18px`；单据工具条约 **36px**（金蝶顶栏约 34px）；主区 `padding: 8px 16px` |

**金蝶对照（本机 Chrome 已量）：** 采购申请单明细区约 8 行可视；价目表改后本机 vite 约十多行（行高更矮）。
