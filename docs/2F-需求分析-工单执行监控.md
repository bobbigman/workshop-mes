# 需求分析：工单执行监控

> 日期：2026-09-23
> 状态：已实施（2026-09-23）。
> 参考：`其它截图/2.jpg` 的「工单执行 / 执行监控」。
> 配套指令：[19-补充执行指令-PC工单执行监控](已做指令/19-补充执行指令-PC工单执行监控.md)。

## 1. 结论与定位

本系统能够实现一个有实际管理价值的 PC「执行监控」页面。工单、工序任务、派工、报工、复核、异常处理已有基础，首版以统一查询与展示为主，预计无需新增业务表。

目标：管理人员打开一个页面，就能看清哪些工单正在做、各道工序报了多少、哪些工单超期或有异常，并进入现有页面处理。

截图的布局可以借鉴，但截图里的班次、产线、暂停停机、质检和入库不能被当作本系统已有能力。

## 2. 逐项能力对照

| 截图内容 | 代码现状 | 首版处理 |
|---|---|---|
| 工单数量、执行中、待开工、已完成 | 已有状态统计 | 展示未开始、执行中、已结束；明确统计范围 |
| 工序流转 | 已有顺序、工序计划数、良品、不良品、执行人 | 展示「工序进度」，不声称设备实时运行 |
| 工单进度排行 | 有进度数据，但列表与看板算法不同 | 先统一计算；优先展示超期、有异常的未结束工单 |
| 现场异常 | 已有设备故障、物料短缺、质量异常及恢复处理 | 展示类型、描述、工单、时间，联动异常处理 |
| 工单明细 | 已有产品、数量、交期、状态 | 复用数据和详情、报工入口 |
| 派工 | 每道工序可派给一个执行人 | 复用详情派工；批量派工不在首版 |
| 报工记录 | 已有 PC / H5 报工与记录 | 连接现有功能 |
| 待办 | 已有待复核、待处理异常；可查询未派工任务 | 按角色和真实业务范围汇总 |
| 班组报工统计 | 有人员、部门快照；没有班次模型 | 后续明确班次和组织口径再做 |
| 工序质量确认 | 有不良记录、报工复核 | 报工复核不等于质检；暂不做质检项目与确认流程 |
| 暂停工单、异常停机 | 有异常，无完整暂停/恢复生产模型 | 暂不做，不从未报工推断停机 |
| 完工入库 | 无对应库存业务模型 | 后续独立需求 |
| 车间、产线筛选 | 未建立相应标准归属模型 | 首版不提供，部门不冒充产线 |

## 4. 关键数据口径

### 4.1 工单进度必须先统一

当前有工序任务时，工单列表完成数取各工序已报良品的最小值；看板把所有工序良品相加后与工单下单数比较。

例：工单 100 件，三道工序分别报 100、80、20 件。列表完成数为 20，看板为 200，进度条封顶后会看起来已经完成。这是首版必须修正的问题。

首版执行建议：保留列表当前完成数量语义，让看板与监控复用同一计算；另定义「工序达成进度」为各有效工序 `良品数 / 该工序计划数` 的最小值，限制在 0%～100%。各工序计划相同时，它与当前数量进度一致；计划不同时，不把它误称为成品产出率。

零计划数、旧数据无工序任务、缺少有效计划等边界必须显式处理，见配套指令。工单状态仍沿用现有业务：手动结束不等于全部报满，不能显示已结束就强制进度 100%。

### 4.2 进度与入账分开

- 现场进度：待复核 + 已通过，排除已退回。
- 正式生产报表、工资：仅已通过。
- 监控沿用现场进度口径，待复核另列；不改变工资和报表规则。

### 4.3 工序进度不等于设备运行

示例：下料 120/120 → 加工 100/120 → 检验 80/120 → 包装 0/120。

工序卡片显示名称、良品/计划、执行人；状态用「未报工、已报未满、已报满」等准确用语。无报工不能推断停机；箭头仅表示工艺顺序，不代表新增前后道强制放行规则。

当前异常可关联工单，不能关联到具体工序，因此只在工单层标记「有待处理异常」。派工执行人也不等于所有实际报工人。

### 4.4 时间与组织范围

「今日新建」「当前执行中」「今日报工」不能共用含糊的「今日」标签。首版用当前状态统计和明确的交期范围筛选，不增加历史时点回放。

部门主要承担组织和报工权限，不能直接等同于产线、车间、早中晚班。不同产品或单位的数量也不能直接相加称作成品产量。

## 5. 首版页面

| 区域 | 内容 |
|---|---|
| 顶部 | 未开始、执行中、已结束、临期、超期、待处理异常 |
| 筛选 | 工单号/产品、工单状态、计划交期起止日期 |
| 中间主区域 | 按工单展示工序进度链及执行人 |
| 中间右侧 | 待处理异常、超期工单，点击查看或处理 |
| 底部主区域 | 工单明细及查看、派工、报工入口 |
| 底部辅助区域 | 待复核报工、未派工工序等待办 |

采用白色内容卡片、浅灰底、明确标题和克制的状态色，借鉴截图信息分区。首版不全站换肤，兼容现有主题；PC 优先，不另做 H5 监控。

默认优先超期、有待处理异常的未结束工单。每 10 秒刷新，展示最后成功更新时间；失败保留旧数据但明确提示，不能装作实时成功。

## 6. 实施边界

1. 新增 PC 监控入口及聚合查询，避免逐工单请求详情和统计只算当前页。
2. 工厂隔离、角色权限和部门报工权限必须保持；待办不得泄露无权查看的数据。
3. 首版不新增业务表，不做批量派工、停机状态机、班次、质检、库存、甘特排程或设备联网。
4. 涉及展示口径调整，实施时同步 PRD 和接口说明，并验证旧工单、不同工序计划数、退回报工等边界。
5. 后续根据现场使用情况再扩展业务；本分析不代表这些后续功能已获实施授权。
