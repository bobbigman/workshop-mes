# 33-接口对接说明（对外查询）

> 用途：让外部工具（自己写的 C# 外挂、伙伴系统、金蝶对接）能**只读查询**本系统的基础资料和单据。
> 系统本身是 .NET 8 Web API，接口已全部存在，本说明只讲「怎么对接」，不涉及新增功能。

## 一、两种用法

1. **在线看 + 试调（推荐先看这个）**：启动后端后，浏览器打开 `http://<服务器IP>:<端口>/swagger`
   - 页面列出全部接口，能直接填参数、点 Execute 试调。
   - 右上角点 **Authorize**，把登录拿到的 token 粘进去，之后所有请求自动带上鉴权。
2. **代码直连**：按下面「二、鉴权」拿 token，再按「四、接口清单」直接 HTTP 调用。

## 二、鉴权（JWT）

- 所有接口（除登录外）都要在请求头带：`Authorization: Bearer <token>`
- token 由登录接口获取，有效期 12 小时（`appsettings.json` 的 `Jwt:ExpireHours`）。
- 步骤：**先登录 → 拿 token → 后续请求带上**。

### 登录接口

```
POST /api/Auth/login
请求体（JSON）：
{
  "factoryCode": "工厂代码",
  "account": "账号",
  "password": "密码"
}
返回：
{ "code": 0, "msg": "ok", "data": { "token": "xxxx", "name": "管理员", "role": 1, "workerViewMode": 1 } }
```

> `workerViewMode`：1=全车间可见(默认) / 2=只看我的任务（docs/200，仅工人手机入口；班组长/管理员不受影响）。
> 对接方用一个**管理员账号**（role=1）登录即可查全部数据；生产/班组长账号有只读权限限制。

### 工人手机视角（docs/200）

### 派工（docs/29 / 201 / 202）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/Assign/my-tasks` | 我的任务（当前用户被派工序） |

### 登录页清浏览器缓存（docs/112，匿名）

```
POST /api/Auth/clear-browser-cache
鉴权：无需 JWT / 无需请求体（登录页专用；官方调用不要带 Authorization）
成功响应头：
  Clear-Site-Data: "cache"
  Cache-Control: no-store
返回：
{ "code": 0, "msg": "ok", "data": { "httpCacheClearRequested": true } }
```

> `httpCacheClearRequested` 只表示服务端已发出清理指令，不表示浏览器一定完成清除；不清理 localStorage / Cookie。
## 三、统一约定

- **返回格式**（所有接口一样）：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

  - `code`：0 = 成功；非 0 = 失败，失败原因在 `msg`。
- **分页**：列表接口用 `page`（默认 1）、`pageSize`（默认 20），返回 `data` 为：

```json
{ "list": [ ... ], "total": 128 }
```

- **多工厂**：数据按工厂隔离，工厂由登录账号的 `factoryId` 决定，接口不用传工厂参数。

#### GET `/api/ExecutionMonitor` 区域与筛选范围

- **鉴权**：登录 JWT 工厂隔离；role=2/3 只读白名单已放行；不扩大写权限。
- **`summary`**：按 `keyword` + 交期筛选后的全集统计（不含已取消）；**忽略**当前 `status`，便于点状态卡切换。含未开始/执行中/已结束/临期/超期/待处理异常数。临期超期仅未开始与执行中（`DueStateHelper`）。
- **`orders`**：与进度链同一分页；默认未结束在前，再按超期、有待处理异常、交期升序、ID。行内 `progressPercent` 为工序达成进度；`ops` 含任务/虚拟标记与派工可用性。
- **`abnormals`**：当前厂待处理异常全集计数；明细最多 10 条；**不随**工单关键词/状态/交期筛选；含未关联工单的异常。
- **`overdueOrders`**：随关键词/交期过滤的超期摘要，最多 10 条 + total。
- **`todos`**：`pendingReviewCount` 仅管理员/班组长（班组长限本组）；`unassignedOpCount` 仅派工授权角色（道工序：真实任务、未派、正计划、未报满）；无权限对应字段为 null，不伪造 0。待办不随工单筛选。

> 各状态/枚举字段的取值，见 `docs/02-数据字典.md`；每个接口的完整字段，以 Swagger 页面为准。

## 五、调用示例

### C#（.NET 8，直接复制可用）

```csharp
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json;

const string Base = "http://192.168.1.100:5000";   // 改成实际服务器地址

using var http = new HttpClient();

// 1) 登录拿 token
var loginResp = await http.PostAsJsonAsync($"{Base}/api/Auth/login", new
{
    factoryCode = "工厂代码",
    account = "admin",
    password = "密码"
});
var login = await loginResp.Content.ReadFromJsonAsync<LoginResult>();
var token = login!.Data.Token;

// 2) 查产品
http.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", token);
var prodResp = await http.GetAsync($"{Base}/api/Product?keyword=&page=1&pageSize=50");
var json = await prodResp.Content.ReadAsStringAsync();
Console.WriteLine(json);   // {code, msg, data:{list, total}}


// 统一返回结构：{ code, msg, data }，按需定义即可
public class ApiResult<T> { public int Code { get; set; } public string Msg { get; set; } = ""; public T? Data { get; set; } }
public class LoginResult { public int Code { get; set; } public string Msg { get; set; } = ""; public LoginData? Data { get; set; } }
public class LoginData { public string Token { get; set; } = ""; public string Name { get; set; } = ""; }
```

> 外部工具项目里把上面的类复制过去即可；如需强类型绑定，再按接口返回字段建 DTO。

## 五补-2、错误追踪（全站）

- 每个 HTTP 响应可带响应头 **`X-Trace-Id`**（服务端生成；勿信任客户端自带关联值）。
- CORS 已暴露 `X-Trace-Id`，浏览器 JS 可读。
- 统一返回仍为 `{ code, msg, data }`：
  - **业务校验**：`msg` 为可读业务提示（如「账号或密码错误」）。
  - **技术故障**：`msg` 回传 SQL/报文等异常详情（密码/Token 脱敏，不含堆栈）；完整堆栈用响应头 **`X-Trace-Id`** 在服务器 `ErrorLogging` 目录日志中检索。
- PC/H5 公共封装 `frontend/src/api/http.js` 展示后端 `msg`（长文案弹窗可复制）；不把追踪号拼进用户 tip。

## 六、边界

- 本说明只覆盖**查询（GET）**；写操作（POST/PUT/DELETE）同样在 Swagger 里有，但对接方一般只读即可，不要用外部程序直接改库。
- 数据权威口径：工资/统计以系统结算结果为准，外部工具只做「取数 + 展示/二次加工」，不承担最终计算。


## 企微事件消息（129）

管理接口均为 JWT 管理员、本厂隔离，沿用 `WechatDueAlert` 授权；factoryId 只取 JWT，不接受客户端指定。统一 `{code,msg,data}`，列表分页为 `{list,total}`。

| 方法与路径 | 契约 |
|---|---|
| GET /api/WechatAlert/rules | 本厂规则数组 |
| POST /api/WechatAlert/rules | 创建规则，见下方字段 |
| PUT /api/WechatAlert/rules/{id} | 编辑/启停；不存在或跨厂拒绝 |
| GET /api/WechatAlert/deliveries?page=1&pageSize=20 | 本厂发送记录分页（pageSize 最大 100） |
| GET /api/WechatAlert/deliveries/{id}/attempts | 本厂该记录的发送/人工处理历史 |
| POST /api/WechatAlert/deliveries/{id}/retry | 仅群规则明确失败，须总开关开启及正式授权；旧session不可重试，重复点击拒绝 |
| POST /api/WechatAlert/deliveries/{id}/verify | 仅 unknown，body 为 `{sent: true/false, note: "核实说明"}`；true 标人工确认，false 须群规则已启用、总开关开启及正式授权才可排队；旧session只允许确认已发送；说明 1～256 字 |
| POST /api/WechatAlert/dispatch-events | 无 JWT，须 X-Cron-Token；有限批次 50 条，code 非 0 表示存在失败/部分成功/未知或基础设施错误 |

规则字段：`name`（1～64）、`eventType`（report_created/order_started/order_completed/abnormal_reported）、`targetChannel`（正常写入仅group，缺省group；历史session只读、停用）、`webhookKey`（群消息，可空=用设置表默认；回显为 ********）、`conditionType`（always/defect_rate/abnormal_device/abnormal_material/abnormal_quality）、`threshold`（always 与异常分类型必须 null；defect_rate 仅报工、0～100 最多两位小数）、`toUser`（≤512；群消息为 mentioned_list，留空只发群不 @；不继承设置默认成员；group支持@all，混填时归一为@all）、`template`（1～1000，限定占位符）、`enabled`。启用群消息须有独立或全局Webhook；可先启用独立规则再开启总开关。旧session不可创建/修改/启用。编辑不改变已排队的接收人/内容快照；停用取消未发送记录。设置表 `webhookKey` 为全厂默认群机器人 key，回显脱敏。

异常占位符另有 `{异常类型}` `{问题描述}` `{上报人}`。工人上报异常与业务同事务入队。

投递状态：pending、processing、success、retry、failed、unknown、partial、cancelled、confirmed。success 是 API 接受；confirmed 是人工确认，不写 API 成功日志。群消息无 partial。消息正文按完整 Unicode 字符截至 ≤2000 UTF-8 字节且 ≤1000 UTF-16 字符。发送历史保存接收人、结果、脱敏错误与人工处理人/说明，Secret/Token/Webhook key 不返回明文。

原 setting/test/push-overdue/cron-push 路径保留。测试/交期仅用全局Webhook，无配置提示补齐，不回退session；默认toUser仅用于这两个入口。所有推送共用工厂互斥和持久额度账本，测试不计额度；原交期批次仍一天一条。事件每次只尝试一次消息请求；群通道不调 gettoken；消息发出后不明结果不自动重试。

### 141 设置与限流补充

- `PUT /api/WechatAlert/setting`：沿用 `enabled/webhookKey/toUser/dailyLimit/noticeSeen`；旧corpId/secret/agentId值保留，不因省略或传值而覆盖。开启须有全局Webhook或至少一条启用且有独立Webhook的group规则。
- `webhookKey`：官方完整HTTPS链接或纯key；回显 `********`，提交该掩码不修改，空值清除；规则清除后用全局默认。全局默认成员为空不@，规则成员为空也不@。
- 所有正常入口仅group。按key哈希与SQL会话锁共享滚动一分钟20次尝试（含测试、明确失败、未知），跨工厂同key共用；超限事件保持pending、约一分钟后再投递，手动入口提示稍后处理且不记成功去重。
- `push-overdue` 的data.status：sent表示实际接受；skipped_*表示未发送（disabled/tier/unconfigured/empty/dedup/busy/limited/rate_limited/paused等）。failed/unknown返回非0 code；cron-push汇总失败或未知也返回非0。总开关关闭/trial各入口不外发。
- 外部失败返回易懂说明与追踪号，脱敏请求/响应上下文只入服务器日志；内部robotKeyHash不回传。结果未知先核实，不自动重发。旧session历史仍可查询。
