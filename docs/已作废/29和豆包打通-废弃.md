# Cursor 改造指令（完整可直接复制发给Cursor）
## 业务背景
当前项目是D:\workspace\pkub\裁切分析\MP42Txt\黑湖小工单_分析\backend，基于ASP.NET Core 8开发的车间MES工单后台，监听本地8080端口；数据库存在sys_mcp_auth鉴权表，需求对接火山方舟Managed Agents，让方舟Agent通过MCP JSON-RPC协议调用工单查询工具。
前端页面可正常访问 [https://2e2c5459.r19.vip.cpolar.cn/mcp#/order](https://2e2c5459.r19.vip.cpolar.cn/mcp#/order)，但MCP协议POST接口404，方舟Agent无法连接MES获取工单工具。

## 现存问题
1. 项目未启用MCP服务模块，没有注册标准JSON-RPC路由 `/mcp/rpc`；
2. 缺少MCP服务DI注册、路由中间件启用代码，POST访问该路径直接404；
3. 未自动扫描项目内工单、报表相关MCP工具方法，无法对外暴露list_tools、call_tool标准MCP接口；
4. MCP鉴权逻辑未绑定sys_mcp_auth表，无法校验请求头Bearer Token `laohu-demo-2026`。

## 修改目的
1. 启用内置MCP模块，注册`/mcp/rpc`全局POST JSON-RPC接口；
2. 自动扫描程序集内所有MCP工具函数，对外提供标准MCP协议能力；
3. 对接sys_mcp_auth表实现Bearer鉴权，校验方舟环境传入的Authorization请求头；
4. 本地地址`[http://localhost:8080/mcp/rpc](http://localhost:8080/mcp/rpc)`可正常接收MCP RPC请求，配合cpolar公网地址给火山方舟调用。

## 改造步骤&代码修改要求
### 1. 修改Program.cs启动入口
1）在WebApplication.CreateBuilder阶段新增MCP服务DI注册
新增扩展方法AddMcpRpc，配置：开启鉴权、扫描当前程序集、绑定sys_mcp_auth鉴权逻辑；
2）在app.UseRouting()后、app.MapControllers()前，调用app.UseMcpRpc()注册MCP路由中间件，固定路由地址`/mcp/rpc`；
3）启动时打印日志：MCP endpoint地址、扫描到的工具数量。

### 2. 补充McpRpc扩展类（若无则新建）
新建McpRpcExtensions.cs，实现AddMcpRpc、UseMcpRpc两个扩展方法；
内置逻辑：
- 自动扫描带McpTool标记的业务方法作为可调用工具；
- 拦截所有POST /mcp/rpc请求，解析JSON-RPC标准报文；
- 读取请求头Authorization: Bearer xxx，查询sys_mcp_auth表校验token有效性；
- 实现list_tools、call_tool两个标准MCP协议方法。

### 3. 数据库初始化脚本补充
新增初始化SQL，向sys_mcp_auth插入测试鉴权记录：
```sql
INSERT INTO sys_mcp_auth(factory_id,auth_code,auth_token,is_finance,code_used,code_expire,token_expire,created_at)
VALUES(1,'MCP001','laohu-demo-2026',0,0,'2099-12-31','2099-12-31',GETDATE());
```

### 4. 验证标准
1. 项目重启控制台输出MCP注册成功日志；
2. PowerShell执行POST请求到[http://localhost:8080/mcp/rpc](http://localhost:8080/mcp/rpc)，携带Bearer laohu-demo-2026，调用list_tools能返回工单、报表工具列表JSON；
3. cpolar公网地址 [https://2e2c5459.r19.vip.cpolar.cn/mcp/rpc](https://2e2c5459.r19.vip.cpolar.cn/mcp/rpc) 同样可正常访问，无404、401报错；
4. 火山方舟Agent填入该公网MCP地址后，会话可正常加载MES工具。

## 约束
1. 不改动原有工单、报表业务接口逻辑，仅新增MCP独立模块；
2. MCP鉴权仅读取sys_mcp_auth表，不新增额外数据库表；
3. 路由固定为/mcp/rpc，不可自定义其他路径；
4. 兼容现有cpolar内网穿透8080端口转发规则，无需修改隧道配置。
