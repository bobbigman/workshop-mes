## 3. 任务清单

### 任务 1 · H5 工人端加"退出"按钮（现场刚需，优先级最高）

**现状**：`frontend/src/views/h5/TabBar.vue` 底部只有 工单/任务/扫码/异常/帮助 五栏，无退出入口。

**取舍（已拍板）**：底部已有五栏，再塞第六栏会挤；**退出放各 H5 页顶部右侧文字按钮**（与登录态同层可见），不占 TabBar。报工/异常等无顶栏的页，在页头右上角同样放「退出」。

**要求**：
1. H5 工人端各主页面顶部右侧有可见「退出」文字按钮（不塞进 TabBar 第六栏）。
2. 点退出 → 清掉本地登录态（token/用户信息，注意 localStorage 键名与登录逻辑一致）→ 跳回登录页。
3. 退出后，浏览器返回不能退回工单界面（用路由跳转替换历史，`router.replace('/login')` 或清栈）。
4. 退出前若有未提交的报工/异常表单，给一句确认提示（"当前填写内容未提交，确定退出？"），别直接丢数据。
5. 失败提示走人话：清除失败/跳转失败要给出可读原因，不吞错。

**验收**：
- [x] H5 主页面顶部有可见「退出」入口（不挤占底部五栏）。（代码已落地，待现场浏览器复测）
- [x] 点退出回到登录页，token 已清，F5/返回不回到工单页。（代码：`router.replace('/login')` + 清登录键）
- [x] 报工/异常页有未提交内容时点退出有确认提示。（`dirty` 传给 H5LogoutBtn）
- [ ] 无报错、无控制台异常。（待浏览器复测）

### 任务 2 · 报工自定义字段（设备/模具等）

**现状**：PC `custom-field/index.vue` 目标下拉仅 `work_order`；`ShowInOrderList` 仅工单有意义；`h5/report.vue` 无自定义字段区。值已有通用表 `sys_custom_field_value(field_id, target_id, value)`，工单侧已在用。

**取舍（已拍板）**：**不改 `prod_report` 表结构**；报工字段定义 `target='report'`，值写入既有 `sys_custom_field_value`，`target_id = prod_report.id`。同步改 `docs/02-数据字典.md` 的 `target` 注释（补 `report`）。`ShowInOrderList` 对 `report` 禁止开启（与现有非 work_order 规则一致）。

**要求**：
1. **后端**：允许 `target=report`；PC【自定义字段】页下拉增加「报工」。
2. **报工存值**：提交报工时一并写入 `sys_custom_field_value`（`target_id=报工记录Id`）；查询报工详情/列表能带回这些值（按现有工单自定义字段读法对齐，最简即可）。
3. **前端**：`h5/report.vue` 在提交区显示本厂 `report` 目标字段输入项，随报工一起提交。
4. 字段未配时不影响正常报工（空则不显示，不报错）。
5. 失败原因可读：字段保存/查询失败要带「位置+做什么失败」上下文。

**验收**：
- [ ] PC 端能新建「报工」目标的自定义字段（设备/模具）。
- [ ] H5 报工页出现对应输入项，提交后值入 `sys_custom_field_value`、能查回。
- [ ] 未配字段时报工流程照常，不报错。
- [ ] 原有工单自定义字段功能不受影响；未改 `prod_report` DDL。

### 任务 3 · 计价单：按产品过滤 + 产品/工序排序 + 失效变色 + 导入

**现状**：前端 `load()` 只传 `{page,pageSize}`；后端 `PriceRuleQueryDto` 已有 `ProductId/OperationId`，但过滤写成「本产品 **或** 通配 null」（匹配计价规则语义），**不是**列表精确筛；无 `DepartmentId/UserId`；排序按 `Id` 倒序；无失效变色；`ImportService` 无计价单类型。

**取舍（已拍板）**：列表筛选用**精确匹配**（选了某产品只看 `product_id=该产品` 的行，不含通配 null 行）；匹配器 `PriceRuleMatcher` 的通配语义不动。排序：产品名称/编号 → 工序名称（或工序序号若可取）→ Id。

**要求**：
1. **过滤**：列表工具栏（产品/工序/部门/人员，可组合）；`load()` 带参；后端补 `DepartmentId/UserId`，且 `ProductId/OperationId` 改为精确等值（有值则 `==`，不要 `OR null`）。
2. **排序**：按「产品 + 工序」稳定排序，便于核对。
3. **失效变色**：`effectiveTo` 已过（相对当前时间）的行灰/浅红；仍可编辑，不锁操作。未到生效日的行本项不要求变色。
4. **导入**：`ImportService` 增加 `priceRule`，Excel 列：产品编号、工序编号、部门、人员、计价方式(1计件/2计时/3固定)、单价、不良扣款、生效时间、失效时间、优先级。失败逐行原因（行号+字段+为什么），不整表吞错。
5. 导入模板表头/示例与现有 user/product 导入风格一致。

**验收**：
- [ ] 计价单列表可按产品/工序/部门/人员精确过滤，多条件组合有效（通配行不会因选了产品被误带出）。
- [ ] 列表按产品+工序排序，顺序稳定可核对。
- [ ] 失效的行颜色明显不同，不影响编辑。
- [ ] 计价单 Excel 导入：正常行成功、错误行逐条报原因（行号+字段+原因）。
- [ ] 无功能回退（原有新增/编辑/删除/`PriceRuleMatcher` 通配匹配正常）。

### 任务 4 · 报工界面不显示无权限工序

**现状**：`h5/report.vue` 工序下拉 `detail.tasks` 列出全部工序任务；当前用户无报工权限的工序也显示，提交才被后端拦。

**取舍（已拍板）**：后端在返回工单详情/`tasks`（报工用）时按当前用户可报工序过滤；**管理员 role=1 不过滤（与提交校验一致）**。前端只展示返回结果，不自算权限。

**要求**：
1. **原则（业务红线：报工权限=部门）**：当前用户所在部门 ∉ 该工序报工权限部门 → 该工序**不显示/不可选**；管理员不受限。
2. 后端过滤，口径与提交时 `ReportService` 部门校验**同一套判断**（抽公共方法更佳，禁止两处各写一套条件）。
3. 避免"列表看不到却还能报"或"列表看到却报不了"。
4. 无可报工序时，报工页人话提示（如"该工单当前没有你可报的工序"），不给空下拉干转。

**验收**：
- [x] 无权限工序在报工界面不显示/不可选。（`by-no` 后端过滤 tasks）
- [x] 有权限工序照常可报；管理员可见全部。（role=1 不过滤）
- [x] 列表权限与提交校验口径一致（共用 `ReportPermissionHelper`）。
- [x] 无可报工序时有人话提示。（「该工单当前没有你可报的工序」）
- [ ] 无权限账号现场实测：列表看不到且提交被拒。（待复测）

### 任务 5 · 工单号简化（A0001-Z9999）——改契约，谨慎

**现状**：`WorkOrderService.NextOrderNoAsync` 自动单号=`GD+yyyyMMdd+3位流水`（最大999，超限报"当日自动工单号已用尽"）。此前 P1「当天删单后建单撞号500」已通过"当天最大尾号+1"修复，本任务改格式时**不得回退该修复**。

**要求**：
1. 自动单号改成 `字母A-Z + 4位流水`，从 `A0001` 开始，`A0001→A9999→B0001→…→Z9999`；单号总长 5 位（A0001）。超过 `Z9999`（即26万单）才报"自动单号用尽，请自定义"，正常使用不会碰到。
2. **历史数据兼容**：已建工单（GD…格式）单号保持不变、可查可扫；唯一索引语义不变；仅**新单**走新格式。不得批量改写历史单号。
3. 撞号防护沿用"库内最大尾号+1"逻辑，但适配新格式（不再依赖日期前缀；按字母段+尾号推进，同字母段取最大尾号+1，满了进下一字母）。
4. 前端/扫码/打印流转卡按单号展示的界面无需大改（单号是纯字符串）；确认查询/搜索对新旧格式单号都有效。
5. 自定义单号能力保留（填了就用自定义，校验不重复）。
6. **契约变更提示**：本项改单号规则，属改契约。若你发现现有代码在别处硬编码了 `GD`/日期前缀/位数假设，必须一并改并列出。

**验收**：
- [ ] 新工单自动单号形如 `A0001`、`A9999→B0001` 正确进位。
- [ ] 历史 GD… 单号工单可查、可扫、不冲突。
- [ ] 当天建多单、删单后再建不复现撞号 500。
- [ ] 自定义单号功能正常。
- [ ] 无对 `GD`/日期前缀的硬编码残留导致报错。
