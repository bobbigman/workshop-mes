## 一、目标（说人话）

一群人共同干同一道工序（如喷涂线、装配线集体作业）时，**一个人扫码报总数，勾上参与的人，系统按人头自动平分产量和工资**，各人记各人的账。工人少填、账能对上、钱分得清。

## 二、业务行为（设计决策，拿主意如下）

1. **触发**：普通报工时，工人勾选"多人共同报工"，从参与人列表勾选≥1 个参与人（**含报工人自己**），填该道工序的良品总数、不良总数，提交。
2. **平分规则**：
   - 良品、不良都按参与人数**自动平分**（黑湖式）。
   - **余数处理**：不能整除的余数归**报工人**，保证"各参与人数量之和 = 报工总数"，一笔不丢、可追溯。
   - 例：3 人报良品 20 → 报工人 8、另两人各 6，合计 20。
3. **参与人范围**（守住"工序报工权限=部门"硬规则）：参与人列表**只允许该工序报工权限部门内的人员**；报工人本身必须已通过部门权限校验。非权限部门的人不能被勾选、勾了也拒绝。
4. **记账**：一次提交在**同一数据库事务**内，为每个参与人生成**一条独立报工记录**（各人 UserId 不同、数量为其平分量）。各条记录独立进各人工资、复核、改数与进度。
5. **进度/报表口径**：工单完成数、工序进度、生产报表仍按**数量合计**（与现有"各道有效良品取最小/合计"口径一致），**不按报工条数**；多人分摊不改变原总数，进度不受影响、不重复计数。
6. **复核**：分摊出的每条记录**各自独立**待复核/通过/退回；退回其中一人不影响其余人。
7. **可选不强制**：多人分摊是工人**主动勾选**的开关，不是强制流程；单人报工原流程不变。

## 三、本期不做（边界）

- 不做"各参与人各自填数量再合计"的手动精确分摊（本轮按黑湖自动平分）。
- 不做手机工资中心、改数、审批、自动绩效；不改工资算法、复核、结算冻结口径。
- 不改任何既有报工数据、工价、客户不良扣款。
- 不把多人分摊做成全员默认；仅现场集体作业时启用。

## 五、后端（ReportService 及模型）

### 5.1 入参
- **当**：需要参与人入参 → 在 `ReportDto` 增加可选字段，如 `List<long>? ParticipantUserIds`（空/不传 = 单人原逻辑）。
- 报工人 = 当前登录用户（沿用 `SubmitAsync` 的 `currentUserId`），不得由客户端覆盖。

### 5.2 分摊拆条（核心）
- **当**：`ParticipantUserIds` 为空或 null → **完全走现有单人报工原逻辑**，不得有行为回归。
- **当**：非空（含报工人，人数≥1）→ 计算每人平分量：
  - 良品：`total / n`，余数归报工人；不良同理。
  - 逐参与人生成一条报工记录（UserId、GoodQty、DefectQty、DefectId、时长、扩展字段）。
- **当**：参与人中有人不在该工序报工权限部门 → 明确拒绝整次提交并提示"XX 无该工序报工权限"，**不静默剔除、不全报**。
- 去重标识、防超额检查与写入、成功回执按 **91 指令**要求执行：分摊 N 条**必须在同一事务**提交，任一步失败整体回滚，**不留"部分人报了、部分人没报"的半笔**；防超额按总数一次校验（不得把分摊后的总量算成 N 份超额）。
- 成功回执返回报工人与参与人数、各自良品/不良、复核状态。

### 5.3 数据与兼容
- 不复用/不破坏批量补报 `BatchNo`、`Allocations` 语义；分摊关联可另加独立字段（如分摊批次标识）便于追溯，具体最小方案开工时按 docs/02 核对后补入指令与数据字典，不得另造整表。
- 历史数据、旧客户端无参与人字段 → 一律按单人处理，兼容旧行为。
- 权限、账套、身份校验在重放/重试时仍必须执行，不得泄露他人记录。

## 七、验收清单（逐项打勾）

### 分摊正确性
- [ ] 良品/不良按人数自动平分，余数归报工人，各人合计 = 报工总数，一笔不丢
- [ ] 3 人报 20 件：8/6/6 或类似，合计恒为 20
- [ ] 各参与人生成独立记录，各人 UserId、数量正确，各自进工资
- [ ] 进度/报表按数量合计，不按条数；多人分摊后工单完成数/进度不变、不重复计数

### 权限与硬规则
- [ ] 非权限部门的人不能被选为参与人；选了也拒绝，不静默剔除
- [ ] 报工人无部门权限仍不可报工；未派工但有部门权限仍可报工
- [ ] 换账号/换账套看不到他人分摊明细

### 可靠性与兼容
- [ ] 分摊 N 条在同一事务；在主记录/分摊中模拟失败，无"部分人报了部分人没报"的半笔
- [ ] 同请求连续/并发/响应丢失后重试，只生成一套分摊结果，不重复分摊
- [ ] 防超额一次校验：剩余 10 件，3 人分摊总数不得超 10（不被当成 3 份各自超额）
- [ ] 单人报工、批量补报、一键补报拆分原流程无回归
- [ ] 复核各自独立：退回一人不影响其余人
- [ ] 参与人中一人复核退回后，其余仍正常

后端分摊与权限需集成验证（非文案镜像测试）；手机/PDA 走查一次完整多人流程；记录实际测试结果，不把静态阅读当运行验收。
