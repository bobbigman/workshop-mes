## 一、目标（说人话）

工人报工要"报得快、记得准、查得到"，不加重工人负担。共三件事：

1. **普通报工不能记重、不能记半笔**——网络抖动、手抖多点一下，都不能让钱和数量对不上。
2. **手机报工页**："报工时长"标注选填；成功提示要交代清楚"哪道工序、几个良品、几个不良、待复核"。
3. **手机加一个只读的"我的报工"**——工人能查自己哪天报了啥、什么状态；改数仍留电脑端。

## 二、本期不做（边界，硬约束）

不做：个人工资页、手机改数/补报/审批、自动绩效、个人效率排名、厕所/停工计时、设备联网、异常流转大改。
不改：任何客户的不良扣款、工价、既有报工数据。
不扩展成重型 MES，保持轻量小工单定位。

## 五、第 1 步：普通报工提交可靠性（先做）

### 1.1 请求去重标识
- **当**：客户端无请求标识字段 → 为普通报工增加"本次提交的唯一标识"（前端生成；**同一批重试沿用同一标识，不得每重试换一个**）。
- **当**：已存在或调用方可加 → 后端据此做持久化去重：同一厂 + 同一用户 + 同一标识 + 同一内容，最多落一笔，返回同一笔回执。
- **当**：同一标识但业务内容变了 → 明确拒绝，不得静默返回另一笔。
- 去重必须**落数据库**（并发也不能写两笔），不能只靠按钮禁用或内存缓存。
- 不复用批量补报的 batch_no 语义；保留原批量补报兼容。

### 1.2 事务完整
- **当**：当前顺序是"先存主记录、再存扩展字段、再更新状态"且非同一事务 → 改成：主记录 + 扩展字段 + 状态更新放进**同一数据库事务**，任一步失败整体回滚，不留下半笔有效报工。
- **当**：报工使工单自动结束 → 以原请求标识重试仍返回原成功结果，不得误判成"新报工/结束单报工"。
- **当**：并发两笔不同请求各报 8 件而剩余只有 10 → 防超额检查与写入必须同事务可靠，不得两笔都读到旧剩余量后合计通过 16 件。

### 1.3 结果回执
- **当**：响应丢失但已成功落库 → 重试返回原记录（含记录 ID）。
- 成功回执需带：记录 ID、工序、良品、不良、提交时间、复核状态；保持现有 ApiResult 包装与既有调用方兼容。
- **当**：提交结果未知 → 保留输入与请求标识，提示"请先查我的报工或按原请求重试"，不得直接说"肯定没保存"。
- 日志完整：按 ThrowHelper/现有日志机制保留上下文（位置 + 做什么失败），异常必抛不吞；不把数据库异常误当去重成功；关键业务字段不脱敏。

### 1.4 校验身份/账套
- **当**：重放/重试 → 仍校验登录身份与账套归属；返回回执不得泄露他人记录。

## 六、第 2 步：报工页小改

- **当**：标题为"报工时长" → 改为"报工时长（选填）"；保留现有输入与校验，不加开关、自动计时或新必填字段。
- 成功提示：从一句"报工成功"改成如"裁切：良品 18，不良 2，已提交，待复核"；**以服务端真实返回为准**（管理员提交不能固定显示"待复核"）。
- 保持"提交后返回""继续报工留页清数"原操作；失败保留输入，确认成功后再清空数量；进度刷新失败不得显示成"提交失败"，不诱导重复报同一批。
- 不新增工人填写事项，不改权限、数量、复核与计价口径。

## 七、第 3 步：手机"我的报工"只读页

### 3.1 页面
- **当**：手机工单页无本人报工入口 → 增加"我的报工"入口（首版不挤底栏，放工单页即可）。
- 默认今天；支持日期范围、工单号、分页；日期按原报工时间，沿用系统业务时区。
- 显示：工单、产品、工序、良品、不良、提交时间、状态（待复核/已通过/已退回），退回时显示原因。
- 空/加载失败/加载中要区分，不得把异常显示成"今天没有报工"。
- 只读：无编辑/删除/代报按钮；提示"数量有误请联系管理员处理原记录，不要重复报"。
- 此页不显示工资预估，不把待复核/已退回说成已结算。

### 3.2 接口与权限
- **当**：需要接口 → 建议独立本人查询入口（如 GET /api/Report/mine），复用现有查询投影，不改原 PC 查询权限。
- factoryId、userId 必须从当前登录上下文取得；客户端传他人 ID 不得扩大范围；检查角色守卫、账套过滤、授权档；能正常报工的工人可查本人记录，不误绑工资功能档。
- 不直接开放管理员工资接口或整个报工列表作为替代。

## 八、验收清单（逐项打勾）

### 可靠性
- [ ] 同请求连续提交、并发提交、成功后响应丢失再重试，均只有一笔报工，回执 ID 相同
- [ ] 同标识不同内容被明确拒绝；新标识相同数量可正常记下一批
- [ ] 第一笔使工单结束后，以原请求重试仍返回原成功结果
- [ ] 在主记录保存后、扩展字段或状态更新处模拟失败，无残留半笔报工
- [ ] 剩余 10 件时，两笔不同请求并发各报 8 件，不得合计通过 16 件
- [ ] 普通 PC 报工、H5、批量补报原流程及旧客户端兼容符合本指令

### 页面与隔离
- [ ] 时长仍非必填；计时填写、连续报工、返回路径正常
- [ ] 成功提示数量及状态准确；刷新失败不显示成提交失败
- [ ] 手机能查本人当天与历史记录，退回原因、日期筛选、分页正确
- [ ] 换参数/换账号/换账套，看不到他人本人列表及待确认请求
- [ ] 无权限部门仍不可报工；未派工但有部门权限仍可报工
- [ ] 三种复核状态显示正确，待复核与已退回不被解释成已入工资

可靠性与权限需后端集成验证（非文案镜像测试）；手机/PDA 走查一次完整主流程；记录实际测试结果，**不把静态阅读当运行验收**。
