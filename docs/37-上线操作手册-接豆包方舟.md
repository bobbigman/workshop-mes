## 0. 先确认三件事（1 分钟）

在动手前，先确认这三样都在，否则后面白忙。

| # | 检查点 | 命令 / 做法 | 合格标准 |
|---|---|---|---|
| 1 | 后端在 8080 跑着 | 浏览器开 `http://localhost:8080/mcp-auth?code=probe` | 能看到「金蝶账号授权」表单 |
| 2 | `Mcp:Token` 值 | 看 `backend/appsettings.json` | 现在还是 `change-me-demo-token-2026`，**下一步先改成你自己的** |
| 3 | 财务账号 | 同文件 `Mcp:FinanceKingdeeAccounts` | 现在是 `boss`，演示可先用 |

> 建议：现在就打开 `backend/appsettings.json`，把 `Token` 改成一段只有你知道的随机串，例如 `laohu-demo-2026`。改完**重启后端**（`stop-dev.bat` 后再 `start-dev.bat`，或手动 `dotnet run`）。

## 1. 开 cpolar 隧道（§二）

### 1.1 装 cpolar（首次，已装跳过）

1. 打开 [cpolar 官网](https://www.cpolar.com)，右上角「免费注册」，用邮箱注册并登录后台。
2. 后台点「下载」，选 **Windows** 版，下载 zip 解压后双击安装包，**一路默认安装**。
3. 开一个 PowerShell（管理员），验证装好：

```powershell
cpolar version
```

能打印版本号就装好了。

### 1.2 绑定你的账号 token

1. 回到 cpolar 后台，左侧点「**验证**」，复制那串 authtoken。
2. 命令行执行（把 `<你的token>` 换成刚复制的）：

```powershell
cpolar authtoken <你的token>
```

看到「saved to ...」之类提示即成功。

### 1.3 开隧道，把本地 8080 映射出去

```powershell
cpolar http 8080
```

执行后会刷出一屏，找到 **`https://` 开头** 的那个公网地址（免费版是随机域名，形如 `https://xxxx.cpolar.cn`，你的会不一样）。

> ⚠️ 免费版随机地址**每 24 小时变一次**；变了就回来重跑这一步 + 下一步 1.4。

### 1.4 把公网地址填进后端配置

1. 打开 `backend/appsettings.json`，把 `Mcp:AuthBaseUrl` 从空 `""` 改成你的公网地址（**不要带末尾 `/`**）：

```json
"AuthBaseUrl": "https://209c3f5f.r19.vip.cpolar.cn"
```

2. **重启后端**。

3. 验收：浏览器开 `https://209c3f5f.r19.vip.cpolar.cn/mcp-auth?code=probe`，能看到授权表单 → 隧道通了。

> 当前隧道（2026-09-17）：必须指 **后端 8080**。若公网返回带 `/@vite/client` 的页面，说明误指前端 5173，方舟 `POST /mcp` 会 404——重跑 `cpolar http 8080`。

## 2. 接豆包方舟（§四）

1. 登录 [火山方舟控制台](https://console.volcengine.com/ark)，进入你的智能体（Agent）配置页。
2. 找到「**添加 MCP / 远程 MCP**」入口（云部署 MCP / Remote MCP）。
3. 传输方式选 **Streamable HTTP**（或叫「HTTP」）。
4. 填：
   - **MCP 地址 / URL**：`https://209c3f5f.r19.vip.cpolar.cn/mcp`（末尾就是 `/mcp`；域名以当时 `Mcp:AuthBaseUrl` 为准）
   - **Headers**：加一条
     - Key：`Authorization`
     - Value：`Bearer laohu-demo-2026`（须与 `Mcp:Token` 一致）
5. 若界面有「测试期 / beta 开关」之类，按 `docs/35` 加 `ark-beta-mcp: true`（不同时期方舟界面字段名可能有出入，以控制台实际为准）。
6. 保存后点「**测试连接**」，能列出 `query_work_order`、`query_report`、`query_salary`、`start_auth`、`calc_schedule_priority` 这些工具，就说明接上了。

> 验收 = 方舟能发现工具。只要工具列得出来，MCP 这层就通了。

## 3. 走一遍完整演示（§五）

在方舟对话里按顺序说：

| 步骤 | 你说的话 | 预期 |
|---|---|---|
| 1 | 「查工单」 | 方舟回「需要授权」，并给出 `start_auth` 的 H5 链接 |
| 2 | 点开链接 | 打开金蝶授权表单页 |
| 3 | 输账号密码（如 `boss` / 任意密码） | 页面显示一个 8 位**授权码** |
| 4 | 把授权码贴回对话 | 方舟用授权码查到工单 / 报工数据 |
| 5 | 说「查工资」 | `boss` 是财务 → 查到工资（当前库空则返回空列表） |
| 6 | 换 `worker1` 授权再「查工资」 | 被拦，提示「仅财务人员可查询」 |

> 全走通 = 授权 → 查询 → 工资拦截整条链路 OK。

## 4. 演示完收尾（§六）

1. 关隧道：回到开 `cpolar http 8080` 的那个窗口，`Ctrl + C` 停掉。
2. 轮换 token：把 `backend/appsettings.json` 的 `Mcp:Token` 再改成另一个新值，防公网残留调用。
3. 把 `Mcp:AuthBaseUrl` 改回空 `""`（下次演示再填），或直接停掉后端。

## 5. 常见坑（先看，别现场翻车）

| 现象 | 原因 | 解法 |
|---|---|---|
| 方舟「测试连接」失败 | `Authorization` 值写错 / 没带 `Bearer ` 前缀 | 核对 token，值必须是 `Bearer 空格 token` |
| 方舟连上了但工具列不出 | 后端没重启 / token 不一致 | 重启后端，确认 appsettings 与方舟填的一致 |
| 公网授权页打不开 | 隧道地址变了（24h） | 重跑 `cpolar http 8080`，重填 `AuthBaseUrl` 再重启 |
| 查工资报「未授权」 | 授权码过期（默认 2 小时） | 重新 `start_auth` 拿新码 |
| 查工资报「仅财务」 | 账号不在 `FinanceKingdeeAccounts` 名单 | 把该账号加进名单，重启后端 |
