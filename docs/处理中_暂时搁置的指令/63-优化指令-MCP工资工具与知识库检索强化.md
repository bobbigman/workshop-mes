# 优化指令：MCP 工资工具与知识库检索强化（先止血，后补刀）

> 状态：**大部分已完成**（P0 人设、P1-1 描述、方案 B 全文截断已落地并部署；P2 工资工具待拍板、P3 稳定性待排期）
> 依据：微信 clawbot（扣子智能体）对话分析——「系统能不能算工资」被误判为「不能」；`docs/34`、`docs/35`、`docs/45`、`docs/54`、`docs/55` + 源码走查
> 目标：让 AI 不再把「MCP 工具清单没有」当成「系统功能没有」，并消除知识库检索截断/不稳导致的脑补。

---

## 0. 结论先行（先说清哪些是误判、哪些是真缺）

clawbot 的分析方向对（MCP 工具清单 ≠ 系统功能全集；根因是版本不同步 + 检索截断逼它脑补），但**有两处事实记错**，别原样转给厂家：

| clawbot 说 | 实际（源码/文档） | 结论 |
|---|---|---|
| `query_salary` 描述还是旧的「数据来自金蝶」 | `SalaryMcpTools.cs` 原描述为「查询工资单列表（财务敏感）…」，本无「来自金蝶」字样 | 记错；但仍补了显式口径（见 P1-1） |
| 未命中没有明确信号、调用不强制 | `Search` 已返回 `no_match` 明确 message，`state` 六种区分；`docs/45` 人设已写「必须先调 search_support_docs」 | 已实现大半 |

**真缺的（按优先级）：**

1. **检索稳定性**（P3 地基）——反复撞到「客服知识目录不存在 / 空返回 / 服务无响应」，根因多在 cpolar 隧道 / 扣子→隧道→本机链路，**非检索源码**（`docs/55` 已证明检索源码正常）。
2. **全文返回 / 截断**（已做方案 B）——`ExcerptMaxChars=300` 且无续读机制，AI 拿不到完整章节 → 顺着 300 字摘录续写。
3. **MCP 工资工具**（P2，先拍板再决定）——`SalaryMcpTools` 只有 `QuerySalary`（查询）；网页端已有工价 CRUD + 工资单生成/确认，但 MCP 没暴露。
