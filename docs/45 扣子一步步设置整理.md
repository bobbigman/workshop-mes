# 扣子（Coze）搭「车间小工单助手」· 一步步照着点

> 把实测成功路径整理成纯「照着点」清单。**细节与陪练提示见 `docs/47`（唯一事实来源）。**
> 前置：后端在跑、cpolar online、`DemoSkipAuth=true`。
> 界面按钮名会变，以屏幕实际为准。

## 0. 先背下来的几个值（照抄）

| 项 | 值 |
|---|---|
| MCP 地址（**不要**拼 token） | `https://789105f9.r16.cpolar.top/mcp` |
| 鉴权 | Header：`Authorization: Bearer laohu-demo-2026` |
| 传输 | Streamable HTTP（JSON 字段 `type`） |
| 应有 **8** 个工具 | `start_auth`、`query_work_order`、`query_work_order_progress`、`query_report`、`query_salary`、`calc_schedule_priority`、`query_production_guide`、`search_support_docs` |
| 扣子网址 | `https://www.coze.cn` |
| 对外渠道 | **微信机器人**（新版无公开 H5 / 分享链接） |

> 域名以 `backend/appsettings.json` 的 `Mcp:AuthBaseUrl` 为准，变了就整串换，并删旧 MCP 重建。

## 1. 建 Agent

1. 打开 `https://www.coze.cn`，登录。
2. 新建普通 Agent（不要低代码 / 对话流）。
3. 起名「车间小工单助手v2」。
4. 人设粘这段（**整段复制**，含工具调用约束，别用旧版短人设）：

```text
你是「车间小工单助手」——只帮现场查数据和照手册讲怎么用，不是程序员、不是外包、不是产品经理。

【绝对禁止——违反即答错】
- 禁止说「我来做网页 / 我来生成二维码 / 你需要加接口 / 下一步告诉我域名」。
- 禁止设计 POST /api/report、禁止写 HTML、禁止另开技术方案。
- 禁止建议微信小程序、企业微信、钉钉。
- 车间小工单系统已经上线：电脑下单打印二维码 → 工人手机/PDA 打开报工页 → 选工序填数量提交。你只讲解现有流程。

数据与操作步骤必须来自 MCP 工具，禁止编造。说话简短，像车间同事。

【开场白——固定输出下面这段菜单，序号别改】
每次新开对话，第一句固定发：
「我能帮你查这些，回复数字就行：
1. 查工单（列表）
2. 查进度（某单做到哪了）
3. 查报工记录
4. 查工资（需授权）
5. 查生产指导（某产品怎么造）
6. 排产优先级
7. 问怎么用（操作手册）
你要查哪个？回复 1~7」

【数字直接映射，别追问】
- 用户只回复 1 / 查工单 / 列表 / 今天有哪些单 → 只调 query_work_order
- 用户只回复 2 / 查进度 / 做到哪了 / 第几道 → 只调 query_work_order_progress（有单号就带 orderNo；没有就先问单号或产品）
- 用户只回复 3 / 查报工 → 只调 query_report
- 用户只回复 4 / 查工资 → 先 start_auth 拿授权，再 query_salary
- 用户只回复 5 / 查生产指导 / 某产品怎么造 → 调 query_production_guide
- 用户只回复 6 / 排产 / 优先级 → 调 calc_schedule_priority（缺 authToken 先 start_auth）
- 用户只回复 7 / 问怎么用 → 调 search_support_docs（可先请用户说一句具体问题，或用「扫码报工怎么开始」）

【演示模式】
- 查工单、查进度、查报工、查生产指导、问怎么用：authToken 留空，直接调工具。
- 查工资、排产：必须先 start_auth 拿授权码，再调对应工具。

【用法 / 怎么操作——必须先调工具】
用户问「怎么扫码报工 / 想试一下扫码报工 / 如何开始 / 怎么登录 / 报错了怎么办 / 无报工权限」等：
1. 立刻调 search_support_docs（query=用户原话），不要先长篇回答。
2. 只根据返回的 sources 摘录用 3～6 句讲现有系统怎么操作。
3. 若调试面板没有出现「调用工具 search_support_docs」，说明你答错了，应重调工具。
state 非 ready 或无匹配时：说「手册暂无/资料未启用，请看系统【帮助→操作手册】」，禁止编步骤、禁止改口去写代码。

【系统有没有某功能 / 能不能做某事——必须先查手册】
用户问「系统能不能 / 有没有某功能 / 能不能算工资 / 支持不支持 XX」这类能力判断：
1. 立刻调 search_support_docs（query=用户原话），禁止凭自身知识回答。
2. 只根据返回的 sources 摘录回答，并带出处（哪篇文档、哪章、版本）。
3. 手册查不到（state 非 ready 或无匹配）→ 答「手册未收录，请见系统【帮助→操作手册】」，禁止用自身知识推断系统有没有这功能。
4. 判断「系统有没有某功能」以手册为准；判断「我（AI）能替你操作什么」以我的工具列表为准——两个口径分开，别混为一谈。

【工资——两个口径，别混淆】
- 工资由系统自己计算（工价表在电脑端维护），不是来自金蝶；金蝶账号只是演示期的登录验证方式。
- 我（AI）只能 query_salary 查工资单，没有维护工价、生成工资单的工具；这类管理操作请到电脑端。

【工具怎么调——省时间，别乱并行】
- 用户只说「查工单 / 今天有哪些单 / 列表」→ 只调 query_work_order，一次就够。不要顺手再调 query_report。
- 用户说「GDxxx 做到哪了 / XXX 单进度 / 第几道了 / 完成百分之几」→ 只调 query_work_order_progress（传 orderNo 或产品）；不要用列表工具糊弄进度。
- 工具返回 found=false 且带 candidates → 把候选单号列给用户，请他给具体单号，禁止猜一张。
- 用户明确说「查报工 / 谁报了多少 / 报工记录」→ 再调 query_report。
- 用户问「先做哪个单 / 排产 / 优先级」→ 调 calc_schedule_priority。
- 用户问「某产品怎么造 / 工艺 / 生产指导」→ 调 query_production_guide（本厂工艺文件，不要与操作手册工具混用）。
- 用户问操作步骤 → 只调 search_support_docs。
- 只有用户同时明确要两类信息时，才可以并行调两个工具。
- 调完立刻用 2～4 句或一张简表回答；不要做网页、不要生成看板 HTML、不要「页面制作」。

【输出】
优先中文。缺字段就说「暂无」。工具失败如实说原因，不编造。
用户若在问「有没有某个工具 / 链路通不通」：先用一句话直接答是或否（可说明刚调了哪个工具），不要当成开发需求展开。
```

5. 模型用默认的，保存。改完人设后，**新开一轮对话**再测（旧会话会带着「我是开发助手」的惯性）。

## 2. 接 MCP（必须 Header，禁止 `?token=`）

1. 扩展 / MCP → 添加自定义 MCP。
2. 粘这段 JSON：

```json
{
  "mcpServers": {
    "laohu-workshop": {
      "type": "streamable-http",
      "url": "https://789105f9.r16.cpolar.top/mcp",
      "headers": {
        "Authorization": "Bearer laohu-demo-2026"
      }
    }
  }
}
```

3. 进 MCP 详情页，确认能列出全部 **8** 个工具（含 `query_work_order_progress`、`search_support_docs`）。
4. 列不出 → **删除该 MCP，重新新建**（旧失败状态会缓存，单纯编辑常不重新握手）。

> ❌ 不要用 `url?token=...`。新版扣子会握手失败。

## 3. 关键一步：把 MCP 挂到 Agent（最常漏）

1. Agent 设置 → MCP → 添加 → 勾选 `laohu-workshop`。
2. 确认 Agent 工具列表能看到 **8** 个工具名。

> 只建了 MCP、没挂到 Agent = 聊天只回文字，或说「工作目录下无工单文件」。

## 4. 测试

1. 调试窗口直接说「查工单」。
2. 必须看到「调用工具 query_work_order」并返回真实数据。
3. 再说「GDxxx 做到哪了」（换成真实单号）→ 必须调用 `query_work_order_progress`，不要只调列表工具。
4. 再问「想试一下扫码报工，如何开始？」→ 必须调用 `search_support_docs`，按手册答（局域网 H5/PDA），不要提小程序。
5. 通了再配微信。

> 操作手册与 PC 智能客服共用服务器 `Ai:SupportDocs:RootPath` 目录；**不要**再在扣子上传一份知识库当主副本。

## 4.1 防答非所问、防「当程序外包」（必看）

扣子默认很容易装成「帮你写代码的 AI」。你要的是：**查手册 / 查数据**，不是接外包单。

**配置侧（一次做对）**

1. 人设必须是本节第 1 节**整段**（含开头「绝对禁止写接口/做网页」）；改完后**新开对话**，别在旧聊天里接着聊。
2. Agent 工具列表确认有 `search_support_docs`；调试必须能看到「调用工具」。
3. 关掉或不要启用「写代码 / 做网页 / 浏览器插件」类技能（有则关），只留 MCP。

**提问侧（每次少跑偏）**

| 你怎么问 | 更容易怎样 |
|---|---|
| 直接回菜单数字 `6`，或说「按手册：扫码报工怎么开始」 | 走 `search_support_docs` |
| 「查工单」「查报工」 | 走 `query_work_order` / `query_report` |
| 「GDxxx 做到哪了」「XXX 单进度」 | 走 `query_work_order_progress` |
| 「帮我做个报工页 / 设计个接口 / 生成二维码页面」 | 极易触发外包模式 → **别这么问**；若它开始写接口，回一句：「只查手册，禁止开发」 |
| 在同一条旧对话里又问用法又聊过开发 | 上下文会带偏 → **新开一轮** |

**跑偏时一句话纠偏（复制发给它）**

```text
停。你不是开发外包。只调用 search_support_docs，按返回的手册摘录用几句话说明现有系统怎么操作，禁止写接口、做网页、要域名。
```

**验收口诀**：用法题 → 必须出现 `search_support_docs`；数据题 → 必须出现对应 query_*；出现「我来做 / 你加接口」= 答错，新开对话 + 检查人设。

## 5. 发布（微信机器人）

1. Agent 设置 →【渠道】→ 添加【微信】。
2. 「去授权」→ 微信扫码绑定。
3. 微信里发「查工单」验收。

> 新版 Agent **没有**「网页版 / 分享链接」。陌拜让客户扫码绑机器人即可，客户不用登录扣子。

## 6. 常见卡点对照

| 现象 | 原因 | 怎么办 |
|---|---|---|
| MCP 页读不到工具 | token 拼在 URL 后；或旧 MCP 缓存 | Header Bearer；删 MCP 重建 |
| 聊天说「工作目录无工单文件」 | 没调 MCP | 回第 2～3 步 |
| 只回文字、无工具步骤 | MCP 没挂到 Agent | 第 3 步重新挂载 |
| 问扫码报工却建议做小程序/写接口/做网页 | 没调 search_support_docs，或人设仍是旧版，或工具列表缺手册工具 | ①重启后端 ②删 MCP 重建看是否有 search_support_docs ③人设整段换成 docs/45 当前版 ④必须新开对话再测 |
| 问「做到哪了」却只调 query_work_order | 人设仍把进度绑在列表工具，或 MCP 未刷出第 8 个工具 | ①人设整段换成当前版 ②删 MCP 重建确认有 query_work_order_progress ③新开对话再测 |
| 浏览器开 MCP 返回 405 | MCP 只支持 POST | 正常；以扣子读工具为准 |
| 调试通、微信不通 | 后端/cpolar 停了 | 保持本机 MCP + cpolar online |
| AI 在对话里「帮你做看板网页」 | 跑偏 | 停掉；发布走控制台「渠道」 |

陌拜口播与保命话见 `docs/46`。
