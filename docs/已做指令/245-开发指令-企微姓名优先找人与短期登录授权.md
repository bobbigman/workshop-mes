## 本次范围与落点

- 新增MCP工具 `identify_report_worker(displayName?, phone?)`、`verify_report_identity(lookupToken, verificationCode)`；后者返回仅供工具使用的 `reportAccessToken`。现有候选/预览/确认/接入检查增加可选该凭证，不要求平台传userid，不把聊天昵称认作认证。
- 新增短期内存授权服务、JWT保护的验证页接口和Vant验证页。页面复用原登录回跳，仅目标员工可确认，验证码只在网页登录后显示，不由MCP查询取得。验证码5分钟、限5次尝试、单次兑换；定位票据10分钟；报工凭证30分钟，重启失效，不存入聊天展示/浏览器长期存储。
- 工具取得凭证后调用原候选/预览/确认。凭证与已有平台身份走不同owner，不能混用彼此候选或确认token；换人/凭证失效后重新验证。匿名定位及认证不启用报工，真实提交仍须原Enabled=true。
- 为避免旧免密链接直接升级为机器人写入授权，授权页在登录态之外再校验一次本账号密码（仅网页内、复用BCrypt）；密码不进MCP、不缓存，账号5次失败后限制5分钟。此为首次验证的正确性补充，不改变原登录流程。
- 新增授权接口只检查/更新内存授权状态，不写员工绑定、不写报工、不新增表；实际入账与回滚/幂等仍由原报工服务负责。服务内部认证过的员工ID不可由HTTP请求体指定。
- 链接使用现有手机可达HTTPS基址，临时地址改变仍须更新配置；不伪造固定userid、不给模型收账号密码，不新增短信服务。

## 行为与口径

- 当已有企微用户名 → 优先精确查姓名；当无用户名/零命中/重名 → 询问手机号后6位；6位仍多或未命中 → 询问完整手机号；不唯一不替选，不披露候选手机号/账号清单。
- 当唯一定位 → 回显员工与工厂并发首次验证链接；用户登录后若身份不符/停用/外部人员 → 拒绝授权，支持切换登录。未点击确认不生成验证码。
- 当用户提供验证码 → 机器人带本次定位票据兑换短期凭证；过期/错误/重复/跨厂拒绝，错误达5次作废定位票据；不把密码发给机器人，不显示长凭证。
- 当携带有效凭证 → 重新核对该厂员工状态、角色与人员类型后继续；未携带则保留原可信平台身份模式。凭证无效不自动降级为其他身份。
- 当报工开关关闭 → 找人及登录验证可以进行，但报工仍返回未启用；接入检查区分平台身份与登录授权两种路径，不能因无userid误称有效登录凭证不可用。
