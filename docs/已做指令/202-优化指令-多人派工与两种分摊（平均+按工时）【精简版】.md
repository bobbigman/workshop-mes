# 202-优化指令：多人派工与两种分摊（平均+按工时）【精简版】

> 状态：已做（2026-10-02）
> 一句话目标：把一道工序从"一次只派一人"升级为**可派多人**，并在现有「多人共同报工」自动平分基础上，新增**按报工时长加权**一种分摊，砍掉权重/复制/班组计件等花哨能力。复用现有报工拆分逻辑。
> 依据/拍板：2026-10-02 多隆老同学与黑帽大人对标黑湖后拍板——黑湖四种分摊偏花哨，中小五金厂大多用不上，砍到"**平均 + 按工时**"两种就够；放 `docs/未做指令/202`（精简版覆盖原版，按此执行）。

## 取舍（定死）
| 项 | 定案 |
|---|---|
| 做/不做 | 做**多人派工** + **新增按工时分摊**；**不做**按权重、复制、班组计件 |
| 复用还是另写 | 复用「多人共同报工」自动平分逻辑（`08-扫码问答 Q13`）；派工复用 `assignee_user_id` 载体改造成多人 |
| 分摊方式 | 两种并存：**平均**（默认，现有）/ **按报工时长加权** |
| PC / H5 | 派工入口在 **H5（Vant）** 与电脑端（Element Plus）都支持；报工分摊在 **H5（Vant）** 报工页 |
| 派工存储 | 一道工序可派多人（`assignee_user_id` 单值字段需评估是否扩为关联表，**待 Cursor 对照数据字典定**） |

## 已核实现状（勿重复做）
- 已有：电脑端派工写 `prod_work_order_operation.assignee_user_id`，一次一人（`03-工单·派工` / 知识库 4.3）。
- 已有：手机「多人共同报工」自动平分，余数归报工人（`08-扫码问答 Q13`）。
- 已有：报工可填 `duration_minutes`（时长），用于按工时加权。
- 缺口：一道工序不能派多人；分摊只有"平均"，无按工时。

## 改动点
- 数据模型（**待核实后改 docs/02**）：
  - 若 `assignee_user_id` 单值不够，新增派工明细表（工单工序 × 多用户）；若评估可复用现有表存多值/JSON 则复用，**由 Cursor 对照数据字典定**，不臆造。
- 后端：
  - 派工：当请求派多人 → 写入该工序多执行人；班组长限本组；空=清空派工。
  - 多人报工分摊：当分摊方式=**平均** → 均分、余数归报工人（现状不变）；当=**按时长加权** → 按各人 `duration_minutes` 占比拆分良品（未填时长者按均分兜底）。各方式合计须等于总良品数（取整尾差归报工人）。
  - 防超额：沿用现有"累计良品达计划量自动拦截"，不新增锁（`06-数据口径`）。
- 前端 H5（Vant）：
  - 报工页「多人共同报工」加分摊方式选择（平均/按工时），多人时各人可填时长。
  - 派工界面支持选多人（若派工改造落地）。
- 前端 PC（Element Plus）：工单详情【执行人】支持多选（若派工改造落地）。
- 文档：改 `docs/02`（派工多值结构）；同步 `SupportDocs/04` 或 `08` 多人报工说明。

## 验收（3～5 条勾选）
- [ ] 一道工序可派多个工人，各人手机【任务】页均显示该工序；班组长限本组。
- [ ] 「多人共同报工」选平均 → 均分、余数归报工人，合计=总良品（现状回归）。
- [ ] 选按工时加权 → 按各人时长占比拆分，合计=总良品；未填时长者按均分兜底。
- [ ] 累计良品达计划量仍自动拦截，防超额行为不变；`docs/02` 已同步派工多值结构。

## 不做 / 边界
- **不做**按权重分摊（主副手）、复制到他人、班组计件模式——属花哨能力，等客户真提再立项。
- **不做**派工后拦截未派工序报工（保"派工=提示"卖点）。
- **不做**推送通知（企微预警默认关）。
- 派工多值存储方式（复用单值/新表/JSON）未核实，**由 Cursor 对照数据字典定**，不臆造。
