# 206-优化指令：工人手机「今日计件」汇总（对标黑湖即时激励）

> 状态：已做（2026-10-02）
> 一句话目标：给工人手机端加一个**「今日计件」汇总卡片**，实时显示本人今天的计件件数、金额（含已通过+待复核），给工人即时"今天赚多少"的反馈，对标黑湖激励点。
> 依据/拍板：2026-10-02 多隆老同学与黑帽大人对标黑湖（工人手机"今天赚了多少钱都能看见"）后拍板；放 `docs/未做指令/206`。

## 取舍（定死）
| 项 | 定案 |
|---|---|
| 做/不做 | 做**今日计件汇总卡片**（本人、实时）；不做工资单生成、不做历史多周期汇总（那归工资报表） |
| 复用还是另写 | 复用 `prod_report.wage_amount`（单笔金额快照）+ 本人报工记录；纯前端聚合，**不动表** |
| 计算口径 | 汇总**今日本人已通过(review_status=1)+待复核(0)** 报工的 `wage_amount` 之和；**不含**已退回；显示件数与金额 |
| PC / H5 | 卡片在 **H5（Vant）** 工人端；电脑端不新增（工资报表已有） |
| 刷新 | 报工提交后即时刷新；进入页面时加载当日数据 |

## 已核实现状（勿重复做）
- 已有：`prod_report.wage_amount`（提交时回填的单笔金额快照）、`good_qty`、`review_status`。（知识库 4.3/5）
- 已有：单笔报工提交时实时预览工价金额（`08-扫码问答 Q8`）。
- 缺口：手机端无"今日计件总额"汇总卡片。

## 改动点
- 后端：
  - 新增（或复用现有报工查询）一个**当日本人计件汇总**接口：按 `user_id` + 今日 `report_time` + `review_status IN (0,1)` 聚合 `SUM(good_qty)`、`SUM(wage_amount)`；不含已退回(2)。返回 `{todayGoodQty, todayWage}`。
  - 口径：按**原报工时间**统计当日（与生产报表一致，`06-数据口径`）；已结算/未结算都计入（只要今日报工）。
- 前端 H5（Vant）：
  - 工人端首页/报工页顶部加「今日计件」卡片：显示"今日 X 件 / ￥Y"。
  - 报工提交成功后即时刷新该卡片；进入页面时加载当日数据。
  - 金额口径注明"按已复核+待复核报工估算，以工资单为准"，避免误导。
- 文档：不改 `docs/02`（复用现有字段，无新表）；如新增接口则同步 `SupportDocs` 接口清单。

## 不做 / 边界
- **不做**工资单生成、周/月历史汇总（归 `报表→工资报表`）。
- **不做**"今日实时总额"的全车间看板（那是老板大屏，另行评估）。
- **不做**推送通知。
- 金额为 `wage_amount` 快照估算，**不代表已发放**，界面须加口径提示。
