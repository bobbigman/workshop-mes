# 424-优化指令：缺锁价报工时自动补绑价目表

> 状态：已做（代码已落地；未现场报工验收，勾选保持空白）  
> 依据：用户 2026-10-29 确认「懒绑定 A」——后来能匹配到价目表则自动生效，不要求复制/再保存；不做「永远跟最新价漂移」。

## 目标

报工（及读本单预算/预览）时：任务尚无 `processing_price`，且该工序尚无报工，且当前能命中有效价目表 → **服务端自动写锁价一次**，再继续原取价/报工；用户零额外操作。

## 决策表

| 条件 | 行为 | 提示 |
|---|---|---|
| 已有锁价 | 照旧读锁价（418 仍可按报工日重算金额） | — |
| 无锁价 + 无该工序报工 + 价目表可命中 | 自动 Preview 写入任务锁价并保存 | 静默成功 |
| 无锁价 + 无报工 + 价目表不可命中 | 阻断 | 沿用价目表缺价/冲突原文 |
| 无锁价 + 已有该工序报工 | 阻断，不补价 | 已有报工但缺少锁价，不能自动补价 |
| 已有锁价后调价目表 | 不替换本单锁价结构/属性证据 | 与 413/418 一致 |

## 落点

- `OperationPricingService.BudgetAsync`：缺锁价时懒绑定（所有报工/`LockedAsync` 入口汇聚于此）
- `OperationPriceListService.PreviewAsync(workOrderId)`：改为走 `BudgetAsync`，不再要求「先有锁价」
- 不改前端、不改表、H5/PC 报工入口共用

## 验收

- [ ] A0008 类：任务锁价全空、通用价目表已启用、无报工 → 直接报合片成功，库中该任务写出 `processing_price`
- [ ] 同工序已有报工且仍无锁价 → 仍阻断，文案含「不能自动补价」

- [ ] 已锁价工单调价后，未走 418 追溯则报工仍认原锁价证据（不因本改动被换掉）
