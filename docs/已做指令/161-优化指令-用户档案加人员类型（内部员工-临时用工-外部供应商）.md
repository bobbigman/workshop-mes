# 161-优化指令：用户档案加"人员类型"（内部员工/临时用工/外部供应商）

> 状态：已做（2026-10-09）
> 性质：内部试用（系统已上线，新增字段+登录权限分支，不影响老账号主流程）
> 目标：让管理员在【用户档案】用一个单选下拉区分"自己扫码领工资的本厂人"和"挂名代报、结算加工费的外部供应商"，把委外厂当员工管，零新表零新流程。
> 依据/拍板：
> - 2026-10-09 黑帽大人提出：委外加工可用一个"外部"标记的员工作为结算对象，灵活结算加工费。
> - 多隆扒黑湖：黑湖用"虚拟用户"（不发账号、不占席位、代报工）解委外/短期工场景，但那是SaaS按席位卖钱的商业设计；咱们内网无席位约束，**临时用工应能自己扫码**。
> - 命名：黑帽大人拍板不用"虚拟用户"（技术味浓），采用"人员类型"三枚举。

## 取舍（已定 / 待确认）

## 本次范围与落点

- 完整流程：管理员在【用户档案】新建"外部供应商-XX加工厂"→ 人员类型选"外部供应商"→ 挂到"委外供应商"部门 → 保存后系统不发登录密码（或发了也登不进）→ 本厂采购员在 PC 报工/补报界面选这个"人"作为作业人员 → 月底工资报表按人员类型筛"外部供应商"导出，就是应付加工费明细。
- 已有能力：
  - 160 号指令已落地"用户↔部门"双向配、Excel 导入、报工交集校验。
  - PC 补报/代报工界面已存在（具体路径待 Cursor 核实）。
- 缺口（待 Cursor 看代码核实后落点）：
  1. `sys_user` 加列 `UserType tinyint not null default 0`；老数据全部默认 0=内部员工，无需迁移脚本。
  2. 用户新增/编辑弹窗加"人员类型"单选下拉（内部员工/临时用工/外部供应商）。
  3. 用户列表加一列"人员类型"，用 Element Plus Tag 标签着色区分（外部供应商标红/橙）。
  4. 后端登录校验：登录时若 UserType=2（外部供应商）→ 硬拒，返回"外部供应商账号不开放登录，由管理员代报工"。JWT 签发前拦截。
  5. 用户 Excel 导入模板加"人员类型"列（填：内部/临时/外部，可空，空默认内部）。
  6. **工资页**（工资列表+工资明细层+导出CSV）加"人员类型"筛选下拉（全部/内部/临时/外部），列表行打类型标签；导出CSV带"人员类型"列。
  7. **PC 报工列表页**加"人员类型"筛选下拉+一列类型标签（外协记录一眼可辨）；不动 H5 报工页。
  8. 工资按色码看板**本次不碰**。
- 数据与契约：sys_user 加列；同步改 docs/02 对应表定义。

## 行为与口径（分叉写成显式条件）

- 当 UserType=0（内部员工，老数据全部默认此项）→ 登录、报工、工资、权限跟现状完全一致，零行为变化。
- 当 UserType=1（临时用工）→ 能登录、能扫码报工，流程同内部员工；报工数据照常进工资表，报表上多一个"临时"标签供财务识别，**不修改工资计算公式**。
- 当 UserType=2（外部供应商）→
  - 登录接口硬拒，前端 H5/PC 登录页提示"外部供应商账号不开放登录"。
  - 由管理员在 PC 补报/代报界面选该用户作为作业人员录入报工记录，走正常报工入库。
  - 报工权限校验照常：该用户所属部门 ∩ 工序权限部门 ≠ 空 才能被选作代报人（避免误选到没权限的工序）。
- 当管理员把某个用户从"内部员工"改成"外部供应商" → 该用户下次登录被拒；历史报工记录保留不动。
- 当导入Excel某行"人员类型"填了无法识别的值（如写错成"外委"）→ 整行报错并指出列名，不静默归默认。
- 当外部供应商账号被误开 H5 登录 → 后端按 UserType 拦截，不依赖前端隐藏按钮。

## 止步线（本次不做，别顺手加）

- 不做委外发料/收货/退料/库存扣减流程（真要做是独立大模块，另立指令）。
- 不做发票管理、应付账款、付款登记（财务在系统外做）。
- 不做临时工合同、临时工价差异化、工价分段。
- 不做 H5 端任何改动（外部供应商不登录，临时用工走现有 H5）。
- **不碰工资按色码看板**（实时可视化，本次不增删筛选/列，避免动颜色计算接口）。
- 不做"按人员类型自动切换工资计算公式"——本次只是报表分组，算钱逻辑不动。
- 不做供应商主数据表（联系人、银行账号、税号等），那是 ERP 的事。
- 不预建隐藏开关、预留字段、抽象基类。
