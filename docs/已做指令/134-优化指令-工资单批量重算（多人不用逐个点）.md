# 134-优化指令：工资单批量重算（多人不用逐个点）

> 状态：已完成（2026-10-02，按 138 落地）
> 一句话目标：工资单列表勾选多张 → 一键"批量重算"。草稿直接原地重算、已确认先软撤回再重算；对标黑湖"整批重生成报表"，杜绝人多逐个点。
> 依据/拍板：2026-10-02 黑帽大人（用户）拍板。多隆核实：单张 recalc / revoke 已实现，缺口是"按单粒度、无批量"。

## 已核实现状（勿重复做）
- 已有：`SalaryController` 单张 `generate` / `{id}/recalc`（草稿原地重算、保留手工项，docs/133）/ `{id}/revoke`（已确认撤回，仅管理员 `Roles="1"`）/ `confirm` / `delete`。
- 已有：`prod_report.duration_minutes`（报工时长）+ `PriceRuleMatcher` 计时公式（amount=duration/60×单价）。
- 已有：`salary_statement` 手工列 `base_salary / meal_allowance / other_allowance / social_tax / other_deduction`（docs/73，仅草稿可改）。
- 缺口：重算是"按单"粒度；多人需逐个进单 recalc/revoke，缺多选批量。

## 改动点
- 后端 `backend\Controllers\SalaryController.cs` + `ISalaryService`：
  - 新增 `POST batch-recalc`，入参 `[long[]] ids`（按当前厂校验归属）。
  - 循环处理，任一张失败不停整批：当 `status=草稿` → 复用 RecalcDraft（原地重算、保留手工项）；当 `status=已确认` → 先**软撤回** `RevokeAsync`（status→草稿、`settled_flag`→0、**保留单与明细、不删单**，仅管理员）再原地重算。
  - 返回逐张 `{id, 成功/失败原因}`，失败单可单独重算。
  - 权限：批内含已确认单时仅管理员（复用 `[Authorize(Roles="1")]`）。
- 前端 工资单列表页（Element Plus，路径以 Cursor 对照现有 Salary 列表为准）：
  - 列表加 el-table 多选（selection）+ 顶部【批量重算】按钮 + 二次确认。
  - 调 batch-recalc，按返回逐行提示成功/失败。
- 文档：不改 docs/02（复用现有字段/逻辑）；新接口签名补记 docs/33 接口说明。

## 验收（3～5 条勾选）
- [ ] 勾选 N 张已确认单批量重算 → 全部回草稿重算、手工项保留、金额按新工价更新、可重新确认
- [ ] 混合勾选（草稿+已确认）→ 草稿直接算、已确认先撤再算，结果一致
- [ ] 非管理员批量重算含已确认单 → 被拒（Roles=1）
- [ ] 单张失败不影响整批，返回逐张成功/失败原因
- [ ] 批量后 settled_flag 已回滚，无重复工资单

## 不做 / 边界
- 不做全周期重新 generate（会生成重复单）。
- 不做 H5。
- 栏位取舍（拿掉底薪/餐补/社保个税）未拍板，另立项，本次不动。
