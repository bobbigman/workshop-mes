## 1. 本次交付

**只做一个 PC 售前演示页：看出哪道工序缺料、缺多少 → 一键模拟补齐 → 复验通过 → 重置。** 客户能看懂这条流程，本次目标就达到；不把样板做成正式缺料管理模块。

沿用 Vue3 + Element Plus，在现有前端开发环境中提供可直接打开的独立演示入口（建议 `frontend/demos/material-shortage.html`，复用现有 Vite 和依赖）。不接正式菜单、业务路由、登录鉴权或服务器配置，默认生产构建不包含该演示入口；不新增打包模式、公开部署或演示服务。开工时先核实这个独立入口的启动方式即可，不搜全库接口、不改后端。

页面始终显示“样板演示 · 模拟数据 · 不影响生产 · 刷新后恢复”，编号使用 DEMO 前缀。只使用本地固定数据，不调用 MES、库存、金蝶或 MCP 接口，不把模拟数据传入正式页面。现有下单、扫码报工和看板不在改动范围内。

## 2. 固定样板与口径

一张 `DEMO-WO-001` 工单，固定数量 100 件，三道工序各一种独立物料；不做工单选择、开工数量输入、物料编辑或跨工序分配。

| 工序 | 物料 / 单位 | 单件用量 | 损耗率 | 需求量 | 工序可用量 | 在途量 | 当前缺口 |
|---|---|---:|---:|---:|---:|---:|---:|
| 裁切 | DEMO-M01 配件 / 个 | 2 | 5% | 210 | 160 | 100 | 50 |
| 装配 | DEMO-M02 紧固件 / 个 | 1 | 0% | 100 | 100 | 0 | 0 |
| 包装 | DEMO-M03 包装袋 / 个 | 1 | 0% | 100 | 80 | 0 | 20 |

计算只覆盖此固定样板：需求 = 100 × 单件用量 ×（1 + 损耗率）；缺口 = max（需求 − 工序可用量，0）。全部数量为整数，不做四位小数、通用精度算法、单位换算或损耗配置。

“工序可用量”是样板分配给本工序的量，不是仓库总库存。在途只展示，不抵扣缺口；旁边直接说明“在途未到货，不能用于当前开工”。不增加动态到货日期或风险预测。

## 3. 一页四个动作

- **查看**：表格显示三道工序及上述数量；状态写“齐套 / 缺料”，颜色只辅助表达。当前选中工序展示相应操作，不额外做统计卡或图表。
- **模拟开工**：当缺口 > 0 → 提示物料与缺口；当缺口 = 0 → 提示“模拟校验通过”。只反馈校验结果，不生成开工、报工或停工记录。重复点击保持同样结果，不累加次数。
- **模拟补齐**：只对当前缺料工序开放；一键把该工序可用量增加当前缺口，不填数量、不做弹窗表单。补齐后更新表格，并提示“已模拟补齐，请再次校验”；齐套时禁用此按钮。在途量保持不变，明确这是人为模拟补料。
- **重置样板**：恢复三行初始数据及当前提示；刷新也恢复。状态仅存在页面内存，不写 localStorage、数据库或文件。

固定样板直接放页面或同目录普通数据文件即可，不建立版本化样板管理、导入导出、通用计算服务或组件库。少量重复文案不值得抽象框架。

## 4. 范围止步线

| 这次保留 | 后续出现明确需求再单独立项 |
|---|---|
| 独立演示入口、固定数据、缺口提示、补齐复验、重置 | 正式产品入口、管理员权限、服务器开关、客户演示包 |
| 当前工序的即时反馈 | 缺料台账、事件去重/解除、统计、停工时长、导出 |
| 固定 100 件、整数数量 | 自定义工单/数量/物料、部分补料、小数精度、共用库存分配 |
| 本地模拟数据 | 金蝶/MCP 对接、库存同步、生产开工拦截、H5/PDA、AI 预测 |

这些后置项不是预留接口、隐藏按钮、测试用例或本次验收要求。不为将来扩展提前建表、加配置、接业务服务。若独立演示入口需要改正式登录、菜单或后端才能实现，应先缩小落点，不继续扩范围。

正式生产接入仍须另行确认真实客户的接口、资料、单位与占用口径。三条业务硬规则、权威 DDL、异常上下文和部署更新约束仍然适用；本次不改生产契约，因此不改 `docs/01/02`。
