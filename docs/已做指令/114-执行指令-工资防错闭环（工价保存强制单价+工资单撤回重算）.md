# 114-执行指令：工资防错闭环（工价保存强制单价 + 工资单撤回重算）

> 状态：已落地（2026-10-01）
> 一句话目标：**堵源头 + 留后路**。A块：工价表新增/编辑时，单价必须 >0，否则不让保存（杜绝"配了条没单价的工价"，从根上避免工资为0）；B块：工资报表对已确认工资单提供【撤回重算】，比照黑湖"工资是可重算派生报表"，已确认单可撤回、改价后重新生成重算。
> 依据：`docs/2G-对标分析-工资计算vs黑湖小工单.md`（黑湖官方口径：配价在源头工价库、工资可重算）；用户（黑帽大人）2026-10-01 拍板。
> 指令写法：全部步骤用「前置判断 → 条件执行 → 收尾」三件套，条件可判定、判断在动作之前；不满足前置判断就停下不硬改。
> 已有基础（核实过，勿重复做）：后端 `POST /api/Salary/{id}/revoke`（`SalaryService.RevokeAsync`，撤回已确认单=删明细删单+回滚 settled_flag）**已存在**；`GenerateAsync` 已返回 `unmatchedCount`；前端 `onGenerate` 已弹"未匹配工价"告警。本次只做 A块拦截 + B块前端接撤回按钮。

---

## 〇、背景（事实）
- 工价表 `BasePriceRule` 单价 `UnitPrice` 是值类型默认0；现 `PriceRuleService.Validate` 只拦 `UnitPrice < 0`，**单价=0 或未填（前端默认0）能保存成功** → 导致报工计价无价 → 工资单金额0。
- 工资报表已确认单目前前端**无撤回入口**，确认即冻结（`settled_flag=true`）；漏算/配错价无法重算，违背 AGENTS.md「钱要可追溯可重算」红线。

---

## 一、改动点（已核实）

### A块｜工价保存强制单价（源头拦截）
- 后端：`backend/Services/PriceRuleService.cs` → `Validate(dto, loc)`（约第 164~176 行），**第 168 行** `if (dto.UnitPrice < 0)` 改为 `if (dto.UnitPrice <= 0)`，文案「单价必须大于0」。新增、编辑（CreateAsync/UpdateAsync 均走 Validate）共用。
- 前端（体验补充，非硬拦）：`frontend/src/views/price-rule/index.vue` 单价输入框（约 86 行）`:min="0"` 改 `:min="0.01"`；`onSave` 保存前先判 `form.unitPrice <= 0` → `ElMessage.warning('请填写单价（须大于0）')` 并 return，不调保存。
- 存量已存在的 0 价规则：**本次不动**，留管理员自查（可选清理，不属本指令）。

### B块｜工资单撤回重算（比照黑湖）
- 后端：`revoke` 已具备，**不改**。
- 前端-API：`frontend/src/api/salary.js` 追加 `export const revokeSalary = (id) => http.post(`/Salary/${id}/revoke`)`。
- 前端-页面：`frontend/src/views/salary/index.vue` 操作列（约 69~81 行）对 `row.status === 1`（已确认）加【撤回重算】按钮（danger 链接）；新增 `async function onRevoke(row)`，调 `revokeSalary(row.id)`，成功后 `ElMessage`「已撤回，可重新生成工资单重算」并刷新列表。

## 二、Cursor 原子指令（前置判断 / 条件执行 / 收尾）

### 步骤0｜A块后端：工价保存拦单价≤0
- **前置判断**：当 `PriceRuleService.cs` 中 `Validate` 方法可定位到 `if (dto.UnitPrice < 0)` 那一行 → 继续；对不上 → 停下报「位置：PriceRuleService.Validate 现状」，不硬改。
- **0a 条件执行**：当定位成功 → 把 `dto.UnitPrice < 0` 改成 `dto.UnitPrice <= 0`，报错文案改「单价必须大于0」；当 `CreateAsync`/`UpdateAsync` 都调 `Validate` → 一并生效（无需另改）。
- **0b 收尾**：当改完 → 下一步骤0验证；当编译失败/校验没生效 → 报「位置：步骤0 失败原因+现状」，不吞。

### 步骤1｜A块前端：工价表单单价必填>0
- **前置判断**：当 `frontend/src/views/price-rule/index.vue` 的单价 `el-input-number` 和 `onSave` 可定位 → 继续；对不上 → 停下报「位置：price-rule/index.vue 现状」。
- **1a 条件执行**：当单价框 `:min="0"` → 改 `:min="0.01"`；当 `onSave` 开头无 `form.unitPrice <= 0` 校验 → 在调保存前插入该校验（`ElMessage.warning('请填写单价（须大于0）')` 并 return）；当已有该校验 → 跳过不重复加。
- **1b 收尾**：当保存逻辑改完 → 下一步骤2；当报错 → 报「位置：步骤1 失败原因+现状」。

### 步骤2｜B块前端-API：封装 revokeSalary
- **前置判断**：当 `frontend/src/api/salary.js` 已存在 `confirmSalary`/`deleteSalary` 导出 → 继续；对不上 → 停下报「位置：api/salary.js 现状」。
- **2a 条件执行**：当文件里无 `revokeSalary` → 追加 `export const revokeSalary = (id) => http.post(`/Salary/${id}/revoke`)`；当已存在 → 跳过。
- **2b 收尾**：当导出写好 → 下一步骤3；当报错 → 报「位置：步骤2 失败原因+现状」。

### 步骤3｜B块前端-页面：加【撤回重算】按钮 + onRevoke
- **前置判断**：当 `frontend/src/views/salary/index.vue` 的操作列（含 `onConfirm`/`onDelete`）可定位 → 继续；对不上 → 停下报「位置：salary/index.vue 现状」。
- **3a 条件执行**：
  - 当操作列有 `row.status === 1` 的显示条件分支 → 在其下加 `<el-button v-if="row.status === 1" link type="danger" @click="onRevoke(row)">撤回重算</el-button>`；
  - 当 `onRevoke` 不存在 → 新增 `async function onRevoke(row)`：`await ElMessageBox.confirm('撤回将作废该工资单并解除报工冻结，改价后可重新生成重算，继续？', '撤回重算')` → `await revokeSalary(row.id)` → `ElMessage.success('已撤回，可重新生成工资单重算')` → `load()` 刷新；当已存在 → 跳过。
- **3b 收尾**：当按钮+函数写完 → 步骤4 编译验收；当报错 → 报「位置：步骤3 失败原因+现状」。

### 步骤4｜编译 + 验收（黑湖口径）
- **前置判断**：当步骤1~3 全部完成 → 编译后端 + 前端；未完成先补齐。
- **4a 条件执行**：当可运行 → 用验收清单逐条过：
  - ① 工价表新增/编辑，单价填 0 或留空 → 点保存报错「单价必须大于0」，**保存不成功**；填 >0 → 保存成功；
  - ② 工价表前端，单价 0/空 → 保存前弹「请填写单价（须大于0）」，不发请求；
  - ③ 工资报表已确认单 → 操作列出现【撤回重算】→ 点它 → 确认框 → 撤回成功、列表刷新（该单消失）、关联报工 `settled_flag` 回滚为 false；
  - ④ 改对工价后重新【生成工资单】→ 金额按新价重算正确、可再次确认。
  - 当任一不符 → 回对应步骤修正重验。
- **4b 收尾**：当全过 → 标记完成；当不符 → 如实报「现状」，不标完成。

## 三、验收入口（黑帽大人验）
- A块：工价表单价填 0 保存 → 报错不让存；>0 → 能存。
- B块：已确认工资单能【撤回重算】→ 撤回后重新生成 → 金额按补/改后的工价正确。
- 全过才算完成。

## 五、一键关闭 / 影响面（备注）
- 不建表、不改数据字典、不动存量报工与已生成工资单；两处改动纯新增校验 + 新增按钮，撤销即还原（还原 A块 168 行、B块按钮与 onRevoke 即可），不影响其它模块。
