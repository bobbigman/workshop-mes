## 二、对外单一通道（Pushplus；企微②隐藏）

- **对外只有一条通道：Pushplus 轻量通道**：客户扫码关注「推送加」服务号，填 Token 即用；无需备案/域名/公众号。主推中小工厂。
- 企业微信自建应用通道②：**内部后置项，对客户完全隐藏**（不在菜单/配置页/文档/话术出现；涉密大客户真要时再内部另议）。

## 三、车间定制告警规则（差异化，竞品抄不走的业务逻辑）

- **分级告警**：重大故障（停机/模具损坏）→ 持续推送、5分钟重复；轻微异常（少量不良/缺料）→ 只推 1 次。
- **时段过滤**：夜间 22:00–07:00 仅推停机重大故障，普通告警静音。
- **按权限分发**：3号线故障只推 3 号线主管+老板；质检异常只推质检负责人，不全员轰炸。
- **降噪去重**：同一设备连续报故障，1 小时内最多推 3 条。
- **工单超时**：派工 N 小时未开工 / 完工未入库自动提醒，N 可配。

## 四、本次范围与落点（建议首版）

- **交付**：事件命中 → Pushplus → 老板/主管个人微信收到（配置 → 推送 → 微信弹通知）。
- **复用**：现有事件规则与发送记录（129/130）；新增「Pushplus 发送器」。
- **入口**：现有「微信预警」配置页，加 Pushplus 通道（Token + 接收人 + 规则）。
- **数据契约**：涉及新表/字段须同步 `docs/02`。

## 五、行为与口径（分叉写成显式条件）

- 当事件命中【重大故障】→ 5 分钟重复推送；当命中【轻微异常】→ 只推 1 次。
- 当触发时段为【夜间 22:00–07:00】且非停机级 → 静音不发。
- 当【同一设备 1 小时内累计推送≥3 条】→ 本次不推（去重）。
- 当【工单超时规则命中】→ 按配置 N 推送对应负责人。
- 当推送失败 → 仅记日志，**不阻断工单主流程**。

## 六、安全（车间场景必须落）

- Token 存服务端环境变量 / 配置（不写死代码、不进日志）。
- Pushplus 后台开**安全 IP 白名单**，仅车间服务器 IP 可调接口。
- 告警文案只保留【设备编号 + 故障类型 + 工单号】，不附带报价/产能/工艺机密。
- Token 泄露 → 后台一键重置失效。
