## 本次范围与落点

- 完整流程：管理员在 PC【用户档案】把某临时工“工价系数”填0.8 → 该工人扫码报工 → 计价口子金额×0.8 → 工资单/工端“今日计件”同步显示折后金额 → 月底工资明细可对账。
- 已有：161 人员类型字段+工资按人员类型筛选/标签；计价单一口子 PriceRuleMatcher→Calculate→salary_statement_item；报工 prod_report.unit_price 实时预览回填（记录原始工价）。
- 缺口（待 Cursor 看代码核实后落点）：
  1. sys_user 加 WageCoeff；老数据默认1，无需迁移。
  2. 用户档案新增/编辑加“工价系数”输入（默认1，可空则1，0.1~9.99）。
  3. SalaryService 所有计价出口（生成工资单、当日试算、今日计件、明细）统一在 Calculate 结果上 × WageCoeff；仅对配了≠1的用户生效。
  4. 工资明细/导出CSV加“系数”列。系数写在 salary_statement_item.wage_coeff（本行实际乘数：计件/计时=当时用户系数，固定与未匹配=1），不读用户当前系数，避免改系数后旧单对不上。
  5. prod_report.unit_price 快照**保持原始工价不变**（不动事实）。报工预览 wage_amount 与工资单应发都是乘系数后的净额。今日计件读的是这条预览金额：设好系数后再报工即显示折后；已报过的记录要等改报工或生成/重算工资单才改写预览。

## 行为与口径（分叉写成显式条件）

- 当 WageCoeff=1（默认，全部老用户/未配用户）→ 计价结果与现状**完全一致**，零行为变化（保证其他账套零影响）。
- 当 WageCoeff=0.8 且为计件 → 工资单金额=good×unit_price×0.8。
- 当 WageCoeff=0.8 且为计时 → 金额=(duration_minutes/60)×unit_price×0.8。
- 当 WageCoeff=0.8 且为固定（月薪）→ 不乘，金额=unit_price。
- 当该用户某条报工有不良扣款 → 应得部分×0.8；扣款 deduct=defect×deduct_price 按原价，不打折。
- 当管理员把 WageCoeff 从0.8改成1 → 已生成工资单金额不变（结果已固化）；撤回重算后按新系数重算。
- 当未配系数（空/1）用户报工 → 预览与结算均为原价，行为同今天。
- 报工页/工端“今日计件”预览 → 按 WageCoeff 显示折后真实收入，与工资单一致。
