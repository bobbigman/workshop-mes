# 109-优化指令：报工复核帮助浮层完善

> 状态：已落地
> 一句话目标：把 PC「报工复核」页右上角「？」/F1 帮助浮层的文案，按真实操作重写，把「工单号手敲+回车、切状态到已通过、已通过也能退回、退回后去 PC 报工页改数（手机只读）」这些关键操作讲清楚，免得班组长/老胡像本次一样卡住。

---

## 一、背景：今天实测踩到的坑（工单 A0001）

用户（黑帽大人）实测复核流程，连续卡在 5 处，根因都是**帮助浮层没写、界面引导缺失**，不是功能 bug：

1. **复核页「工单编号」下拉没有 A0001** → 因为下拉只列「有待复核报工」的工单（`docs/106`、`ReviewService.OrderOptionsAsync` 硬编码 `review_status=0`），A0001 三条全是「已通过」，不在下拉里。
2. **手敲 A0001 显示「无数据」没反应** → 该框是 `el-select` + `filterable + allow-create`，敲完必须**按回车确认**值才生效；「无数据」只是下拉源里没有，属正常提示。
3. **查不到已通过的报工** → 复核状态下拉默认「待复核」，必须**切到「已通过」**才看得到、才退得了 A0001。
4. **前面的勾选框勾不了** → 勾选框 `:selectable="row.reviewStatus===0"`，只给「待复核」行勾，用于【批量通过】；已通过/已退回的行勾不了是正常，**退回根本不用勾选，直接点行内红色【退回】**。
5. **退回后工人不知道去哪改** → 手机端「我的报工」页是**纯只读**（`h5/my-reports.vue` 第 48 行明写「只读查询…不要重复报」），**没有修改入口**；改数只能走 **PC「报工」页【修改】**（`report/index.vue` 第 52 行，待复核/已退回报工可改，已通过禁用），或让管理员/班组长代改。

**结论**：功能全通，纯是帮助文案没把这些操作路径写清楚。本次只改帮助浮层文案，不动任何业务逻辑。

## 三、Cursor 原子指令（按用户通用模板）

**一句话目标**：落地上面的 `/review` 帮助文案，让班组长/老胡按「？」/F1 就能完成复核、退回、退回后改数全流程。

**现状事实（已核实）**
- 帮助配置源文件：`frontend/src/help/pageHelp.js`，`'/review'` 段当前在第 117–147 行（title/value/items 结构，现文案简略，缺本次要补的 5 个操作点）。
- 后端/前端功能均已具备，本次**不新增业务逻辑、不改数据字典**，纯文案替换。

**前置确认（无需人拍板，直接执行）**

**原子步骤（每步独立，满足条件才执行）**

- **步骤1｜定位并替换**：当 `pageHelp.js` 存在 `'/review'` 段 → 把该段整个对象（第 117–147 行）原样替换成上面「最终版」；当找不到 `'/review'` 键 → 停止并报「未找到 /review 帮助配置段」，不擅自新建。
- **步骤2｜检查文案格式**：当替换完成 → 逐条核对：①每条 `how` 是一句连贯中文大白话；②界面不出现 `what`/`how`/`who` 英文标签；③`who` 只在权限差异条目带「班组长或管理员」；④8 条 `items` 齐全。当任一不符 → 修正后重查。
- **步骤3｜保存**：当步骤1、2 通过 → 保存文件。
- **步骤4｜页面验收**：当已保存 → 启动前端，登录 PC 打开「报工复核」页，点右上角「？」或按 F1，逐条核对 5 个关键点：①工单编号手敲+回车 ②状态切「已通过」能查到已通过单 ③勾选框只有待复核能勾 ④已通过的单也能【退回】 ⑤退回后指引去电脑端报工页【修改】、手机端只读。当 5 点全对上 → 标记完成；当任一点对不上 → 回步骤1按现状重写再验。
- **步骤5｜回归**：当完成 → 抽查「报工」「工单」「生产报表」等其它页帮助浮层未被误改（只动了 `/review` 段）；当有误改 → 回滚只保留本次改动。

**一键关闭**：纯前端文案改动，不新增功能；任何一步不想继续 → 停止即可，用 `git checkout -- frontend/src/help/pageHelp.js`（或手工还原）即可整体回滚，不影响业务数据。

**失败原因要求**：任何一步失败，日志/回显必须写明「位置 + 做什么失败 + 现状」，不吞错、不脱敏。

**验收口径**：PC「报工复核」页「？」/F1 弹出的内容与「最终版」8 条完全一致，且 5 个关键操作点能指导班组长完成「退 A0001 这类已通过报工 → 去 PC 报工页改数」全流程，即为完成。
