# 优化指令：手机工单列表（状态 Tab + 数量 + 点选报工）

> 状态：已实现  
> 依据：黑湖手机「工单」列表截图（全部 / 未开始 N / 执行中 N / 已结束 N）+ 用户确认的「最小落地」4 点  
> 目标：工人不必只会扫码；可先看工单列表，点进去报工  
> 原则：轻量对标；复用现有报工页与列表接口；不做逾期标签、工序百分比链、完整底部五 Tab App

---

## 1. 背景与差距

| # | 黑湖（截图） | 本项目现状 | 本期 |
|---|-------------|-----------|------|
| 1 | 手机「工单」列表 + 状态 Tab 带数量 | 仅 PC 有状态 Tab；H5 无列表 | **做** |
| 2 | 点工单进入详情/报工 | H5 只能扫码/输工单号进报工 | **做**（点卡片 → 现有报工页） |
| 3 | 底部「工单 / 报工 / …」多 Tab | 仅 `/h5/scan`、`/h5/report` | **做简化底栏**：工单 \| 扫码 |
| 4 | 逾期、剩余天数、工序 % 圆点链 | 无交期字段；详情已有 tasks | **不做**（二期） |
| 5 | 「快速操作」、中间「+」建单 | 建单在 PC | **不做** |

**「如何新增报工」答法（实现后）：**

1. 手机打开工单列表 → 选状态 → 点一张工单 → 填数提交；或  
2. 底栏「扫码」→ 扫/输工单号 → 填数提交（原路径保留）。

## 2. 自主拍板

| 项 | 决定 | 理由 |
|----|------|------|
| 新页面路径 | `/h5/orders` | 与现有 `/h5/scan`、`/h5/report` 并列 |
| 生产人员默认首页 | role=2 登录后进 `/h5/orders`（不再直接丢到 scan） | 对齐黑湖「先看工单」；扫码仍可从底栏进 |
| 状态 Tab | `全部` / `未开始(0)` / `执行中(1)` / `已结束(2)` | 对齐截图；**不含「已取消」**（取消单不进现场主列表，与看板口径一致） |
| Tab 数量口径 | 各状态张数 = 本工厂 `prod_work_order` 按 status 计数；「全部」= 0+1+2 之和（不含 3） | 简单、可缓存一次拉回 |
| 列表数据 | 复用 `GET /api/WorkOrder`（已支持 `status` + 分页） | 少造接口 |
| 状态数量接口 | **新增** `GET /api/WorkOrder/status-counts` → `{ all, notStarted, doing, done }` | 一次查出四个数字，切 Tab 不必重算 |
| 列表卡片字段（最小） | 工单号、产品名、数量、状态、创建时间 | 够用；不做剩余数/进度条/%链 |
| 点卡片行为 | `router.push({ path: '/h5/report', query: { order: orderNo } })` | 100% 复用现报工页（摘要/继续报工/时长） |
| 底栏 | 两入口：`工单`(`/h5/orders`) + `扫码`(`/h5/scan`) | 不做任务/+ /看板 |
| 已取消工单 | 列表与 counts 均排除 status=3 | 现场不打扰；PC 仍可查 |
| 权限 | role=2 可访问 `/h5/*`；列表接口已有 RoleGuard 限制——**须放行** `GET /api/WorkOrder` 与 `GET /api/WorkOrder/status-counts` 给 role=2 | 否则列表调不通 |
| RoleGuard 调整 | role=2 白名单增加：`GET /api/WorkOrder`（仅列表）、`GET /api/WorkOrder/status-counts`；**仍禁止** PUT/POST/DELETE 工单 | 只读列表 + 报工提交 |

## 3. 后端

### 3.1 状态数量

```
GET /api/WorkOrder/status-counts
→ { code:0, data: { all, notStarted, doing, done } }
```

含义：

| 字段 | SQL 条件 |
|------|----------|
| notStarted | status = 0 |
| doing | status = 1 |
| done | status = 2 |
| all | status IN (0,1,2) |

工厂隔离：`factory_id = 当前用户工厂`。

### 3.2 列表（已有）

```
GET /api/WorkOrder?status=&keyword=&page=&pageSize=
```

- 不传 `status` = 全部（实现时须 **排除 status=3**，或 H5 固定传「非取消」——**拍板：Query 增加默认过滤，当请求头/来源不便区分时，增加 query `excludeCancelled=true`，H5 列表固定带上**）  
- **更干净拍板**：`WorkOrderQueryDto` 增加 `bool ExcludeCancelled { get; set; }`；H5 传 `excludeCancelled=true`；PC 不传则仍可看到已取消（PC 已有「已取消」Tab）。

### 3.3 RoleGuard（必改）

现白名单大致：`GET by-no`、`POST Report`、`GET Report/defects`。

增补：

- `GET /api/WorkOrder`（注意：不要放行 `GET /api/WorkOrder/{id}` 以外的写操作；若用精确匹配，列表是无 id 的 GET）  
- `GET /api/WorkOrder/status-counts`  
- 已有 `GET /api/WorkOrder/by-no` 保留  

路径匹配注意：`/api/WorkOrder` 与 `/api/WorkOrder/123` 区分——role=2 **允许**列表与 status-counts、by-no；**允许** `GET /api/WorkOrder/{id}` 亦可（只读详情，报工页已用 by-no，可选放行 Get 备用）。

**禁止**：POST/PUT/DELETE WorkOrder、transition、copy 等。

## 4. 前端

### 4.1 新页 `frontend/src/views/h5/orders.vue`

结构：

1. 标题「工单」  
2. Tab：全部(all) / 未开始(notStarted) / 执行中(doing) / 已结束(done)，文案带数量，如 `执行中 18`  
3. 副文案：`总计 ( N )`（当前 Tab 列表 total）  
4. 卡片列表：工单号、产品、数量、状态标签、创建时间  
5. 点击卡片 → `/h5/report?order=xxx`  
6. 底栏组件（见下）

交互：

- 切 Tab → 带对应 status 调列表（全部不传 status，但 `excludeCancelled=true`）  
- 进入页 / 从报工页返回时刷新 counts + 列表（`onMounted` + `onActivated` 若用 keep-alive；否则 onMounted 即可）  
- 空列表提示：「暂无工单」  

### 4.2 底栏 `frontend/src/views/h5/TabBar.vue`（小组件）

| 项 | 路由 | 说明 |
|----|------|------|
| 工单 | `/h5/orders` | 列表 |
| 扫码 | `/h5/scan` | 原扫码页 |

在 `orders.vue`、`scan.vue`、`report.vue` 底部引入（报工页也可显示，方便返回）。

### 4.3 路由与登录跳转

`router/index.js`：

- 增加 `{ path: '/h5/orders', ... }`  
- role=2 且访问非 h5/board 时：`next('/h5/orders')`（原为 `/h5/scan`）  
- 登录成功后若 role=2：前端登录页跳 `/h5/orders`（查 `login/index.vue` 一并改）

### 4.4 API 封装

`frontend/src/api/prod.js`：

```js
export const getOrderStatusCounts = () => http.get('/WorkOrder/status-counts')
// getOrderList 已有；H5 调用时加 excludeCancelled: true
```
