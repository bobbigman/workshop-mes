## 已实现契约

`query_risk_brief(period?, topN=3, authToken?, chanType?, sessionId?)`

- period默认today，只支持today/今日/今天与week/本周；未知或空串明确拒绝。topN为1～10，默认3。
- 正式模式未绑定/停用/非管理员拒绝，在查询业务数据前返回失败。绑定账号必须属于当前钥匙工厂；角色每次请求重读。演示仍拒绝缺少厂上下文。
- 业务时区取 `Ai:BusinessTimeZone`（默认Asia/Shanghai），按自然日计算，单次查询固定一个快照时间，禁用DateTime.Now直接减日期。
- 今日：当前未结束工单中全部超期、今天至未来3天（含第3天）临期、工序滞留；本周：交期截至本周日（周一开始），保留当前全部超期与滞留。只查status=0/1，无交期仍可因滞留入选，不按创建日期把老超期单滤掉。
- 滞留：未完成且计划数大于0的工序，超过3个自然日无有效报工；无报工从工单创建日计。ReviewStatus=0/1有效，2退回不刷新；已完成工序不计滞留，未来报工不纳入当前快照。
- 进度复用 `WorkOrderProgressQuery` / `WorkOrderProgressCalculator`，整单完成数为工序Min，不累加工序。查询前按厂过滤，进度汇总也排除外厂报工；仅返回生产定位、进度与风险字段，不返回工资/工价或派工人员信息。
- 全集筛选后排序：重点产品 → 超期 → 滞留 → 交期升序 → 工单ID，再取Top-N；分批加载避免SQL Server参数过多。无风险的重点产品不凭标记生成风险。

成功输出：

```json
{"code":0,"msg":"ok","data":{"period":"today","asOfDate":"yyyy-MM-dd","dueThroughDate":"yyyy-MM-dd","total":0,"truncated":false,"summary":"今日无超期、临期或滞留风险工单","scopeNote":"...","list":[],"fallbackText":"..."}}
```

list每项包含：id、orderNo、productCode、productName、isRiskFocus、dueDate、daysToDue、doneQty、remainQty、progressPercent、progressHint、overdueDays、stagnantOperations（operationName/daysWithoutReport）、reasons、suggestion。

- summary为确定性规则摘要，不冒充AI综述；无风险明确返回平安报，同时scopeNote说明仅交期/滞留，不扩大成全厂无任何风险。
- fallbackText含摘要及Top-N原因/建议；工具查询失败照常抛错，不吞异常生成平安报。
- 模型按给定排序组织120字以内大白话，重点产品须点名；数据过长时先摘要再列可完整呈现的首项，不截断工单号。备用列表保留完整条目，不受120字摘要限制。
- 「GDxxx做到哪了/第几道/进度」仍走query_work_order_progress；列表、工资各走原工具。本次不改原进度/列表工具。
