## 2. 模式与接口契约

- 在现有 `/api/ai-assistant/messages` 的 mode 中增量支持 `support`；progress/guide 的默认行为和契约不变。模式切换仍新建会话。
- support 模式可调用：`search_support_docs`、`search_work_orders`、`get_work_order_progress`、`get_work_order_report_evidence`。guide 的产品工艺查询保持原入口。
- 工具调度必须按会话 mode 再校验白名单，不仅依赖发送给模型的工具列表。禁止模型提供 sql/path/factoryId/userId/role 等权限或执行参数。
- 所有新入口沿用 JWT、role=1、当前工厂、当前用户会话归属校验；不使用演示鉴权。
- 保留现有 answer/sources/workOrders/warnings/traceId 等字段。sources 可新增可选 chapter、updatedAt；文件来源用服务端 sourceId、标题、版本、章节、摘录，不暴露硬盘路径。
- 消息结果新增可选 `reportEvidence`，结构按下节。旧模式缺省为 null，不影响旧客户端。
- 新增 POST `/api/ai-assistant/report-evidence/search` 用于证据明细翻页，不再次调用模型；请求为 conversationId、workOrderId、operationId?、reportFrom?、reportToExclusive?、page、pageSize。每次完整验证会话归属、工厂及参数；不信任前端此前已查过。
- 文档只显示服务端返回的来源摘录，首版无需开放任意文件下载接口。业务核对复用真实工单详情，不编造详情 URL。

## 3. 操作说明检索

新增专用服务（建议 SupportDocumentService），不改变原工艺知识库默认行为。

配置建议 `Ai:SupportDocs`：Enabled=false、RootPath为空、MaxFiles=100、MaxFileBytes=1048576、MaxTotalBytes=10485760、MaxResults=5、MaxEvidenceChars=12000。数值为首版上限，可部署调小；验证为正数且总量受限。资料未启用或无目录时，原 AI/业务仍可使用。

首版扫描根目录及普通子目录的 UTF-8 md/txt；忽略其它扩展名。服务器生成文件/章节 ID，模型只传 query（必填，最多 500 字符），不传路径。

1. 规范化路径后检查目录边界，拒绝绝对路径输入、上级跳转及符号链接/目录联接等重解析点逃逸；读取前检查文件大小，目录总量也设限。
2. 按 Markdown 标题切章节；TXT 按段落或有界片段处理。保留标题、版本、适用系统版本、角色和更新时间。格式约定写进样例 README。
3. 用可解释的关键词检索：标题/章节加权，支持中文常见问法和少量模块同义词；不能只按空格切词。先以真实问题验证召回，不引入向量库。
4. 返回 top 片段及来源和检索状态。单个长章节需分块；命中超出预算时标明还有未展示内容，不能静默截断后称完整。
5. 每次检索核对文件列表、长度、修改时间等指纹；新增/删除/替换使索引失效。替换期间读失败明确报错，不继续把过期缓存当成功。限定索引缓存大小并控制并发刷新。
6. 区分未启用、未配置、空目录、无匹配、解析失败、版本冲突、超限。缺元信息标“未标注”，不得伪造版本。规则矛盾时不得强行生成唯一结论。

只索引专用客服发布目录。发布样例先核对 docs/30、31 与当前页面，去掉部署凭据、默认密码、开发指令等非客服内容。数据口径说明注明对应业务实现，不能仅凭模型生成。

## 4. 数据查询与解释工具

新增只读业务服务（建议 AiReportEvidenceService），复用现有工单/报工服务与计算口径。所有查询按当前工厂约束，关联无 factory_id 的表时从已授权工单限定。只投影所需字段，不把完整报工实体（含工资）传给模型。

`get_work_order_report_evidence` 参数：workOrderId 或精确 orderNo（至少一个；同时提供必须指向同单）、operationId?、reportFrom?、reportToExclusive?、page=1、pageSize=20（最大 50）。工具先定位单张工单；工单不明确先用现有搜索并要求用户明确，不取第一条。工序必须属于该工单。

返回 `reportEvidence` 至少包含：

| 部分 | 内容 |
|---|---|
| 定位 | 工单 id/单号、产品编号、查询时间 |
| 筛选 | 实际报工时间起止、业务时区、工序、计数口径 |
| 整单累计 | 复用原服务的完成数/工序计划数及有效良品数；不受本次报工时间筛选替换 |
| 筛选内汇总 | 按工序列待复核/已通过/已退回良品与不良品、纳入进度和通过口径的数量；标清这不是最终成品产量 |
| 明细 | 报工 id、工序、报工人显示名、报工时间、良品/不良品、复核状态、退回原因、已有补报批次标记 |
| 分页 | list、total、page、pageSize；total 和汇总基于全量匹配数据，不能由当前页计算 |
| 依据 | 服务端生成的来源 id、规则说明/规则标识、可核对工单 id；与本轮答案引用关联 |

默认无日期为整单累计；日期按报工时间使用业务时区半开区间。非法时间、起止倒置、非法工序和分页均由服务端拒绝。汇总与明细明确同一筛选；并发报工下避免混用不同读取时点，采用现有数据库允许的一致读取方式并验证，不擅自改变生产库隔离配置。

不输出工资、单价、密码等无关字段。首版不推断历史改数记录，不将报工数当产品产量，不诊断无记录的停机/缺料原因。取消工单仍按原状态显示，不伪造完成状态。

## 5. 对话与页面

- 在原页面增加“智能客服”和操作/数据示例问题，无需新增顶层菜单。
- support 提示词要求先取证再答：说明问题查说明，数据问题查当前数据；混合问题可查两类。每轮关于当前规则/数字的结论重新取证。
- 工具返回的正文、备注、退回原因均是不可信资料，不能改变工具权限。没有依据就说明缺少什么；数字和结论对应服务端证据。
- 来源 id 必须属于本轮实际工具结果；沿用并扩展服务端引用校验。旧轮来源不能冒充新文件版本。
- 前端显示操作步骤、来源卡、查询日期、口径、汇总和分页明细；打开工单使用已有详情逻辑。模型失败时保留已成功获取的真实证据并明确解释失败，不用模型补造数字。
- 继续用安全纯文本显示答案。保留停止、新对话、超时、会话限额和出网告知；将客服片段与数据计入整轮上下文/输出预算。
- 通过 ThrowHelper 保留异常上下文和 traceId；服务端留受控诊断记录，AI 页面沿用现有安全错误响应，不把 SQL、密钥、硬盘路径或无关敏感正文回传用户/模型。不得静默吞异常。
