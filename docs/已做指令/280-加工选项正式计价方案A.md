# 280 加工选项正式计价（方案A）

> 2026-10-24方向调整：后续按400—408改为产品属性驱动的集中工序价目表；本指令保留实施历史。已锁价工单及工资快照仍须兼容，新录入路径按迁移账套局部撤回。

状态：已做，2026-10-23；服务断言已验证，未部署、未连接现场SQL Server验收。

## 确定的行为

1. PC工序新增“加工计价”入口：按产品维护基础价/成套价，设置计价单位、每计价单位对应产品报工数量、不良扣价；配置加工单选组和选项附加价（显式零价允许，缺价禁止）。一工序可多个单选组，各组叠加；有/无加工用一个二值单选组，不引入公式引擎。
2. 基础价可指定每组哪些值已包含（精确到选项值，不是整组含糊跳过），并限定各组可选值；不适用组合通过限制选项处理。客户尚未确认的项目不录入有效计价资料，不默认为免费；不预置客户整张Excel。
3. 产品对应工艺的工序，在建单时选基础价和每组一个加工要求。仍保留已包含项目的实际选择。服务端重算并与预览指纹比较；配置或价格变化须重新预览，不能提交客户端金额。
4. 保存工单时锁定完整计价依据（配置版本、基础价、组/选项名称及附加金额、包含说明、计价/报工单位与换算、不良扣价、选项ID）。调价不改已锁定工单和历史报工。已有任何报工（含退回）禁止改选择或重新计价；改交期/计划数不影响原价格。新复制工单复制选择、按当前配置重新定价，旧选项失效必须重选。
5. 已配置此功能的工序采用方案A计件价，替代该工单工序旧工价表（仍乘人员工资系数）；旧工价表的部门/人员差异仅在未启用方案A的任务沿用。配置界面明确说明。未配置工序保持原流程；启用后旧未定价且无报工任务在PC补齐，不能报工自动套新价；已有旧报工（含退回）的未锁价任务继续旧模式，不半途切换。
6. 普通/代报/多人分摊/批量补报、PC/H5预览统一读任务已锁价。报工复制其快照；工资生成、改数、撤回重算沿用报工快照。换算先计算再四舍五入，不能先截断每把单价。时间规则不会覆盖已锁定计件任务。
7. 数据：base_operation.pricing_config NVARCHAR(MAX) NULL；prod_work_order_operation.processing_price NVARCHAR(MAX) NULL。JSON结构由强类型服务校验；配置版本防覆盖。EF迁移与DbCompat共用幂等SQL；不改历史数据。
8. 独立API /api/operation-pricing：管理员配置、产品工序配置、预览。所有查询按厂隔离，PC只呈现本厂产品/单位。原工序复制不复制独立计价资料。无新增模板概念。
9. 最终组合特价首版通过独立基础/成套价及其允许选项与包含范围维护，不增加通用条件表达式。价格调整在配置保存后只用于新定价，不新增重复生效期机制。
10. PC普通/代报及H5报工只读展示加工要求，不增加工人选价动作；管理配置仅PC。移除工单工具栏演示入口，正式入口在工序“加工计价”；原独立演示路由保留供历史参考。
