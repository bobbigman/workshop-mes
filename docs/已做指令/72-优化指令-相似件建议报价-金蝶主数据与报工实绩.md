# 72-优化指令-相似件建议报价（金蝶主数据 + 报工实绩）

> 状态：代码已落地，待演示服预埋数据后验收  
> 定位：**打单卖点 / 演示能圆**；不是 CAD 识图，不是黑湖式 AI 拆单。  
> 依据：会话拍板——客户比选要「有报价能力」；买了未必天天用；增量必须挂在**车间实绩**，禁止做成金蝶数据搬运壳。  
> 前提假设：金蝶云星空/K3 Cloud **标准功能**（物料、BOM、工艺路线、成本价）均可通过 WebAPI 访问；**本仓库当前未实现金蝶主数据对接**，本期一并落最小适配层。  
> **上门演示约定（拍板）：不连客户账套。** 只连我方演示服务器；报工实绩预埋好，金蝶对接在演示服上事先配通（真测账或 Mock 样例均可）。对客户话术：「这是演示账；装到贵厂再接贵司金蝶。」

---

## 1. 一句话目标

业务员在 PC 选「像哪些老产品」+ 填/选金蝶物料号 → 系统给出**建议报价**（材料来自金蝶，工时/不良来自本厂报工闭环）→ 演示时能讲清「金蝶不用录第二遍、报价对得上实做」。

---

| 环境 | 金蝶 Mode | 数据 |
|---|---|---|
| 开发机 / 无金蝶 | `Mock` | Mock 样例物料 + 本机报工 |
| **上门演示服** | `K3Cloud`（接我方测试账）或 `Mock`（样例装得像真的） | **预埋**已复核报工（含时长）+ 物料/BOM 已能查出 |

禁止：比选现场临时连客户金蝶、临时要对方账号密码。

## 2. 做 / 不做（取舍定死）

| 做 | 不做 |
|---|---|
| PC 仅管理员（role=1）「建议报价」页 | H5 / PDA / 工人端 |
| 人工点选 1～N 个**本厂历史产品**作相似件 | CAD/DWG 上传识图、几何特征抽取 |
| 金蝶：物料成本价、BOM 汇总材料费、标准工艺（有则展示） | 在金蝶里自动开销售报价单写回（首版只读金蝶） |

**交付节奏：** 先 PC 演示闭环；现场/写回金蝶以后再说。

## 3. 最小闭环（数据流）

```
[人] 选相似产品(+可选金蝶物料)
        │
        ├─► 本厂 prod_report（已复核 review_status=1）
        │     → 按产品汇总：总时长 / 良品数 / 不良数
        │     → 建议人工 = 平均单件工时 × 工价(或人工费率配置)
        │
        └─► 金蝶适配器
              → 物料成本价 + BOM 材料费合计（无 BOM 则仅物料价）
              → 标准工艺路线（只展示，不自动拆单落库）
        │
        ▼
  建议报价 = 材料建议 + 人工建议
  报价含税/毛利 = 建议报价 × (1 + markup%)   // markup 页面可改，默认来自配置
```

**卖点口径（对外一句话）：**  
金蝶的料和标准工艺不用录第二遍；人工用你们车间真实干了多久估，不是纯拍脑袋。

## 4. 自主拍板（实现前定死）

| 项 | 决定 | 理由 |
|---|---|---|
| 相似件怎么来 | **人工多选**本厂 `base_product`（可搜编号/名称）；不做向量/图片相似 | 演示可控、实现最小 |
| 实绩口径 | 仅 `review_status=1` 的报工；按时长字段汇总（`duration_minutes`）；无时长的计件报工 → 该条不计入「平均工时」分母，页面提示「部分报工缺时长」 | 与工资/复核口径一致；不造假时长 |
| 单件平均工时 | 仅 `duration_minutes>0` 的报工：`SUM(duration_minutes) / SUM(good_qty)`（good_qty 合计为 0 则跳过并提示） | 大白话好讲 |
| 人工单价来源 | 优先：相似产品在 `base_price_rule` 命中的**计时**单价（PriceType=2，取匹配分最高）；都无 → 用配置 `Kingdee:DefaultLaborRatePerHour`（元/小时） | 复用已有工价表，避免新引擎 |
| 不良怎么进报价 | 首版只**展示**不良率；页面可选手动「不良预留%」加在（材料+人工）上 | 演示够用，避免争议算法 |
| 金蝶无物料/失败 | 材料区标红提示；允许「仅人工建议」也能出结果（演示不崩） | 演示能圆 |
| 本厂无相似实绩 | 人工建议=0 + 明确提示「无历史报工，请人工估」 | 不吞异常、不编数 |
| 落库 | 首版**只算不存**（不做 quote_suggest_log） | 最小闭环 |
| 拆单 | **不自动建工艺/工单**；金蝶标准工艺只读展示 | 与「不做 AI 拆单」一致 |
| 配置 | `appsettings`：`Kingdee:Mode=Mock|K3Cloud`；**已部署机禁止覆盖 appsettings** | 对接与演示分离 |
| 上门演示 | 只用我方演示服；金蝶与报工事先就绪；不向客户要账套 | 见 §1.1 |

## 5. 金蝶适配（最小接口）

后端抽象 `IKingdeeMasterDataClient`，两种实现：

| 方法 | 用途 | Mock 行为 |
|---|---|---|
| `GetMaterialAsync(code)` | 物料名称、成本单价 | 固定样例：`DEMO-MAT-001` 等 |
| `GetBomMaterialCostAsync(code)` | BOM 展开材料费合计（及明细列表） | 返回 2～3 行假 BOM |
| `GetRoutingAsync(code)` | 标准工序名称列表（seq+名称） | 返回「下料/机加/检验」 |

- `K3Cloud`：标准 WebAPI（ValidateUser + ExecuteBillQuery）；FormId/字段名走配置，便于演示服与客户账差异。  
- 超时/鉴权失败：抛带 **网址+报文摘要+返回** 的异常（`ThrowHelper.Api`）；预览接口捕获后材料区失败、人工区仍可出。  
- **禁止**把金蝶密码写进前端；凭证只在服务端配置。

## 7. API

统一 `{ code, msg, data }`；仅 role=1（工人/班组长由 RoleGuard 默认 403，本控制器不加白名单）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/QuoteSuggest/preview` | body：`similarProductIds[]`、`kingdeeMaterialCode?`、`markupPct?`、`defectReservePct?` |
| GET | `/api/QuoteSuggest/products` | 本厂产品下拉（编号/名称搜索，分页） |
| GET | `/api/QuoteSuggest/kingdee/material` | query `code=` 试连金蝶/Mock 物料 |
| POST | `/api/QuoteSuggest/export` | 同 preview body，导出 xlsx |
