## 0. 先看清现状（别再当「没写 MCP」）

| 项 | 事实 |
|---|---|
| MCP 框架 | `Program.cs` 已 `AddMcpServer().WithHttpTransport(...).WithToolsFromAssembly()` |

## 2. 配置清单（动手前填齐）

文件：`backend/appsettings.json` → `Mcp` 段

| 配置项 | 作用 | 要求 |
|---|---|---|
| `Token` | 方舟调 MCP 的静态入口 token | 改成自有串（演示可用 `laohu-demo-2026`，演示完轮换） |
| `AuthBaseUrl` | 授权 H5 外链用的公网根 | `https://xxxx.cpolar.cn`（**无末尾 /**）；开隧道后再填，填完重启后端 |
| `AuthLocalBaseUrl` | 未配公网时本地回退 | 默认 `http://localhost:8080`，一般不动 |
| `FactoryId` | 工厂 | 默认 `1` |
| `FinanceKingdeeAccounts` | 可查工资的金蝶账号名单 | 演示可用 `boss`；上线换真实财务号 |

## 3. 打通步骤（按序）

### 3.1 本地确认后端 MCP 活着

1. 启动后端：`cd backend` → `dotnet run`（或项目惯用的 `start-dev.bat`），监听 **8080**。
2. 浏览器：`http://localhost:8080/mcp-auth?code=probe` → 能出「金蝶账号授权」表单。
3. （可选）用 `curl.exe` 探 MCP 入口（须带 Bearer；具体 initialize/list 报文以当前 MCP SDK 为准，**以不 404、不 401 为最低门槛**）：

```powershell
# 路径必须是 /mcp；Token 与 appsettings 的 Mcp:Token 一致
curl.exe -s -o NUL -w "HTTP:%{http_code}`n" -X POST "http://localhost:8080/mcp" `
  -H "Authorization: Bearer laohu-demo-2026" `
  -H "Content-Type: application/json" `
  -d "{}"
```

- **404** → 多半打错路径（写成了 `/mcp/rpc`）或打到了前端静态站，不是「没注册 MCP」。
- **401** → Token 不一致或漏了 `Bearer ` 前缀。
- 其它非 404 → 入口已挂上，再进方舟做「测试连接」列工具。

### 3.2 开 cpolar，指到后端 8080

1. `cpolar http 8080`，记下 `https://xxxx.cpolar.cn`（免费版会变，变了重配）。
2. 写入 `Mcp:AuthBaseUrl`，**重启后端**。
3. 验收：浏览器开 `https://xxxx.cpolar.cn/mcp-auth?code=probe` 能出授权表单。

### 3.3 火山方舟控制台

1. 打开方舟 Agent → 添加远程 MCP。
2. 传输：**Streamable HTTP**（或界面上的 HTTP）。
3. **MCP URL**：`https://xxxx.cpolar.cn/mcp`（末尾就是 `/mcp`，**不要** `/mcp/rpc`）。
4. Headers：
   - `Authorization` = `Bearer <与 Mcp:Token 完全一致>`
   - 测试期若界面要求：按当时方舟文档加 beta 头（如 `ark-beta-mcp: true`）。
5. 保存 → **测试连接**。

**验收：** 方舟能列出 `start_auth`、`query_work_order`、`query_report`、`query_salary`、`calc_schedule_priority`。

### 3.4 对话闭环（业务授权）

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 对话说「查工单」 | 触发 `start_auth`，给出 H5 链接（域名应是 `AuthBaseUrl`） |
| 2 | 打开链接，输金蝶账号（如 `boss`）+ 任意密码（当前假验证） | 页面显示授权码 |
| 3 | 授权码贴回对话 | 能查工单 / 报工 |
| 4 | 「查工资」 | `boss` 成功；换 `worker1` 授权再查 → 拦「仅财务人员可查询」 |

本地 JSON-RPC 闭环已在 `docs/35` 勾过 ✅；本节要补的是 **「在方舟对话里」** 再走一遍。

### 3.5 演示收尾

1. 停 cpolar（`Ctrl+C`）。
2. 轮换 `Mcp:Token`；`AuthBaseUrl` 可改回空。
3. 勿把演示 Token 长期暴露在公网。

## 4. 常见坑（先对这张表，再改代码）

| 现象 | 原因 | 解法 |
|---|---|---|
| 方舟 404 | URL 写成 `/mcp/rpc` 或隧道打到前端 | 改为 `/mcp`；确认 cpolar 映射本机 **8080 后端** |
| 401 unauthorized | Header 无 Bearer / Token 与配置不一致 | 值必须是 `Bearer ` + 空格 + token；改配置后重启后端 |
| 连上但工具为空 | 后端未起 / 未扫到工具程序集 | 确认 `dotnet run` 无异常；勿删 `[McpServerToolType]` 类 |
| 授权链接是 localhost | 未配或配错 `AuthBaseUrl` | 填公网根地址后重启 |
| 查数说未授权 | 授权码过期（默认 2h）或未贴码 | 重新 `start_auth` |
| 查工资「仅财务」 | 账号不在 `FinanceKingdeeAccounts` | 加名单并重启 |
