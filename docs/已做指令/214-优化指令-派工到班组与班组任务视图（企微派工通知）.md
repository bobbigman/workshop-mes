## 本次范围与落点
- 交付：班组长派工（可选班组）→ 班组内工人任务页可见 → 工人扫码报工；企微开则派工通知。
- 数据与契约：工序行 `assignee_department_id`（已同步 docs/02）；企微事件码 `operation_assigned`（文案「派工」）。
- 216 补丁：`ck_wechat_rule_event` 增加 `operation_assigned`（否则规则落库被 CHECK 拦住）。

## 行为与口径（分叉显式，禁止脑补）
- 当班组长把工序派给【班组（部门）】→ 写 `assignee_department_id`、清空个人派工；该部门工人任务页可见。
- 当派给【个人】→ 清空 `assignee_department_id`；仅该人任务页显示。
- 任务页合并：工人可见 = 「派给我的」∪「本部门被派的」。
- 当企微总开关开启且有启用派工群规则 + Webhook → 派工/改派成功后同事务待发，计划任务投递。
- 当企微总开关关闭或 trial → 静默跳过。
- 取消派工 → 不触发派工通知。
- 报工权限仍按部门（红线2）；派工不拦报工。

## 止步线
- 不做派工后拦截未派工序报工；不做班组计件/排程；不新增第二套推送通道。
