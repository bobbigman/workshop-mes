## 本次范围与落点

- **交付流程**：工人在**企业微信机器人**发 `138xxxx1234` / 登录账号 / 姓名 → 企微侧调 MCP `get_report_link_by_identity` → 后端按解析顺序查本厂用户 → 取/补生成 login_qr_secret → 拼 `{Mcp:AuthBaseUrl}/#/login?pq={secret}` → 企微机器人回「张三师傅，点这里报工」+ link → 工人点链接 → 企微内置浏览器打开 → 150号 pq 换 JWT（30天）→ 进工作台点任务报工
- **已有**：150号 login_qr_secret 机制与 `POST /api/Auth/login-by-qr`；H5 `workerHomePath` 工作台；企微 MCP 对接（与 87 号等同源 MCP，渠道为本能力的企微机器人，不是扣子）
- **已落**：`ReportLinkMcpTools` + `McpReportLinkService`；链接基址优先 `Mcp:AuthBaseUrl`；企微侧提示词「要报工→调本工具；link 原样、禁 localhost」
- **数据与契约**：不改表（复用 `sys_user.login_qr_secret`）；不改 docs/02；`{base}` **优先跟 MCP 公网入口 `Mcp:AuthBaseUrl`**（与授权页同源、cpolar 改一处即可），空且非本机时才回落 `Instance:PublicBaseUrl`；不回落 `AuthLocalBaseUrl`；禁止 localhost
- **轻重**：一个 MCP 工具 + 企微侧一条规则；不动工资/结算/看板；本工具**不要求**企微会话绑定（绕开认人卡点）

## 联调踩坑（已消）

- **现象**：直调 MCP 返回 `https://…cpolar…/#/login?pq=…`，企微对话里曾被改成 `http://localhost:8080/#/login?pq=同一串` → 手机 `ERR_CONNECTION_REFUSED`。
- **结论**：改写在**企业微信机器人对话侧**（不是扣子、不是后端）。后端按 `Mcp:AuthBaseUrl` 出链；`cardText` 内嵌完整 URL 兜底。
- **处置结果（2026-10-09）**：企微提示词约束原样发 link 后真机通过；勿误判为要删重建机器人。

## 行为与口径（分叉写成显式条件）

- 当【`identity` 为空/空白】→ 回「请发您的手机号、登录账号或姓名」，不返回链接
- 当【`identity` 匹配 `^1\d{10}$`】→ 按本厂 `phone` 查；**不**再回落到账号/姓名
- 当【非手机号格式】→ 先按本厂 `account` 精确匹配；未命中再按本厂 `name` 精确匹配
- 当【任一凭证命中恰好 1 人且 status=1】→ 取/补生成 secret，返回 `{ name, account, link, cardText }`；`link`=`{AuthBaseUrl}/#/login?pq={secret}`（基址见上）
- 当【命中恰好 1 人但 status=0】→ 回「该账号已停用，请联系管理员」，不返回链接
- 当【手机号或姓名命中多人】→ 不返回链接；回「找到多人：姓名(账号)、…，请发手机号或登录账号」
- 当【查无此人】→ 回「未找到该员工，请核对手机号/登录账号/姓名，或联系管理员在用户管理里录入」，不返回链接
- 当【AuthBaseUrl 与 PublicBaseUrl 皆空或皆为本机】→ 后端明确失败，禁止拼 localhost / 相对路径假装成功
- 当【命中但 login_qr_secret 为空】→ 后端自动生成新 secret 再拼链接（150号轮换逻辑不变）
- 当【工人点链接】→ 企微内置浏览器打开，复用150号 pq 换 JWT，进 `workerHomePath`；与150号行为完全一致
- 当【30天内再次点同一链接】→ localStorage 已有 JWT，直接进工作台，不用再发凭证
- 当【消息是查工单/查进度等业务问句】→ 不触发本工具，走现有对话工具
- 当【该用户对某工序无部门报工权限】→ 进了工作台也报不了该工序（三条硬规则，沿用既有校验）
