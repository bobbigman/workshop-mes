## 已核实现状（勿重复做）
- 已有：单张 `generate` / `{id}/recalc`（草稿原地重算、保留手工项）/ `{id}/revoke`（已确认撤回，仅管理员 `Roles="1"`）/ `confirm` / `delete`。

- 缺口：重算是按单粒度、无批量；5 手工列仍掺发薪结算项。

## 改动点
- 后端 `backend/.../SalaryController.cs` + `ISalaryService` + DTO：
  1. 新增 `POST batch-recalc`，入参 `[long[]] ids`（按当前厂校验）。循环处理，任一张失败不停整批、返回逐张 `{id, 成功/失败原因}`：当 `status=草稿` → 复用 RecalcDraft（原地重算）；当 `status=已确认` → 先**软撤回** `RevokeAsync`（status→草稿、`settled_flag`→0、**保留单与明细、不删单**，仅管理员）再原地重算。**现有 RevokeAsync 语义统一改为软撤回（docs/67 删单语义废弃）**。
  2. 5 手工列处理：当库中 5 列历史值**全为 0** → DbCompat 直接 `DROP COLUMN`；当任一列**非 0** → 保留列不删、前端不再录入、公式不再计入、列加注释「历史遗留，停用」（防丢钱，红线）。
  3. 应发合计公式改为：Σ(salary_statement_item.amount − deduct_amount)。
  4. 兼容：旧端仍传已删字段 → 后端忽略，不报错。
- 前端 工资单列表页 + 编辑/确认页（Element Plus，路径以 Cursor 对照现有 Salary 页为准）：
  1. 列表加 el-table 多选 + 顶部【批量重算】按钮 + 二次确认，调 batch-recalc，按返回逐行提示成功/失败。
  2. 编辑/确认页去掉「底薪/餐补/其他补贴/社保个税/其他扣款」全部输入框，只剩报工明细。
- 文档：改 docs/02（salary_statement 表定义，删列或标停用）+ docs/73（手工列定义同步）+ docs/33（batch-recalc 接口签名）。
