## 本次范围与落点
- 交付流程：【用户管理生成个人二维码 → 印工牌/发工人 → 工人扫自己的码 → 免密登录 + 30 天 token → 打开即已登录 → 扫工单码报工 → 填数提交回传】
- 已有：「用户管理」模块（PC）；`scan.vue` → `/h5/report?order&op`（Vant）；JWT 鉴权（账号密码登录签发，`ExpireHours=12`）
- 数据与契约：`sys_user.login_qr_secret NVARCHAR(64) NULL` + 过滤唯一索引；改表同步 `docs/02` + `DbCompat`；免密 JWT 与账号密码 JWT 同体系（角色/权限/部门口径一致），仅过期时间不同
- 用户维护界面：列表每行「二维码」→ 弹窗预览（姓名/账号 + 码 + URL）、「复制链接」「打印」「导出 PNG」「重新生成」；打印须勾「背景图形」、码 ≥5cm
- 轻重：改用户管理页 + 免密签发接口 + 长 token 策略；不动工资/结算；老登录原样保留

## 使用步骤（管理员 + 工人）
- **管理员准备（一次）**：用户管理 → 选员工 → 点「二维码/打印」→ 生成个人码（`登录地址?pq=xxxx`）→ 二选一发放：① 打印印工牌/贴工位；② 把链接发企微/微信给工人
- **工人使用·路A（存链接点一下，最省事）**：首次收到链接点开 → 免密登录进系统（不输密码）→ 把链接收藏进浏览器书签 /「添加到主屏幕」→ 以后每天点桌面图标直接进工作台 → 扫工单码报工；30 天内免密，到期再点一次链接
- **工人使用·路B（扫工牌/工位上的码）**：打开手机相机或微信「扫一扫」→ 对准工牌/工位上个人码 → 识别出链接 → 确认「在浏览器中打开」→ 免密登录进系统 → 之后扫工单码报工
- **本质**：个人码就是一条免密登录 URL，扫码与点链接是同一个入口；工人不会存书签就贴工位扫码，会加书签就点一下更省事

## 行为与口径（分叉写成显式条件）
- 当【`pq` 有效且该用户 `status=1`】→ 后端按用户签发 **30 天** JWT → 登录页写入 localStorage → 进 H5 工作台（生产人员走 `workerHomePath`；有 `redirect` 且安全则回跳）
- 当【个人码失效 / 用户停用 / `pq` 无效或空】→ 提示「个人码无效或账号已停用，请使用账号密码登录」，不发 JWT，留在登录页
- 当【已登录（长 token 有效）】→ 打开 H5 直接进入，无需再扫码
- 当【登录页 URL 带有效 `pq`】→ 自动免密登录，**工人无需手动切换入口**；当【无 `pq`】→ 登录页照常显示账号密码框，不新增扫码 tab/切换按钮
- 当【过期 / 换设备 / 清缓存】→ 需再扫一次个人码免密登录
- 当【管理员点重新生成】→ 写入新 `login_qr_secret`，旧码立刻失效
- 当【非扫码环境（普通浏览器/PC 网页）】→ 维持现有账号密码登录，行为不变
- 当【该用户对当前工序无部门报工权限 / 未派工】→ 校验不通过，登录后也进不去该报工（三条硬规则）
