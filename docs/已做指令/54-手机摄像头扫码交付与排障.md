# 54 · 手机摄像头扫码：交付与排障手册

日期：2026-09-22。状态：**已修复（0922-10）并真机通过（百度浏览器）。**
来源：`docs/未做指令/11-排查指令-手机摄像头扫码异常-Cursor接手.md`。

本文给两类人看：**实施/部署的人**（怎么把扫码落地到客户现场、怎么验收、怎么排障），以及**现场工人**（手机扫码怎么用、打不开怎么办）。

---

## 一、这次到底踩了什么坑（一句话版）

手机扫码页「打开摄像头扫码」一点就闪回。排查到最后发现：**摄像头、权限、HTTPS 全都正常**，是扫码库 `qr-scanner` 一启动识别引擎，就把百度浏览器页面弄崩了。

`qr-scanner` 的识别引擎是用 `new Worker(URL.createObjectURL(new Blob(...)))` 在后台开一个 Worker。百度浏览器（以及不少国产浏览器内核）对这套支持不稳，页面直接闪退。

**解决办法：换成 jsQR**——纯 JavaScript、在主线程里跑，不开 Worker、不碰 Blob、不碰 WASM。跟独立检查页一样，不依赖任何容易崩的东西。换完百度浏览器立刻正常。

---

## 二、交付前提（部署到客户手机前，先确认这四条）

1. **手机能访问的局域网地址**：手机打开的是 `https://192.168.x.x:端口`，不是只有本机能开的 `localhost` / `127.0.0.1`。
2. **HTTPS**：手机网页开摄像头要求 HTTPS。内网 HTTP 通常打不开摄像头。
3. **证书被手机信任**：证书的 SAN 要覆盖访问用的 IP/域名，并且手机已经信任这个证书（安装/导入了 CA 或该证书）。
4. **打印标签里的链接基址**：二维码里若印的是「报工页链接」，它的「前端基址」必须用上面那个手机能访问的 HTTPS 地址。

> 一句话：手机扫码 = 手机能访问的 HTTPS 地址 + 信任的证书 + jsQR。

---

## 三、技术要点（以后改代码、升级时别回退）

- **解码库用 jsQR，不用 qr-scanner。** 移除 qr-scanner 后，前端构建产物里**不应再有** `qr-scanner-worker.min-*.js`；如果又出现了，说明有人把库换回去了。
- 扫码页启动顺序固定为：
  1. `getUserMedia({ video: { facingMode: { ideal: 'environment' } } })`（后置优先；报 `OverconstrainedError` 时回退 `video: true`）
  2. `video.srcObject = stream`
  3. `await video.play()`
  4. 进入扫描状态，`setInterval` 循环：`drawImage` + `getImageData` + `jsQR()` 解码
  5. 命中工单号 → 停流 → 跳 `/h5/report?order=...`（**不自动提交报工**）
- 主文件：`frontend/src/views/h5/scan.vue`；二维码解析规则：`frontend/src/utils/scanPayload.js`（摄像头与 PDA 共用）。
- **诊断记录存在 `localStorage['h5.scan.diagnostics.local']`**（崩溃/重载也不丢）。之前用过 sessionStorage，页面一崩记录就没了，等于瞎测。
- 独立检查页 `frontend/public/camera-check.html` 不加载扫码库，是判断「摄像头能力本身是否正常」的对照基线：它正常、业务页不正常，就说明问题在扫码库/页面逻辑，不在摄像头。

## 四、现场验收清单

交付扫码功能时，逐条在客户手机上过一遍，都勾上才算过：

- [ ] 点「打开摄像头扫码」→ 允许权限 → 出现**持续**的摄像头画面，不闪回、不丢页面
- [ ] 对准工单流转卡二维码 → 自动跳到对应工单的报工页，**不自动提交**
- [ ] 后置摄像头能扫到实际标签（默认后置优先）
- [ ] 拒绝权限 / 点取消 / 15 秒超时 / 切后台，都有清楚提示，不残留摄像头占用
- [ ] 手动输入工单号、PDA 扫码枪模式，均不受影响
- [ ] 用手机**系统自带浏览器**和**百度浏览器**各测一次（两种内核都过才稳）

## 五、排障（先收证据，别瞎改）

**不要**让用户反复「刷新、再点一下、发同样截图」。让用户发一段能定位的日志：

1. 手机打开诊断版链接（`scan-check` 后随便填个值）：

   ```
   https://<IP>:<端口>/?scan-check=0922-10#/h5/scan
   ```

2. 点一次蓝色「打开摄像头扫码」按钮。
3. 点诊断区里的 **「复制日志」**，把复制的文字原样发回来（比截图清楚，且包含版本、网址、浏览器 UA、逐条时间线）。

日志能直接区分四种情况：

| 日志特征 | 结论 |
|---|---|
| 出现 `NotAllowedError` / `PermissionDeniedError` | 用户拒绝了权限，或浏览器/系统未授权 |
| 第一行「安全环境：否」 | 网址不是 HTTPS / 证书未被信任 |
| 时间线走到「视频已开始播放」后**断掉**，导航类型 `back_forward` | 扫码库（Worker）崩页面 —— 本项目的坑 |
| 走到「识别器已就绪，等待二维码」但扫不出 | 识别正常，问题在朝向/距离/光线/标签 |

### 症状对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 点按钮没反应、也没权限弹窗 | HTTP 或证书未信任 | 换 HTTPS、信任证书 |
| 一闪而过、画面消失、页面像被重开 | 扫码库 Worker 崩内核 | 确认用 jsQR（本项目已换） |
| 画面正常但扫不出二维码 | 朝向/距离/光线/标签内容 | 换后置、拉远/拉近、补光、核对标签 |
| 提示「摄像头被占用」 | 别的应用占着摄像头 | 关其它应用再试 |
| 手动输入能开、扫码不行 | 标签内容或扫码头 | 核对标签、切扫码枪模式试 |

## 六、给现场工人的话（可直接抄进使用手册）

- 要用**摄像头**扫码，网址必须是管理员给的 **HTTPS** 地址，且手机已经信任证书。
- 底部「扫码」→ 第一次点「打开摄像头扫码」，浏览器问权限时点**允许**（不要开麦克风）。
- 打不开摄像头、或提示需要 HTTPS 时：点「手动输入工单号」，或让管理员检查 HTTPS / 证书。
- 手机扫码**不会自动提交报工**，扫完只是打开对应工单的报工页，你自己填数量再提交。

## 七、PWA 桌面图标（可选增强：点图标直接进扫码，不输网址）

工人不想每次输网址，可以在手机桌面放一个图标，点了直接全屏进扫码页。

### 技术实现（已内置，随前端构建自动带上）

| 文件 | 作用 |
|---|---|
| `frontend/public/manifest.json` | 应用清单：名称、`start_url: /#/h5/scan`、`display: standalone`（全屏无地址栏）、主题色 `#3370ff`、图标 |
| `frontend/public/sw.js` | Service Worker：满足可安装要求 + 静态资源离线缓存 |
| `frontend/public/icons/icon-*.png` | 192 / 512 / maskable 三张图标 |
| `frontend/index.html` | 挂 `link[rel=manifest]` + apple 系列 meta |
| `frontend/src/main.js` | 生产构建下 `navigator.serviceWorker.register('/sw.js')` |
| `frontend/scripts/generate-icons.ps1` | 生成图标脚本（换 logo 重跑即可） |

这些文件在 `npm run build` 时随 `public/` 原样进 `dist/`，部署到 `wwwroot` 后即可用（后端 `UseStaticFiles` 对 `.json/.js/.png` 的 MIME 均正确）。

### Service Worker 缓存策略（防手机卡旧版）

本项目在「手机还是旧版」上被坑过，所以缓存刻意保守：

- **HTML 导航**：network-first，网络失败才回退缓存 —— 保证永远拉到最新 index.html。
- **静态资源（/assets/ 带 hash）**：cache-first，hash 变了自动抓新 —— 安全。
- **/api/ 与跨域请求**：绝不缓存 —— 业务数据必须实时。

### 手机怎么加图标

工人操作步骤（含示意图）已写入 [`docs/31-使用手册-工人（手机端）.md`](31-使用手册-工人（手机端）.md)「把扫码页放到手机桌面」一节。图在 `frontend/public/manual/pwa-*.png`（安卓菜单 / iPhone 分享 / 桌面图标，均为示意）。

- **Chrome / 系统自带浏览器**（推荐）：打开 `https://<IP>:<端口>/#/h5/scan` → 右上角菜单「添加到主屏幕 / 安装应用」→ 桌面出现「小工单」图标。点开是**全屏 standalone**，走系统内核。
- **百度浏览器**：菜单里「添加到桌面」多数只是建一个**快捷方式**（仍走百度内核、带地址栏）。扫码现已修复可用，但不是全屏。
- **iOS Safari**：底部「分享」→「添加到主屏幕」。

> 想要真正「绕开百度内核、全屏稳定」，建议工人用手机自带浏览器或 Chrome 添加图标。
