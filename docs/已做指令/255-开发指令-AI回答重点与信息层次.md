# 255 · AI 回答重点与信息层次

2026-10-20。依据用户第三轮截图反馈。状态：已实现，本地验证通过；未部署，未调用真实模型验收。

## 目标与取舍

回复要像向车间负责人汇报：先结果、再重点、最后简短提醒。通过模型表达约定与页面展示一起改善，而非继续放大字号。不改工具权限、查询条件、进度计算或接口，不增加模型调用。不人为把无进度说成未开工，不从一页数据推断全量汇总。

## 实现

- 进度/客服模式共用表达约定：开头一句结论，真实数量加粗；有依据时列最多三项重点工单；需要明细时给精简表格；结尾只保留必要提醒。简单问题不强制凑章节。
- 对数据提问不追加整段操作手册、内部参数/状态枚举、重复只读免责声明；用户问口径、操作或写操作时再解释对应内容。失败、不完整、分页和证据限制仍须明确，来源引用仍保留。
- 表格控制必要列，强调工单号、关键进度或交期；只按实际字段与可靠日期计算，不臆造指标。不用红色或图标给未知事实制造紧急程度。
- 回答已包含 Markdown 表格时，下方原始业务表格默认折叠；用户可展开查看详情、翻页、查询时间。回答没有表格时原表格默认展开。报工证据与候选卡片保持可用。
- 聊天区域限定盒模型和宽度，避免宽表让整页向右溢出。日期字段按返回的业务日期展示，不转 UTC 后造成交期提前一天。
