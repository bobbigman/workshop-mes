## 2. 逐项补全内容（每项：入口 → 步骤 → 常见失败/口径）

### 2.1 工资与工价表（来源 docs/21，已实现）→ 扩 `docs/30` 手册

**入口：** 管理员 PC，基础数据「工价表」、报表「工资报表」。仅管理员，无工人端。

**工价表怎么配：**
- 新增工价规则：选产品 / 工序 / 部门 / 人员（**均可留空 = 不限**），选类型（1 计件 / 2 计时 / 3 固定），填单价、扣款单价、生效起止、优先级。
- 更具体（维度填得多）的规则优先；同具体度按优先级、ID 排序。

**工资怎么算（人话口径，务必写进手册）：**
- 计件：良品数 × 单价；计时：时长（小时）× 单价；固定：单价一次。
- 不良品按「扣款单价」扣钱；**只有复核通过的报工才进工资**（待复核、已退回不算）。
- 工时按报工时刻取价；改数后重算。

**工资报表怎么用：**
- 选周期（月 / 周）、可选人（空 = 全厂）→「生成工资单」→ 生成草稿。
- 看明细：逐条报工 + 金额；**未匹配到工价规则的明细标红**。
- 「确认」工资单：**存在未匹配标红时确认会被阻断**，须先补工价规则；确认后该批报工冻结（不可再改数）。
- 草稿可删除重算；**确认后不可删、不可直接重算**。
- 导出：CSV/Excel。

**常见失败：** 生成后明细全红 = 工价没配（工序/产品维度对不上）；确认报错 = 有报工没工价；"已结算报工不可修改" = 这张工资单已确认过，先找负责人。

### 2.2 派工到人（来源 docs/29 演示最小版，已完成）→ 扩 `docs/30` + `docs/31`

**管理员 / 班组长 PC 端：**
- 工单详情 → 工序列表每行有「执行人」下拉，选本厂工人 = 派工；选空 = 取消。
- 可改派（重新选人）。**一张工序只派一人。**
- **未派工不影响报工**（不强绑，工人仍可自选工序报）。

**工人手机 H5：**
- 底部新增「任务」页，看到**派给自己的任务**（工单号、产品、工序、剩余量、交期）。
- 点任务卡片跳转去报工。

**常见失败：** 工人看不到任务 = 班组长没派 / 派了别人；想给一道工序派多人 = 本期不支持，另议。

### 2.3 异常上报（来源 docs/28，已完成）→ 扩 `docs/30` + `docs/31`

**工人手机 H5：**
- 底部「异常」页 → 选类型（官方三类）→ 可选拍照 + 写描述 → 上报。

**班组长 / 管理员 PC：**
- 「异常」处理列表，**待处理异常对管理员 + 班组长全员可见**（不按班组分）。
- 处理回填后，看板上的红色高亮 + 滚动播报消除。

**看板：** 有待处理异常时红标 + 滚动条；处理完消失。

**常见失败：** 报完看板没变化 = 还没被处理回填；不是报工，别在报工页误操作。

### 2.4 执行监控（来源 docs/19 补充执行，已完成）→ 扩 `docs/30`

**入口：** 管理员 / 班组长 PC「执行监控」。

**页面上有什么：**
- 顶部状态统计：未开始 / 执行中 / 已结束 / 临期 / 超期。
- 工单筛选：关键词（工单号 / 产品编号 / 名称）、状态、交期起止。
- 工序进度链：每道工序名、良品 / 计划、执行人；状态分「未报工 / 已报未满 / 已报满」。
- 待处理异常、超期工单、待复核数、**未派工工序数**（未派工待办按"道工序"计）。

**进度口径（关键，务必写对）：**
- **工序达成进度 = 各正计划工序（良品/计划）的最小值**，0~100%。
- 工单完成数 = 各道有效良品（待复核 + 已通过）的**最小值**，与工单详情、列表同一口径。
- 看板同口径，**不再跨工序简单求和**（旧看板曾求和，已改）。
- 只计待复核 + 已通过的报工；**生产报表只计已通过**。

**常见失败：** 完成数/进度看哪个页面对不上 = 先分清"工单详情最小口径 vs 报表已通过口径"；有工序只报不良 = 属"已报未满"，不是"未报工"。

### 2.5 批量导入（来源 docs/57，已完成）→ 扩 `docs/30`

**入口：** 管理员 PC，产品定义 / 工序 / 用户 **三个页面**各有「导入」按钮（不良品项 / 工艺路线无入口，手录）。

**步骤：**
1. 点「下载母版」（.xlsx）。
2. 填数据：**第 2 行是格式示例，不能照抄，要填本厂真实数据**。
3. 点「上传」选文件 → 结果对话框「成功 N / 失败 M」+ **逐行原因（行号 = Excel 真实行号）**。

**规则（务必写清）：**
- 只支持 .xlsx。
- 关联列（部门编码、不良品名称、单位名称、路线编号、工序编码）：**填了必须在本厂存在，匹配不到 = 该行失败；留空 = 不挂关联，不报错**。
- 产品编号唯一、账号唯一、密码复杂度等既有规则不变。
- 好行入库、坏行报错，**不整批回滚**；失败行不留半截数据。

**常见失败：** 整行失败 = 关联列填了本厂没有的编码；行号对不上 = 中间有空行；空文件 = 明确报"没有可导入的数据行"。

### 2.6 多账套登录选厂（来源 docs/52，已完成）→ 扩 `docs/30` + 更新 `docs/31` 登录说明

**登录：**
- 系统有 **≥2 个账套（工厂）时，登录页出现「账套/工厂」下拉，先选厂再登录**；只有 1 个账套则无下拉（锁定）。
- 传了不存在的账套 → 明确报「账套不存在」。
- 登录后数据按工厂隔离，**不同账套数据互不可见**。

**工厂标识：** PC 侧栏、H5 顶栏、车间看板标题都显示**当前登录的工厂名**，先看清在哪个厂。

**管理端：** PC 可一键新建账套（灌演示数据 + 管理员）。

**常见失败：** 登录后看不到别家数据 = 正常，工厂隔离；手机端首版**不能**切换账套，要切找管理员。

### 2.7 企业微信预警（来源 docs/20，已实现但默认关闭）→ 并入 `docs/30` 或 `docs/manual/遇到问题`，作小条目

- **默认关闭**，需管理员先配置企业微信：工厂企业微信认证 + 自建应用，填 CorpID / Secret / AgentId / 接收人。
- 配置入口：PC「微信预警」菜单 → 填信息 → 打开「启用推送」→ 测一条 → 需要时点「推送超期工单」。
- **自动定时推送本期未做**；要每天自动推需另挂定时任务。

**常见失败：** 收不到预警 = 多半没开「启用推送」或企业微信没配好；不确定先测一条。
