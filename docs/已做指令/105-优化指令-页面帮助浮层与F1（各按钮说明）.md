# 105 - 优化指令：页面帮助浮层 + F1（各按钮详细说明）

> 状态：已实现
> 依据：`docs/30` / `docs/31` 操作手册、`docs/help`（`@/help/manual`）现有整页手册
> 痛点：用户（老胡）在「报工」页看到「待复核」不知道怎么处理 —— 按钮 / 状态 / 跨页去向全靠翻整页手册，太蒙。
> 目标：每个 PC 页面右上角加「？帮助」，并按 **F1** 弹出 **本页按钮说明** 浮层：逐按钮讲「干嘛的、谁能用」，并写清「待复核要去报工复核页」这类 **跨页指引**。
> 原则：**只动前端、不动后端**；先覆盖核心页，后续可扩；H5 手机端本期不做（手机上没 F1、也已有帮助 tab）。
> 方案：复用 `@/help/manual` 的手册风格，新增「每页帮助」数据 + 一个全局帮助组件。

***

## 0. 为什么做（人话）

系统已有一整本操作手册，但它是个独立文档页。班组长 / 工人干活时，看到「报工」页的「待复核」「+ 报工」这些按钮，不知道点了会怎样、下一步去哪。我们要让**每个页面自己就能解释自己**：点一下「？」或按 F1，当前页每个按钮 / 状态 / 入口都说明白，尤其把「这个状态要去哪个页面处理」这种跨页逻辑讲清楚。

## 1. 已有底子（别重复造轮子）

* 整页手册已有：`frontend/src/views/help/index.vue` + 数据 `@/help/manual`、搜索 `@/help/parser`。
* PC 主布局在 `frontend/src/views/layout/index.vue`（header 已有「切经典版 / 报工端 / 退出」等按钮区，可加「？」）。
* 路由在 `frontend/src/router/index.js`，业务页有固定 `path`（`/report`、`/review`、`/order` 等），可作帮助内容的匹配键。
* **看板 `/board` 是独立全屏路由**（不进 `layout/index.vue`），本期不挂帮助；另开一期再在看板自有 header 挂。

***

## 2. 交付物

新增 2 个前端文件（帮助数据 + 帮助组件）+ 在主布局挂 1 处 + 文档收尾。**无后端改动。**

## 3. 原子步骤（每步都带条件判断）

### 步骤 1：新增「每页帮助」数据文件 `frontend/src/help/pageHelp.js`

按路由 `path` 建键（先覆盖 **5** 个核心页：`/report` 报工、`/order` 工单、`/review` 报工复核、`/stat` 生产报表、`/product` 产品定义）。

* **当** 后续要扩其它 layout 子页 → 只在本文件加键即可。
* **当** 目标是看板 `/board` → **本期不做**（看板不进主布局；另开一期在 `board/index.vue` 自挂）。

每条帮助结构（人话字段）：

```
{
  '/report': {
    title: '报工页',
    value: '在这查报工、补报、替工人代报，月底对账不扯皮。提醒：状态是「待复核」的报工，在这只看得见，要处理得去报工复核页。',
    items: [
      { what: '【查询】按钮', how: '输入工单/产品编号或名称后点它，筛出你要的报工。', who: '所有能登录的人' },
      { what: '【+报工】按钮', how: '点它新增一条报工（补报）。', who: '管理员或有报工权限的人' },
      { what: '【代报工】按钮', how: '替工人代填报工（管理员/班组长可见）。', who: '管理员或班组长' },
      { what: '【一键补报未完工序】按钮', how: '按工单把还没报满的工序一次补齐（仅管理员）。', who: '管理员' },
      { what: '复核列（待复核）', how: '这条还没被班组长确认，暂时不算入生产报表和工资。要处理它：去左侧「生产管理 → 报工复核」，由班组长或管理员点【通过】才入账；点【退回】则要填原因、工人改数后再走复核。', who: '复核操作只有班组长/管理员能做' },
      { what: '操作列【修改】', how: '改这条报工数量。注意：状态「已通过」的改不了，要先退回才能改。', who: '报工人本人或管理员' }
    ]
  }
  // …其余页照此
}
```

* **内容要求（两条都必写）**：

1. `value`（价值开场白，1\~2 句）：讲清**本页对你有什么用**—— 能省什么麻烦、能帮你干什么、什么时候用。**不许空喊**（如 "本页功能丰富" 算空喊，不合格）；落到具体好处。
2. `items`：每页都必写「本页每个主要按钮 / 状态 / 入口 + 谁能用」；凡是有跨页去向的状态（待复核、退回等），`how` 里必须写清「去哪个页面、点哪个按钮」。
3. **字段名说明**：`what` / `how` / `who` 只是**代码里的数据键名（给 Cursor / 程序员看）**，工人界面**不显示这三个英文词、也不拆成三栏**；只展示合成的一句中文大白话（见步骤 2 的渲染铁律）。

* 当某页暂时没写帮助 → 该页不配置键，走步骤 4 的兜底提示。

### 步骤 2：新增帮助组件 `frontend/src/components/PageHelp.vue`

* 外观：一个「？」帮助按钮 + 右侧抽屉（el-drawer 或仿现有卡片风格）。
* **数据匹配**：
  * 组件用 `useRoute()`，`watch(route.path)` 去 `pageHelp` 里取当前页配置；
  * 当匹配到配置 → 抽屉**顶部先渲染该页 `value`（价值开场白，比标题醒目、给一个区块）**，再往下渲染 `items`；
  * **渲染铁律（给车间工人看，不露英文、不拆三栏）**：`what` / `how` / `who` 只是代码键名，**界面上一律不显示这三个英文词、也不按"名称 / 说明 / 谁能用"拆成三栏**；每条渲染成**一句连贯中文大白话**（把"这是什么 + 怎么用 + 权限差异"拼进一句），例如「【待复核】：这条还没确认，要处理去报工复核页，由班组长 / 管理员点【通过】才入账」；`who` 只在确有权限差异时才并入话里带一句，普通按钮不提。
  * 当没匹配到 → 抽屉里显示「本页暂无专项说明，去【操作手册】搜索」，给一个跳 `/help` 的链接。
* **顺序要求（价值前置，防 "烦"）**：抽屉打开第一屏必须是「标题 → 价值开场白」，让用户先看到 "这页对我有什么用"，再看到按钮清单；**不得把按钮说明顶在最前面**。
* **关闭**：点关闭 / 抽屉外空白 / 再按 F1，都能关（记开关状态，别重复开）。
* **触发（两种都接）**：
  1. 点「？」按钮 → 开 / 关抽屉；
  2. 全局 **F1** 快捷键 → `window.addEventListener('keydown', e => { if (e.key === 'F1') { e.preventDefault(); toggle(); } })`（当抽屉开着再按 F1 就关闭；浏览器默认的 F1 帮助要拦掉）。

### 步骤 3：在主布局挂载（仅 PC layout）

文件：`frontend/src/views/layout/index.vue`

* 在 header 右侧按钮区加一个「？」帮助按钮（与「切经典版 / 报工端 / 退出」同排），点击派发 PageHelp 的开关；并挂载 PageHelp 组件。
* **条件判断**：
  * **当** 处于 PC 主布局且 `!isMobile`（与「切经典版」同条件）→ 显示「？」并挂 F1 监听；
  * **当** `isMobile`（窄屏响应式）→ 不显示「？」、不挂 F1；
  * **当** 路由是 `/h5/*` → 本布局根本不渲染，无需处理；
  * **当** 路由是 `/board` → 本布局不渲染，本期不做看板帮助。
* 提醒：F1 监听要在组件卸载时移除（`onUnmounted`），避免多个页面叠加；`isMobile` 变化时同步增删监听。

### 步骤 4：文档收尾（当功能实现并通过验收后再做）

* `docs/31`（手机端手册）不涉及；改 `docs/30`（管理员电脑端手册）：加一句「每个页面右上角「？」或按 F1，可看本页按钮说明」。
* `docs/04` 开发计划：勾选对应行（若有）。
* 本文件移入 `docs/已做指令/`，状态改为「已实现」。
