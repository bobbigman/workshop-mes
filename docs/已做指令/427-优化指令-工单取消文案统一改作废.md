### 1.2 业务定义（已定，本次只改叫法，不改规则）

- 「作废」= 原「取消」动作：工单不再生产，`status` 由 0/1/4 置为 **3**；作废后不能新增报工、不能补报；【全部】列表不含作废单；在作废页签点【恢复】回到 `status=0` 未开始。
- 作废不是删除：报工、派工等历史记录保留；【删除】按钮语义不变。
- 状态码与流转规则维持现状：0 未开始 / 1 执行中 / 2 已结束 / 3 已作废（原已取消）/ 4 草稿；`reopened` 规则（docs/422）不变。

## 4. 红线与不变量（任何档位都不得违反）

- **I01 状态码不变**：作废 = `status = 3`；不新增状态、不重排 0/1/2/3/4 含义。
- **I02 接口与代码标识符不变**：前端 action `'cancel'`、后端 `case "cancel"`、DTO 属性 `Cancelled`、查询参数 `ExcludeCancelled`、`counts.cancelled` 全部保留原名；只改显示文字。
- **I03 业务规则不变**：
  - 可作废前置：`status ∈ {0,1,4}`；`status=2`（已结束）、`status=3`（已作废）不可再作废；
  - 作废成功：`Status=3`、`Reopened=false`；恢复成功：`Status=0`、`Reopened=false`；
  - 作废/已结束单禁止报工、禁止补报的校验照旧；【全部】与 H5 列表仍排除 `status=3` 与 `status=4`；
  - 工资汇总、排程、看板超期/临期口径照旧按 `status` 数值判断，不按中文文案判断。
- **I04 不得误伤无关「取消」**，以下一律不改：
  - 弹窗底部「取消」按钮（关闭对话框语义，如 `order/index.vue` 编辑弹窗 footer）；
  - 「取消派工 / 已取消派工」（`assign` 相关前后端）；
  - 企微报工预览的 `cancel=true`（作废预览，与工单状态无关）；
  - 筛选区「再点一次取消」选中状态、工资单「作废」既有措辞、其它模块（价目表、MCP 钥匙等）的「取消」。
- **I05 异常不吞**：后端 `ThrowHelper` 调用方式、参数名（如 `nameof(TransitionAsync)`）不变，只改提示文案内容。
- **I06 不做数据迁移**：历史 `status=3` 记录无需脚本处理；页面按新文案渲染旧数据即可。
