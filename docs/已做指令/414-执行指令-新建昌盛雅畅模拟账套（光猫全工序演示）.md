# 414 执行指令：新建「昌盛雅畅」模拟账套（光猫全工序演示）

## 一、背景

客户：**昌盛雅畅科技有限公司**，东莞通讯类电子产品制造厂（光猫、路由器、PON模块、交换机、网络终端），SMT及DIP组包测车间，工人多（作业员/测试员/质检员）。

用途：**销售演示**——先给客户看"贴合他们实际的模拟产品"，再约15分钟沟通说明"简单好用"。

**对外口径统一为「样板账套演示」，不冒充真实客户数据。**

## 二、目标

在本机演示环境新建「昌盛雅畅」模拟账套，产出一套贴合该电子厂、可直接演示的模拟数据：

- 光猫一条线**全工序走通**；
- **15~20人分到各工序**，车间看板更丰满；
- 含**不良记录**与**预警单**，演示"不良汇总 / 哪个工序不良多 / 临期超期预警"更有说服力；
- 工单、工资闭环可核算，数据可直接取数/截图给演示用。

## 四、边界与铁律

1. **对外统一口径「样板账套演示」**，不冒充真实客户数据。
2. **不复制 HY 伞业模板**：按电子厂真实档位逐项重建（部门、工序、编号、字段、价目表、数据结构都不同），禁止图省事套用统一行数模板（如一律6行）。
3. **报工 / 工单 / 工资等带业务校验的数据，只走接口或模拟操作，禁止 SQL 直插**（避免报工超额）。
4. 纯基础配置（产品、工序、单位、部门、价目表）可 SQL 批量导入。
5. 脚本**幂等可重跑**，不污染正式账套。

## 五、执行顺序

1. 读取技能三件套：`D:\workspace\pkub\bee\docs\技能\workshop-data-sim\`（SKILL.md、references\current-contract.md、scripts\sim_demo_data.py），先确认接口实测契约与脚本用法。
2. 确认账套环境：新建独立的「昌盛雅畅」模拟账套（不在现有账套里混）。
3. 基础配置 SQL 导入：部门（5个车间）、产品（光猫主 + 4辅）、工序（6道）、单位。
4. 价目表按电子厂行情重建并导入。
5. 改 CONFIG 顶部（账套 / 产品 / 工序 / 编号前缀如 SIM-CM-）→ 运行 `sim_demo_data.py` → 验证。
6. 报工 / 工资走接口或模拟操作，补足 15~20 人分到各工序。
7. 补几笔临期/超期预警单。
8. 取数 / 截图给演示用（对接「15分钟沟通脚本」的光猫6道工序演示）。

## 六、验证标准

- 光猫工单闭环：建单 → 派工 → 各工序报工 → 完工，一路走通。
- 15~20 人工资已生成，区间按人数与工价重算合理（参考上次 10 人 200.00~200.25 的合理分布，按本次人数/工价调整）。
- 报工不超额：全部走接口，无 SQL 直插。
- 车间看板：各工序产量 / 进度 / 不良可见。
- 存在不良记录与临期/超期预警单（演示用）。
- 脚本可重跑，账套数据不污染正式环境。

## 七、待确认项（执行前在新聊天里向用户确认）

1. **不良数据**：默认放几笔（演示"哪个工序不良多 / 不良汇总"更有说服力）；如客户场合不需要，可跳过。
2. **人数分配**：15~20 人在各工序的具体分配（如 SMT 3~4人、DIP 3人、波峰焊 2人、测试 4人、组装 4人、包装 3人，可按需调整）。
3. **主产品**：确认光猫为主推；是否连带路由器做浅演示。
