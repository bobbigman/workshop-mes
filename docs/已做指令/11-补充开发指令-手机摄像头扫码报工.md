## 三、交互要求

1. 首次打开扫码页，显示「打开摄像头扫码」「手动输入工单号」「扫码枪模式」。摄像头启动前不显示正在扫描的假状态。
2. 点击启动后检查安全上下文和摄像头 API，只请求视频，不请求音频。2026-09-22 兼容性修复：改用已通过真机独立检查的默认摄像头请求（`video: true`）；原后置偏好请求阶段导致页面重建的具体原因仍待确认，首要验收完整扫码链路。**不做摄像头设备列表 UI**；默认设备可能为前置，需记录真机选中的摄像头。
3. 展示真实视频画面，使用适合移动浏览器的内联播放设置，提供停止/重试入口。
4. 识别成功一次只处理一个结果；停流后进入现有 `/h5/report`，通过路由 query 传递工单号，禁止字符串手拼未编码参数。
5. 手机手动模式聚焦可见输入框；确认非空后进入现有报工流程。
6. PDA 模式保留自动聚焦、回车触发、输入清空和失焦恢复；恢复焦点仅限 PDA 模式，不与手动输入、按钮或摄像头模式争抢焦点。
7. 记住设备上次选择的摄像头/PDA 模式（`localStorage` 键 `h5.scan.mode`，值 `camera` | `pda`）；无历史偏好时默认摄像头待启动。重新进入已选择 PDA 模式的设备可直接使用实体扫描键。
8. 启动、授权等待时仍能取消和切换模式，防止用户不处理授权弹窗导致页面无法使用。

## 四、实现约束

### 4.1 摄像头与依赖

- 采用 `qr-scanner`（核实当前 npm 最新稳定版 API、许可及 Vite 构建行为），更新项目现有依赖锁文件。
- Worker / 识别资源随前端发布：由 Vite 打包 `qr-scanner` 内部动态导入的 worker，检查构建产物包含 `qr-scanner-worker.min-*.js`；不再设置库已废弃的 `WORKER_PATH`。禁止远程 CDN 和视频上传；断开公网、保留局域网时应可扫描。
- 使用 Vue3 `<script setup>` 与现有 Vant 风格，避免引入整套额外 UI。
- 显式维护启动中、扫描中、结果处理中、停止/错误等必要状态；启动按钮防连点，结果加互斥锁。
- 识别成功、停止、切换输入方式、路由离开、组件卸载、页面进入后台时释放识别器及视频 tracks。
- 为异步启动设置会话标记或等效取消机制：权限结果在用户离页后返回时，应立即释放新获得的视频流，不再跳转或更新失效组件。
- 回到前台提供重新开启入口，不静默持续占用摄像头。
- 每帧未识别到二维码是正常现象，不能当作业务异常持续提示；初始化、设备和解析失败须明确处理，不空 catch。

### 4.2 内容解析

新增纯函数工具（建议路径 `frontend/src/utils/scanPayload.js`），摄像头与 PDA 共用，避免两套规则。

1. 纯工单号：去首尾空白，非空且长度 ≤ **64**（对齐 `docs/02` 中 `prod_work_order.order_no NVARCHAR(64)`）；兼容长号、短号及既有自定义编号；不得限定为 `A0001` 或 `GD` 格式，不强制改大小写。
2. 完整报工链接：只接受 HTTP/HTTPS URL 中与当前站点同源的地址，拒绝带用户名/密码的地址；校验应用基路径和 hash 报工路由，解析 `/#/h5/report?order=...`。
3. `order` 必须唯一且非空，正确处理 URL 编码，不重复解码；提取后再按工单号校验。
4. 外站 URL、非报工路径、缺失或重复参数、不支持的协议均返回可读错误；绝不使用扫描原文作为任意网页跳转目标。
5. 手动输入走工单号校验，不强制套用 URL 解析；不要无意破坏已存在的自定义工单编号。盘点发现兼容冲突时记录具体样例并先补充取舍。
6. HTTP 旧来源、旧域名/旧端口不自动放行；需要兼容时列出明确的可信来源和测试样例后再补充规则。本期不新增通用来源配置后台。

配套自动化：项目前端**无 Vitest**，不为扫码单独引入测试框架。用 `node --test` 跑纯函数用例（如 `frontend/src/utils/scanPayload.test.mjs`），脚本可挂到 `package.json` 的 `test:scan`（可选）。

### 4.3 报工页与鉴权

- 复用现有按工单号查询接口和报工页；查询与报工始终走当前登录账号、工厂和部门权限逻辑。
- 不新增扫码即报工、不绕过部门权限、不跨工厂搜索、不生成默认工单。
- 查询失败需有可读错误与返回扫码/重新输入入口；保留现有接口错误上下文，不与公共错误提示重复弹出。
- 扫码页按现有登录规则访问；不在二维码中保存 JWT。
- **登录回跳（本期必做、最小改动）**：未登录访问 `/h5/*` 时，路由带到 `/login?redirect=<站内 fullPath>`；登录成功后仅当 `redirect` 以 `/h5/` 开头才回跳，否则保持现有默认首页。`http.js` 401 清登录态时，若当前为 `/h5/*` 同样带上该 `redirect`。禁止外站或非 H5 路径回跳。

### 4.4 DDL/API 与范围边界

本期预期无 DDL 变更、无新增后端 API、无现有接口契约变更。摄像头视频留在手机本地，业务只接收工单号。若实现发现确需改变契约，先补充本指令及对应权威文档，不擅自扩大范围。

## 五、部署要求

1. 服务器提供实际手机可信的 HTTPS；证书 SAN 覆盖访问域名/IP，链路完整且有效。
2. 严格内网场景采用内部 CA 并在受管手机建立信任；记录目标浏览器实测，不能只跳过证书警告。
3. 推荐前端静态页面和 `/api` 共用 HTTPS 入口，反向代理到现有后端；检查页面与接口无混合内容错误。
4. 检查站点响应的摄像头权限策略；如通过嵌入页面访问，还需验证嵌入权限，优先使用直接打开的站点页面。
5. 更新打印设置中的前端基址；核对新打印的链接二维码与实际入口相同。旧标签不批量改号，其兼容边界按第四节执行。
6. 无法接触现场手机/证书配置时，继续完成可独立进行的代码和构建工作，明确列出待部署、待真机验收项，不能将未验证项打勾。
