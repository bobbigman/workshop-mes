# 优化指令：企业微信交期预警「自动定时推送」

> 状态：**已实现（2026-09-26）**
> 依据：`docs/20`（企业微信预警，已实现）；`docs/15`（交期预警与看板）；`docs/02`（`sys_wechat_alert_setting` / `sys_wechat_alert_log`）
> 目标：**每天到点自动扫描临期/超期工单，推送交期预警到企业微信**，替代现在的手动点按钮
> 交付节奏：仅 PC / 服务端；不引入后台常驻进程

---

## 背景

`docs/20` 已实现：企微通道 + 配置页 + 手动推送（`push-overdue`），但**自动定时未做**。本次补齐。

**已具备、勿重做**：临期/超期判定走 `DueStateHelper`（`DueWarnDays=3`）；表已建。

---

## 拍板（2026-09-26）

### 鉴权：方案 A

- 新增免登录口：`POST /api/WechatAlert/cron-push`
- 校验请求头 `X-Cron-Token` = `appsettings` 的 `WechatAlert:CronToken`（空则拒绝，禁止裸奔）
- 扫本实例所有 `enabled=1` 的厂，逐厂推一次
- 附带 `backend/scripts/wechat-alert-cron.ps1` + schtasks 示例（逐实例挂）
- 原 `POST /api/WechatAlert/push-overdue` 保留（JWT，配置页手动按钮）

### 去重 / 推送粒度：方案 A（沿用现状）

- **一天一批、一条企微消息**：临期（黄）+ 超期（红）写在同一条里
- `alert_key` = `due-alert:yyyy-MM-dd`（按厂 + 日去重；`UNIQUE(factory_id, alert_key, send_date)`）
- **「同一工单同一天不重复」= 当日批次不重推**（当天再触发直接跳过，不拆成按工单连推）
- 必须在配置页写清楚，避免和实施理解成「按工单各推一条」

### 配置页文案（必改）

每日上限旁 / 推送说明处写清：

> 交期预警：**一天一批一条消息**（临期+超期写在一起）；**当日批次不重推**（同一天再点或定时再跑也不会重复发）。每日上限限制一天最多推几条不同告警。

按钮文案：`推送超期工单` → `推送临期/超期工单`

---

## 技术路线（硬约束）

**用 Windows 计划任务定时调 `POST /api/WechatAlert/cron-push`，不引入 BackgroundService / HostedService。**

理由：IIS 回收会杀常驻进程；多实例逐实例挂任务可控。

---

## 本期做什么

### 1. 增强 `push-overdue` / 共用推送逻辑

- 纳入「临期（黄）」+「超期（红）」；复用 `DueStateHelper.Calc`（`DueWarnDays=3`）
- 内容含：工单号 / 产品名 / 当前工序（首道未报满） / 计划交期 / 剩余或已超期天数；超期在前、临期在后
- `alert_key` = `due-alert:yyyy-MM-dd`；条数上限取配置 `daily_limit`（不再写死 Take(20)）
- 返回可查结果：`sent` / `skipped` / `orderCount` 等，便于验收

### 2. 执行规则

- `enabled=0`：静默跳过（不报错）
- 卡 `daily_limit`；写 `sys_wechat_alert_log` 去重
- 推送对象：配置的接收人 UserId（不新增映射）

### 3. 失败重试与日志

- 企微 API 失败：`SendWecomTextAsync` 有限次重试（3 次），仍失败抛错、记 log，不无限循环

### 4. 非代码前置（实施侧）

- 企微认证 + 自建应用；填 CorpID / Secret / AgentId / 接收人
- 打开「启用推送」，测一条
- 服务器 `appsettings` 配好 `WechatAlert:CronToken`（增量包勿覆盖）→ 挂计划任务调 cron 脚本
