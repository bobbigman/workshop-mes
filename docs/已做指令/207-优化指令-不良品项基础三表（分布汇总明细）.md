# 207-优化指令：不良品项基础三表（分布/汇总/明细）

> 状态：已做（2026-10-02）
> 一句话目标：新增【不良品报表】基础三表——**分布、汇总、明细**，让老板/管理员看清"不良原因分布、集中在哪道工序、谁报的"，对标黑湖不良品统计的基础能力；**不做**柏拉图/趋势/直通率（后置）。
> 依据/拍板：2026-10-02 多隆老同学与黑帽大人对标黑湖（有不良品项分布/汇总/明细报表）后拍板；放 `docs/未做指令/207`。先做性价比最高的基础三表。

## 取舍（定死）
| 项 | 定案 |
|---|---|
| 做/不做 | 做**分布/汇总/明细**三表；**不做**柏拉图（占比排名图）、趋势图、直通率FPY |
| 复用还是另写 | 复用 `prod_report` 字段（`defect_id`/`good_qty`/`defect_qty`/`operation_id`/`user_id`）；复用现有 `ReportStat` 聚合逻辑 |
| PC / H5 | 报表在 **PC（Element Plus）**；H5 不做（老板/管理员看电脑） |
| 数据前提 | 依赖工人报工时**必填不良原因**（系统已有"不良>0必选原因"） |
| 时间口径 | 按**原报工时间**，可选今日/本月/上月（与生产报表一致） |

## 已核实现状（勿重复做）
- 已有：`prod_report.defect_id`（不良原因）、`good_qty`/`defect_qty`、`operation_id`、`user_id`、`review_status`。（知识库 4.3）
- 已有：不良品项**自定义 + 按工序关联**（`base_operation_defect`）；生产报表按人看良品/不良/次数（`03-工单`）。
- 已有：`/api/ReportStat/production` 等统计接口模式可复用。
- 缺口：无"不良原因×工序/人"的分布/汇总/明细报表。

## 改动点
- 后端：
  - 新增（或扩展 ReportStat）**不良品统计接口**，返回三块：
    - **分布**：按 `defect_id` 汇总次数/不良数，可下钻到 `operation_id`（看"哪道工序这个原因最多"）。
    - **汇总**：按 `operation_id`×`defect_id`×`user_id` 汇总不良数、良品数、不良率。
    - **明细**：逐条不良报工记录（工单、工序、人、时间、原因、不良数）。
  - 过滤：可选时间范围（今日/本月/上月）、工单/产品关键词。
  - `review_status` 口径（已拍板，2026-10-02）：**默认取待复核(0)+已通过(1)，不含退回(2)**，页面上标注口径。**生产报表/工资仍只算已通过(1)**——两表用途不同（不良品报表=质量分析看现场全貌，生产报表/工资=对账只算已通过），不强求同数。
- 前端 PC（Element Plus）：
  - 新增【报表 → 不良品报表】页，三页签（分布/汇总/明细），带时间/工单筛选。
  - 分布页可用简单表格+占比（不做图表库），满足"哪个原因最多、哪道工序"。
  - **口径说明（复用现有说明位）**：**不加独立提示小字**。口径说明（"本报表含待复核+已通过、不含退回；生产报表/工资只算已通过，两表用途不同，数字可能不一致"）**填进现有单据/页面的"帮助/价值点/说明"位**，与其它单据说明保持一致。
- 文档：不改 `docs/02`（复用现有字段，无新表）；如新增接口则同步 `SupportDocs` 接口清单。
