## 本次范围与落点

- 交付：一条完整流程【员工维护企微UserId → 派工给某人 → 企微群@到该人本人】。
- 已有：`prod_work_order_operation.assignee_user_id` 派工到人字段（docs/29 已完成）；「派工通知」规则已建并启用（docs/217）；全局企微群 Webhook 已配置；群消息通道可用。
- 缺口：
  1. 现有规则「Webhook群内@人」是**写死固定名单**，派任何人的工都会@名单里所有人——**不符合「派给谁@谁」语义**，本次不作为派工@依据。
  2. 员工账号 `sys_user` 无「企微UserId」字段，无法稳定自动@到人。
- 数据与契约：`sys_user` 增加 `wecom_userid NVARCHAR(64) NULL`；**改表必须同步 `docs/02-数据字典.md`**。PC 端用户管理/员工档案页增该字段可编辑入口。
- 派工事件投递：`EnqueueAssignAsync` 只把被派工人的 `wecom_userid` 写入待发接收人；字典改在 `docs/开发手册和方案/02-数据字典.md`（根目录 `docs/02-数据字典.md` 当前是删除状态）。

## 行为与口径（分叉写成显式条件）

- 当【派工给胡忠谦（本厂 `sys_user.wecom_userid=HuZhongQian`）】→ 群消息自动 **@HuZhongQian**，其他人不@。
- 当【派工给 PuTao（`wecom_userid=PuTao`）】→ 群消息自动 **@PuTao**，其他人不@。
- 当【同一工序派给多人】→ 全部 @被派工人，**同一UserId只@一次**。
- 当【被派工人未维护 `wecom_userid`】→ 只发群不@，**派工/报工主流程不阻断、不报错**。
- 当【派给班组、没有具体工人】→ 只发群不@（不把班组展开成全员）。
- 当【取消派工】→ 不发（沿用现有：取消不调用待发）。
- 当【规则「群内@人」里手填了固定名单】→ **不@固定名单**，只@被派工人本人（固定名单字段本次不使用，可留空）。
- 当【总开关关闭 / 规则未启用 / 群Webhook未配置】→ 静默不发，不阻断主流程（沿用 docs/217 既有口径）。
