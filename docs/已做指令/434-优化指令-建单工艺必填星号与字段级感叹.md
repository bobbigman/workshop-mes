# 434-优化指令：建单工艺必填 `*` 与字段级错误标识

> 状态：已做（2026-11-03；后端隔离目录编译通过；未现场点选）  
> 性质：正式；不改表、不改金额规则  
> 目标：【文员】在【PC 建工单·本单工序工价】看到【取价必填工艺字段标 `*`】；【重新取价/正式保存失败且能定位到字段时】在该输入旁标红（感叹/校验态），不再只丢整段文案。  
> 依据：用户确认按推荐（先 `*` 再字段级标识）；419；承接 433。

## 1. 取舍

| 项 | 决定 |
|---|---|
| `*` 含义 | 当前产品+工序生效价目：`RequiredFieldIds` ∪ **基础/最终价行条件**用到的本工序工艺字段；收费组激活条件未填不算必填；不是「凡工艺字段都必填」 |
| 无价目/选表失败 | 不标 `*`（取价时仍红字总提示） |
| 字段级标识 | 预览失败响应带 `data.fieldId`；前端该 `el-form-item` `:error`；改值后清除 |
| 非字段级失败 | 无价目、多命中等仍只工序卡片总提示 |
| 不做 | H5；改价目编辑页；收费组「未填=不适用」不标 `*` |

## 2. 契约

- `GET .../operation-price-list/product/{id}`：`data[]` 增加 `requiredFieldIds: number[]`（可空）
- 业务失败：`{ code, msg, data: { fieldId } }`（仅缺属性/数字非法等字段级）；旧客户端忽略 `data` 仍可读 `msg`
- `http` 拦截器把 `fieldId` 挂到 reject 的 Error 上

## 3. 验收

- [ ] V01 价目 Required 含「工艺动作」→ 建单该工序标签带 `*`
- [ ] V02 未填点重新取价/提交 → 该框标红；`msg` 仍可读
- [ ] V03 无价目表 → 不标 `*`；总提示仍有
- [ ] V04 产品固有缺 → 不误标在工艺框上
