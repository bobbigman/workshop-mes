# Cursor 开发指令 · 体验账套到期自动清理（体验期默认7天可配 · 清空资料 · 禁用账号）

> 日期：2026-09-29｜状态：已完成
> 定位：把推广定稿里的**体验账套（500元定制，有效期默认7天，appsettings 可配、代码不写死）到期后「自动清空资料 + 自动禁用账号」**落地为一个后台定时清理服务，与指令 88（配额）、89（授权有效档）配合但不混同。
> 依据：[未来落地总规划（最终定稿）§二/§五](../推广方案/未来落地总规划｜产品体系+定价+服务器规则+引流模式+渠道规则（最终定稿）.md)、[docs/02](../02-数据字典.md)、已做指令 [89-轻量授权](89-开发指令-轻量授权（云激活+宽限期）.md)、现有后台服务 `ErrorLogCleanupService`。
>
> **2026-09-29 复核纠偏（开工前必读）**：①历史库**不回填**到期列；②私有版/`Deployment:Private=true` 永不清理；③清理清单补 `sys_print_setting`；④「新建写到期」只认显式体验账套路径，见 §三/步骤2。
> **落地要点**：`TrialAccountCleanupService`、`TrialCleanupOptions`、`DeploymentOptions`；`AuthService` 登录拦截；`FactoryService` SaaS 新建写到期；`LicenseCloudService` 转正式清空到期列。

## 〇、与 88 / 89 的分工（防止 Cursor 混同，先讲清）

| 指令 | 管什么 | 到期后做什么 |
|---|---|---|
| **89 轻量授权** | 合同档 `license_tier` + 有效期是否**有效**（云激活/宽限期） | 超期**有效档降 trial**，**不删数据**，续费自动恢复 |
| **88 存储配额** | 每客户总容量/单文件上限/类型白名单 | 超限**拒绝上传**，不清理存量 |
| **本条（90）** | **体验账套（trial）本身的体验期（默认 7 天，可配）** | 到期**自动清空该工厂全部资料 + 删附件磁盘 + 禁用登录**，不可逆 |

> 判据：89/88 针对「正式客户续费/扩容」，本条针对「体验账套试玩结束后清场」。**体验账套到期 ≠ 授权降档**，是**清场**。

## 一、已查证现状（开工前必须复核，不靠历史文档猜）

| 项 | 现状 | 证据/入口 |
|---|---|---|
| 体验账套形态 | 独立工厂（factory），如 CJ001 厨具五金厂演示账套；`license_tier='trial'` | `docs/63-执行指令-厨具五金厂演示账套.md` |
| 后台定时服务范式 | 已有 `ErrorLogCleanupService`：`BackgroundService` + `SemaphoreSlim` 门闩防重入 + 可注入时钟（测试）+ 启动先清一次 + `Task.Delay` 间隔 + 同步清理入口供验收 | `backend/Common/ErrorLogCleanupService.cs` |
| 到期时间载体 | 现只有 `license_expires_at_utc`（89 云端授权用，**不可**当体验到期复用，语义冲突） | `docs/02:48`、指令 89 §四 |

**结论**：新增 1 个到期时间列 + 1 个后台清理服务 + 登录拦截校验。清理服务**完全照抄 `ErrorLogCleanupService` 的安全套路**（门闩、时钟注入、同步入口、保守不误删），不另起炉灶。

## 二、技术栈与硬约束（不可变更）

- .NET 8 Web API + EF Core + SQL Server；命名空间 `ahu.MicrosoftMes`；后台服务放 `Common/` 或 `Services/`，与 `ErrorLogCleanupService` 同级。
- `docs/02` 需**新增 1 列**（体验到期时间，见步骤 1），其余表结构不动。
- 清理必须**按删除依赖倒序**、**按 factory_id 隔离**，绝不越界删其它工厂数据。
- 清理**不可逆**：正式版/转正账套**绝不触发**；只对 `trial` 且到期的账套。
- 异常统一 `ThrowHelper`；日志完整、不脱敏（工厂 code + 清理了哪几张表 + 行数 + 删了多少附件 + 失败原因）。
- 生产环境清理**可一键关闭**（配置开关，默认开）；关闭时照记"发现到期但未清理"的日志。

## 三、业务口径（规则定死，禁止另造）

- **体验有效期**：体验账套创建即记 `trial_expires_at_utc = 创建时刻 + TrialCleanup:DurationDays`（默认 7 天，**代码不写死**；对齐定稿"账套有效期 7 天"）。
- **谁算体验账套（防误伤，条件定死）**：
  - **进入清理队列的硬判据** = `license_tier='trial'` **且** `trial_expires_at_utc IS NOT NULL` **且** `trial_cleaned_at_utc IS NULL` **且** 已过期（含 GraceMinutes）。
  - **`trial_expires_at_utc = NULL` = 永不进清理**（历史库、私有单厂、未标体验的账套一律安全）。
  - **当** `Deployment:Private=true`（私有买断，指令 88）→ 清理服务整段跳过（等同 Enabled=false 的日志行为）；新建也不写到期列。
  - **当** 89 正式客户授权过期 → 运行时有效档降 trial，但**DB `license_tier` 仍是 enterprise/flagship**，且转正时已清空 `trial_expires_at_utc` → **绝不进本清理**（与 89 不混同）。
- **到期判定**：上述硬判据 + `trial_expires_at_utc + GraceMinutes < now_utc`（用 `DateTime.UtcNow`）。
- **清场范围（该 factory_id 下全部业务资料 + 附件）**，依赖倒序（对照 docs/02 全表；实现以本清单为准）：
  1. `salary_statement_item` → `salary_statement`
  2. `prod_report`
  3. `prod_abnormal`
  4. `prod_work_order_operation` → `prod_work_order`
  5. `base_knowledge_file`（同时删磁盘 `RootPath/{factory_id}/` 整个目录；提交成功后再删盘）
  6. `base_price_rule`
  7. `sys_custom_field_value` → `sys_custom_field_option` → `sys_custom_field`
  8. `sys_wechat_alert_log` → `sys_wechat_alert_setting`
  9. `sys_print_setting`
  10. `base_product`（须先于工艺路线，对齐 AGENTS 删除倒序）
  11. `base_routing_step` → `base_routing`
  12. `base_operation_defect` → `base_operation_department` → `base_operation`
  13. `base_defect_item`
  14. `sys_department_user` → `sys_department`
  15. `base_unit`
  16. `login_setting`、`sys_mcp_auth`（该工厂的）
- **账号处置**：**不物理删 `sys_user`**（防 `created_by` 等外键连环炸）；改为**登录拦截**（见步骤 4）。`sys_factory` 记 `trial_cleaned_at_utc`（清理时间，防重复清理）。**不删 `sys_factory` 行本身**。
- **禁用判定**：`license_tier='trial'` 且 `trial_expires_at_utc` 非空且已过期（或已写 `trial_cleaned_at_utc`）→ 该工厂所有账号**禁止登录**，文案见步骤 4。
- **转正路径**：**当** 体验账套在到期前转正式版（`license_tier` 改为 enterprise/flagship，或私有 `Deployment:Private=true`）→ **清空** `trial_expires_at_utc`（置 NULL），不再进清理队列。

## 四、原子步骤（每步显式带条件判断）

### 步骤 1 · `sys_factory` 加体验到期列（DDL 变更，改 docs/02）

- 在 `docs/02-数据字典.md` 的 `sys_factory` 增加：
  - `trial_expires_at_utc  DATETIME2 NULL`  —— 体验账套到期（UTC）；**空 = 不进清理队列**（历史库/私有/未标体验）。
  - `trial_cleaned_at_utc DATETIME2 NULL`  —— 体验账套已完成清场的时间（防重复清理、可审计）。
- **当** 数据库未同步 → 走现有 `DbCompat` 幂等 `ALTER`（`IF COL_LENGTH(... ) IS NULL`），与 license_tier 列同套路；**禁止**对历史行回填到期时间。
- **当** 历史库已有工厂（含 `license_tier='trial'`）→ **两列保持 NULL**，不猜、不回填。原因：现网默认档就是 trial，回填 `created_at+7天` 会立刻清掉私有单厂/演示账套真实数据。
- 同步 EF 实体 `SysFactory` + `AppDbContext` 映射。
- 验收：`docs/02` 已补两列；`dotnet build -c Release` 0 错 0 警；兼容脚本可重复执行不炸；已有工厂 `trial_expires_at_utc` 仍为 NULL。

### 步骤 2 · 体验账套创建/转正时写入到期列（业务入口挂点）

> 现状：`FactoryService.CreateAsync` / `SeedData.SeedFactoryAsync` 新建一律 `license_tier='trial'`，**没有**单独的「体验账套」勾选。必须用条件分支，禁止「凡新建都写到期」误伤私有多厂。

- **当** `Deployment:Private=true` → 新建账套**不写** `trial_expires_at_utc`（保持 NULL）。
- **当** SaaS（`Deployment:Private=false`）且走管理端「新建账套」成功 → **写** `trial_expires_at_utc = UtcNow + DurationDays`，`trial_cleaned_at_utc = NULL`（对齐 500 元体验钩子：云上新开账套默认即体验）。
- **当** 启动种子 / `InstanceBootstrap` / `SeedData.EnsureAsync`（本机演示 F001 等）→ **不写**到期列（NULL），避免开发库被清。
- **当** 体验账套**转正式**（`LicenseCloudService` 回写 `license_tier` → enterprise/flagship）→ **清空** `trial_expires_at_utc`（置 NULL）。
- **当** 只是正式客户续费/宽限/有效档降 trial（89）→ **不动**这两列。
- 落点：`FactoryService.CreateAsync`（写到期）；`LicenseCloudService` 成功回写正式档（清空到期）；种子路径显式跳过。
- 验收：SaaS 新建能看到到期=创建+配置天数；私有新建 / 启动种子到期列为 NULL；转正后清空。

### 步骤 3 · 后台清理服务 `TrialAccountCleanupService`（核心，照抄 ErrorLogCleanupService 套路）

- 新建 `BackgroundService`，命名空间 `ahu.MicrosoftMes.Common`（或 `Services`，与日志清理同级）。
- 结构照抄 `ErrorLogCleanupService`：`SemaphoreSlim` 门闩（重入跳过）、可注入 `Func<DateTime>` 时钟（测试）、`ExecuteAsync` 启动先跑一次 + `Task.Delay` 间隔、`RunCleanupSafeAsync` 不抛死、同步入口 `CleanupOnce` 供验收。
- 配置 `TrialCleanupOptions`（`IOptionsMonitor`）：`DurationDays`（体验期，默认 7）、`IntervalMinutes`（默认 60）、`Enabled`（默认 true）、`GraceMinutes`（到期后再留的宽限，默认 0 即到点就清，可配）。
- 逻辑 `CleanupOnce(opt, nowUtc)`：
  0. **当** `Deployment:Private=true` 或 `Enabled=false` → 查出到期候选只打「发现 N 个未清理（code 列表）」日志，**不删**，返回 0。
  1. 查出所有 `license_tier='trial' AND trial_expires_at_utc IS NOT NULL AND DATEADD(minute, GraceMinutes, trial_expires_at_utc) < nowUtc AND trial_cleaned_at_utc IS NULL` 的工厂。
  2. **当** 没有 → 直接返回 0。
  3. **当** 有 → 逐个按 §三依赖倒序**在一个事务内**删该 factory 的数据表；删 `base_knowledge_file` 记录后删磁盘 `RootPath/{factory_id}/` 目录（先校验路径不越界、非重解析点，保守跳过越界项）。磁盘删除放在事务提交**成功之后**（避免库回滚了磁盘已删）；若磁盘删失败 → 记错误日志，**不回滚已清库**（账号已禁用，可人工补删目录）。
  4. **当** 全成功 → 写 `trial_cleaned_at_utc = nowUtc` 并提交；记日志（工厂 code、每表删的行数、删附件数）。
  5. **当** 某表失败 → 事务回滚，**该工厂整体不动**（不留下半清空状态），记错误日志带上下文，继续处理下一工厂。
- 磁盘删除安全：复用 `ErrorLogCleanupService` 的 `IsReparsePoint` + 路径越界防护逻辑；`RootPath/{factory_id}/` 目录存在才删，不存在跳过。
- 验收：造一个 `trial_expires_at_utc` 已过去的工厂 → 跑 `CleanupOnce` → 数据清空、附件目录删除、`trial_cleaned_at_utc` 已写；再造一个到期列为 NULL / 未到期 / 已转正的 → 不动；`dotnet build -c Release` 0 错 0 警。

### 步骤 4 · 登录/访问拦截（到期禁用账号）

- 在 `AuthService.LoginAsync`（密码校验通过后、发 JWT 前）加校验：
  - **当** `license_tier='trial'` 且 `trial_expires_at_utc` 非空且已过期（含 GraceMinutes）→ **拒绝登录**，文案：「体验账套已到期，请联系部署方转正式版或重新开通体验」。
  - **当** `trial_cleaned_at_utc` 非空 → 同样拒绝。
  - **当** `trial_expires_at_utc` 为空 / 未到期 / `license_tier` 非 trial / `Deployment:Private=true` → 正常放行（**绝不误伤正式客户与私有版**）。
- 落点：仅 `AuthService`（手机号登录暂未开放，无需双挂）；与 89 的 `RefreshAsync`/`GetStatusAsync` 并列，**先做体验到期拦截，再走授权云**（到期体验不必再打云）。
- 验收：过期体验账套任意账号登录被拒且文案准确；到期列 NULL 的 trial / 正式 / 私有不受影响。

### 步骤 5 · 配置开关 + 一键关闭（生产可关、日志完整不脱敏）

- 在仓库 `appsettings.json`（开发默认）增：`TrialCleanup:{Enabled, IntervalMinutes, GraceMinutes, DurationDays}`；**代码常量兜底**（Enabled=true、Interval=60、Grace=0、Duration=7）。私有客户机默认靠 `Deployment:Private` 跳过，不必改 Enabled。
- **体验账套容量默认 200M** = 指令 88 的 `StorageLimits.trial.TotalBytes`，本指令**不重复配置**。
- **当** `Enabled=false` 或 `Deployment:Private=true` → 后台服务**跳过清理**，但照记「发现 N 个到期体验账套未清理（工厂 code 列表）」日志，不脱敏。
- **当** `Enabled=true` 且非私有 → 步骤 3 正常执行。
- **当** 部署更新 → 只发增量包，不覆盖服务器 `appsettings*.json`（见 `DEPLOYMENT_NOTES.md`）。
- 验收：开关两态 + Private=true 各测一次；关闭时到期账套留有"未清理"日志证据。

### 步骤 6 · 前端提示 + 文档同步（范围收窄，有则改无则跳）

- **当** PC 管理端已有「新建账套」对话框 → 补一句说明：「SaaS 体验账套默认 {DurationDays} 天有效，到期自动清空资料并禁用账号（不可逆）」；天数可写死文案占位或调只读配置接口——**若无现成配置接口，文案写「默认 7 天（以服务器配置为准）」即可，不做新接口**。
- **当** 登录返回可带 `trialExpiresAtUtc`（可选，非本条必须）→ 顶栏临近到期提示；**无则跳过顶栏**，本条不做大改 UI。
- 同步 `docs/02`（两列）、`docs/01`/`03` 各补一句；`docs/30` **当**有合适小节再补，无则跳过。
- 验收：新建账套文案可见（有对话框时）；文档已同步；`dotnet build` 通过。

## 五、边界（对外口径，先跟客户说清）

- **体验账套到期清空不可逆**：体验期（默认 7 天）到期后资料（含附件）自动删除，不做保留/导出；需要数据就在到期前转正式版。
- **转正式版才保数据**：到期前转 enterprise/flagship/私有 → 不清理、数据全保留。
- 正式客户（enterprise/flagship/私有）**绝不会**触发本清理；本清理只认 `license_tier='trial'`。
