# 418 开发指令：工价按生效日期与本月追溯重算

> 状态：代码已实施并完成专项验证；未部署，远程账套未作调整。
> 用户授权：2026-10-25要求落地；三项口径已明确一次确认。

> 交付范围：PC管理入口、共同后端取价规则、历史与审计、增量DDL及专项验证。

## 已定决策

1. 调价只改金额、不良扣价。条件、产品范围、计价单位与换算等结构另走原维护入口；已启用价格不能用普通PUT绕过调价。
2. 计时报工跨日时，整条按报工业务日期取价，不拆小时。业务日期统一北京时间；明确UTC输入先转换，再截日期。
3. 已有未来调价安排时阻断，不覆盖原安排。
4. 普通调价不改已有报工与工资；追溯只允许本月1日至今天选起点，原因必填，覆盖起点至本月底的已有报工。
5. 旧工单保留预算与工艺事实，后续报工按业务日期取价。工单预览/原Token仍核对预算，工资预览和提交使用日期价格。

## 事实与实现落点

- `PriceTimelineService`保存与选取有效价格；`OperationPricingService.BudgetAsync/LockedAsync`区分原预算和报工价格。
- `PriceChangeService`独立构建完整预览和原子提交，不串联已有可部分成功的批量重算。
- `ReportPriceSnapshot.Calculate`与`WageCalculator`继续承担金额计算；计件/计时、固定、扣价、换算和舍入保持原口径。
- PC价表列表/详情增加“调整工价”，列表增加“调价记录”；新建、普通编辑、复制入口继续使用原表单。
- 新增两张表：`base_operation_price_revision`与`base_operation_price_change`。DDL以02为准，脚本`backend/scripts/418-price-change.sql`，后端启动兼容建表并建立基线。
- 同厂调价、价表维护、工单相关写入、报工/复核、工资生成/确认/撤回/重算/删草稿先取共同事务锁，再取原有对象锁。

## 金额与历史依据

- 报工显示金额沿其AppliedWageCoeff；旧记录缺此字段时，仅在工资明细系数可重现原显示金额时采用，不能倒推系数或套当前人员系数。
- 工资明细沿其WageCoeff；固定价计算器仍取实际系数1，扣价不乘人员系数。
- 原工资明细数量、分钟、金额/扣额及主表合计须能由旧依据解释，冲突先阻断。
- 前后快照、价格时间线、整单撤回涉及的报工标记、工资明细/主表及操作者/原因持久留存；审计查询严格本厂。
- 同日纠错保留旧内容，旧分段标替代，不产生倒置日期；跨日关闭段到前一天。
- 上线基线起点为当前版本可核实的UpdatedAt、ActivatedAt及EffectiveFrom业务日期最大值；元数据无效时才从上线当天开始。不把当前价回填到更早未知历史。
