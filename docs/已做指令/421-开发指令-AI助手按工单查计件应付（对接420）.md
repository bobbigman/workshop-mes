> 目标：让【管理员】在 PC「AI 助手」用自然语言问到与 420 同口径的应付金额（尤其选「老板」角色时）；并同步企微 MCP 管理员查询。

**口径（与 420 完全一致，禁止 AI 另算）**：
- 「计件工资」口语 = 420 口径1 全计价合计（计件+计时+固定），回答时用 **应付合计 `payableTotal`**，可附带计件/计时/固定分列与未复核金额。
- 已完工 = `status=2` 台账 `payableTotal`；已取消不进。
- 有 item 用固化应发，否则 `wage_amount`；NULL→0 并提示未计价笔数。

## 4. 数据与接口契约

**不改** HTTP `/api/Salary/*` 契约与 docs/02。AI/MCP 只包一层。

| 工具名（推荐） | 参数 | 成功返回（给模型的精简 JSON） | 失败 |
|---|---|---|---|
| `get_work_order_payable` | `orderNo?` `orderId?`（都有则 orderId 优先，同 420） | orderNo、product、qty、status、payableTotal、unreviewedAmount、unpricedCount、unknownPriceTypeAmount、byOperation/byUser 可截断（名称+小计，避免超长） | 透传业务 msg |
| `get_completed_work_orders_payable` | 无 | payableTotal、unreviewedAmount、unpricedCount、list 行（orderNo、product、qty、payableTotal、unreviewedAmount）；若行过多可只返回合计+前 N 行并注明 totalRows | 透传 |

**I01**：金额来源与舍入 100% 委托 `WorkOrderSummaryAsync` / `CompletedWorkOrdersAsync`，禁止在 Dispatcher 里重算或把报工良品×单价。

**权限**：`factoryId`/`userId`/`role` 不得从模型参数传入（沿用 `RejectForbiddenArgs`）；服务端从 AI 会话或 MCP 绑定取。

**许可证**：调用前检查 PieceWage（与 `RequireLicenseFeature` 同口径；实现可用现有 License 辅助，待核实具体 helper 名）。

## 5. 事务、并发与恢复

只读；无事务；无写入。工具失败必须返回明确错误给模型，禁止空成功。并发查询以查询时刻为准（同 420）。

## 6. 核心伪代码

```text
// ToolsForMode("progress") 与 ToolsForMode("support") 均增加两工具
Dispatch get_work_order_payable / get_completed_work_orders_payable:
  RejectForbiddenArgs；EnsureToolAllowed(progress|support)
  role==1 否则 B11；PieceWage 否则 B11b
  调 WorkOrderSummaryAsync / CompletedWorkOrdersAsync(session.FactoryId)
  返回精简 JSON + 证据 id（sal_wo_* / sal_done_*）

SystemPrompt(progress) 与 SystemPrompt(support):
  工具列表写明可用上述两个查「工单应付」「已完工应付合计」
  必须先调工具再报金额；口语「计件工资」对应 payableTotal（含计时/固定）
  按人/按月工资单、改数、发放 → 引导工资报表，不调本工具、不编造
```
