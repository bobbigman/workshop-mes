## 本次范围与落点

- `WecomReportMcpTools` 的候选、预览、确认增加统一错误边界；新增 `check_work_report_readiness` 只读工具，不新增表，不改变权限、确认与幂等策略。
- 接入检查不查询候选、不产生/取消预览、不写流水；就绪仅代表程序可检查项通过，不证明平台身份头不可伪造或已完成真机验收。
- 业务拒绝 → 返回原错误码和可读原因；技术故障 → 返回非零码及追踪号，服务器保存脱敏上下文，禁止把失败当成功或空候选。
- 同步机器人遇错处理、人设未配置时的发布步骤和接入说明；提供配置示例但不改现有appsettings中的实际写入状态。

## 行为与口径

- 当未启用/缺身份/未核验/绑定不匹配 → 工具正常返回明确拒绝内容，机器人依据msg告知下一步，不空泛重试。
- 当检查工具被调用 → 即便未启用也返回各项可检查状态；缺身份等不执行绑定查询；不回显原始userid、手机号、哈希或核验用户ID。
- 当候选或预览技术异常 → 告知本次未完成并联系管理员查追踪号；当确认技术异常 → 告知结果待核实、按原凭证查账/重试，不说“未入账”或自动重建一笔。
- 当取消技术异常 → 告知取消未确认，不允许机器人继续使用旧预览；仅追踪和明确恢复后才继续。

## 止步线

不修改所有MCP查询工具、不开放调试堆栈、不自动启用报工/生成员工映射，不重做身份体系或企业微信平台。后台返回可读错误不等于已证明企微一定按该错误回复。
