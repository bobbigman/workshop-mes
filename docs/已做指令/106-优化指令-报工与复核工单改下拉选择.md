# 106-优化指令：报工与复核的工单号改下拉选择

> 状态：已实现
> 依据：`docs/22`（复核双轨）、`frontend/src/views/report/index.vue`、`frontend/src/views/review/index.vue`、`frontend/src/api/prod.js`、`frontend/src/api/review.js`
> 对标：黑湖小工单——工人/班组长**不手工敲工单号**，靠扫码/点选，极简交互、消灭键盘输入
> 痛点：报工页（顶部筛选、新增/代报/补报三个弹窗）和复核页的「工单编号」全是手工 `el-input` 敲字，慢、易敲错。
> 目标：把这几处工单号手工输入改成**下拉选择**（可输入过滤 + 可手敲兜底），选项显示「工单号 + 产品名」；选中自动带出/加载详情。
> 原则：后端只加最小参数/接口；先做 PC；H5 已有扫码/点选，本期不碰。

---

## 0. 为什么做（人话）

工人和班组长文化参差、车间又吵，让老胡敲一长串工单号，又慢又容易打错。黑湖的做法是扫码和点选。电脑端这几处也改成**点一下选**，选了自动带出产品，少敲字、不错字；漏单时仍可手敲兜底。

## 1. 已有底子（别重复造轮子）

- 工单列表：`getOrderList` → `GET /WorkOrder`，已有单状态 `status`、`excludeCancelled`、`keyword`、分页；**尚无**「未结束 = 非 2 非 3」一次过滤。
- 按单加载：`getOrderByNo` → `GET /WorkOrder/by-no`，报工页已在用。
- 待复核列表：`getPendingReviews` → `GET /Review/pending`（按报工行分页，不是按工单去重）。
- 待改位置：
  - `report/index.vue`：顶部 `q.orderNo`；新增 `createForm.orderNo`；代报 `proxyForm.orderNo`；补报 `batchForm.orderNo`（4 处 `el-input`）。
  - `review/index.vue`：顶部 `q.orderNo`（1 处 `el-input`）。

## 2. 交付物

- 后端：`GET /WorkOrder` 增加 `excludeFinished`；`GET /Review/order-options` 返回有待复核报工的工单去重列表。
- 前端：报工页 4 处 + 复核页 1 处改 `el-select`；文档收尾。

## 3. 拍板结论（已定，勿再改语义）

| 项 | 选定 | 理由 |
|---|---|---|
| 报工下拉数据源 | **`excludeFinished=true`**（status ∈ {0,1}） | 一次拉干净；不用二次合并，也不用大 pageSize 混已结束单 |
| 弹窗兜底 | **`allow-create` + 原 `getOrderByNo`** | 新单未进缓存、查已结束/取消单时不卡死 |
| 复核下拉数据源 | **有待复核报工的工单**（含已结束但仍有 pending） | 复核目标是清 pending；只列未结束会漏「单已结束、报工还挂着」 |

## 4. 原子步骤

### 步骤1：后端 `WorkOrder` 加 `excludeFinished`

- `WorkOrderQueryDto` 增加 `bool ExcludeFinished`。
- `QueryAsync` 条件（当未传单值 `Status` 时）：
  - 当 `ExcludeFinished == true` → `status != 2 && status != 3`；
  - 否则当 `ExcludeCancelled == true` → `status != 3`（现有逻辑保留）。
- **明确不做**：不为下拉倒全部历史工单。

### 步骤2：后端 `Review/order-options`

- 新增 `GET /api/Review/order-options`：返回本厂**当前有待复核报工**（`review_status=0`）的工单去重列表，字段：`orderNo`、`productName`。
- 权限与班组长本组过滤与 `PendingAsync` **同一套**（管理员全厂；班组长仅本组报工人相关工单）。
- 按 `orderNo` 升序或按最近报工时间倒序均可，实现时选一种并固定。

### 步骤3：报工页下拉数据 helper

- `report/index.vue` 维护 `orderOptions`，`onMounted`（及打开弹窗前可刷新）调：
  `getOrderList({ excludeFinished: true, page: 1, pageSize: 500 })`
  映射为 `{ value: orderNo, label: \`${orderNo}（${productName}）\` }`。
- 当工单量通常几十～几百 → 一次加载即可；`filterable` 本地过滤。本期不做 remote（车间量级够用）。

### 步骤4：报工页顶部筛选改下拉

- `q.orderNo`：`el-select`（`filterable clearable allow-create default-first-option`），选项来自 `orderOptions`。
- 选中/清空 → 更新 `q.orderNo` 并 `load()`（或仍点「查询」；**推荐选中即查，与弹窗选中即加载一致**）。
- 产品编号/名称筛选不动。

### 步骤5：报工页三个弹窗改下拉

- 新增 / 代报 / 补报：工单号改为同上 `el-select`；**选中或手敲确认 → 自动调** `loadOrder` / `loadProxyOrder` / `loadBatchOrder`（去掉必点【加载】；【加载】按钮可删）。
- `allow-create`：不在列表的号仍走原 `getOrderByNo`（含已结束拦截提示）。
- 单工序自动选中、防超额等逻辑不动。

### 步骤6：复核页顶部改下拉

- `q.orderNo`：`el-select`（`filterable clearable allow-create`），选项来自 `GET /Review/order-options`（**不是** `excludeFinished` 工单列表）。
- 选中/清空 → 更新并 `load()`。
- 工人姓名、复核状态筛选不动。
- 当复核状态下拉切到「已通过/已退回」→ 顶部工单下拉仍展示「有待复核的工单」作快捷点选；其它工单靠 `allow-create` 手敲（避免倒全部历史已通过单）。

### 步骤7：文档收尾（实现并通过验收后）

- `docs/30`：报工/复核补一句「工单编号可下拉选择，也可手敲」。
- `docs/04`：勾选对应行（若有）。
- 本文件移入 `docs/已做指令/`，状态改为「已实现」。
