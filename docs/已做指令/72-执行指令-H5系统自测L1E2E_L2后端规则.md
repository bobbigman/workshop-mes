# 72-执行指令-H5 系统自测（L1 界面 E2E + L2 后端规则自测）

> 依据：`70-执行清单`（用例编号 H5-xx）、源码核对（`frontend/src/views/h5/*`、`backend/Services/ReportService.cs`）、`start-dev.bat` / `vite.config.js`（端口、账套、账号）。

## 1. 目标与范围

- **目标**：一条命令把 H5 的界面交互 + 业务硬规则自测跑完，输出可读报告；未覆盖的真机项单列清单。
- **L1 界面 E2E**：Playwright 自动点 H5 真页面（登录/工单/任务/报工/异常/导航）。
- **L2 后端规则自测**：Node 脚本直调真实后端 API，断言硬规则错误文案。
- **范围**：H5（`/h5/*` + 登录），不含看板/工资/排产/电脑端后台。

## 3. L1 界面 E2E（Playwright）—— Cursor 实现

### 3.1 脚手架
- 在 `frontend/` 加 `devDependencies: playwright`，执行 `npx playwright install chromium`。
- 测试目录：`frontend/tests/e2e/`；配置 `frontend/playwright.config.js`：
  - `use: { baseURL: 'https://localhost:5173', ignoreHTTPSErrors: true, trace: 'retain-on-failure' }`
  - `ignoreHTTPSErrors:true` 解决 dev 自签证书信任问题。
  - `webServer`：前端起 `npm run dev`（5173）；后端由 `start-dev.bat` 或手动先起（8080）。
- package.json 加脚本：`"test:e2e": "playwright test"`。

### 3.2 spec 清单与用例映射（沿用 70 编号）

### 3.3 报工 spec 关键断言（report.spec.js）
- 40：进入报工页见 工单号 + 计划/已完成/剩余。
- 41：未选工序点【提交报工】→ toast「请选择工序」。
- 42：选工序 → 剩余可报变化（与所选工序对应）。
- 43：点 `+10`/`-1` → 良品数增减且**不超剩余、不为负**。
- 44：点【报全部剩余】→ 良品=剩余数。
- 46：良品 5、不良 3、不选原因 →「有不良品时必须选择不良品原因」。
- 47：分钟填 60 →「时长填写不正确」。
- 48：时长 24h 后再 +1 分钟（或直接 24h30m）→「单次报工时长不能超过24小时」。
- 49：正常提交 →「报工成功」→ 回扫码页；重开该单剩余减少。
- 51：某工序报满后再提交 →「该工序已报满，不可继续报工」+ 按钮禁用。

### 3.4 摄像头/PDA 处理（明确取舍）
- 摄像头真实取景识别：Playwright 可用 `--use-fake-ui-for-media-stream --use-fake-device-for-media-stream` 假摄像头跑通"打开→出画面→停止"流程，但**真实流转卡识别放真机**，不纳入 L1。
- PDA 扫码枪本质=键盘输入+回车：用 `page.keyboard.type(工单号)+Enter` 可模拟，纳入 L1（`scan-manual` 或单独 `scan-pda.spec.js`）。
- 诊断面板（`?scan-check`）、iPhone PWA：真机项。

## 4. L2 后端规则自测（Node 脚本）—— Cursor 实现

### 4.1 位置与脚本
- `frontend/tests/api/` 或独立 `tests/api-selfcheck/`；用 Node 内置 `fetch` + `node --test`（与现有 `test:scan` 一致）。
- 依赖：无新增（用 fetch）。
- 直连 `http://localhost:8080`，先 `POST /auth/login` 取 token，带 `Authorization: Bearer`。

### 4.2 用例与断言（错误文案与后端一致，已核实）
| # | 操作 | 断言 |
|---|---|---|
| A1 | 管理员 token 调受保护接口 | 200 |
| A2 | 无 token 调受保护接口 | 401 |
| A3 | 良品>0 超工序剩余提交 | 报错含「剩余可报」 |
| A4 | 不良>0 不传 defectId | 报错含「有不良品时必须选择不良品原因」 |
| A5 | durationMinutes > 1440 | 报错含「单次报工时长不能超过24小时」 |
| A6 | goodQty/defectQty 为负 | 报错含「良品/不良品数不能为负」 |
| A7 | 用不在工序报权部门内的工人账号提交 | 报错含「无报工权限」 |
| A8 | 同批重复提交 | 复核通过前不重复计入进度（查进度不变）或报满锁定 |
| A9 | `POST /Abnormal` 关联不存在工单 | 报错（工单不存在） |
| A10 | `POST /Abnormal` 合法 | 200/成功 |
| A11 | 未登录访问 `/h5/*` 页面本身（前端） | 跳登录（归 L1 login-05） |

### 4.3 测试数据约定（防污染）
- 脚本开头用管理员 `POST /WorkOrder` 造一张**独立测试工单**，编号带前缀（如 `AUTOTEST-<时间戳>`），产品/工艺复用 F001 现有数据。
- 测完 `DELETE /WorkOrder/{id}` 清理；个别不能删的在报告标注"遗留待人工清"。
- 不碰真实生产工单/真实报工；所有断言数据均为脚本自造。

### 4.4 运行
- package.json：`"test:api": "node --test tests/api/"`。

## 8. 边界与注意事项
- 前端 dev 为 HTTPS 自签：E2E 用 `ignoreHTTPSErrors`，**不要**为测试改证书/代理生产配置。
- 后端必须连真实 SQL（F001 账套）；测试账号用 `admin`（管理员，可豁免权限）和 `zhangchu`（工人，测权限=部门）。
- 报工/异常为**写操作**：测试数据独立、可清理；任何报工只落在自造工单上。
- 发现新错误（与本文断言不符）→ 按「用例编号 + 实际返回 + 期望」反馈，先改实现再跑，勿降级跳过。
