## 1. 首版范围

新增 PC「执行监控」，建议路由 `/execution-monitor`。在当前生产相关菜单内增加入口，保留现有工单、报工、异常、看板页面。

页面包含：状态统计、工单筛选、工序进度链、待处理异常、超期工单、工单明细、待复核与未派工待办。详情/派工/报工/复核/异常操作尽量进入现有页面；若现有页面不支持定位，补充最小路由参数及处理，不能只跳到一个无法定位目标的空入口。

## 2. 数据规则（必须实现并写入权威文档）

### 2.1 进度统一

- 进度统计仅包含 `review_status=0/1`；正式报表与工资仍仅 `=1`。
- 工序良品数按工单 + 工序汇总，不按派工执行人过滤；派工不限制其他有部门权限的人报工。
- 有任务行：工单 `doneQty` 保持现列表语义（各任务工序良品最小值），`remainQty=max(0,qty-doneQty)`；看板与监控必须使用同一逻辑，取消跨工序简单求和。
- 新增明确的展示字段 `progressPercent`：取所有正计划工序 `doneQty/planQty` 的最小值，再限制在 0～100%。页面标「工序达成进度」，保留原始各工序数量；不得称为成品产出率或机器利用率。
- 零计划工序不参与百分比，显示「无需报工」；如存在负计划数等非法数据，按现有异常规范报告，不静默生成正常进度。没有正计划工序时百分比为空，显示「暂无有效计划」。
- 旧工单无任务行时，优先复用详情已有的工艺路线兜底（不落库）并逐工序汇总；路线也不存在时显示「无工序计划」、百分比为空，不拿跨工序总和伪造成品完成数。兼容字段需保留时明确标记不可用并检查消费者。
- 本期不修改工单状态机；手动结束但未报满，仍显示真实百分比。已取消默认排除。
- 对工单列表、旧看板、新监控及受共享逻辑影响的 H5 做回归；不改变原报工/复核/工资规则。

### 2.2 工序与异常

- 工序框显示工序名、良品/计划、执行人；状态区分未报工、已报未满、已报满。只有不良报工时也属于已报未满，不能显示未报工。
- 顺序箭头只展示工艺路线，不新增前后道报工约束。
- 工单层标「有待处理异常」，不把工单异常绑定到猜测的工序，不显示未经记录的严重等级、设备停机状态。
- 未派工待办计数单位为「道工序」：未开始/执行中工单、真实任务行、执行人为空、正计划数且尚未报满；虚拟旧任务不能直接派工。

### 2.3 筛选、计数和排序

- 工单主区域筛选：关键词（工单号/产品编号/产品名称）、工单状态、交期起止日期。无交期范围时包含未设交期；指定范围时排除未设交期。结束日期按次日零点前处理。
- 状态卡按关键词/交期筛选后的全集统计，但忽略当前状态筛选，保证点击状态卡可切换；卡片旁说明范围。临期/超期只算未开始和执行中，复用交期工具；状态卡不含已取消。
- 主列表和进度链采用同一分页数据，避免两份全量重复加载。默认未结束工单在前；未结束内部按超期优先、存在待处理异常优先、交期升序（空最后）、ID 兜底排序。
- 异常区和待办区明确标「当前权限范围，不随工单筛选」。异常包括未绑定工单的异常；数量为全集计数，明细最多 10 条并有查看全部入口。超期工单区随关键词/交期过滤，最多 10 条并显示总数。
- 待复核数遵守现有 ReviewService 的本组/管理员范围；无复核权限隐藏。未派工仅向现有派工授权角色提供。只读监控遵守已有工单查询权限。
- 不提供含糊的「今日工单」「报工完成率」，不添加没有模型支持的班次、产线等筛选。

## 3. 后端实现建议与接口契约

建议新增 `GET /api/ExecutionMonitor`，使用现有 ApiResult 包装。Controller 只负责参数、鉴权和调用；Service 做聚合。命名空间 `ahu.MicrosoftMes`。

参数：`keyword`、`status`、`dueFrom`、`dueTo`、`page`、`pageSize`。校验日期范围、状态及分页，限制 pageSize 上限（建议 100）。

返回至少包括：

- `generatedAt`：服务端生成时间。
- `summary`：未开始、执行中、已结束、临期、超期数量。
- `orders: {list,total}`：分页工单；含 ID、编号、产品、数量、完成/剩余、状态、交期状态、progressPercent、异常标记、工序数组（任务 ID、工序 ID、顺序、名称、计划、良品、不良、执行人、派工可用性）。
- `abnormals: {list,total}`：当前权限范围内待处理异常，含现有异常字段。
- `overdueOrders: {list,total}`：超期工单摘要。
- `todos`：有权限的待复核记录数、未派工工序数。无权限字段不返回敏感明细，不用伪造的 0 冒充实际计数。

最终字段可与现有规范一致，但必须同步 `docs/33-接口对接说明.md`，前后端一致。所有查询以登录 JWT 的工厂身份隔离，关联数据同样校验本厂；检查角色中间件白名单，不只隐藏按钮。

统计在数据库侧尽量完成；工序和报工批量查询，禁止逐工单 N+1 请求、加载全厂历史报工到内存再反复筛选。用小型共用计算/查询组件统一进度，不造通用报表平台。新增只读聚合接口不应扩大任何写权限。

## 5. 验证样例

| 场景 | 预期 |
|---|---|
| 100 件，三道计划均 100，良品 100/80/20 | 完成数 20，工序达成 20%；列表/看板/监控一致 |
| 工序计划 100/80，良品 100/80 | 工序达成 100%，原始数量保留，不用 80/工单数量误称工序达成 |
| 某工序待复核 30、通过 20、退回 10 | 现场良品 50；正式报表只入账 20 |
| 工序仅报不良品 | 已报未满，不是未报工 |
| 手动结束但工序未报满 | 状态已结束，进度仍为实际比例 |
| 计划为 0、全部无有效计划、无任务但有路线、无任务无路线 | 无除零，按第 2 节明确处理，不虚构 100% |
| 无交期、交期边界、已取消工单 | 按筛选与现有交期规则，不把已取消计入超期 |
| 关联工单异常、未关联异常、已恢复异常 | 仅待处理进入异常总数；未关联仍展示；不标具体故障工序 |
| 多页工单 | 卡片和总数取全集，分页不改变总数 |
| 不同工厂及管理员/班组长/工人 | 不串厂；班组长待复核不越组；写操作权限不扩大 |
| 请求失败、快速筛选、切页、离开监控页 | 旧响应不覆盖新筛选；错误可见；定时器无泄漏 |
