# 67 · 优化指令 —— 工资单撤回重算（Salary revoke）

> 归属：**已做指令**（后端已实现，见同编号执行指令）
> 对标依据：`docs/2G-对标分析-工资计算vs黑湖小工单.md`——本系统「确认即冻结、仅草稿可删、无撤回」把纠错路径堵死，违反 AGENTS.md「钱要可追溯可重算」红线。黑湖把工资当可重算的派生报表。
> 触发案例：66 执行时赵江陵工资单漏计「包装」，确认后无法 API 修正（19.60 定格）。
> 分工：多隆出指令与验收清单，Cursor 实现。

---

## 1. 目标

给已确认的工资单开一道「撤回 → 作废 → 重算」的门，让漏算/错算/复核延迟导致的错误工资可重来，且全程留痕、不破坏报工事实。

## 2. 现状与问题（事实）

- `salary_statement.status`：0草稿 / 1已确认 / 2已发放
- `DELETE /api/Salary/{id}` **仅草稿可删**；已确认单被拦「仅草稿可删除」，且无任何撤回接口
- 确认后 `prod_report.settled_flag=1`（冻结禁改/禁删），仅删**草稿**工资单时才回滚为 0（`docs/02` §说明）
- `salary_statement_item.report_id` **全局唯一**（一条报工最多结算一次）；`uk_statement_period` 唯一（同人+周期只能一张单）
- 因此：已确认工资单无法作废 → 漏算报工无法再归集，错误金额永久定格

## 3. 接口设计

新增：`POST /api/Salary/{id}/revoke`

### 语义：作废已确认工资单（撤回确认）
| 项 | 内容 |
|---|---|
| 方法/路径 | `POST /api/Salary/{id}/revoke` |
| 请求体 | 无 |
| 权限 | 仅管理员（role=1） |
| 前置条件 | 工资单 `status=1`（已确认） |

### 撤回动作（单事务，原子）
1. 校验存在且 `status=1`；否则报错 `仅已确认工资单可撤回`（人话：只有已确认的工资单才能撤回）
2. 删除该单全部 `salary_statement_item`（释放 `report_id` 唯一占用）
3. 删除 `salary_statement` 行（释放 `uk_statement_period`）
4. 将该单关联报工 `prod_report.settled_flag` 回滚为 0（解除冻结、可再结算）
5. 记录撤回留痕：操作人 + 时间 + 原工资单 id/金额（走现有日志/审计通道，不新增表）

> 撤回后：该工人该周期无工资单，重新 `POST /api/Salary/generate` 会全新归集该周期全部 `review_status=1 AND settled_flag=0` 的报工（含之前漏的），按工价快照重算金额。**赵江陵案例即可修复**（撤回 19.60 → 重算 22.00）。

## 4. 业务规则与边界

| 场景 | 行为 |
|---|---|
| status=0（草稿）调用 revoke | 报错；草稿应走既有 `DELETE` |
| status=2（已发放）调用 revoke | **禁止**，报错 `已发放工资单不可撤回`（发薪后财务纪律，本版不做） |
| status=1 正常撤回 | 作废并回滚，如上 §3 |
| 撤回后重复 generate | 因 period/明细已释放，正常新建，不冲突 |
| 并发撤回同一单 | 事务 + 状态校验，二次调用报错 |
| 报工事实 | 不改 good/defect/unit_price 等事实，只解 `settled_flag` |

## 5. 数据字典变更（`docs/02`）

在 `prod_report.settled_flag` 说明处追加回滚条件：
> 确认工资单时置 1；**删除草稿工资单、或撤回（revoke）已确认工资单**时回滚为 0。

## 6. 改动范围

- `SalaryService`：新增 `RevokeAsync(id)`（事务：删明细→删单→回滚 settled_flag→留痕）
- `SalaryController`：新增 `POST /api/Salary/{id}/revoke`（RoleGuard 仅 admin）
- 复用现有 `ThrowHelper.cs` 抛错（带上下文）
- **不改**：数据表结构、复核逻辑、工价快照口径、`generate` 计算逻辑

## 7. 验收清单

- [ ] 管理员 token：对已确认工资单 `POST /api/Salary/{id}/revoke` → `code=0`；`GET /api/Salary/{id}` 返回不存在（已作废）
- [ ] 关联报工 `settled_flag` 回滚为 0（`GET /api/Report` 可查）
- [ ] 重新 `generate` 同人同周期 → 新建工资单，**包含此前漏算的报工**，金额重算正确
- [ ] 回归场景（赵江陵）：撤回 19.60 → 重算 = **22.00**（含包装，组装驳回不计）
- [ ] 草稿单调用 revoke → 报错「仅已确认工资单可撤回」，数据不变
- [ ] 已发放单（status=2）调用 revoke → 报错「已发放工资单不可撤回」
- [ ] 非管理员调用 revoke → 403
- [ ] 撤销后确认操作：重新 generate → confirm 正常闭环，报工再次冻结

## 8. 不做

- 不做「已发放」工资单撤回（发薪后禁止，财务纪律）
- 不新增撤回日志表（用现有日志/审计；如后续要审计报表再单列）
- 不动复核、防超额、工价版本逻辑（本次只开撤单门）
