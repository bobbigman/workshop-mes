## 二、页面与字段落点

入口复用 `/operation-price-list`，基础资料菜单下，角色管理员且具有计件功能授权；“销售”不是新增角色或绕过权限依据。列表与详情在同一路由切换，保留查询/工序/状态/日期筛选、分页、浏览和复制。

列表至少显示：单据编号、名称、工序（界面可称价目表类型）、产品范围（产品编号+名称/通用表）、明细行数、状态、生效~失效、更新时间、编辑/复制/删除。必须能区分同工序不同产品的表。9张客户Excel工作表仅为演示数据范围，不写死为系统枚举或全厂工序上限。

单据头：编号、名称、工序、产品、生效/失效日期、状态只读显示、计价单位、报工单位、换算数量、备注。产品空选项显示“通用表（不限产品）”，不新增模板管理。新增/复制编号由用户填写并校验本厂唯一，保存后编号只读；不引入未定义的自动编号规则。工序下拉值绑定 operationId，不按名称充当ID。

- 每表一道工序、一套单位换算。计价单位/报工单位/换算数量必须可维护，不从“打”自动猜12或从行推断。
- 头备注新增 `remark`，不挪用名称或行note；实施时同步02完整DDL、EF及DTO，长度上限1000。
- 主操作：保存、启用（仅停用表显示）、停用（仅启用表显示）、退出；不放提交/审核、批量填充等占位按钮。
- 复制生成未保存草稿，清空编号、版本和启用锁定标记，带当前表头/明细，保留产品可改，不带历史引用及快照。
- 保存失败保留输入，重复提交防护，离开提示未保存内容；成功返回列表并展示服务端实际状态和版本。

## 三、保存、状态、锁定

保留“完整草稿保存即启用”的已定交互，不用状态下拉与之竞争。以下判定全部在服务端执行：

| 原状态/动作 | 结果 |
|---|---|
| 新增或草稿点保存，存在未确认/单价空行 | 存草稿，展示具体待补项；0元已确认行不算未定价 |
| 新增或草稿点保存，明细完整 | 通过全部启用校验后存启用；有冲突或其他错误则整次失败，不悄悄改草稿 |
| 启用表点保存 | 维持启用，必须通过全部启用校验；失败则原表不变，不能自动降草稿 |
| 启用表点停用 | 维持内容、改停用，已有工单快照不变 |
| 停用表点保存 | 维持停用，允许整理待定行，不自动重新启用 |
| 停用表点启用 | 通过全部启用校验后启用；否则保持停用并报具体原因 |

“待确认”以 confirmed=false 为主，单价null为未定价；旧note含“待确认”的数据也必须阻断启用并要求人工确认，不能仅删除文字即自动确认。无行可存草稿，不能启用。

首次成功启用后工序永久锁定；停用或改回不完整数据也不解锁。新增 `activated_at DATETIME2 NULL` 作为持久标记，DTO返回可编辑能力；服务端比较原值拦截绕过前端的请求。复制是新表，可选工序，但改工序后清空不适用条件/收费组并提示重新配置。已有启用及停用旧表保守视为已启用过，迁移时设置锁定标记并注明迁移时间不是实际历史启用时间。

所有保存/状态操作带expectedVersion；状态、版本、头体同事务更新，重叠检查保证并发下不能同时启用冲突表。不能只做一次无锁查询。SQL Server写操作在业务事务内先取得同厂sp_getapplock事务锁，再读表校验，避免不同编号插入的范围锁升级死锁；锁超时明确提示稍后重试。

## 四、单据体和条件编辑器

主表7个业务列：**行号 / 品名规格 / 取价条件 / 属性区间 / 单价 / 单位 / 收费组**。原型“数量范围”改为“属性区间”，仅摘要当前数字属性条件；不引入订单数量阶梯、不另存第二套区间。“单位”只读继承表头。

- 品名规格写入行 `label`（可空，上限256），仅展示，不参与匹配；新增强类型JSON字段须回写405/02，不能覆盖note。
- 行号是显示顺序，rowId是稳定标识；新增/复制重新生成，插入/排序不改原rowId。
- 点击行号/品名规格打开行详情，维护 kind（基础/附加/最终）、deductPrice（基础/最终）、includedRowIds（基础/最终）、confirmed、source和note；必须有可见入口，不能因主表省列丢掉这些能力。行详情保留备注原文供确认，主表不单列备注。
- 收费组保留独立可折叠维护区：稳定key、名称、适用条件、required。附加行必须选择有效组；删除被引用组/行先阻断并列引用，不默默清空。非附加行不能带groupKey，附加行不带扣价/包含项。
- “新增行 ▾”内联展开新增/插入，点击子项后收起。新增尾部追加未确认、amount=null行；插入到选中行前，无选中则末尾追加。删除选中行可删到空表（只能草稿），被当前包含项引用则阻断；修改现行表不改历史报价。
- 原始分档价说明保留note，不转成未经确认的自动规则；不得把显示文字当成主键或计算公式。

条件编辑器字段只列本厂产品固有字段及**当前工序**工艺字段，隐藏非取价全局外观字段；不建“工艺动作”条件字段，动作由工序选择表达。

首版仅 `eq/range`：单选用eq、数字用eq或区间；界面 <、≤、>、≥ 转为range单边界并设置开闭，不发送新运算符。各条件AND；空条件须由用户显式选“不限”。不提供“属于{27,30}”多值集合，本次不扩展in/OR。需要不连续档位时分别建互不重叠规则；互斥组同一行覆盖多个选项的能力另行定义，不能偷偷拆成可能重复收费的OR。

数字值按404校验，范围不得上下界全空、反向或为空区间；整数和小数按字段约束处理。条件弹窗取消不修改原行，保存后回写强类型conditions并生成摘要，不解析摘要反建条件。

## 五、字段归属及工单最小依赖

统一409：产品8个固有字段；工艺属性存工单对应工序；颜色等全局外观不参与取价。404旧 `workorder` 表述不作为新增target依据，现有工单全局target实际为 `work_order`。

实施采用最小归属契约：

- 产品定义仍 `target=product`；工序工艺字段新增 `target=work_order_task`，定义带所属 operationId（本厂且必填），值的targetId绑定本厂任务ID；全局外观仍 `work_order`。同一工艺可在不同工序定义不同稳定字段ID，field_key按本厂+target+operationId唯一，跨环境解析必须带归属工序，不能只按名称查找。
- 不使用 `target=operation` 存每单工艺值；不把taskId冒充orderId。实施前在02写完整字段/约束DDL及兼容方案，再实现实体/DTO；不得只加前端输入框。
- PC建单/复制按工序录入 `operationAttributes`（operationId -> 字段ID -> 字符串/null），工序不得重复；服务端验证在本单产品路线内、本厂、字段所属工序正确。创建中尚无taskId时先验证输入，随后与任务、属性和锁价同事务保存。
- 有效属性仅产品固有值＋当前工序工艺值，不允许工艺输入覆盖固有值。固有关键属性缺失要求补产品，不再借工单全局属性兜底。未填null不等于0/否/免费；必需规则所缺字段明确报错，无关字段不阻断。
- 新复制工单带工艺输入但重新试算锁价；数量/交期编辑保留原快照。属性模式已锁价工单首版禁止直接改工艺值（即使无报工），需新建/复制工单；改产品沿用既有无报工重建规则并清理不适用工艺值。有报工禁止改产品，历史金额不重算。

## 六、表级取价及接口

仅本厂、当前工序、status=1且业务日落在含首尾的生效期内的表参与候选。先按表头productId找该产品专属表：唯一则只在该表匹配，缺属性/缺规格直接报错，不回通用；无有效专属表才找productId=null通用表，再无则缺价。停用、草稿、未到期、已过期专属表不阻断有效通用表。

同厂同工序同productId（null作为同一通用范围）的启用表日期不得重叠；不同产品专属表可并存，专属表与通用表可并存。选中表内基础/最终价必须唯一，收费组、包含项及单位金额规则沿405；缺价必须列产品编号、工序、表编号、具体缺失字段/未匹配条件，金额不当0。

补齐现有 `/api/operation-price-list`，不新建另一套路由：

- GET列表/详情返回表头productId、remark、activatedAt及强类型details；POST/PUT输入表头productId、remark、expectedVersion及details，行不再接收productId。服务端生成实际状态、版本和锁定结果，保存后读取真实结果，不由前端猜。
- `POST /{id}/status`：目标状态只接受启用/停用及expectedVersion，按第三节校验；禁止普通PUT绕过状态转换。
- `DELETE /{id}`：带expectedVersion，仅未启用过且无业务引用的草稿可删；其他表提示停用。产品删除检查表头productId及计价映射，工序/单位/字段/选项删除检查现行表全部引用，历史快照保留。
- 复制复用前端取详情生成新草稿即可，不为已有功能重复建设copy接口。
- `/preview` 新增可选operationAttributes（当前operationId的字段值）、workOrderId（已有单据上下文）及expectedVersion。已有单据从服务端读取并校验产品/工序/厂，不接受输入覆盖已有锁价；新单预览校验工艺输入，返回属性指纹、候选表版本、逐行结果及原因。正式建单重新从服务端计算并校验指纹/版本，变化则提示重预览，不采用客户端成交金额。
- **价目表维护允许输入规则单价amount/deductPrice；禁止客户端指定的是工单成交价、报工结算金额。** 两者不可混淆。

管理员角色、计件授权、JWT厂隔离、字段/产品/工序/单位所属厂、expectedVersion、错误上下文均在服务端检查；不因演示放宽。
