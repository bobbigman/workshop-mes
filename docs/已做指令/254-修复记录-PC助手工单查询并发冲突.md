日期：2026-10-20。状态：代码已修复并通过独立 SQL Server 回归断言；未部署、未重启运行中的后台。

## 根因

`backend/logs/mes-error-20261020.log` 在 08:59 UTC（北京时间 16:59）的同一轮请求中多次记录 `search_work_orders` 异常：`A second operation was started on this context instance before a previous operation completed`。堆栈定位到 `AiToolDispatcher.QueryWorkOrdersForAiAsync` 的 `Task.WhenAll` 和 `WorkOrderService.GetAsync`。

列表查询本身完成后，为补齐进度，代码并行读取本页多张工单详情。相关服务共用请求范围的 EF Core DbContext，不能同时执行多个数据库操作。因此逾期、未完成乃至无筛选查询只要命中多张工单，都可能失败。助手只收到统一的“工具执行失败”，无法识别该代码故障，改变筛选条件没有解决作用。这不是无数据或用户权限不足的证据。

## 修复和验收

- 按页内顺序逐张 await 读取进度，复用原有完成量口径与工厂身份，不改变查询条件、排序、分页、接口或表结构。
- 每张详情读取前检查取消；失败时明确提示工单号，不再保留默认零完成量冒充已读取。
- 增加真实 SQL Server 独立测试库回归：多工单列表必须成功，完成量 80、剩余量 20 与零进度工单保持正确，且不能混入其他工厂的工单。
