## 本次范围与落点

- 交付：一条完整流程【进 MCP 页 → 点「生成报文」（已有钥匙先确认）→ 弹窗显示完整报文 → 整段复制 → 发给对接人 → 按客户端支持的格式配置】
- 已有（代码证据）：`frontend/src/views/mcp-key/index.vue`（现生成钥匙页）；`backend/Services/McpKeyService.cs`（CreateAsync 生成 32 位 token，库存哈希、明文只返回一次）；`backend/Controllers/McpKeyController.cs`（RoleGuard 管理员）；`McpTokenMiddleware.cs`（钥匙鉴权，本次**不改**）；日志已记 `factory/alias/keyId`，不落明文。
- 缺口已核实（2026-10-07 对照代码定死）：
  - **当前厂取法**：管理员 JWT 带 `FactoryId`（`JwtHelper.GetFactoryId(User)`，与其它管理接口一致）。**当** JWT 有有效厂 → 用该厂；**禁止**再从前端传 `factoryId`。不读 `Mcp:FactoryId`（那是万能钥匙/演示中间件用的）。
  - **MCP 地址来源**：报文地址**不得写死**。**当** `Mcp:Url`（appsettings）非空 → 用其值；**否则**用当前 HTTP 请求的 `Scheme://Host` 拼 `/mcp`。docs/101 样例地址仅文档演示，不进代码。

- 数据与契约：`sys_mcp_key` 表结构不改；同步 Controller + `frontend/src/api/mcpKey.js` + 页面。
- 文档：改行为 → 同步 docs/101 与 SupportDocs/09 的「管理员发钥匙」段落（由选厂生成改成一键生成完整报文）；docs/02 无 DDL 变更则不改。
- 轻重看依赖：只改 1 个页面 + 1 个后端方法入参（契约），不动鉴权中间件、不动 7 个 MCP 工具——**属轻量优化**，但涉及改接口契约，故走指令。

## 行为与口径（分叉写成显式条件，禁止执行方脑补）

- 当管理员进入 MCP 页 → 界面**不显示**：工厂下拉、别名输入框、备注输入框、列表的"工厂/别名/备注"列。只显示：「生成报文」主按钮 + 钥匙列表（状态 / 有效期 / 创建时间 / 操作=吊销）。
- 当点击「生成报文」并完成必要的替换确认 → 后端生成 token（沿用 GenerateKey(32)），弹窗显示**完整 JSON 连接报文**（`{}` 格式，客户端支持此格式时可整段导入），格式示例（以实际账套/地址为准）：
  ```json
  {
    "mcpServers": {
      "太阳神厨具五金厂 (CJ001)": {
        "type": "streamable-http",
        "url": "https://103.39.222.133:11302/mcp",
        "headers": {
          "Authorization": "Bearer <新生成的token>"
        }
      }
    }
  }
  ```
  整段一键复制；明文 **token** 只显示一次，关闭弹窗时清空 `created`（不只隐藏弹窗）。弹窗提示"请立即复制发给客户，关闭后不再显示"。`connectionText` 使用 JSON 序列化生成（正确转义账套名、地址），返回整段 JSON（含 `url`/账套名/Bearer），非分行文本。客户端支持导入此格式时可整段粘贴；WorkBuddy/扣子/豆包兼容性分别联调，未验证前不承诺全部通用。
- 当列表存在本厂有效钥匙（status=1）→ 点「生成报文」先提示"继续生成将使旧连接失效，客户需改用新报文"；取消则不请求生成，确认后替换；首次生成无需确认。后端在事务内对本厂加 SQL Server 更新锁，再读取旧钥匙并吊销、生成新钥匙；保存和提交成功才返回明文，失败回滚，旧钥匙仍有效。同厂并发请求串行处理，后生成的钥匙替换前一把。
- 当点击「吊销」→ 确认框提示"吊销后客户立即连不上"，确认后 status=0；列表该行状态变"已吊销"。
- 当复制 → 整段报文复制；复制失败给手动选中提示。
- 日志仍记录 `factory/alias/keyId`，**不落明文 token**（现状已满足，确认不回归）。
