## 本次范围与落点

- 调整ReportIdentityDirectory/Service/Tickets；`identify_report_worker`增可选factorySelectionToken、factoryNumber，不接模型任填厂ID。仅完整手机号匹配多厂后返回候选厂名与短期选择凭证，不展示他人手机号/账号/员工ID。
- 多厂选择凭证10分钟、单次使用，绑定入口MCP上下文；快照只包含实际匹配结果，错误/越界/过期/跨入口拒绝。厂内同手机号有多个账号不能随便选员工，提示管理员核对。
- 登录定位票据保存目标厂与入口厂；网页登录须该目标厂本人JWT+密码。验证码兑换后报工始终按短期授权的目标厂执行，不能再用入口厂覆盖；凭证不能挪到另一入口MCP厂使用。
- 不改表，不改报工部门、数量、前道校验；其他MCP查询及原平台身份模式仍按钥匙定厂。更新PRD、人设和说明，重新生成可粘贴人设。

## 行为与口径

- 当姓名唯一 → 回显真实员工姓名和工厂，发验证链接；多项/零项 → 问后6位；6位未唯一 → 问完整手机号；完整号零命中 → 请管理员核对。
- 当完整手机号命中多个工厂 → 只列这些实际工厂，问“您在哪个工厂报工”；名字由数据库取，不凭聊天记忆写两个固定选项。用户选序号后才生成目标厂验证链接。
- 当完整号只对应一个厂但该厂重号多账号 → 不自动挑员工，联系管理员；当工厂名称重复 → 显示数据库工厂代码辅助区分，不用厂ID作为语音选择项。
- 当选择过期/已用/越界/来自另一个入口或账号失效 → 明确拒绝并重新定位；没有授权目标厂凭证时不能查询该厂任务或提交。
- 当授权目标厂与入口厂不同 → 只在该有效登录凭证范围内查询/报工；其他工具不自动扩权，不改变全局MCP上下文。

## 止步线

不按输入姓名/手机号直接入账、不硬编码工厂、不枚举无关员工信息、不跨其他数据库/服务器搜索、不修改所有MCP工具的厂权限、不测试写入报工。
