用户定稿模板（缺属性类统一对齐）：

```text
产品「{产品编号}」缺少属性「{属性名}」，无法按价目表算工价。
请到「产品定义」补全后再选该产品。
```

数字非法类对齐同一骨架，第二句可略改为检查该属性是否填了合法数字。

## 2. 完整流程与范围

入口：PC `#/order` 选产品 / 保存或预览取价 → `PriceTimelineService` → `SelectTable` / `Calculate` / `Matches`。  
落点：`backend/Services/OperationPriceListService.cs`（及为带出编号/名称所需的调用方传参，如 `PreviewAsync`、`PriceTimelineService`）。  
不改：HTTP 路径、DTO、价目匹配算法、锁价金额。

实现约束（执行方可选最小改法）：

- 提示里的产品标识用 `base_product.code`，不用数字 `productId`；工序用工序**名称**（或「编号+名称」若名称易重），不用裸 `operationId`。
- `Matches` / `Calculate` / `SelectTable` 今日签名若只有 id：允许增加 `productCode`、`operationName`（或等价展示上下文字符串）参数，由已有产品/工序查询处传入；调用链补齐即可。
- 条件运算符对用户显示：`eq`→「等于」、`range`→「在…～…」（含开闭可用「含/不含」极简，不必复述 IncludeMin 技术细节）。
- 缺属性两处文案（`RequiredFieldIds` 与 `Matches` 空值）**合并为同一用户可见句式**，避免两套说法。
