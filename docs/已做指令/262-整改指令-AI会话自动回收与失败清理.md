# 262-AI会话自动回收与失败清理

> 状态：已做；2026-10-20 用户授权按建议整改。编译及18项针对性测试通过；不部署、不重启现有服务，运行现场待更新后验收。

## 范围与取舍

- 现状：前端刷新丢失会话编号，首次请求失败也会留下后端会话，达到每用户3个时阻塞提问，页面没有能力清理这些旧会话。
- 保留内存缓存容量保护：MaxSessionsPerUser（默认3）和MaxSessions（默认100）作为缓存容量；满额时自动回收范围内最久未使用且未在生成的会话，再创建新会话，不要求用户清理。
- 先按工厂+用户回收，再按全局容量回收；回收不迁移或复用旧会话内容。仅当容量全部被正在生成的请求占用时，提示正在处理、稍后重试。并发保护独立于闲置会话数量：同一会话不并发生成，同一用户正在生成的会话数不超过其容量；全局在处理请求不超过总容量。
- 新请求创建与占用生成状态原子完成，取旧会话后开始生成也要核实仍在缓存，避免回收与发问竞争；空闲过期不清除正在生成的会话，完成时更新空闲计时。
- 首次请求异常或取消、没有成功返回可用结果时删除新会话；已返回真实证据的降级回答属于有效结果，保留会话。已有会话后续请求失败仍保留先前上下文，原异常照常抛出。
- 已过期/已回收会话仍返回明确提示：上下文已过期或被回收，请点击“新对话”重新开始；不自动重放问题或拿别人的上下文续聊。复用现有新对话按钮，不增加历史会话管理界面。
- 不改数据库、身份授权、工具权限、角色题目、模型配置，不修改本地部署配置。

## 验收

- [x] 超过用户/全局缓存容量后仍可创建新会话，最久闲置会话被回收，正在处理的会话不被回收。
- [x] 过期清理避开正在处理的会话；生成结束后从结束时间计算空闲期。
- [x] 只有全部容量被生成请求占用才拒绝；释放后可继续；跨工厂/用户访问仍拒绝。
- [x] 新会话首次失败、超时或取消不遗留；有效回答/证据降级回答保留；旧会话失败仍可继续。
- [x] 并发创建/开始生成不突破容量、不使用已回收上下文；错误不吞。
