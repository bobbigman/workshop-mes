# 执行指令：MCP 口径与知识库检索加固

> 状态：**已完成（B 方案 + P0 人设 + P1-1 描述）**
> 完成日期：2026-09-24
> 依据：微信 clawbot 与用户关于「工资能不能算」答错偏差的复盘；`docs/45`、`docs/47`、`backend/Mcp/SupportDocsMcpTools.cs`、`backend/Mcp/SalaryMcpTools.cs`、`backend/Services/SupportDocumentService.cs`
> 目标：消除 AI「拿工具清单当功能全集、查不到就脑补」的偏差，让 AI 只当手册翻译器。

---

## 1. 根因（一句话）

扣子把「MCP 工具清单」当成「系统功能全集」，又赶上检索不稳/截断，就顺着残章脑补。工资功能系统内已有（工价表在电脑端维护、系统自己算），但 MCP 只暴露 `query_salary` 查工资单，没有维护工价/生成工资单的工具，于是被误判成「工资来自金蝶、系统算不了」。

---

## 2. 本次已做

### B 方案 · 摘录加长 + 截断提示（根治「截断逼脑补」）

`backend/Services/SupportDocumentService.cs`：

- `ExcerptMaxChars` 300 → **800**（单条来源最长摘录，减少从头截 300 字逼模型续写）。
- 命中较多截断时，`message` 增加一句「检索命中较多，正文已截断；如需完整内容，可缩小问题或追问具体章节。」

`MaxEvidenceChars=12000` 已够放 5 条 800 字摘录，配置未动。无表变更、无新依赖、MCP 返回结构未变。

### P0 · 人设三条（`docs/45` 第 1 节，人设主副本）

1. **能力判断强制查手册**：问「系统能不能 / 有没有某功能 / 能不能算 X」必须先调 `search_support_docs`，禁止用自身知识推断；查不到就答「手册未收录」。
2. **工资两个口径**：工资由系统自己算（工价表在电脑端维护），**不是来自金蝶**；金蝶账号只是演示期登录验证。
3. **功能口径 vs 操作口径**：系统有没有某功能看手册；AI 能替你操作什么看工具列表——两个分开。

### P1-1 · `query_salary` 描述澄清来源

`backend/Mcp/SalaryMcpTools.cs` Description 补「工资由系统计算（工价表在系统内维护，非来自金蝶），本工具只读查询」。
