# 426-开发指令：PC内置AI与MCP多账套隔离加固

> 状态：已实现待现场验证；A/B段代码完成，隔离测试通过，未部署。
> 日期：2026-10-30。性质：真实业务权限边界加固，测试使用独立测试数据。
> 本轮交付：代码、验证及文档；逐项执行，不部署或操作真实业务数据。
> 后续实施终点：代码、针对性验证、必要文档；不含部署、配置换钥匙、真实报工或工资调整。
> 目标：当前用户在PC内置AI查询时，服务端锁定本人、本厂及当前权限；外部MCP按有效钥匙定厂，特殊跨厂能力不扩散到普通查询。
> 依据：本次多账套讨论、只读核查、AGENTS.md、01 PRD、419指令模板。实施前重新核对工作区现状，不覆盖其他未提交改动。

### A/B段边界

- **A段：已有权限边界的加固。** PC当前身份复核、前端身份切换、MCP实际厂授权校验、厂列表收口、关联查询补防线、错误输入拒绝，以及特殊入口回归。
- **B段：外部MCP查询身份契约升级。** 无可信平台身份时如何验证本人、旧绑定是否继续有效、演示免绑定如何退出真实业务。改变现有交互，必须先确认；不能因A段通过就宣称整个MCP已安全。

## 2. 完整流程与范围

### 2.1 PC内置AI

当前登录 → 每次业务请求核验账号有效、归属当前厂且有权限 → 创建/读取本人本厂会话 → 执行模式白名单工具 → 查询本厂对象及关联 → 结果回到发起身份对应的页面。

- PC业务AI维持管理员范围；H5操作帮助维持原有效角色及仅手册范围，不新增H5业务聊天。
- messages、work-orders/search、report-evidence/search、会话删除及AI连接测试/状态接口按实际职责核验身份；连接测试仍仅管理员，不能因只读就向普通账号开放。
- 外部MCP钥匙管理接口同样复核当前有效管理员，防止停用或降权后的旧JWT继续生成/吊销钥匙。
- 不新增AI写入工具，不增加跨厂汇总；不改变工资计算口径、报工部门权限和删除依赖规则。

### 2.2 外部MCP A段

总开关检查 → 验钥匙 → 核验实际厂存在且可用于业务 → 写本请求上下文 → 按实际厂检查功能授权 → 原用户权限检查 → 业务执行。

`/mcp-auth`按有效配对码确定实际厂后校验；不能把`/mcp`的钥匙检查机械套到授权网页。实施前核对McpAuthController全部路由及匿名页面，确保静态授权页仍可打开，生成/兑换等业务操作按真实配对厂授权。

不改实例维护的跨厂语义；不临时关闭已有聊天报工入口。特殊报工凭证只授予原报工流程，不授予普通工单/工资查询权限。

### 2.3 直接落点

- 后端：Controllers/AiAssistantController、McpKeyController、McpAuthController；Services/AiAssistantService、AiToolDispatcher、AiSessionStore、McpKeyService、KnowledgeService、AiReportEvidenceService；Common/InstanceMiddleware；Mcp/McpTokenMiddleware；Program中间件顺序。
- 回归：WorkerHelpService、ReportIdentityService、WecomReportMcpTools、MaintenanceSqlMcpTools及相关业务服务。
- 前端：views/ai-assistant/index.vue、api/aiAssistant.js、实际登录/退出流程、PC布局与composables/usePcTabs。只处理本需求涉及的身份边界，不重写整个页签系统。
- B段落点：McpWxBindService、McpDataAccess、WxBindMcpTools及全部使用绑定身份的查询工具；确认方案后补契约再实施。

## 3. 业务决策表

检查顺序：认证 → 当前用户/工厂 → 功能权限 → 会话归属 → 对象范围 → 执行。技术失败不按空结果或认证成功处理。

| 分支 | 条件 | 返回/用户行为 | 写入范围与后续状态 | 验证 |
|---|---|---|---|---|
| B01 | JWT缺失、无效、过期 | 按现有认证契约拒绝，不调用模型或业务工具 | 不创建会话、不改业务数据 | V01 |
| B02 | 用户不存在、停用、不属于JWT工厂；工厂不存在或已清理不可用 | 明确要求重新登录/联系管理员；不沿旧JWT角色继续执行 | 拒绝；相关旧会话不能再被该身份读取 | V02 |
| B03 | PC业务AI/钥匙管理请求的当前角色不是管理员 | 403；H5帮助保留自身校验与范围 | 不调用业务工具、不变更钥匙 | V03 |
| B04 | 会话属于其他厂或其他人，或模式不一致 | 拒绝；不返回会话存在与内容细节 | 不改原会话 | V04 |
| B05 | 模型指定身份/厂别/SQL，或调用模式外工具 | 明确拒绝，不因提示词放行 | 无业务写入 | V05 |
| B06 | 输入其他厂记录ID/编号，或对象不存在 | 统一“未找到或无权访问”；不查询另一厂解释原因 | 无业务写入 | V06 |
| B07 | 主对象合法，但关联指向其他厂/失效对象 | 明确数据关联异常并拒绝相关结果；不拼接他厂名称、工艺或附件 | 不自动修复、不迁移关联 | V07 |
| B08 | 同页/其他浏览器标签退出、换账号或换厂 | 立即清空旧消息、候选、分页证据和会话ID，取消可取消请求 | 页面回到新会话或登录入口 | V08 |
| B09 | B08后旧请求返回，或页面关闭/缓存恢复后返回旧结果 | 丢弃，不写新页面；旧请求finally也不能覆盖新请求状态 | 新身份状态保持不变 | V09 |
| B10 | MCP无钥匙、钥匙无效/过期/吊销，或解析无合法厂 | 401；合法钥匙指向不存在/不可用厂时明确拒绝 | 不进入业务工具，无默认厂回退 | V10 |
| B11 | 请求包含账套标签，但空白、非正整数、多值歧义或各处不一致，或与钥匙厂不符 | 格式错误按400，不匹配按403；不只检查第一个标签 | 不修改上下文指向其他厂 | V11 |
| B12 | 钥匙合法，但实际厂无MCP功能授权 | 按现有授权错误契约拒绝；配置厂是否有授权不影响结论 | 无业务写入 | V12 |
| B13 | 本厂有效管理员查MCP钥匙工厂选项 | 原结构返回当前厂一项；不存在不得返回全实例列表 | 不变更钥匙；生成/吊销继续限当前厂 | V13 |
| B14 | 有246有效跨厂报工授权 | 原候选/预览/确认按已验证目标厂；入口厂绑定仍校验 | 仅原报工流程，其他查询不扩权 | V14 |
| B15 | 普通钥匙/演示免绑定请求维护SQL；或PC模型调用维护工具 | 没有独立维护权限则拒绝；PC白名单始终不包含维护工具 | 无SQL执行；合法维护权限保留原415流程 | V15 |
| B16 | 数据库/模型/身份校验技术失败、用户请求取消 | 按现有异常上下文和脱敏规则返回，不能降级为通过或无数据 | 释放会话忙碌状态；不自动重试写操作 | V16 |

## 4. 数据与接口契约

### 不变量

- I01：PC身份仅来自已验证JWT和数据库当前用户，模型/浏览器传厂号不构成授权。
- I02：普通MCP厂别仅来自有效钥匙；配置钥匙也只对应配置厂；未知厂禁止兜底到1。
- I03：当前用户有效且归属一致；敏感工具执行前再核对当前权限，不能只在创建对话时校验。
- I04：所有会话内容、分页、候选和返回结果受用户＋工厂约束；页面缓存不能越过身份切换。
- I05：主对象及有厂归属的关联对象同厂；没有FactoryId的中间表经其父对象校验，不凭空增加字段。
- I06：246特殊报工和415维护权限保持独立；厂钥匙不是管理员身份，报工授权不是查询授权。
- I07：本次不改变工资事实、历史快照、金额、业务权限角色及三条业务硬规则。

### 接口与兼容性

| 接口/对象 | 本次契约 |
|---|---|
| `/api/ai-assistant/*` | 路径及成功结构不变，身份从JWT取得；增加当前账号/归属/角色核验。普通账号用既有worker-help入口 |
| `GET /api/McpKey/factories` | 返回结构保持列表，内容收口为JWT当前厂；跟踪前端调用，去掉暗示可管理任意厂的逻辑，不新增账套管理选择器 |
| `/api/McpKey`及吊销 | 现有当前厂约束保留，补当前有效管理员检查，不允许传厂号替代JWT |
| `/mcp` | 工具名/业务参数原则上不变；实际厂授权检查移至定厂之后；全部factoryid/X-Factory-Id/query标签统一核对 |
| `/mcp-auth`相关路由 | 以服务端配对码对应厂作业务授权依据；不新增默认厂回退；实施时逐路由确认并同步接口说明 |
| 日志 | 记录追踪号、入口、用户、实际厂、工具和拒绝类别；不记录Token、维护钥匙、验证码或完整聊天凭证 |
| 数据表 | 默认不改表；若确需改表，先核对02权威DDL、补充本指令和SQL Server迁移，不能为身份校验预建框架 |

账号角色改变时，以数据库当前权限为准。已发出的外部模型请求无法收回；发现身份失效后，后续工具调用和结果返回应再次阻断。不给“停用瞬间必定终止所有已在执行的SQL”作无依据保证。

只读业务服务可能包含既有进度状态纠偏，不能未经核实承诺绝无写库；实施先查清并记录。未授权/跨厂拒绝必须发生在这些调用之前，原有纠偏如保留只能影响当前厂。

## 5. 并发、缓存与失败恢复

- PC页面保存请求发起时的身份标记及本轮请求序号；返回时核对身份和序号，再应用消息/分页/错误/加载状态。前端身份标记只防显示串用，不替代服务端认证。
- 同标签身份变化由已有登录/退出状态机制通知；跨标签监听实际认证存储变化；同时覆盖页面重新激活和发送/返回检查，不能只监听storage事件。
- 页签仅在隐藏但身份未变时可保留当前会话；换身份必须清除对应缓存。关闭页签、卸载清理监听器及请求；恢复时重新核对身份。
- 服务端继续复用AiSessionStore的本人本厂归属和并发保护，不引入共享全局CurrentFactoryId；验证失败不得留下永久Busy状态。
- 本次新增校验不要求跨请求长事务，不引入队列。业务查询不额外写授权快照；绑定和报工沿原事务与幂等规则，不能在加固中重复提交。
- 钥匙吊销在后续请求重新验证时生效；执行中的请求不宣称强制中断。数据库校验失败必须失败关闭，不能使用旧缓存放行。
- 测试不清理、不迁移、不更新生产资料；若独立测试库需种数据，采用独立命名并记录范围，不复用真实个人凭证。

## 6. B段已确认项：外部查询本人验证

**实施方向（2026-10-30用户已确认）：** 正式业务查询不再以手机号直绑或模型传入sessionId授予账号权限；有可信平台身份时走经过核验的绑定，无可信身份时通过现有网页登录能力生成独立、短期、限定查询权限的凭证。凭证绑定入口厂和本人，不复用或扩权246报工凭证。

用户已确认的业务结果（见第10节落地契约）：

1. 旧手机号直绑记录不能单独继续查询，用户首次需要重新验证本人；不批量删除历史绑定。
2. 无可信平台身份的客户端采用上述“网页登录验证后查询”流程；不宣称已核实真实平台自动认人。
3. 正式业务入口不允许DemoSkipAuth绕过个人权限；演示使用独立模拟实例/测试数据，不凭环境名称放行。

已按第10节补充凭证、接口、有效期、防重放、撤销和兼容契约后实施，测试结果见第11节。
