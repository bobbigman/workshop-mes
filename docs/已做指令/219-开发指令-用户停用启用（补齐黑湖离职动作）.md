## 行为与口径（分叉写成显式条件）

- 当管理员在用户列表点"停用"→ 弹二次确认："停用后该用户将不能登录、不能报工、不能被派工；历史报工与工资单保留。确定停用 XX？"→ 确认后 `Status=0` → 列表状态列变灰、按钮变"启用"。
- 当管理员对已停用用户点"启用"→ `Status=1` → 状态列变绿、按钮变"停用"。
- 当操作对象是当前登录人（用 `JwtHelper.GetUserId(User)` 比对）→ 后端直接报错"不能停用自己"；前端按钮置灰。
- 当操作对象是本厂 `Role=1` 且本厂已启用 Role=1 用户仅剩这一人 → 后端报错"最后一个管理员不可停用"，防止锁死系统。
- 当用户已被停用 → 已签发的 JWT 不主动作废，等其自然过期；账号密码登录、个人扫码登录、选厂接口本就实时查 `Status==1`，立即拦截。
- 当用户已被停用 → 历史报工记录、工资单、看板统计、报表查询、工价汇总**数字完全不变**；不因 Status 改变任何历史口径。
- 停用/启用接口幂等：对已是目标状态的账号重复调用，直接返回成功，不报错。

## 止步线

- 不做"离职"概念：不加离职日期、离职原因、离职审批、交接人字段。
- 不做 JWT 强制下线 / Redis 黑名单 / token 版本号。
- 不做批量停用/导出未启用清单。
- 不做 H5/Vant 端停用入口。
- 不新增"停用备注"字段。
- 不动"删除"按钮原逻辑（删除仍由 DeleteGuard 把关）。
- 不改 UserCreateDto，编辑弹窗里不暴露 Status 开关。
