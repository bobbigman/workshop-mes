## 1. 做（范围，演示最小版）

### A. 数据：一列搞定，不建表

- `prod_work_order_operation` 加 `assignee_user_id BIGINT NULL`（执行人；空=未派工）。
- 复用优于新建（AGENTS 简洁优先）：**一张工单工序只派一人**，一列够用，不建派工表。

```sql
IF COL_LENGTH('prod_work_order_operation', 'assignee_user_id') IS NULL
  ALTER TABLE prod_work_order_operation ADD assignee_user_id BIGINT NULL;
```

- 实体 `ProdWorkOrderOperation` 加 `AssigneeUserId`；`AppDbContext` 映射列名。
- 同步 `docs/02-数据字典.md`（`prod_work_order_operation` 加 `assignee_user_id`）。

### B. 后端

- 新建 `Services/AssignService.cs` + `Controllers/AssignController.cs`（命名空间 `ahu.MicrosoftMes`）。
- 接口（RESTful，前缀 `/api`）：

| 方法 | 路由 | 说明 |
|---|---|---|
| GET | `/api/Assign/my-tasks` | 当前工人（role=2/3）的任务列表：工单号、产品、工序、计划数、已报、交期、工单状态；按工单创建时间倒序 |
| PUT | `/api/Assign/{taskId}` | body `{ userId: number \| null }`；派工/改派/取消（null=取消）；校验 taskId 属于本厂工单、userId 属于本厂 |

- `WorkOrderDetailDto.Tasks` 的 `WorkOrderTaskDto` 加 `AssigneeUserId` / `AssigneeName`，`LoadTasksAsync` 填充（join `SysUser`）。
- `DeleteGuard`：删用户前检查是否被派工引用（`prod_work_order_operation.assignee_user_id`），命中则提示「先在工单详情取消派工」——**已加**（成本低，避免悬空引用）。

### C. 权限（RoleGuardMiddleware）

- 派工 `PUT /api/Assign/{taskId}`：role∈{1,3} 白名单。
- `GET /api/Assign/my-tasks`：role∈{2,3} 白名单（班组长也能看自己被派的任务）。
- role=2 调派工接口 → 403。

### D. 前端

#### D1. PC 派工（`frontend/src/views/order/` 工单详情）

- 工单详情页工序列表（`Tasks`）每行加「执行人」下拉：选本厂生产人员（role=2 为主，可含 role=3）；选空=取消派工。
- 选人后调 `PUT /api/Assign/{taskId}`，成功刷新详情。
- API 封装：`frontend/src/api/assign.js`（`myTasks` / `assign`）。

#### D2. 工人端「我的任务」（H5）

- 新增 `frontend/src/views/h5/tasks.vue`：卡片列出派给我的任务（工单号、产品、工序、剩余量、交期），点卡片跳 `/h5/report?order=工单号` 去报工。
- TabBar（`frontend/src/views/h5/TabBar.vue`）加「任务」tab（`/h5/tasks`），放在「工单」右侧。
- 路由（`frontend/src/router/index.js`）加 `/h5/tasks`。
