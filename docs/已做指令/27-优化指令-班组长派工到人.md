# 优化指令：班组长派工到人 + 任务提醒

> 状态：**待做（未开始）**  
> 依据：`docs/16` 第三期；`docs/1D` 纠偏 1（派工，🟢）；UC-13 班组长派工  
> 目标：班组长把工单各工序任务派给具体工人；派工后工人端收到任务提醒；急单可调优先级并推送  
> 前置：`docs/22`（班组长角色 role=3 + 复核双轨）已完成  
> 原则：瘦身版。先跑通「派工到人 + 工人能看见自己的任务」，不急着接企业微信实时推送。

---

## 1. 功能定位

| 项 | 内容 |
|---|---|
| 名称 | 班组长派工到人 + 任务提醒 |
| 入口 | 班组长（role=3）在工单内派工；工人看「我的任务」 |
| 做什么 | 工单→工序任务→指定执行工人（点选）；派工后工人端可见；急单可调优先级 |
| 不做什么 | 不接企业微信实时推送（试用期系统内提醒即可）；不做拖拽排程引擎；不做班组表（复用部门） |

**一句话：** 把「这道工序谁来做」从"工人自己抢"变成"班组长派"，工人打开手机就知道今天干什么。

---

## 2. 自主拍板（开工前定死；实现细节当天重查代码现状）

> 以下只定「意图 + 方向」，具体表结构 / 字段 / 接口在开工当天按当时 `docs/02` 与 `ProdModels` / `WorkOrderService` 现状重查，不得照抄旧结论。

| 项 | 方向 | 理由 |
|---|---|---|
| 派工粒度 | 工单工序（`prod_work_order_operation`）→ 执行工人 | 复用现有工单工序任务表，不新开维度 |
| 工人身份 | `sys_user.id`（role=2 为主，role=3 也可） | 最小改动 |
| 派工关系存储 | 新增派工表（工单工序 + 工人 + 优先级 + 派工人 + 时间），SQL Server `IDENTITY/NVARCHAR/DATETIME2` | 对齐 docs/02 风格 |
| 工人报工是否强制"先有派工" | **暂不强绑**：派工是"任务视图 + 提醒"，报工仍可按现有自选工序兜底 | 不因派工上线而卡死现报工流程 |
| 优先级 | 任务表加 `priority`；急单可调，调完工人端排序变化 | 对齐 UC-13 |
| 提醒通道 | 试用期**系统内**（工人刷新任务列表可见）；正式期再接企业微信（`docs/1B`/`docs/20` 通道已有） | 交付节奏，别一上来卡推送 |
| 终端 | **先 PC**（班组长在电脑派工）；工人端「我的任务」先做 PC 只读或 H5 只读，开工当天拍板 | 先管理动作，后现场动作 |
| 权限 | 派工仅 role∈{1,3}；工人只能看派给自己的任务 | 沿用 22 三角色 |
