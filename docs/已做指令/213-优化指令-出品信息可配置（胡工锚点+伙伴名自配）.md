# 213-优化指令：出品信息可配置（胡工锚点 + 伙伴名自配）

> 状态：已完成（2026-10-04）
> 性质：正式生产（改了后端接口返回契约 + 前端消费形态）
> 目标：让【每个独立部署实例】通过【appsettings 配置一个伙伴名】得到【对应的署名文案】，胡工锚点恒定不被改
> 依据/拍板：黑帽大人 2026-10-04 口头定案：没配伙伴 → 胡工单方版；配了伙伴 → 胡工、{伙伴} 联合出品

## 取舍（定死）
| 项 | 定案 |
|---|---|
| 做/不做 | 做：只做"伙伴名一个字段"最小版 |
| 复用还是另写 | 复用现成 `InstanceOptions` + `/api/instance-info` + 前端 `getInstanceInfo()`，只加字段；**胡工锁为代码常量，不入配置** |
| PC / H5 | 两端共用同一逻辑（署名在登录弹窗/关于/帮助/优势，均现有页面） |
| 挂载/入口时机 | 登录版权弹窗是用户点「版权」才开：若此时伙伴信息未加载，先 await `getInstanceInfo()` 再拼文案，避免短暂显示单方版 |

## 本次范围与落点
- 交付：一条完整流程【配置伙伴名 → 重启后端 → 4 个页面署名随实例变 → 胡工不变】
- 已有 / 缺口：
  - 后端：`InstanceOptions` 已有 `DisplayName` 等；`InstanceController.Get()` 已匿名返回 code/displayName/factoryCode/version/supportProviderName —— 缺口：无 `CreditPartner`（已补）
  - 前端：`utils/instanceDisplay.js` 的 `CREDIT_LINE`/`CREDIT_ROLES` 目前是**写死常量**，被 4 页消费（`login`/`about`/`help`/`advantages`）；`api/auth.js` 已有 `getInstanceInfo()` —— 缺口：改为响应式 + 拉 instance-info 覆盖（已补）
- 数据与契约：不持久化、不改表；仅后端接口返回加 1 字段
- 文档：不改表、不改业务规则，无需同步权威文档

## 行为与口径（显式分叉）
- 当 `Instance:CreditPartner` 为空 → 署名行 = **小蜜蜂报工・胡工**；角色行不渲染；全文不出现"联合出品"
- 当 `Instance:CreditPartner="大灰狼"` → 署名行 = **小蜜蜂报工・胡工、大灰狼 联合出品**；角色行 = **产品研发：胡工｜客户成功经理：大灰狼**
- "保留所有权利"恒显示，独立常量，**不与署名拼接**（避免登录弹窗重复）
- 胡工锚点：署名与角色行两处的"胡工"恒为代码常量，任何配置都不改它
- 当 `instance-info` 拉取失败 → 各页回退到"未配版"（胡工单方版），不白屏

## 止步线
- 不做数据库存伙伴名（appsettings 即可）
- 不做多伙伴列表 / 伙伴角色名自配 / 非"客户成功经理"角色扩展
- 不改 `document.title`、`instanceName`、厂名眉标逻辑
- 不为本次预建接口、开关或隐藏入口
