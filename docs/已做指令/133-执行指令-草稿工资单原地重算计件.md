# 133-执行指令：草稿工资单原地重算计件

> 状态：已落地（2026-10-01）
> 一句话目标：草稿工资单操作列加【重算】，按**当前工价**重算已有计件明细与应发合计，**保留**底薪/餐补/补贴/扣款手工项；不必再「删除→重新生成」。
> 拍板：用户 2026-10-01 选 **B**（相对 A「删单重出」）。
> 依据：114 只做了已确认【撤回重算】；草稿仍须删再生成，体验绕。

---

## 取舍（定死）

| 项 | 定案 |
|---|---|
| 谁可点 | 仅草稿（`status=0`）；已确认仍走【撤回重算】 |
| 重算范围 | **只重算本单已有明细行**的工价匹配与金额；不自动拉入本周期新增报工（要收全量仍删后【生成工资单】） |
| 手工项 | 底薪/餐补/其他补贴/社保个税/其他扣款 **原样保留** |
| 应发合计 | `计件小计 + 底薪+餐补+其他补贴 − 社保个税 − 其他扣款`（复用已有 `CalcTotalAmount`） |
| 报工快照 | 同步回填 `prod_report.unit_price` / `wage_amount`（与生成时一致）；**不改** `settled_flag`（草稿本来就未结算） |

---

## 改动点

### 后端
- `ISalaryService` / `SalaryService`：新增 `RecalcDraftAsync(id, factoryId, operatorUserId)`
  - 单不存在 → Biz「工资单不存在」
  - `status != 0` → Biz「仅草稿可重算；已确认请先撤回」
  - 明细关联报工缺失 → Biz 带 `reportId`，不吞
  - 按 `PriceRuleMatcher.Match/Calculate` 更新每条 `salary_statement_item`；回填报工预览价
  - 写回 `total_amount`；返回 `{ unmatchedCount, pieceworkAmount, totalAmount }`
- `SalaryController`：`POST /api/Salary/{id}/recalc` → 调上述方法（鉴权同确认/删除，不要求仅 role=1）

### 前端
- `api/salary.js`：`recalcSalary = (id) => http.post(`/Salary/${id}/recalc`)`
- `views/salary/index.vue`：草稿操作列加【重算】；`onRecalc` 确认框 → 调接口 → 成功提示（含未匹配数若 >0）→ `load()`；操作列宽度略加宽

## 验收

- [ ] 草稿行有【重算】；已确认行无此按钮（仍只有撤回重算）
- [ ] 先改工价再点草稿【重算】→ 明细单价/金额变、应发合计变；手工列数字不变
- [ ] 非草稿调 `POST .../recalc` → 业务失败提示，不改数据
- [ ] 重算后若仍有未匹配明细 → 返回 `unmatchedCount`，前端有提示；点确认仍被拦（原逻辑）
