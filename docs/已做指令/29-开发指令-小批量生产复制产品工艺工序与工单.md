## 本次范围与落点

- 建议流程：列表行“复制” → 带入资料的新建表单 → 修改差异 → 保存 → 列表出现新对象；取消不写入。
- 产品、路线、工序落点：`frontend/src/views/product/index.vue`、`routing/index.vue`、`operation/index.vue`；后端对应 `ProductService.cs`、`RoutingService.cs`、`OperationService.cs`。产品页已核实有新建/编辑及路线选择；本次已接入三种复制入口。
- 工单落点：`frontend/src/views/order/index.vue`、`backend/Services/WorkOrderService.cs`、相关 API/Controller。已核实有 `POST api/WorkOrder/{id}/copy`；改造前确认后直接建单，复制产品、数量、工序任务及自定义值，交期为空，状态未开始，创建人沿用来源创建人。
- 数据为真实业务数据。建议不改表；按实际需要调整接口。改业务规则同步 PRD，确需改表同步数据字典，命名空间保持 `ahu.MicrosoftMes`。

## 行为与口径

- 当点击复制 → 读取本厂来源，打开新建表单；不立即创建数据库记录。
- 当产品工艺相同 → 引用原路线；当需要改工艺 → 建立新路线，复用已有工序，允许增减与排序；不修改原路线或历史工单。
- 当保存产品并复制路线 → 产品、路线、步骤及本次相关字段整体成功或整体回滚；取消不留下空路线。
- 当保存失败 → 保留表单输入并给出上下文，允许修正重试；保存中禁止重复点击，成功后关闭表单；不自动重试 POST。成功响应丢失时先查列表确认，首版不提供网络重放幂等令牌。

| 数据或关联 | 实施处理方式 |
|---|---|
| 新对象 ID、创建时间 | 重新生成；创建人字段存在时使用当前操作人 |
| 产品/工序/路线编号 | 清空，由用户填写新编号；产品编号按本厂唯一校验，其余遵循已有校验 |
| 名称、产品单位/供应商等现有录入字段 | 带入可改；名称可重复；不新增“规格”字段，现有产品/工序表单仅复制其已支持的固定字段；工单自定义值按所属对象读取 |
| 产品单价 | 带入并在表单中明确展示，可修改；独立计价规则不复制、不新增 |
| 产品路线 | 默认引用；选择复制修改时引用新路线 |
| 路线步骤 | 复制顺序与工序引用，不新建每道工序 |
| 工序权限部门、不良品项 | 复制关联并展示，可调整；所有引用须属于本厂，报工仍按部门校验 |
| 产品/工序附件 | 首版建议不复制，保存后按现有入口上传；界面说明附件未带入 |
| 工单产品、数量、普通自定义字段 | 带入可改；只读取本厂、对应对象类型的字段值，不能仅按 TargetId 跨类型复制 |
| 工单交期、单号、状态 | 交期重新填写；单号按现有规则新生成；状态未开始 |
| 工单工序与计划数 | 建议按保存时所选产品和当前新建工单规则生成；调整数量不能沿用旧计划数。本次按此实施 |
| 报工、进度、派工、异常、历史工单 | 不复制；来源记录不变 |

保存使用已有基础数据管理权限，并在后端校验本厂来源及关联，不能只隐藏按钮。产品编号唯一、部门报工权限、删除依赖倒序三条硬规则不变；异常通过 ThrowHelper 带上下文，影响计价的值必须可核对。
