# 151-优化指令：登录选厂改为按账号归属（客户登录前不见邻厂）

> 状态：已实现，待现场联调截图（2026-10-08）
> 性质：正式生产（改登录契约 + 数据可见边界，线上登录入口）
> 目标：让客户打开登录页时**看不到任何"账套/工厂"下拉、看不到别家厂名**；输账号密码后，一个账号只挂 1 厂则无感直进，挂多厂才在登录后选、且只选自己有权的厂。
> 依据/拍板：黑帽大人 2026-10-08 拍板。起因：客户在登录页下拉里看到"太阳神厨具五金厂(深圳)"等厂名，觉得自己在云上、跟别家合租，不安全。
> 与 51 的关系：**本指令取代 51 中"登录页 el-select 全量选厂"那一段**。51 的"单库多 factory_id 隔离、不做多库"结论仍有效；但 51 把全量厂名匿名铺在登录页下拉，正是本次要拔掉的病根，勿照 51 把下拉做回来。

## 取舍

| 项 | 方案及依据 | 状态 |
|---|---|---|
| 选厂时机 | 不在登录前让用户选厂；改为"先验账号密码 → 后端按账号查其关联厂 → 1 厂直进 / 多厂才选"。避免客户未验身就被喂一屏邻厂名 | 已定（大人拍板） |
| 全量匿名接口 | 51 的 `GET /api/factories`（`[AllowAnonymous]` 返回所有启用厂）下线，或改成"登录后才返回**当前账号有权的厂**"。登录前任何人抓包都拿不到全量厂名清单 | 已定 |
| 账号↔账套关系 | **不加关联表**。复用 `sys_user` 已有唯一索引 `(factory_id, account)`——同一 account 在不同 factory_id 下本就能各存一行。登录用 `account+password` **不带 factory** 匹配，命中几行=这个账号挂几厂。零改表（大人 10-08 拍板：直接 SQL 匹配用户，不另建关系表） | 已定 |
| 多厂账号密码 | **各厂独立，不做跨厂同步**。`account` 只是厂内唯一、跨厂允许重名；若按 account 全表改密，会误伤别厂里恰好同名的不相干工人。改密**只动当前登录 `factory_id` 那一行**，绝不按 account 批量更新。多厂账号想要同密码，由各厂管理员分别设（大人 10-08 拍板） | 已定 |
| 多厂第二步契约 | **A：短时选厂票据**。验密只做一次；命中多厂时后端不发 JWT，改发 `selectToken`（短有效期约 2 分钟、audience 限定 select-factory、payload 锁死合法候选 factoryCode 集合），前端再 `POST /select-factory(token, factoryCode)` 才换正式 JWT。**不选 B**（不二次上送密码）。UI 走 **C：同页两态**（账密态 → 选厂态），不新开路由、不另起登录跳转 | 已定（大人拍板 A+C） |
| 密码校验方式 | 取出候选行后用 BCrypt verify 逐行校验，**严禁 SQL 用等号比 password_hash** | 已定 |
| 单厂账号体验 | 绝大多数客户账号只挂 1 厂 → 登录后零选择、直进，右上角挂本厂名，全程不见"账套"二字 | 已定 |
| PC / H5 | 先 PC 登录页（Element Plus）；H5/PDA 沿用"当前已登录账套"，本期不做现场端切厂 | 已定（沿用 51 止步线） |

## 本次范围与落点

- 交付一条完整流程：打开登录页 → 只见账号+密码两框 → 输对密码 →（按下面分叉）直进 或 选自己有权的厂 → 进系统看本厂数据。
- 已有 / 缺口：
  - 已有：单库 `factory_id` 隔离、JWT 带 `FactoryId`、`AuthService.LoginAsync`、`InstanceOptions`（见 51 第 2 节现状，Cursor 开工前复核行号）。
  - 缺口：登录页全量下拉要拆；匿名全量厂名接口要收；"一人挂多厂"的关联与登录后选厂流程要新建。
- 数据与契约：**不改表**（不加关联表）。登录查询由"factory_id + account"改为"按 account 取候选行 + BCrypt 逐行验密"；JWT 仍带最终选定行的 `FactoryId`。
- 文档：本指令不碰 docs/02 DDL；验收后归档，并在 51 顶部标注"选厂段落以 151 为准"。

## 行为与口径（分叉写成显式条件，禁止脑补）

- 当 `POST /login`（account, password）→ 按 account 取出候选行、用 BCrypt 逐行验密：
  - 验密失败 / 0 行 → 统一 401"账号或密码错误"；
  - 验密通过且只命中 1 行 → **直接发正式 JWT**（带该行 factoryId），前端进系统；
  - 验密通过且命中 ≥2 行 → **不发 JWT**，返回 `{ needSelectFactory:true, candidates:[{factoryCode,factoryName}], selectToken }`；`selectToken` 约 2 分钟有效、仅限 select-factory 用、payload 锁死这次合法的候选 factoryCode 集合。
- 当 `POST /select-factory`（selectToken, factoryCode）→ 校验 token 有效未过期、且 factoryCode 在 token 锁死的候选集合内；通过才发正式 JWT（带该 factoryId），否则拒、不发 JWT；伪造/篡改 factoryCode、token 过期或复用一律拒。
- 当 打开登录页 → 页面只渲染"账号 + 密码"，**不出现账套/工厂下拉，不出现任何厂名**；登录页初始化请求里**不再有匿名全量厂名接口**。
- 当 多厂账号在同页从"账密态"切到"选厂态" → UI 不新开路由、不重新登录，候选列表来自上一步 `candidates`；选完才拿正式 JWT 进系统。
- 当 账号密码校验通过、且该账号只关联 1 个账套 → 不弹选厂，直接进系统，右上角显示该账套 `factory_name`。
- 当 账号密码校验通过、且该账号关联 ≥2 个账套（厂家运维 / 一人管多厂）→ 登录后进入"选择要进入的工厂"页，列表**只列出该账号有权的厂**（`factoryCode + factoryName`），选一个才放行；JWT 写入最终选定的 `factoryId`。
- 当 任何人在登录前抓包/调接口 → 拿不到"服务器上一共有哪些厂"的全量清单；客户 A 的列表里永远不出现客户 B/C/D 的厂名。
- 当 账号或密码错误 → 统一报"账号或密码错误"，不泄露账号是否存在、也不泄露该账号属于哪个厂。
- 注意："存在多个账套才显示选择"指的是**该账号自己挂了多个**，不是"服务器上有多个厂就让所有客户都选"——后者会把普通客户又推回看到邻厂的老问题。

## 止步线（本次不做）

- 不做 H5/PDA 端切厂、切厂后记住上次选择（后置）。
- 不做"新建账套 / 一键灌演示数据"管理端（那是 51 另一摊，本指令只管登录选厂观感）。
- 不做多库多实例；`WorkshopMesB` 维持 51 的冻结结论。
- 不做登录页除"拆下拉"以外的视觉改版（登录图自配等见 69，另算）。

## 验收（全勾才交付）

- [ ] 普通客户账号（挂 1 厂）打开登录页：页面上无"账套/工厂"下拉、无任何厂名；输账号密码后直接进，右上角是本厂名。
- [ ] 抓登录页初始化与登录前所有请求：不存在一个匿名接口返回全量厂名清单；客户账号在验密前无法枚举服务器上其他客户。
- [ ] 挂 ≥2 厂的账号输对密码后：弹出选厂列表，列表里**只有它有权的那几个厂**，选一个才进，且进后产品/工单/报工/看板数据按选定厂隔离、互不可见。
- [ ] 错误密码统一提示，不泄露账号存在性与所属厂；伪造 `factoryCode` 调 select-factory、或 selectToken 过期/复用，一律拒且不发 JWT；密码只在第一步上送一次（抓包确认第二步 select-factory 不带密码）。
- [ ] 回归：JWT 仍带 `FactoryId`，报工/看板/工资等核心查询的 `factory_id` 隔离未被破坏；走 DbCompat 幂等升级不重复报错。
