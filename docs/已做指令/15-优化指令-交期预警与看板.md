# 优化指令：交期预警与看板三态（对标黑湖「查看」第一期）

> 状态：已实现  
> 依据：1D《对标黑湖真实设计的修正稿》v1.1（官方原文逐字核对）；PRD §4.14 车间看板；现实现 `WorkOrderService` / `ReportStatService.BoardAsync` / `board/index.vue`
> 目标：把黑湖"查看"的核心价值先落地——工单带**计划交期**，看板用**三态颜色（正常/预警/延期）**区分，临期、超期工单**红色/黄色高亮**，厂长不用跑车间就能看出谁要拖期
> 原则：**先做不动角色模型的一块**。黑湖"复核、派工、工人上报异常"都依赖"班组长"角色（当前 role 只有 1 管理员 / 2 生产人员），属后续期；本期只做"交期 + 预警 + 看板颜色"，零角色改动、零新表，性价比最高。

## 0. 对标黑湖落地分期总览（先看全貌，再干第一期）

黑湖"查看—复核"闭环要落地共 5 件事，按**依赖关系**分期如下：

| 期 | 黑湖对标项 | 依赖 | 本期？ |
|---|---|---|---|
| **第一期（本文）** | 交期字段 + 交期预警（临期/超期）+ 看板三态颜色 | 只加字段、改看板，**不动角色** | ✅ 做 |
| 第二期 | 角色模型扩展（加"班组长"）+ 报工复核（双轨：进度实时、复核卡入账） | 必须先有"班组长"角色 | ❌ 后置 |
| 第三期 | 班组长派工到人 + 任务提醒 | 依赖第二期角色 | ❌ 后置 |
| 第四期 | 工人一键上报异常（设备故障/物料短缺/质量异常）| 依赖第二期角色 | ❌ 后置 |

> **为什么不先做复核：** 当前 `sys_user.role` 只有 1/2，没有班组长；`prod_report` 无状态字段、报工即计入统计（10/14 号指令已实现）。引入复核要动角色模型 + 回改报工聚合口径，是一整期工程。而交期预警零依赖、价值直接命中"厂长实时看进度"这个黑湖最强调的卖点，所以放第一期。

## 2. 自主拍板（实现前定死，避免返工）

| 项 | 决定 | 理由 |
|---|---|---|
| 交期字段 | `prod_work_order.due_date DATETIME2 NULL`，可空 | 老工单没交期，不能 NOT NULL 否则历史数据炸 |
| 谁录入交期 | 建单/编辑表单里加"计划交期"日期框（现有建单人=管理员即可，**不新增"计划员"角色**） | 轻量版 role 只有 1/2，不为交期扩角色 |
| 临期阈值 | 常量 `DueWarnDays = 3`（3 天内到期=临期）；二期再做可配置 | 黑湖官方无具体天数，先写死，避免过度设计 |
| 三态判定 | 仅对**未结束**(status 0/1)工单：`now > due_date` → 延期(overdue)；`0 < due_date - now ≤ 3天` → 预警(warning)；其余/未设交期 → 正常(normal) | 已结束(2)、已取消(3)不参与 |
| 颜色 | 正常=蓝(#3370ff)、预警=黄(#ff9a2e)、延期=红(#f53f3f) | 对齐黑湖"正常/预警/延期"三态语义 |
| 交期是否必填 | **非必填**；未填交期的工单不参与临期/超期判断，标"正常" | 不强加负担；逐步引导填 |
| 改表方式 | 加列走 `DbCompat.EnsureAsync`（幂等 `IF COL_LENGTH IS NULL`），不动已上线表结构 | 项目已有兼容策略 |
| 是否引入后台定时任务 | **否**。看板打开时实时计算临期/超期，不搞 BackgroundService | 黑湖是"打开看板即算"，非定时扫描；且本期零基础设施改动 |

## 4. 后端改动

### 4.1 新增：交期三态枚举（`Models/ProdModels.cs` 或 Service 内）

```csharp
public static class DueState
{
    public const string Normal = "normal";    // 正常
    public const string Warning = "warning";  // 预警（临期）
    public const string Overdue = "overdue";  // 延期（超期）
}
```

判断逻辑抽成一处（供列表、详情、看板复用）：

```csharp
private const int DueWarnDays = 3;

// 返回 (state, dueDate)；仅未结束工单参与临期/超期
private static string CalcDueState(byte status, DateTime? dueDate, DateTime now)
{
    if (status >= 2 || dueDate == null) return DueState.Normal;  // 已结束/已取消/未设交期
    var span = dueDate.Value - now;
    if (span < TimeSpan.Zero) return DueState.Overdue;           // 已超期
    if (span.TotalDays <= DueWarnDays) return DueState.Warning;  // 临期
    return DueState.Normal;
}
```

### 4.2 `WorkOrderCreateDto` / `WorkOrderUpdateDto` 增加交期

```csharp
public DateTime? DueDate { get; set; }   // 计划交期，可空
```

- `CreateAsync`：建单时写入 `DueDate`。
- `UpdateAsync`：编辑时更新 `DueDate`（改交期不算"改数量/换产品"，无报工限制）。
- `CopyAsync`：复制时**不复制**交期（交期是新单的事，复制留空）。

### 4.3 `WorkOrderListDto` / `WorkOrderDetailDto` 增加

```csharp
public DateTime? DueDate { get; set; }
public string DueState { get; set; } = DueState.Normal;  // normal/warning/overdue
```

- `QueryAsync` 列表：Select 时带 `DueDate`，填充时算 `DueState`。
- `BuildDetailAsync` 详情：同样带 `DueDate` + `DueState`。

### 4.4 `ReportStatService.BoardAsync` 看板扩展

`BoardDto` 增加两个统计 + 每条进度带交期三态：

```csharp
public class BoardDto
{
    // ... 现有字段不变 ...
    public int DueWarnCount { get; set; }      // 临期工单数
    public int DueOverdueCount { get; set; }   // 超期工单数
    public List<BoardOrderProgressDto> Orders { get; set; } = new();
}

public class BoardOrderProgressDto
{
    // ... 现有字段不变 ...
    public DateTime? DueDate { get; set; }
    public string DueState { get; set; } = DueState.Normal;
}
```

`BoardAsync` 里对 `orders` 逐条算 `DueState`，并统计 `DueWarnCount` / `DueOverdueCount`。

- 报工、复核、权限、防超额逻辑**全部不动**（复核属第二期）。
- `RoleGuardMiddleware` 不动。
