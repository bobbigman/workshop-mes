### 2.1 工单状态机（扩展）

状态取值（`prod_work_order.status`，`TINYINT`）：

| 值 | 含义 | 说明 |
|----|------|------|
| 0 | 未开始 | 创建默认 |
| 1 | 执行中 | 有报工或手工「开始」 |
| 2 | 已结束 | 全部工序完成或手工「结束」 |
| 3 | 已取消 | 手工「取消」 |

流转操作（统一接口 `POST /api/WorkOrder/{id}/transition`，Body `{ action }`）：

| action | 流转 | 约束 | 说明 |
|--------|------|------|------|
| start | 0 → 1 | 仅 0 | 手工开工 |
| finish | 1 → 2 | 仅 1 | 手工结束（提前完工） |
| withdraw | 2 → 1 或 1 → 0 | 2/1 | 撤回/反完成；报工记录**保留**，仅状态回退 |
| cancel | 0/1 → 3 | 0/1 | 取消；取消后不可再流转 |
| restore | 3 → 0 | 仅 3 | 取消反悔（可选） |

规则：
1. 所有流转仅管理员(role=1)。
2. 非法流转（如 2→start、3→任意除 restore）抛业务异常。
3. 取消工单不计入看板「进行中/已完成」；保留在列表（已取消 tab）。
4. 撤回后，报工记录与工序进度不删（下次报工/结束再判定）。

### 2.2 工序级计划数（新增表）

新增 `prod_work_order_operation`（工单工序任务）：

```sql
CREATE TABLE prod_work_order_operation (
  id           BIGINT IDENTITY(1,1) NOT NULL PRIMARY KEY,
  work_order_id BIGINT NOT NULL,               -- 工单
  operation_id  BIGINT NOT NULL,               -- 工序
  seq           INT NOT NULL DEFAULT 1,        -- 顺序
  plan_qty      INT NOT NULL DEFAULT 0,        -- 该工序计划数
  -- 唯一索引：work_order_id + operation_id；work_order_id + seq
);
```

逻辑：
1. **创建工单**：按产品路线的工序顺序，自动生成任务行，`plan_qty` 默认 = 工单 `qty`。
2. **换产品**：重置任务行 = 新产品路线工序；`plan_qty` 默认 = 工单 `qty`。
3. **编辑工单**：任务行可单独改 `plan_qty`（生产任务 tab）。
4. **报工完成判定（改造）**：
   - 工序完成 = 该工序 `SUM(prod_report.good_qty) >= plan_qty`
   - 工单完成 = 所有任务行工序都完成
   - 报工后工单 `status` 至少置 1；全部工序完成置 2
5. 工单级 `qty` 保留 = 总计划数（列表/看板分母、流转卡打印）。

### 2.3 工单编辑（全面放宽，覆盖 docs/07）

编辑接口 `PUT /api/WorkOrder/{id}`，Body：

```
{ orderNo?, productId?, qty?, planQty? , ext? }
```

| 字段 | 策略 | 约束 |
|------|------|------|
| 工单号 `orderNo` | **可改** | 工厂内唯一（排除自身）；非空；改后二维码内容随新号 |
| 产品 `productId` | **可换** | 存在且属本工厂；换产品=重置工序任务，已有报工时前端确认 |
| 数量 `qty` | 可改 | `>= 1`；若**所有工序均无报工**，同步改各任务 `plan_qty=qty`；有报工则 `qty >= 已报良品合计` |
| 工序计划数 `planQty` | 可改（任务行） | 每行 `plan_qty >= 该工序已报良品` |
| 自定义字段 `ext` | 可改 | 按 key 更新/插入；单选值须在选项内 |
| 状态 `status` | 不改（走 §2.1 流转接口） | — |

状态约束（与 docs/07 一致并放宽）：
- **已取消(3)** 禁止编辑。
- **已结束(2)**：默认禁止编辑（走「撤回」再改）；若需直接改，先 `withdraw`。
- 未开始(0)/执行中(1) 可编辑。

### 2.4 复制工单

`POST /api/WorkOrder/{id}/copy`：
- 复制产品、数量、自定义字段、工序任务；**新工单号**（按生成规则新取）；状态置 0；不复制报工。

### 2.5 前端交互（工单）

- 列表操作列：编辑、状态流转(开始/结束/撤回/取消按状态显示)、复制、打印、删除。
- 状态 tab：全部/未开始/执行中/已结束/已取消（对齐黑湖）。
- 编辑弹窗：4 个分区——基本信息(工单号/产品/数量)、自定义信息、生产任务(工序计划数行)、操作说明。
- 换产品/改工单号：前端 `ElMessageBox.confirm` 二次确认。

| 项 | 说明 |
|----|------|
| 接口 | `PUT /api/Report/{id}`，Body `{ goodQty, defectQty, defectId }` |

| 权限 | 管理员可改任意；生产人员仅可改**本人**当次报工（可选，首期管理员全放开） |
| 前端 | 报工列表操作列「编辑」 |

## 5. 基础资料 / 单据 · 修改指令（完整，自包含）

> 统一规则（贯穿以下所有对象）：
> - 仅管理员（role=1）可改；生产人员只报工。
> - 所有读写带工厂隔离（`factoryId`）。
> - 删除仍走 `DeleteGuard`（有引用就拦）；**修改默认放行**（改错别字不必先删关联）。
> - 前端模式：列表操作列「编辑」→ 复用创建弹窗 → `editingId ? updateXxx(id, form) : createXxx(form)`。
> - 异常 `ThrowHelper.Biz`，不吞。
