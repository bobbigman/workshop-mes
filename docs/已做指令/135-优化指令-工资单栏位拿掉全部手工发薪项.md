# 135-优化指令：工资单栏位拿掉全部手工发薪项（底薪/餐补/社保/其他补贴/其他扣款）

> 状态：已完成（2026-10-02，按 138 落地）
> 一句话目标：`salary_statement` 去掉全部 5 个手工发薪列——底薪、餐补、其他补贴、社保个税、其他扣款；应发合计只剩报工计件/计时金额与不良扣款，彻底对标黑湖「工资=报工结果，不掺发薪结算」。
> 依据/拍板：2026-10-02 黑帽大人（用户）分两次拍板：先拿底薪/餐补/社保，续拿其他补贴/其他扣款 → 全拿。

## 取舍（定死）
| 项 | 定案 |
| 做 | 拿掉全部 5 列：`base_salary`(底薪) / `meal_allowance`(餐补) / `other_allowance`(其他补贴) / `social_tax`(社保个税) / `other_deduction`(其他扣款) |
| 保留 | `salary_statement_item.deduct_amount`(不良扣款)——报工核算骨架，关联报工，不动 |
| 复用 | 复用现有 recalc/revoke/批量重算（docs/134）逻辑，本次不碰 |
| PC/H5 | 先 PC（Element Plus）；H5 不做 |

## 已核实现状（勿重复做）
- 已有：`salary_statement` 5 个手工列（docs/02 247-263；docs/73），默认 0、仅草稿可改。
- 已有：应发合计 `total_amount` = 计件明细求和 + 底薪+餐补+其他补贴 − 社保个税 − 其他扣款（docs/73）。
- 已有：`SalaryController.UpdateComponentsAsync`（{id}/components）改手工项；docs/134 批量重算方案。
- 缺口：5 列仍在，应发合计仍掺手工发薪项。

## 改动点
- 后端 `backend/.../SalaryService.cs` + DTO（`UpdateComponentsAsync` 入参）：
  - 当这 5 列历史值**全部为 0** → DbCompat/迁移直接 `DROP COLUMN base_salary, meal_allowance, other_allowance, social_tax, other_deduction`（干净删）。
  - 当任一列**存在非 0 历史值** → **保留列不删**（防丢已确认工资钱，违背可追溯红线），仅：前端不再录入、公式不再计入，列加注释「历史遗留，停用」。
  - 应发合计公式改为：Σ(salary_statement_item.amount − deduct_amount)，即纯报工计件/计时金额减不良扣款。
  - 兼容：旧端仍传已删字段 → 后端忽略，不报错。
- 前端 工资单编辑/确认页（Element Plus，路径以 Cursor 对照现有 Salary 页为准）：
  - 去掉「底薪 / 餐补 / 其他补贴 / 社保个税 / 其他扣款」全部 5 个输入框；确认页只剩报工明细。
- 文档：改 docs/02（salary_statement 表定义，删列或标停用）+ docs/73（手工列定义同步/删除）。

## 验收（3～5 条勾选）
- [ ] 工资单编辑/确认页不再显示任何手工发薪输入项
- [ ] 应发合计 = Σ(amount − deduct_amount)，不再含任何手工加/扣项
- [ ] 库中存在非 0 历史值时：列未删、历史已确认单金额不变
- [ ] 全为 0 时：DROP COLUMN 成功、无残留引用报错
- [ ] 单张 recalc / 批量重算（docs/134）不受影响

## 不做 / 边界
- 不动 `salary_statement_item.deduct_amount`（不良扣款，与报工关联，是核算骨架）。
- 不改计时工资（`duration_minutes` 已实现）。
- 历史有非 0 值时保留列只停用，不删数据。
