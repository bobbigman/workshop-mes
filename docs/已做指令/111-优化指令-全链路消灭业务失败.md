# 111-优化指令 · 全链路消灭"业务失败"这 4 个字

> 日期：2026-10-01｜状态：**已完成**（2026-10-01 本地真启验收通过）。
> 用户红线：**所有地方、无论何时，都不允许出现"业务失败"这 4 个字**（用户可见兜底）。
> 拍板（2026-10-01）：
> 1. **仅 msg 为空**走「请洽软件提供商 + 错误信息 + 追踪号」模板；有 msg 仍只显示后端 msg（长技术错误弹窗另附追踪号）。
> 2. 独立 `Support` 配置节，**不写联系方式**；提示语固定「请洽您的软件提供商」（可选 `ProviderName` 覆盖称呼，默认空）。
> 3. 验收走真启服务，核对一次失败请求的 TraceId 与日志一致。

## 一、为什么改（业务背景，用大白话）

笼统的「业务失败」四个字什么也没说，车间侧会以为系统坏了。需要把**具体错误信息 + 追踪号**交给用户，空 msg 时再提示去找软件提供商。

## 二、现状盘点（开工前复核）

1. `http.js` 字面量 `'业务失败'` 当时已不存在，兜底为「请查看服务器日志」；已读 `X-Trace-Id`。
2. 缺口：文案未按「请洽软件提供商」；无 `Support` 节；wwwroot 旧包仍含「业务失败」。

## 三～四、实施摘要（落地）

### 改动文件清单

| 文件 | 改动 |
|---|---|
| `backend/Common/SupportOptions.cs` | **新增** Options（仅 `ProviderName`） |
| `backend/appsettings.json` | 新增 `Support` 节（默认空） |
| `backend/Program.cs` | `Configure<SupportOptions>` |
| `backend/Controllers/InstanceController.cs` | `instance-info` 增加 `supportProviderName` |
| `frontend/src/api/http.js` | 空 msg 模板 + 长技术错误附追踪号；导出 `setSupportProviderName` |
| `frontend/src/api/auth.js` | `getInstanceInfo` 成功时写入提供商称呼 |

### 空 msg 兜底模板

`请求失败，请洽{您的软件提供商|ProviderName}，错误信息：服务端未返回详细原因，追踪号 {id}`

### Support 接入方式

独立节 `Support`（非挂 Instance），与 `ErrorLoggingOptions` 同类 `Configure`；经现有匿名 `GET /api/instance-info` 下发，避免前端多一次请求。**无联系方式字段**（按拍板）。
