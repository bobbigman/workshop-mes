# 226-优化指令：H5工单列表默认落"执行中"，同tab内按交期紧急度排（对标黑湖0217改版）

> 状态：已做（2026-10-12）
> 性质：内部试用（现场工人天天用，真实数据真实权限）
> 目标：工人手机进"工单"页，一抬头就是**正在干的活**，而不是一屏已完工旧单；要查历史手动切"已结束"。
> 依据/拍板：黑帽大人 2026-10-12 现场反馈"前面一大片都是已完工的"；黑湖做法已扒官方原版，见下。

## 黑湖官方做法（实锤，不脑补）

来源一：黑湖官方更新日志《0217版本｜手机端全新UI重磅发布》（xiaogongdan.net/72.html，2022-02-17），附新旧版对比截图。

- 工单页顶部：「全部工单 ▼」视图下拉 + 搜索框 + 排序图标 + 筛选漏斗。
- 横向状态 tab **四个，不合并**：**全部 / 未开始 N / 执行中 N / 已结束 N**，每个 tab 带数量角标。
- 卡片按状态分组列，"执行中"组卡片带「加急」红标、工序圆形进度条。
- 底部主导航五个：**工单 / 任务 / ＋ / 看板 / 个人**。

来源二：黑湖官方《手机端登录步骤》《手机端使用指南》《电脑端怎么进》（xiaogongdan.cn，2026-07）。

- "权限验证通过后，手机端会加载该工人的**待办工单**……登录成功后看到**当日待报工的工单、待领取的任务**。"
- "工人打开小工单后，**首页直接显示分配给自己的当天工单和工序任务，不需要翻层级菜单**。"
- "登录后看到的是和自己相关的工序任务列表，**不会看到全厂数据**——工人只看到派给自己的活。"

> **关键结论：黑湖一线工人登录后首页不是"全部工单"，而是底部「任务」tab（派给自己的活），已完工的单子根本不进工人视野，不存在"混在前面"这回事。** 0217 截图里那个四 tab 的工单页，是**班组长/计划员/厂长的管理视角**，不是工人首页。
>
> 对应到咱项目：
> - `orders.vue` = 黑湖"工单"tab（管理视角，四 tab 结构本来就对，不合并）
> - `tasks.vue` = 黑湖"任务"tab（工人首页，权限按人过滤）
> - `workerViewMode` 开启时直接跳 tasks.vue —— 这才是对齐黑湖工人首页的正道。
>
> 现场"前面一大片已完工"的根因怀疑：那厂要么**没开 workerViewMode**，要么**没派工数据**（tasks.vue 空，工人退回 orders.vue 找活）。

## 取舍（已定 / 待确认）

| 项 | 方案及依据 | 状态 |
|---|---|---|
| 现场根因排查 | 本机 WorkshopMes：三厂 `worker_view_mode` 均为 1（全车间可见）；派工表 0 行。太阳神厨具五金厂(深圳) 执行中 11、已结束 33，和「前面一大片已完工」对得上。工人视角开了也会因没派工落到空任务页，所以这次改的是工单页默认 tab。 | 已查 |
| tab 结构 | **保留四 tab：全部 / 未开始 / 执行中 / 已结束**，带数量角标。对齐黑湖 0217 官方截图，不合并。 | 已定 |
| 默认 tab | orders.vue 进页默认落「执行中」。工人视角开着的厂本就跳走 tasks.vue，零影响；没开的厂改完投诉当场消失。 | 已定（黑帽大人 2026-10-12 拍板 A） |
| 排序 | 同一 tab 内：先按交期紧急度（已逾期 > 临期 > 正常），同档按工单 ID 倒序（新派的在前）。已结束 tab 内按 ID 倒序（最近完工在前）。 | 已定 |

| PC 是否改 | 电脑端工单页同样默认落「执行中」。【全部】【已结束】仍可手动切。2026-10-12 现场在 `#/order` 看到已结束排在最前，黑帽大人要求电脑端一并改。 | 已改 |
| 工人视角 | 已开 workerViewMode 的厂进页直接跳 `/h5/tasks`（对应黑湖底部"任务"tab），本指令不影响。 | 已定（现状保留） |
| 报工权限=部门 | 本期不做按部门过滤列表；点单进 report.vue 照旧校验工序报工部门权限。 | 已定（止步线内） |

## 本次范围与落点

- 交付：手机 H5「工单」页（`frontend/src/views/h5/orders.vue`）一次完整流程：进页默认"执行中" → 切 tab 看未开始/已结束/全部 → 搜工单号 → 点单去报工。
- 已有：
  - 后端 `WorkOrderService.QueryAsync` 支持 `Status` 过滤；`getOrderStatusCounts` 返回 all/notStarted/doing/done；`FillListProgressAsync` 已算好 doneQty/remainQty/DueState(normal/warning/overdue)。
  - 前端 tabs 配置已存在，计数已接通。
- 缺口：
  1. `statusTab` 默认值从 `'all'` 改为 `'1'`（执行中）；
  2. `loadList()` 按当前 tab 传 `status` 参数（现状已支持，只是默认值不对）；
  3. 拿到 list 后前端按 DueState 权重（overdue=0, warning=1, normal=2）再按 ID 倒序稳定排序；已结束 tab 不重排，保持后端 ID 倒序；
  4. tab 角标计数映射对齐黑湖：全部=all、未开始=notStarted、执行中=doing、已结束=done（现状已一致，核对即可）。
- 数据与契约：**不改表、不改后端接口签名**。
- 文档：docs/31《工人手机端使用手册》顺手补一句"进页默认看执行中"。

## 行为与口径

- 当工人进 /h5/orders 且未开工人视角 → 默认落在「执行中」tab，列表只含 status=1 的工单，逾期的排最顶。
- 当工人点「未开始」→ 只看 status=0；点「已结束」→ 只看 status=2，最近完工在最上；点「全部」→ 维持现状（排除已取消），混排，便于搜历史单号。
- 当工人在任一 tab 搜工单号/产品 → 只在当前 tab 范围内搜。
- 当某厂在制工单超过 100 条 → 本期接受前端截断，现场再回来改后端排序。
- 后端 Status 与 ExcludeFinished 参数优先级维持现状，前端不撞参数。

## 止步线
