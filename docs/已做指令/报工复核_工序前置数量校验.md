# 报工复核_工序前置数量校验

> 状态：已实现（2026-10-09）
> 性质：内部试用
> 一句话目标：报工复核页面，自动按工艺路线读取上工序已复核通过的良品，算出本工序可报上限；报工数量超上限则行高亮预警，批量通过自动识别并跳过异常单据，保留人工特批放行入口。

## 取舍表
- ✅ 做：同工单上下游工序数量校验；列表新增"上工序合格库存（可报上限）"列；超限行高亮 + 数量异常标签；批量通过过滤异常单据；超限单据单点通过加二次确认弹窗；提示文案全部内置页面
- ❌ 不做：自动退回单据；锁死前端报工提交；跨工单、跨工艺路线追溯；多分支/返修回流复杂工艺自动分摊计算（异常场景统一走人工特批）

## 范围落点
报工复核列表页面，**PC 端与 H5 端本期一次做完**（PC `frontend/src/views/review/index.vue`、H5 `frontend/src/views/h5/review.vue`，两端同口径）。全厂通用，所有账套均开启，不绑定 HY 账套。

## 行为与口径
- 工序上限计算规则
  - 当为本工单工艺路线**首道**工序（按工单任务行 Seq，无任务行则按产品工艺路线 Seq）：可报上限 = 工单计划投产总数（order.Qty）
  - 当非首道工序：可报上限 = 同一工单、工艺路线**紧邻上一道工序**已复核通过（ReviewStatus=1）良品合计；不看更前道次，不做前序加总
- 占库存口径
  - 同工单同工序已通过+待复核良品合计（**含本笔**）≤ 可报上限，才判合规；避免同工序多人、同单分批各报各的绕过上限
- 页面展示规则
  - 列表新增字段：【上工序合格库存/可报上限】，展示计算出的最大允许报工数
  - 当同工序累计占用 ≤ 可报上限：行样式正常，无标记，可勾选、可批量通过
  - 当同工序累计占用 ＞ 可报上限：整行浅黄色高亮，状态栏新增橙色【数量异常】标签；批量操作自动跳过该行；单独点击通过弹出确认弹窗

## 界面提示文案（内置页面）
1. 列表悬浮提示（鼠标放【数量异常】标签）："本工序报工良品超过上工序已审核合格产出，正常生产逻辑不合理，若为返工、补料可手动特批通过"
2. 批量通过弹窗（勾选含异常单据时弹出）
   - 标题：存在工序数量异常单据
   - 正文：本次勾选共 XX 条单据，其中 XX 条报工数量超出上工序合格库存，系统将自动跳过异常单据，仅批量通过合规单据。
   - 按钮：【查看异常明细】【确认仅通过合规项】【取消批量操作】
3. 单条超限单据「通过」二次确认弹窗
   - 标题：工序数量异常确认放行
   - 正文：当前工序报工良品 XX 件，上工序累计合格仅 XX 件，超出正常生产数量。请确认是否为返工、补料、特采等特殊场景，确认后才可完成复核通过。
   - 输入框（选填）：特殊情况备注
   - 按钮：【取消】【确认特批通过】（特批备注**不落库**，仅弹窗确认）
4. 列表新增列头：上工序合格库存（可报上限）

## 止步线
仅校验同一工单、标准顺序工艺路线的前置已审核良品；不自动处理多分支、返修回流复杂计算，异常全部交由人工判断。

## 验收标准
1. 首道工序自动取工单计划数作为校验上限，页面正常展示
2. 非首道工序自动取紧邻上一道已复核通过良品作为上限，展示可报上限列；同工序累计良品（含已通过/待复核）超出上限判异常
3. 报工数量超上限（本笔或同工序累计），行高亮 + 橙色异常标签，悬浮提示正常显示
4. 批量通过时检测异常单据，弹窗提醒，自动过滤异常行不操作
5. 超限单据单点通过弹出特批确认弹窗，可放行且备注不落库
