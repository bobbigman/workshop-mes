## 三、发现的问题清单（分级）

| 级别 | 问题 | 描述 | 建议处理 |
|---|---|---|---|
| **P0 严重** | 报工负数漏洞 | `POST /Report` 传 goodQty=-1 / defectQty=-1 均 code=0 且写入数据；连锁导致工单列表「报工汇总数量非法」整体崩溃 | **必须修复**：`SubmitAsync` 增加「良品/不良品数不能为负」校验（对齐 `UpdateAsync`）；修复后清理已污染数据（见 docs/75） |
| **P1** | 新建工单偶发 500（根因已锁定） | `WorkOrderService.NextOrderNoAsync`（670 行）用「当天单号 Count + 1」拼单号；**当天删除过工单（真删）后 Count 变小 → 生成序号与存量重复 → 撞唯一索引 `IX_prod_work_order_factory_id_order_no`**。日志铁证：`重复键值 (1, GD20260927008)`。撞号抛 `DbUpdateException` → code=500「操作失败」 | Cursor 改单号生成：用「当天 Max 序号」而非 Count，或查重 + 重试；并补测当天删单后再建单不复现 |
| 澄清 | 删除=真删（初版「软删观察」为脚本误判，已勘误） | 删除为级联真删（`RemoveRange`+`SaveChanges`），删除后 `GET /{id}` 返回 `HTTP 200 + code=1「工单不存在」`；初版脚本只按 HTTP 状态判定误判为软删 | 无需修复；前端按 `code` 而非 HTTP 状态判断结果即可 |
| 环境 | 登录/列表偶发瞬态失败 | 探针与部分请求偶发登录失败、列表返回空 | 自测脚本已加请求重试缓解；非功能 bug，但需留意部署环境稳定性 |
