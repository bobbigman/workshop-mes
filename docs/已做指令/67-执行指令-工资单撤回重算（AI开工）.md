## 1. 一句话目标

给**已确认**工资单开一道「撤回 → 重算」的门：漏算/错算/复核延迟导致的错误工资可重来，**全程留痕、不破坏报工事实**。修复赵江陵事件（19.60 定格）。

## 2. 现状（勿重造）

- `salary_statement.status`：0草稿 / 1已确认 / 2已发放
- `DELETE /api/Salary/{id}` 仅草稿可删；**已确认单无任何撤回接口**
- 确认后 `prod_report.settled_flag=1`（冻结）；仅删草稿工资单才回滚为 0
- `salary_statement_item.report_id` 全局唯一（一条报工最多结算一次）；`uk_statement_period` 唯一（同人+周期一张单）
- → 已确认单无法作废，漏算报工无法再归集，错误金额永久定格

## 3. 改动范围（最小，只开撤单门）

| 层 | 改动 |
|---|---|
| `SalaryService` | 新增 `RevokeAsync(id)` |
| `SalaryController` | 新增 `POST /api/Salary/{id}/revoke`，`RoleGuard` 仅 admin（role=1） |
| 抛错 | 复用 `Common/ThrowHelper.cs`，带上下文（位置+做什么失败） |
| **不改** | 数据表结构、复核逻辑、工价快照口径、`generate` 计算逻辑 |

### `RevokeAsync(id)` 语义：单事务、原子
1. 校验存在且 `status=1`；否则抛「仅已确认工资单可撤回」（人话）
2. 删除该单全部 `salary_statement_item`（释放 `report_id` 唯一占用）
3. 删除 `salary_statement` 行（释放 `uk_statement_period`）
4. 该单关联报工 `prod_report.settled_flag` 回滚为 0（解除冻结、可再结算）
5. 留痕：操作人 + 时间 + 原工资单 id/金额（走现有日志/审计，不新增表）

撤回后：同人同周期无工资单，重新 `POST /api/Salary/generate` 会全新归集该周期全部 `review_status=1 AND settled_flag=0` 报工（**含之前漏的**），按工价快照重算。

## 4. 业务规则与边界（写进实现）

| 场景 | 行为 |
|---|---|
| status=0（草稿）调 revoke | 报错；草稿走既有 DELETE |
| status=2（已发放）调 revoke | **禁止**，报错「已发放工资单不可撤回」 |
| status=1 正常撤回 | 作废并回滚（如上） |
| 撤回后重复 generate | period/明细已释放，正常新建不冲突 |
| 并发撤回同一单 | 事务 + 状态校验，二次调用报错 |
| 报工事实 | 不改 good/defect/unit_price，只解 settled_flag |

## 5. 数据字典（`docs/02` 追加说明，不建表）

`prod_report.settled_flag` 说明处补：确认工资单时置 1；**删除草稿工资单、或撤回（revoke）已确认工资单**时回滚为 0。

## 6. 验收清单（逐条勾）

- [ ] 管理员：对已确认单 `POST /api/Salary/{id}/revoke` → `code=0`；`GET /api/Salary/{id}` 返回不存在（已作废）
- [ ] 关联报工 `settled_flag` 回滚为 0（`GET /api/Report` 可查）
- [ ] 重新 `generate` 同人同周期 → 新建工资单，**含此前漏算报工**，金额重算正确
- [ ] **回归（赵江陵）**：撤回 19.60 → 重算 = **22.00**（含包装，组装驳回不计）
- [ ] 草稿单调 revoke → 报错「仅已确认工资单可撤回」，数据不变
- [ ] 已发放单（status=2）调 revoke → 报错「已发放工资单不可撤回」
- [ ] 非管理员调 revoke → 403
- [ ] 撤回后重 generate → confirm 正常闭环，报工再次冻结

- 不动复核、防超额、工价版本逻辑（本次只开撤单门）
