# 优化指令：手机报工界面（少看、少填、数字大）

> 状态：已实现  
> 依据：`docs/未做指令/33`、`34` 的分析，以及随后拍板的「做 / 不做」  
> 目标：工人单手、几秒能完成一次常规报工。页面只改看起来和点起来，不改报工规则。

## 1. 做

只改这 4 个页面 + `theme.css` 里新增的 H5 尺寸变量：

| 页面 | 改什么 |
|---|---|
| 报工 `report.vue` | 剩余可报放大；良品数大输入；±1 / ±10；「报全部剩余」只填数字；不良数为 0 时藏起原因；「继续报工」「提交报工」固定在底栏上方 |
| 工单 `orders.vue` | 卡片加进度条；剩余改成一行大字；去掉创建时间；工序只显示当前和下道；去掉「总计」 |
| 扫码 `scan.vue` | 改成「正在等扫」的画面；扫码枪仍自动聚焦、回车跳转；另加「手动输入工单号」 |
| 底栏 `TabBar.vue` | 高度改用 H5 变量，好让报工按钮挨在它上面；扫码图标略大一号。文案仍是「工单 / 扫码」 |
| `theme.css` | 只**新增** `--h5-*` 尺寸变量。颜色继续用现有 `--app-*` |

## 2. 不做（硬边界）

- 不改接口、不改表、不改报工校验、不改部门权限。
- 不自动选工序。列表接口没有「这个人现在能报哪道」，权限仍在提交时由后端拦。
- 状态名保持「未开始 / 执行中 / 已结束」，不改成待生产 / 生产中 / 已完成。
- 搜索框保持展开，不收成图标。
- 不做悬浮大圆按钮，不另起一套颜色。
- 不改 `769px` 以上的 PC 变量，不改电脑端页面。
- 工序列表没有序号字段，卡片上不编「03 ·」。只写工序名。

## 3. 逐文件

### 3.1 `frontend/src/styles/theme.css`

在现有 PC 尺寸变量后面追加，不改原值：

- `--h5-page-padding: 12px`
- `--h5-card-radius: 12px`
- `--h5-card-padding: 14px`
- `--h5-control-height: 48px`
- `--h5-qty-height: 56px`
- `--h5-qty-font: 28px`
- `--h5-action-height: 52px`
- `--h5-tabbar-height: 56px`

### 3.2 `orders.vue`

卡片顺序：状态 + 工单号 → 产品编号和名称 →「已完成 a/b」+ 进度条 + 百分比 →「剩余 N」+ 交期 → 当前工序 / 下道工序 →「去报工 ›」。

- 进度 = 已完成 / 计划，计划为 0 时显示 0%，不超过 100%。
- 当前工序 = 第一条「计划 > 0 且完成 < 计划」的工序；下一条是下道。全部做完显示「工序已完成」。没有工序列不显示这行。
- 交期颜色仍用原来的临期 / 超期判断，颜色改走主题变量。
- 整张卡仍点进 `/h5/report?order=工单号`。
- 删掉「总计」。搜索、四个状态 Tab、接口参数不动。

### 3.3 `report.vue`

- 摘要改成一行「计划 / 已完成」，下面单独放大「剩余可报」。未选工序时仍显示「—」。
- 良品输入高 56px、字号 28px、居中。
- `-10 -1 +1 +10` 和「报全部剩余」只改输入框里的数字，范围夹在 0 和剩余可报之间。没选工序或已报满时，这些按钮禁用。
- 提交、继续报工、时长、工序下拉、校验、请求报文都不改。
- 不良数 ≤ 0 时不显示原因，并清掉已选原因，避免藏起来还把旧原因提交上去。大于 0 时展开，原校验（有不良必须选原因）不动。
- 两个按钮固定在底栏上方，留出 `safe-area`。文案：「继续报工」「提交报工」。

### 3.4 `scan.vue`

- 中间是扫描框样子，文案「等待扫描工单」「请扫描工单流转卡二维码」。
- 收码输入框仍在，页面打开就聚焦，回车仍跳 `/h5/report?order=`。失败提示不变。它不做成虚线输入框，避免工人以为要点一下才能扫。
- 「手动输入工单号」展开另一个输入框。空着点确定，提示「请输入工单号」，不跳转。

### 3.5 `TabBar.vue`

高度用 `--h5-tabbar-height`，底下仍加安全区。扫码图标 24px，工单图标 22px。不改路由、不改文案。
