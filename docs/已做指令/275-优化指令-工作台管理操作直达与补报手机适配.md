# 275-优化指令：工作台管理操作直达与补报手机适配

> 状态：已实现并完成代码级验证；真机待验收；2026-10-23。
> 性质：正式生产界面优化。
> 本次交付：用户明确要求先写指令、再自动落地；交付实现、必要验证和归档，不部署。
> 目标：班组长、管理员从手机工作台直接找到代报/复核及其有权限的补报操作，不再到后台菜单层层查找。

## 已定取舍与落点

- 依据本次用户认可的分析：在扫码按钮之后、我的任务之前增加紧凑管理入口，任务再多也不会把入口挤到底部；不增加底栏项目。
- 班组长：代报工、报工复核（复核仍受已有授权档限制）。管理员：再加“一键补报未完工序”“补报开工记录”。普通工人不显示这些入口。
- 代报与补报含义分开；班组长可代记本组实际数量，不因此获得管理员批量补报或计时补报权限。
- 复核复用 `/h5/review`；其余复用PC `/report` 中已有Element Plus弹窗，通过明确站内action定位，不另写H5业务表单、后端接口或数据表。
- 当前落点：`h5/home.vue`、`report/index.vue` 和一个前端入口权限工具。代报已有272布局，批量补报/待补报开工记录及详情需补手机布局。

## 行为与边界

1. 工作台管理按钮只按现有角色/授权展示。“代报工”直接打开代报弹窗；管理员两项补报分别直达批量表单或待处理开工记录列表；先显示表单，不先加载/展示报工记录管理列表。
2. 新来源为 `/report?from=h5&action=proxy|batch|pending`。进入时再次校验action与角色；伪造或未知action不打开表单、不请求补报数据，提供返回工作台。来源参数只用于导航，不授予权限，后端校验不改。
3. 从工作台进入的代报/批量补报，提交成功或取消/关闭后返回工作台；失败保留表单。待补报列表关闭回工作台，详情取消回列表、成功后回工作台。原PC入口保持原关闭与刷新行为；刷新直达地址可重新打开对应表单，不自动提交。
4. 手机补报弹窗使用全屏、正文滚动和可见提交区，标签上置；待报工序与待补报记录用纵向卡片，长产品名/工单号允许换行。电脑保持原表格与弹窗。
5. 管理员计时开始、结束时间分行，保留日期及秒、原时区语义；仍组合为原字段提交，缺一端或结束不晚于开始明确提示，不自动补时间。按工序拆人保持每道合计规则，不改数量默认值、上限与工资计算。
6. 加载失败与无记录区分，给出重试；切换工单先清除失效详情、旧请求不回填新工单，未加载完成不可提交。提交时防重复点击及关闭；沿用原API、上游确认、事务和幂等机制，不扩展报工权限。

## 止步线
