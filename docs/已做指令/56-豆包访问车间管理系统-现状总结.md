## 二、连接器与调用方式

- **连接器**：豆包侧"老胡极情报工"，指向本机 `http://localhost:8080/mcp`。
- **鉴权头**：`Authorization: Bearer laohu-demo-2026`。
- **协议**：MCP `streamable-http`，SSE 响应 `event: message / data: {...}`。
- **解析要点**：`tools/call` 结果需取 `data:` 行 → 去前 6 字符 → 一层 `ConvertFrom-Json` 拿 `result.content[0].text` → 再 `ConvertFrom-Json`；JSON 引号被转义为 `\u0022`。
- **中文 body 正确姿势**（关键）：Windows PowerShell 5.1 `Invoke-RestMethod -Body [string]` 会把中文按系统 ANSI(GBK) 发送、服务端按 UTF-8 解成乱码 → **假 no_match**。正确做法二选一：
  1. `curl.exe + --data-binary "@文件"`（UTF-8 无 BOM 请求体）；
  2. `Invoke-RestMethod -Body ([System.Text.Encoding]::UTF8.GetBytes($json))`。
  纯英文（PDA）不受影响。

## 三、关键经验与坑（务必记住）

1. **中文检索"失效"是假的**：之前判"服务中文检索 bug"，实为 PS5.1 发中文 body 的编码坑，服务端检索逻辑（字符级 `IndexOf`）本无问题。修复=脚本用 UTF-8 发请求，勿动检索源码。详见 `docs/55-执行指令-修复SupportDocs中文检索bug.md`。
2. **连接器只能在豆包工作任务模式用**：侧边栏「技能・连接器・伙伴」进入连接器专区确认启用；本机 localhost 连接器仅豆包电脑端可用，网页端云电脑 / 换机器 / 手机端访问不到（手机的 localhost 是手机自己）。
3. **演示扫描扫码报工靠报工 H5，不靠豆包**：豆包是"AI 查询/管理问答"角色；现场扫码报工（识别流转卡、选工序、填数、提交）用报工 H5（手机浏览器 / 微信 / 企业微信扫码打开）做最顺。
4. **安全提醒**：当前演示 token + 演示模式挂在公网，生产必须先关 `Mcp:DemoSkipAuth`、换强 token。

## 四、当前演示方案（零成本，笔记本打天下）

- **带哪台**：带那台跑着 WorkshopMes + SQL Server 的笔记本（数据服务都在其上），别带错。
- **现场**：手机/平板连**同一 WiFi**（含笔记本开移动热点），扫码报工 H5 直接访问笔记本内网地址，不卡、不依赖隧道。
- **手机豆包查询**：演示"AI 查车间"（产量 / 谁没报工 / 最后一次报工）。
- **微信 clawbot**（扣子智能体 + MCP + 微信渠道）：链路长（微信→扣子→隧道→本机）约 10 秒，演示时当"远程微信版"一句话带过，别现场干等；脱离扣子直连不可行（clawbot 是扣子托管渠道，不独立）。

## 五、后续路线（有客户后再投入）

1. **轻量云服务器上云**（≈100~200 元/年，2C4G 国内，选大陆地域）：同时扛车间系统（客户试用）+ 宣传网站 + `/mcp`，一个 HTTPS 域名全包。
2. **域名 + ICP 备案**（免费，约 1~2 周）：大陆服务器绑域名硬门槛，现在即可并行申请。
3. **HTTPS 证书**：Let's Encrypt 免费，90 天自动续。
4. 上云后：手机豆包 / clawbot / 微信扫码 / 客户试用全部切到 `https://域名`，本机不再常开。
5. **正式交付客户**：客户内网部署固定 IP（项目本意），公网隧道仅留远程管理用。

## 六、分工与协作约定

- **豆包（老同学）**：程序分析员，负责分析、写指令、规划、独立复核；不写代码。
- **Cursor**：负责改代码、自测、部署、跑验收；豆包锁死判据并对运行结果独立复核。
- 验收规则：判据锁定，脚本以仓库内为准；任何一条 FAIL = 不得交付。
