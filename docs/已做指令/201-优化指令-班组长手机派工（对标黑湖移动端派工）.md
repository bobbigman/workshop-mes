# 201-优化指令：班组长手机派工（对标黑湖移动端派工）

> 状态：已做（2026-10-02）
> 一句话目标：给班组长/管理员加一个 **H5 手机派工入口**，把电脑端工单详情的【执行人】下拉搬到手机，写同一字段 `assignee_user_id`；派工**仍是提示、不拦报工**。
> 依据/拍板：2026-10-02 多隆老同学与黑帽大人对标黑湖（黑湖支持班组长手机派工）后拍板立项；放 `docs/未做指令/201`。

## 取舍（定死）
| 项 | 定案 |
|---|---|
| 做/不做 | 做手机派工入口；**不做"派工后拦截报工"**（保留"没派也能报"卖点） |
| 复用还是另写 | 复用电脑端派工逻辑与 `assignee_user_id` 字段；后端视现有接口决定复用/补一个 |
| 推送 | **首版不做**消息推送（企微预警默认关）；工人手机【任务】页自行可见 |
| PC / H5 | 后端逻辑通用；新增界面在 **H5（Vant）**；电脑端行为不变 |
| 派工范围 | 班组长限本组人员；管理员可派全厂（沿用现有权限） |

## 已核实现状（勿重复做）
- 已有：`prod_work_order_operation.assignee_user_id`（派工执行人，空=未派工）；电脑端工单详情【执行人】下拉自动保存。（`03-工单·派工` / 知识库 4.3）
- 已有：角色权限——管理员/班组长可派工，班组长限本组。（知识库 1 / 03-工单）
- 已有：H5 工单详情/任务页（Vant）。
- 缺口：手机端无派工入口；后端"派工保存接口"是否已有**待核实**（电脑端可能内联保存走工单更新接口，需 Cursor 对照代码确认）。

## 改动点
- 后端：
  - **待核实**电脑端派工是否已有独立接口；没有则补一个 `PUT /api/WorkOrder/{id}/operations/{operationId}/assignee`（body: `userId` 或 null）。
  - 当 `userId` 非空 → 校验该用户存在且属本厂、班组长派工限本组 → 写 `assignee_user_id`。
  - 当 `userId` 为空 → 清空该工序派工（取消派工），同电脑端清空逻辑。
  - 当请求者是生产人员（role=2）→ 403，无派工权限。
  - 派工**不改变**报工权限/拦截逻辑，不触碰 `prod_report`。
- 前端 H5（Vant）：
  - 班组长/管理员在工单详情（或工序任务卡片）加【派工】操作：弹出工人选择（本厂用户列表，班组长过滤本组），点选后调上述接口，回显执行人姓名。
  - 已派工人显示姓名；点【取消派工】清空。
  - 未派工序显示"未派工"。
- 文档：不改 `docs/02`（复用现有字段，无新表）；若补新接口则同步 `SupportDocs` 接口清单或 `docs/33`。

## 验收（3～5 条勾选）
- [ ] 班组长在手机工单详情可派工给本组工人，回显姓名；工人手机【任务】页出现该工序。
- [ ] 管理员可派全厂；班组长派到非本组人被拒或不可选。
- [ ] 手机【取消派工】后，工人任务页不再显示该工序，电脑端执行人同步清空。
- [ ] 生产人员（role=2）无派工入口/调接口返回 403。
- [ ] 派工后**未派工/已取消派工的工单仍能正常扫码报工**，报工行为零变化。

## 不做 / 边界
- **不做**"派工后拦截未派工序报工"；不改变"派工=提示"的规则。
- **不做**手机派工的消息推送（企微预警默认关，暂不接）。
- **不做**多人同工序派工（本期仍一道工序一次一人，同电脑端一致）。
- 后端是否已有派工接口未核实，**由 Cursor 对照代码确认**后再决定复用或新建，不臆造。
