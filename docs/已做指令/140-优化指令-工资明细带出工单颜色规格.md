# 140-优化指令：工资明细带出工单「颜色 / 规格尺码」

> 状态：已完成（2026-10-02，运行时验收通过）
> 一句话目标：工资明细（139 的明细查询）与导出 CSV 里带上工单的颜色、规格尺码两列，财务能对上 A0001 这种"颜色黑 / 尺码M"的账。复用现有色码取数，不改表。
> 依据/拍板：2026-10-02 黑帽大人反馈：工单有颜色/规格，工资报表看不到。已核实系统有 `ReportStat.SkuSummary`（docs/102 色码汇总）按 `product+color+spec` 取数先例。

## 取舍（定死）
| 项 | 定案 |
| 做 | 工资明细加「颜色 / 规格尺码」两列（只读展示 + 导出），数据来自工单自定义字段 |
| 复用 | 复用现有色码取数（`ReportStat.SkuSummary` 的 `color/spec` 取值逻辑），不新写取数 |
| 不做 | 不改表、不参与金额计算；颜色/规格不参与工价（除非另立项按颜色计价） |
| PC/H5 | 先 PC（Element Plus）；H5 不做 |

## 已核实现状（勿重复做）
- 已有：颜色/规格是工单**自定义字段**，`field_key` 约定 `color`=颜色、`spec`=规格/尺码（docs/102、`SysCustomField`/`SysCustomFieldValue`）。
- 已有：`ReportStatController.SkuSummary` 已按 `product.code + color + spec` 分组汇总（docs/102），有取数先例可复用。**取数链路已核（ReportStatService.cs SkuSummaryAsync 126-178 行）**：① 报工 `prod_report` join 工单 `prod_work_order`（on `OrderId`）；② color/spec 字段 id 取自 `sys_custom_field`（`Target="work_order"` 且 `FieldKey∈{color,spec}`）；③ 值取自 `sys_custom_field_value`（`FieldId`∈{color,spec} 且 `TargetId`=工单 id），Lookup(orderId, fieldId) 兜底空串。
- 已有：工资明细 `salary_statement_item` → `prod_report` → 工单（order），可带出自定义字段。
- 缺口：139 明细查询与导出未含颜色/规格两列。

## 改动点
- 后端（在 139 明细查询/导出基础上）：
  - 明细行追加 `color`、`spec` 两列：按 `salary_statement_item.report_id → prod_report → 工单 order_id`，color/spec 按 `sys_custom_field(Target="work_order", FieldKey∈{color,spec})` 找字段 id、再按 `sys_custom_field_value(FieldId, TargetId=工单 id)` 取值（**直接复用 ReportStatService.cs SkuSummaryAsync 126-178 行 Lookup 逻辑**，不新写）。
  - 导出 CSV 追加这两列。
  - 不改表、不改金额公式。
- 前端 工资明细（139 的报表层明细 + 原【明细】单子）：
  - 明细行加「颜色 / 规格尺码」两列展示。
  - Element Plus。
- 文档：docs/33 补接口字段（明细含 color/spec）；docs/02 不改（未新增表/列）。
