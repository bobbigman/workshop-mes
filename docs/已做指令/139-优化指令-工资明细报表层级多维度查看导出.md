# 139-优化指令：工资明细报表层级多维度查看 + 导出

> 状态：已完成（2026-10-02，运行时验收通过）
> 一句话目标：工资报表页加「按工序 / 时间维度」切换，明细（人员/工序/良品/不良/单价/扣款/金额）直接在报表层级显示并导出，不靠点进【明细】按钮——对齐黑湖「报表可分维度切」。
> 依据/拍板：2026-10-02 黑帽大人拍板；对标黑湖官方（工资报表按员工/工序/时间维度查看、可导出）。

## 取舍（定死）
| 项 | 定案 |
| 做 | 报表层新增维度筛选（工序 / 时间）+ 明细直显 + 明细导出 CSV |
| 复用 | 复用现有 `salary_statement_item`（明细）+ `prod_report`（工序/良品/不良），靠 join，**不改表** |
| 不做 | 不改确认 / 重算 / 批量重算逻辑；H5 不做 |
| PC/H5 | 先 PC（Element Plus）；H5 不做 |

## 已核实现状（勿重复做）
- 已有：`salary_statement`（按人/周期汇总）+ `salary_statement_item`（明细：report_id / calc_qty / unit_price / amount / deduct_amount）。
- 已有：`prod_report` 报工事实（工序、良品、不良，字段以 Cursor 对照代码为准）。
- 已有：`GET /api/Salary`（列表）、`GET /api/Salary/{id}`（详情，进单子看明细）、`GET /api/Salary/export`（导出 CSV）。
- 缺口：明细只在「明细」按钮进单子看，报表层无维度筛选、无明细直显/导出。

## 改动点
- 后端 `backend/.../SalaryService.cs` + Controller：
  - 新增「工资明细多维度查询」接口：入参 `periodType, periodValue, operationId?(工序筛), 时间范围?`；返回明细行 `人员 / 工序 / 良品 / 不良 / 单价 / 不良扣款 / 小计`。数据源 = `salary_statement_item` join `prod_report`（工序/良品/不良取 prod_report，单价取 item 快照）。
  - 新增明细导出 CSV（或扩展现有 `export`），列含上述字段。
  - 不新增表/列（复用现有）；如需冗余字段（如明细行直接带工序名）→ 先问人再动 docs/02。
- 前端 工资报表页（Element Plus，路径以 Cursor 对照现有 Salary 页为准）：
  - 加维度筛选（工序下拉 / 时间范围）；选后报表层直接列出明细行。
  - 加【导出明细 CSV】按钮；原【明细】进单子保留（不回归）。
- 文档：docs/33 补两个接口签名；docs/02 一般不改（未新增表/列）。
