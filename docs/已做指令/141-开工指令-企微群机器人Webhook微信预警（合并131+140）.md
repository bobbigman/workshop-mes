- group 成员校验允许 UserId 或精确的 `@all`；有 `@all` 时规范化为仅 `@all`。保留旧session成员校验，不全局放开 `@`。

## 页面与升级兼容

- 入口沿用 `/#/wechat-alert`。保留启用开关、Webhook、默认 @成员、每日上限、保存/发送测试、手动交期推送、群规则、发送记录；交期说明写“临期+超期每天汇总一条，当日不重推”。
- 前端移除自建应用输入项；规则通道固定群机器人，无需单选项下拉。事件类型继续保留报工成功、工单开始、工单结束、异常上报。
- 存量session规则在页面显示停用提示，可查看原配置但不可继续启用；管理员按原模板和成员重新建立group规则。历史发送记录仍可查。
- 升级幂等停用session规则；其尚未发送的投递通过现有停用/跳过机制处理并显示原因；已进入发送阶段但未落结果的旧投递保留为未知，允许人工确认已发送，不允许重新排队，禁止继续发送、禁止转群或删除历史账本。发送器最终出口再次检查通道，覆盖在途记录与重试入口。
- 全局未配Webhook时，测试/交期提示补配置；有效的独立Webhook群规则仍可在总开关开启后投递。开启总开关须有全局Webhook或至少一条启用且有有效目标的group规则。
- 帮助文案：企业微信创建纯内部群 → 群设置中添加消息推送/群机器人（名称随客户端版本可能不同）→ 复制Webhook。无需域名备案或自建应用可信IP；服务器需能出站访问 `https://qyapi.weixin.qq.com`。手机锁屏通知取决于通知权限、免打扰和系统设置，不能承诺必定弹窗。

## 发送行为与保护

- 工人异常上报：设备/物料/质量分别按已启用规则匹配，规则成员对应机修/仓库/质检；未配置规则不发送，规则未填成员只群通知。不自动猜负责人，不新增角色表。
- 异常及工单事件沿用“业务与待发记录同事务、事务提交后由计划任务投递”；外部HTTP调用不得放进业务事务。推送失败记账本，不改变已经成功的业务结果；数据库/入队失败仍按现有异常规范处理，不吞异常。
- 群规则Webhook非空用本规则，否则用全局默认；均无则不生成待发，页面提示目标缺失。默认 @成员仅用于测试和交期，规则空成员不继承。
- 交期沿用75的每日批次键与看板临期/超期判断，手动和cron共用去重。事件和交期共享现有每日额度；测试不占每日额度。
- 总开关关闭或trial试用：测试、手动、cron、事件投递、重试均不调用外部推送；待发沿用停用/暂停机制，不能绕过开关或授权。
- 每机器人每分钟最多20次发送尝试：按规范化key统一计数，覆盖测试、交期、事件及重试，不按工厂或规则各算一份；同实例并发共用持久计数/锁，复用现有账本，不另建队列。事件超限保留待发并延后；测试/交期超限返回明确提示，交期不记成功去重，允许后续触发再处理。不同MES实例共用机器人时仍受企微总限额约束，部署建议各实例独立机器人。
- 明确失败写尝试账本，沿用现有重试策略；超时、断连等无法确定送达的情况标记结果未知，不自动重发，先核实后按现有人工流程处理。
- 群消息请求使用 `POST https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key={key}`，JSON为 `msgtype=text`、`text.content`、`text.mentioned_list`；复用现有文本长度保护。
- 报错提供易懂提示及追踪号；只有响应能证明原因时才区分key无效/机器人删除，否则提示“Webhook不可用，请检查机器人配置”，不猜错误原因。请求网址、报文、响应和异常上下文落盘前脱敏，Webhook key/Secret/Token不得出现在日志、账本、错误提示或接口明文返回中。
- 测试失败在当前页提示；异步事件失败在发送记录展示，不能通过让工人上报失败来提示推送问题。关闭总开关并保存后停止后续发送，已发出的请求无法撤回。
