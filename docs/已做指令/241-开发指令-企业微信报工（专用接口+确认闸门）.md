## 行为与口径（分叉写成显式条件）

- 当【工人在企微对话报数】→ 企微后台 deepseek 解析成结构化 JSON（单号/工序/良品/不良/原因），附会话 userid，调 MES 专用预览
- 当【userid 在 `WxBinds` 有绑定、解析字段完整、部门有报工权限】→ 返回解析预览卡（“单号xx/工序yy/良品100/不良0，对吗？”）+ 短时一次性待确认 token，**不落库**
- 当【工人回“确认”】→ 企微后台带确认 token 调 MES 确认动作 → 复用 Submit 校验 → 落库 → 看板可见
- 当【确认 token 过期 / 不匹配 / 已使用】→ 拒绝并要求重新预览，不落库
- 当【userid 未绑定】→ 提示“请先对机器人报手机号绑定”，不放行
- 当【部门无报工权限 / 超额 / 前道数量不符】→ 校验不通过，拒绝并回显原因（三条硬规则，异常不吞）
- 当【解析字段缺失 / 歧义（如数量非数字、单号查不到）】→ 拒绝并请工人重新说清，不猜不补
- 当【复杂报工（有不良原因 / 多工序 / 字段多）】→ 企微后台引导回退走 149 发卡进 H5 表单，不强行对话直录
- 当【非企微环境（PC 网页）】→ 维持现有账号密码登录 / JWT 报工，行为不变

| 数据或关联 | 处理方式 |
|---|---|
| `WxBinds` 绑定 | 复用只读查找，不新建不删除；用于定位报工 MES 用户 |
| 报工流水 | 走现有报工表/`ReportService`，新增 `source=3` + `confirmed_at`；不改历史数据 |
| 待确认 token | 短时（默认 5 分钟）一次性；`IMemoryCache`；确认后标记已用并可幂等回放 |
| 重复提交 | 同一确认 token 只落一次（缓存 Used + `client_request_id=token`） |
