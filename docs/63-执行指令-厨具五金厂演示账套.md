## 1. 背景

五金厂（WJ001）种子数据仅含「冲压件标准线」四道工序，不适用于打蛋器（需组装/包装）。
本次**新建独立工厂「厨具五金厂」（CJ001）**，不走旧五金厂，不修改任何代码和数据表。

## 4. 执行步骤

### 步骤 0：确认环境

后端服务运行中（`http://localhost:8080`），`GET /api/factories` 返回 200。

### 步骤 1：建厂

```
POST /api/factories
{ "FactoryCode": "CJ001", "FactoryName": "厨具五金厂" }
```

此时自动灌入种子骨架：admin/banzhang/gongren、冲压组/打磨组/质检组、XC/CY/DM/ZJ、RT-WJ、WJ-001/WJ-002 及演示工单、自定义字段（批次/材质）。后续步骤会清理掉与本厂无关的旧数据。

### 步骤 2：登录拿 Token

```
POST /api/auth/login
{ "FactoryCode": "CJ001", "Account": "admin", "Password": "Admin123" }
```

记下返回的 `token`，后续请求均带 `Authorization: Bearer {token}`。

### 步骤 3：清理种子旧数据

**必须先清后建，避免外键冲突。删除倒序：工单 → 产品 → 路线。**

| 顺序 | 操作 | 说明 |
|---|---|---|
| 3a | `GET /api/workorders?pageSize=50` 找到种子工单 ID | 该工单关联冲压件A |
| 3b | `DELETE /api/workorders/{id}` | 删种子工单 |
| 3c | `GET /api/products?pageSize=50` 找到 WJ-001、WJ-002 的 ID | |
| 3d | `DELETE /api/products/{id}` ×2 | 删两个冲压件产品 |
| 3e | `GET /api/routings?pageSize=50` 找到 RT-WJ 的 ID | |
| 3f | `DELETE /api/routings/{id}` | 删五金标准线 |

### 步骤 4：查询现有数据，收集 ID

| 查询接口 | 目的是拿什么 ID |
|---|---|
| `GET /api/departments?pageSize=50` | 找到「质检组」的 ID（包装工序挂到质检组） |
| `GET /api/operations?pageSize=50` | 已有 XC/CY/DM/ZJ 四道工序 ID，供路线引用 |
| `GET /api/units` | 找到「件」的 ID，供产品引用 |
| `GET /api/customfields?target=work_order` | 找到「批次」「材质」的 fieldId，供工单引用 |

### 步骤 5：新建「组装组」部门

```
POST /api/departments
{ "Code": "ZZ", "Name": "组装组", "MemberIds": [] }
```

记下返回的 ID。

### 步骤 6：新建不良品项

```
POST /api/defectitems → { "Name": "组装松动" }
POST /api/defectitems → { "Name": "包装破损" }
```

分别记下两个 ID。

### 步骤 7：新建工序「组装」和「包装」

组装工序：
```
POST /api/operations
{ "Code": "ZZ", "Name": "组装", "DeptIds": [组装组ID], "DefectIds": [组装松动ID] }
```

包装工序：
```
POST /api/operations
{ "Code": "BZ", "Name": "包装", "DeptIds": [质检组ID], "DefectIds": [包装破损ID] }
```

### 步骤 8：新建工艺路线「厨具标准线」

```
POST /api/routings
{
  "Code": "RT-CJ",
  "Name": "厨具标准线",
  "Steps": [
    { "OperationId": 下料ID, "Seq": 1 },
    { "OperationId": 冲压ID, "Seq": 2 },
    { "OperationId": 打磨ID, "Seq": 3 },
    { "OperationId": 质检ID, "Seq": 4 },
    { "OperationId": 组装ID, "Seq": 5 },
    { "OperationId": 包装ID, "Seq": 6 }
  ]
}
```

### 步骤 9：新建产品「打蛋器」

```
POST /api/products
{ "Code": "DDQ-001", "Name": "打蛋器", "UnitId": 件ID, "RoutingId": 厨具标准线ID }
```

### 步骤 10：建工单（系统自动生成工单号）

不传 `OrderNo`，由系统按 `GD{日期}+序号` 自动生成，看起来就是正常的工单流水号。

```
POST /api/workorders
{
  "ProductId": 打蛋器ID,
  "Qty": 5,
  "Ext": { "批次fieldId": "第一批", "材质fieldId": "304不锈钢" }
}
```

### 步骤 11：启动工单

```
POST /api/workorders/{工单ID}/transition
{ "Action": "start" }
```

## 6. 注意事项

- 所有新建操作的 ID 由数据库自增生成，脚本中动态获取，不硬编码。
- 步骤 3 的清理必须在建新数据前完成（删除倒序：工单→产品→路线），否则产品关联已有工单/工序/路线无法删除。
- 自定义字段「批次」「材质」在清理旧数据后仍然存在（不关联具体记录即可），在步骤 10 中直接复用。
- 工单不指定 OrderNo，由系统自动生成 `GD{日期}{三位序号}`，完全看不出模拟痕迹。
- 密码 `Admin123` 如需更换请建厂后修改。
