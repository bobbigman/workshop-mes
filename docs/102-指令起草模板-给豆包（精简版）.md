# 102-指令起草模板（给豆包，精简版）

> 用途：豆包起草 `docs/未做指令/` 的开发/执行指令时照此写；Cursor 负责把关与编码，不靠长剧本遥控。
> 原则：**半页到一页够用**；取舍写清、条件写清；少翻三遍。
> 依据：本仓库 AGENTS.md + docs/06 开发规约 + 原 `指令起草规范-给豆包.md`。

---

## 一、什么时候才写指令

| 写 | 不写（用户可直接让 Cursor 改） |
|---|---|
| 改表 / 改接口契约 | 改文案、样式、改个常量 |
| 有做/不做、A/B 取舍要拍板 | 范围一句说清、不改契约 |
| 跨前后端多文件、以后要验收复盘 | 修漏、对齐已有指令的遗漏 |

拿不准：先写**半页取舍表**问人，别先写成长篇执行剧本。

---

## 二、固定结构（照抄标题）

```markdown
# NNN-执行/优化指令：一句话标题

> 状态：待做
> 一句话目标：……
> 依据/拍板：……（谁、哪天、选了啥）

## 取舍（定死）
| 项 | 定案 |
| 做/不做 | …… |
| 复用还是另写 | …… |
| PC / H5 | ……（本仓库默认先 PC） |

## 已核实现状（勿重复做）
- 已有：……（接口/按钮/表）
- 缺口：……

## 改动点
- 后端：路径 + 改什么（当 X → A；当 Y → B）
- 前端：路径 + 改什么（同上）
- 文档：是否改 docs/02（改表必须改）

## 验收（3～5 条勾选）
- [ ] ……
- [ ] ……

## 不做 / 边界
- ……
```

---

## 三、必须写清的「当…则…」（缺了算不合格）

有分叉就写成显式条件，禁止让执行方脑补：

- 有/无白名单、有/无接口、空/非空
- 草稿 vs 已确认、管理员 vs 工人
- PC（Element Plus）vs H5（Vant）——**禁止抄错组件库**
- 复用已有接口 vs 新建

示例：`当 status===0 → 显示【重算】；当 status===1 → 显示【撤回重算】；勿在草稿上做撤回。`

---

## 四、禁止写进指令的（会拖慢 Cursor）

1. **逐步「前置判断 → 条件执行 → 收尾」原子剧本**翻三遍（改动点里写一次条件即可）。
2. **绑死过时行号**当硬条件（可写「Validate 里 UnitPrice 比较那行」，勿写死「第 168 行必须」）。
3. **验收绑死本机某人某单**（写行为：单价填 0 不能存，即可）。
4. **「核对不动」当成改动条**、范围含糊牵一发动全身却不标「先问人」。
5. **编造黑湖/现网事实**；没出处就写「未核实，待 Cursor 对照代码」。
6. **重复做已有能力**（起草前尽量写「已有基础」；不确定就标「待核实」）。

---

## 五、篇幅与口吻

- 目标：**约 40～80 行**；超过一屏半先自砍。
- 大白话，按钮名/接口路径用真名；少空话。
- 技术栈以仓库为准：.NET 8 + SQL Server + Vue3；PC=Element Plus，H5=Vant。

---

## 六、自检（发出前勾一遍）

- [ ] 有一句话目标 + 取舍表
- [ ] 分叉都写成了「当…则…」
- [ ] PC/H5 组件库没抄错
- [ ] 写了「已有 / 缺口」或标了待核实
- [ ] 验收 ≤5 条、可勾选
- [ ] 没有长原子步骤剧、没有假行号硬绑
- [ ] 全文未明显超一页（或已说明为何必须长）
