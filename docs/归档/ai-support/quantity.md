# 数量与进度

> 与操作手册同源生成；维护 docs/30、31 和 docs/manual 正文后运行 npm run manual:sync。

## 报工后生产报表为什么没增加

先到【生产管理 → 报工】按工单查询复核状态。

- 待复核：计进度但未进报表，请班组长或管理员核对通过。
- 已退回：不计有效进度和报表，核对原因修改原记录再复核。
- 已通过：再查报表是今日、本月还是上月。按原报工时间统计，今天复核昨天的记录，不算今天报工。

不要为了让报表增加重复报工。

## 完成数为什么是 80，不是 180

有任务时工单完成数取各道有效良品（待复核和已通过的报工）最少值。例如裁切 100、包装 80，工单为 80；还有一道检验没报，最少值就是 0。

看板与工单详情、列表用同一个最少值口径：这张单显示 80，不会显示 180。「工序达成进度」取各正计划工序（良品/计划）的最小值（0～100%）。生产报表只计已通过。比较数字先确认页面和统计口径。

旧工单如果没有工序任务，打开详情时会尝试按产品路线补出任务；确实没有路线和任务时，列表会按该单有效良品合计显示，不能套用“各道取最少”。先找管理员检查产品路线，不要把没有任务当成已完成。

## 工单找不到、结束后又变执行中

找不到：完整工单号查询，再切状态。【全部】不含已取消，取消单到【已取消】查；手机没有已取消页签，找管理员。

状态变动：有效报工更新进度，各道报满可自动结束；退回、改数减少有效量后可能回执行中或未开始，管理员也能手动结束、撤回。

核对原报工数量、复核状态和工单详情，不把“已结束”当成“全已复核”。

## 超出计划数、剩余可报为零

1. 检查工序是否选对，本次良品是否误填累计数。
2. 管理员查计划和有效报工（待复核、已通过的）：待复核、已通过都占上限，退回不占。
3. 订单计划真有变更，由管理员核实后调整；原记录错了，按改数流程纠正。

不要用不良数、换工序或换工单绕过限制。不良数只记真实不合格件。

## 工价和工资报表

谁来做：负责计价结算的管理员。入口：**基础数据 → 工价表**、**报表 → 工资报表**。

1. 在工价表点【+ 新增工价】，选适用产品、工序、部门或人员；未选条件表示不限，核对适用范围。
2. 选【计件（元/件）】【计时（元/小时）】或【固定（单笔）】，填单价、不良扣款、生效时间，需要时设失效时间、优先级，点【保存】。
3. 报工并复核后，进工资报表点【生成工资单】，选按月或按周，填周期如 2026-09、2026-W37，按需选人员，点【生成】。
4. 打开【明细】，核对人员、周期、数量、单价、扣款和【匹配】。未匹配的先核查工价，不能把缺价直接当成零工资认可。
5. 草稿核对无误再【确认】；只要有明细标着红色【未匹配】（没匹配到工价），【确认】会被系统阻断并提示先补齐工价；确认后该批报工冻结，不能再改数。带走核对数据可用【导出 CSV】（导出的表格文件，用 Excel 能打开）。

做完怎么看：工资单由【草稿】变为【已确认】。确认涉及结算，相关报工受结算限制（已结算的不能随便改），不要当成普通保存。

注意：工资以已通过报工为基础（待复核、已退回不算）。算法：计件=良品数×单价，计时=时长（小时）×单价，固定=单价一次；不良品按【不良扣款】单价扣钱；工时按报工时刻取价，改数后重算。草稿有误先核对报工和工价，按草稿删除、重新生成处理；已确认交结算负责人核查。具体薪酬规则由工厂确定。
