1系统分层架构（前后端分离，局域网 H5）

自上而下 4 层；技术栈：.NET 8 Web API + EF Core + SQL Server，前端 Vue3。

表现层 · 三个入口
PC 后台（Vue3 + Element Plus） H5 手机 / PDA 报工（Vue3 + Vant） 大屏看板（ECharts） 工单二维码 / 打印标签（80×60）
▲ ▼
接口层 · HTTP API（RESTful JSON）+ JWT 鉴权
登录鉴权 JWT + BCrypt REST 接口按模块分组 列表统一分页
▲ ▼
应用层 · .NET 8 Web API（Controllers / Services）
系统配置 基础数据（产品/工序/工艺/工价） 制造知识库（作业指导书/图纸/图片上传） 生产管理（工单/报工/异常） 报表 / 工资（计件 + 手工列凑应发） 建议报价（金蝶材料 + 车间实绩） 产品优势速览（演示页） 大屏看板 自定义字段 / 导入 AI 助手（可选·默认关）
▲ ▼
数据层 · EF Core → SQL Server
业务表（sys_ / base_ / prod_ / salary_） 自定义字段键值表 sys_custom_field* AI 会话：进程内存，无新业务表

2核心业务流程 · 一单到底

电脑下单出二维码 → 工人扫码报工 → 复核 → 老板大屏看进度。

① 电脑下单出码
创建工单（引用产品+工艺路线），生成工单号二维码 / 流转卡
→
② 扫码报工
PDA 扫码头 / 手机摄像头 / 手动输工单号 / 电脑「+报工」；选工序填良品、不良数提交
→
③ 部门权限校验
当前用户所在部门 ∈ 该工序的报权部门，否则拒绝（管理员不受限）
→
④ 复核（双轨）
班组长 / 管理员复核；复核通过才入生产报表 / 工资口径
→
⑤ 进度实时更新
大屏 / 工单列表按工序实时累计进度；异常走 prod_abnormal

* 报工提交后进度即实时更新；复核是「入账/工资」关口，两条轨分开。三条硬规则见文末。

3AI 助手数据流（本机白名单，不绕公网）

PC 页面提问 → 本机后端 → DeepSeek 工具调用 → 本机白名单业务工具 → 答案 + 来源卡片。

PC 页面
仅管理员；默认关闭（配置 Ai__Enabled）
→
后端入口
POST /api/ai-assistant/messages
→
DeepSeek 工具调用
模型决定调哪个本机工具，不直接触库
→
本机白名单业务工具
查进度问工艺智能客服
search_support_docs（客服文档）
get_work_order_report_evidence（报工证据）
制造知识库文件（产品/工序挂的指导书/图纸/图片）
→
答案 + 来源卡片
只读；客服文档是证据、不改权限

⚠ 密钥放环境变量 Ai__ApiKey，不进仓库/浏览器；报工证据只投影白名单字段，不读工资/单价。

4核心表关系（ER 主链 + 模块分组）

表名全部来自数据字典 docs/02；主链用「→」表示引用方向。

系统 sys_

sys_factory（多租户）
sys_user / sys_department / sys_department_user
sys_print_setting · sys_mcp_auth

基础数据 base_

base_product（产品定义·编号唯一）
base_operation + 报权部门/不良品关联
base_routing → base_routing_step
base_price_rule · base_unit · base_defect_item · base_knowledge_file

生产 prod_

prod_work_order（工单）
prod_work_order_operation（工序计划数）
prod_report（报工记录·良品/不良）
prod_abnormal（异常上报）

工资 salary_

salary_statement（工资单·按人/周期；含底薪等手工列）
salary_statement_item（工资明细·逐条对应报工）

扩展

sys_custom_field / _option / _value（自定义字段键值）

① 主业务链（产品 → 工单 → 报工 → 工资）

base_product→ prod_work_order→ prod_work_order_operation→ prod_report→ salary_statement_item→ salary_statement

② 报工权限链（工序 ← 报权部门 ← 用户部门）

base_operation（工序·多选报权部门）→ base_operation_department→ sys_department→ sys_department_user→ sys_user

③ 工艺路线 & 不良品项关联

base_routing→ base_routing_step→ base_operation 　·　 base_operation→ base_operation_defect→ base_defect_item
三条业务硬规则（红线）
  • ① 产品编号唯一（相当于身份证），名称可重复。
  • ② 工序报工权限 = 部门（不是人）：报工前校验当前用户部门是否属于该工序报权部门。
  • ③ 删除依赖倒序：工单 → 产品 → 工艺路线 → 工序 → 不良品项 → 单位 → 部门；有下级禁止直接删。
