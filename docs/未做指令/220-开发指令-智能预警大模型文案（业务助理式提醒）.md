# 220-开发指令：智能预警「大模型文案」接入（业务助理式提醒）

> 状态：待做（只做工单超期/临期一个演示场景）
> 性质：正式生产（增量；复用已实现推送链路）
> 目标：让老板/车间主管在企微收到**有判断力的交期预警文案**（业务助理口吻，不是系统告警），推送链路与稳定性不降级
> 依据/拍板：2026-10-09 黑帽大人拍板：只做超期/临期；**无数据源维度（客户/产线/物料/设备等）不开发、不入指令**

## 做（唯一范围）

- 只做工单【超期】【临期】两类；**推送粒度沿用 75：一天一批一条**，不按工单拆推。
- 复用已实现链路，不重造（`docs/15/20/75/131/141`）：`cron-push` + Windows 计划任务、`DueStateHelper.Calc`（`DueWarnDays=3`）、`alert_key=due-alert:yyyy-MM-dd` 按厂+日去重、`daily_limit`；**缺口仅「最紧急 1 张的主文由大模型生成」**。
- 取数：定时任务**直调后端 Service/查库**组装上下文，不走 MCP（MCP 是给豆包/扣子对话用，非服务间通道）。字段来自 `prod_work_order` / `prod_work_order_operation` / `prod_report` / `base_product` / `base_operation`，口径对齐 `docs/87`（`doneQty=Min`、双轨 0+1/1、交期差天用 `AiBusinessTime`，禁 `DateTime.Now` 直接减）。
- 模型：复用现有 AI 助手 DeepSeek 通道与 key（`docs/26/25/51`、`docs/服务器信息/AI助手APIKey部署配置说明.md`）；不新增业务表。
- 文案存 `sys_wechat_alert_log.content`（已有列，`NVARCHAR(1000)`）。

## 行为与口径（方案 2，2026-10-09 拍板）

- 当批次含超期/临期工单 → 取**最紧急 1 张**（超期优先；同档按交期从早到晚，即超期时长降序）→ 组装上下文 → 调模型生成 ≤80 字**主文放整条消息首行**；其下仍为 75 标题行 + **其余工单**模板列表（成功时 hero 不重复进列表）。
- 消息形态示例：`{AI主文}\n【微聚】交期预警（…）\n· [临期/超期] 其余…`；模型失败时整条退回纯 75 模板（含 hero 行）。
- 当该张为【超期】→ 上下文含：工单号、产品名、当前工序（首道未报满）、计划交期、已超期天数、进度百分比、剩余工序数 → 文案给「已超期 + 可执行建议」。
- 当该张为【临期】（`DueWarnDays=3`）→ 同字段给「剩余天数」，语气「提醒加紧」而非「超期」。
- 当【当日批次已推送】（`alert_key=due-alert:yyyy-MM-dd` 按厂+日去重，含义同 75「当日批次不重推」）→ 跳过，不重复调模型、不重复推。
- 当【该张模型调用失败 / 超时 / 返回空或无效文案】→ **该行回退 75 模板**，整批仍推；错误记日志，不吞。
- 当【整条文案超长】（>1000）→ 截断；主文目标 ≤80 字。
- 当【工厂 enabled=0】→ 静默跳过；当【daily_limit 已满】→ 停止本次（均沿用 75）。

## 调用模型 API 的 Prompt 模板（可直接用）

系统提示 + 结构化数据 + 输出要求三段式；**模型只做语言组织，不猜数、不算数**：

```text
你是车间生产助理。下面给一张工单的真实数据，请用「提醒同事」的口吻写一段交期预警文案，
语气像业务助理，不要像系统告警、不要感叹号堆砌。

规则：
1. 只能使用下面提供的数据，缺失的信息一律不写、不许猜测或编造。
2. 不要自己计算任何数字（进度、天数、百分比只用给定值）。
3. 给出 1 条可执行建议（催办/调人/调整优先级），并说明原因。
4. 输出 80 字以内的简体中文；只输出文案，不要任何前缀解释。

工单号：{order_no}
产品名：{product_name}
当前工序：{operation_name}
计划交期：{due_date}
距交期：{days_to_due} 天（正=剩余，负=已超期）
完成进度：{progress_percent}%
剩余工序：{remaining_ops}
```
