# 51 · 优化指令 —— 多账套：登录选厂 + 单库多工厂（演示用）

> 状态：**未做（本指令即为开工依据）**
> 场景：伙伴说"客户是做五金的"，要在同一套系统里放多个账套（如五金厂 / 标准演示厂），各自有独立的产品、工艺、工单、报工数据，方便演示与模拟。
> 核心红线（读 AGENTS.md）：**走单库多账套（factory_id 隔离），不走多库多实例；升级沿用 DbCompat + docs/02，不另建升级体系；不手改生产表。**

---

## 1. 结论与取舍

- **账套 = 工厂（`sys_factory` 的一行）**。所有业务表已带 `factory_id`，唯一索引含工厂（`sys_user`/`base_product`/`prod_work_order` 等），单库内天然可隔离多个账套，**表结构一个不用改**。
- **不做多库**：`appsettings.WorkshopMesB.json`（第二库 `WorkshopMesB`）这条路线**冻结不扩展**；若要做"演示工厂B"，在主库新建一个工厂灌数据即可。
- 升级机制不变：加表/加字段只改 `backend/Data/DbCompat.cs`（幂等 `IF COL_LENGTH ... ALTER`）+ `docs/02`，一个库一次改、所有账套自动一起升，工作量恒等于 1。
- 交付节奏遵循 AGENTS：先 PC（管理端建账套/登录选厂），后 H5/PDA；首版不做两端齐全。

---

## 2. 现状事实（Cursor 开工前先核实）

- 登录：`backend/Controllers/AuthController.cs` → `Services/AuthService.cs:55 LoginAsync`。
  - `LoginDto` 已含 `FactoryCode` 字段（`AuthService.cs:16-21`）。
  - 现逻辑（`AuthService.cs:60-71`）：`configured = Instance:FactoryCode`；若前端传的 `requested` 非空且 ≠ configured 则**拒绝**；随后用 configured 查工厂 → 按 `factory.Id + account` 查用户 → JWT 带 `user.FactoryId`。
  - 前端登录页**不传** FactoryCode（`frontend/src/views/login/index.vue` 注释："由服务端 Instance:FactoryCode 钉死"）。
- 实例信息：`backend/Controllers/InstanceController.cs` 匿名返回当前实例 `factoryCode/displayName`，注释明确"不作为选厂入口"。
- 实例配置：`backend/Common/InstanceOptions.cs`，绑定 `appsettings.json` 的 `Instance` 段。
- 工厂表：`sys_factory`（`sys_factory.id / factory_code(unique) / factory_name / created_at`），见 `docs/02-数据字典.md`。
- 初始化/灌数：`Program.cs:229 EnsureCreated()` + `Instance:SeedDemoData` + `Instance:BootstrapOnStartup` 按**配置工厂**灌演示数据；无 EF Migrations。

## 3. 改动清单

### 3.1 后端（先做，PC 管理动作优先）

1. **放开登录工厂校验**（`Services/AuthService.cs:55-71`）
   - 改为：优先采用前端传入的 `dto.FactoryCode`；为空则回退 `_instance.FactoryCode`。
   - 安全线：`requested` 非空时必须能在 `sys_factory` 中查到**且启用**，否则报"账套不存在或未启用，请联系管理员"，不落库。
   - 去掉"非空且不匹配则拒绝"的旧逻辑。
   - 保持 `LoginResultDto` 与 JWT 生成不变（JWT 已带 `FactoryId`，下游业务无需改动）。

2. **新增匿名"可用账套列表"接口**
   - 建议扩 `InstanceController.cs` 或新建 `FactoryController.cs`，路由如 `GET /api/factories`，`[AllowAnonymous]`。
   - 返回 `[{ factoryCode, factoryName }]`（仅登录页选厂用）。
   - **红线：绝不返回连接串 / 密钥 / JWT / 密码**（沿用 `InstanceController` 注释约束）。
   - 若需控制可登录账套，可加 `enabled` 过滤（见 3.3，可后置，首版允许暂不过滤）。

3. **管理端：新建账套（工厂）+ 灌演示数据**
   - 提供 PC 管理入口（先 PC）：创建 `sys_factory` + 初始化该工厂的基础数据（部门/单位/工序/产品/工艺/工单/工价）+ 管理员账号。
   - 复用现有种子逻辑（`SeedDemoData`）抽成"按指定 factoryCode 初始化"的通用函数，供新账套调用；不要在启动种子外另写一套初始化体系。
   - 至少给一个可复用的初始化接口或管理页面，能"一键新建五金厂账套并灌入一套演示数据"。

### 3.2 前端（登录页选厂）

4. `frontend/src/api/auth.js`：新增取账套列表接口调用；`login` 透传 `factoryCode`。
5. `frontend/src/views/login/index.vue`：
   - 拉账套列表 → 显示"账套/工厂"下拉（`el-select`，选中项 = `factoryCode`）。
   - **仅 1 个账套时隐藏下拉，保持现状直接登录**（兼容单工厂部署）。
   - 登录时把选中 `factoryCode` 传给 `login`。
   - 请求账套列表失败时降级为"不选厂、按配置默认"，不挡登录。

### 3.3 数据 / 文档（可选，建议）

6. 建议给 `sys_factory` 加 `enabled BIT NOT NULL DEFAULT 1`（启停账套），走 `DbCompat.cs` 幂等补列 + `docs/02` DDL 同步；**首版可先不做**，用 `factory_code` 存在性即可。
7. `docs/02-数据字典.md`：如加字段则同步 DDL；`docs/51` 本指令归档为已做。

### 3.4 冻结多库

8. `appsettings.WorkshopMesB.json` 顶部注释标注"**已冻结，不作为多账套手段**"；不删库、不迁移现有数据。

## 5. 明确不做（红线）

- 不做多库多实例；`WorkshopMesB` 仅冻结，不扩展。
- 不引入 EF Migrations 新升级机制，不用 `EnsureCreated` 之外的方式跑建表。
- 不改动所有业务表结构（`factory_id` 已够用）。
- 手机号登录维持禁用（`AllowPhoneLogin=false`）。
- 首版不做 H5/PDA 端选厂切换；现场端沿用"当前登录账套"。

---

## 6. 风险与注意

- 放开校验后，任何存在的启用账套都能被选 —— 建议后续加 `enabled` 开关（3.3）。
- 登录只是**选择入口**，数据隔离靠既有 `factory_id` 过滤，本指令不改隔离逻辑，避免动到报工/看板/工资等核心查询。
- 首次打开登录页会请求账套列表，网络异常须降级不挡登录。
