# 268-优化指令：报工成功回显本单金额（对标黑湖"每扫一下都在算钱"）

> 状态：**已并入 270，不再单独实施**（2026-10-23 黑帽大人拍板）。原定位是"Toast 加金额轻量版"，270 直接把 Toast 升级成"恭喜入账"喜庆弹窗，已把本指令的金额口径、多人合报本人那份、无价降级 Toast、计时/固定工资口径、111 红字不受影响等验收点全部吸收。本文件保留作历史依据，Cursor 实施时以 270 为准。
> 一句话目标：报工提交成功那一刻，Toast 直接回显「本单 +¥X.XX」（多人合报显示「本人 +¥X.XX」），把"扫码"这个动作和"算钱"这个结果焊死；补上 206「今日计件」只有累计、没有"这一下多少钱"的缺口。
> 依据/拍板：2026-10-23 多隆老同学与黑帽大人对标黑湖后拍板；与 206「今日计件汇总」同族——206 做"今天累计"，本指令做"本单金额"。
> 指令写法：全部步骤用「前置判断 → 条件执行 → 收尾」三件套；条件可判定、判断在动作之前；不满足前置判断就停，不硬改。

## 一、动机：为什么「今日累计」不够

| 维度 | 206 今日计件（已做） | 本指令 本单回显（待做） |
|---|---|---|
| 反馈频率 | 一天一个总账，扫多少次都是同一个数在涨 | **每扫一下一个精准的数** |
| 工人感知 | "我今天赚了 ¥1.50" | "**我这一下 3 件 = ¥0.50**" |
| 工价配错 | 总数错了不易察觉（记不住每单多少件） | **这单金额不对当场爆** |
| 因果链 | "扫码→算钱"稀释成"今天→总钱" | "这一下→这一下多少钱"焊死 |

核心价值：本单回显让工人变成免费的"工价质检员"——工价配错在扫码那一刻就现形，当场找班组长/实施方，不等月底对账爆发。这是"人盯人交付"最直接的抓手。

## 三、改动点（纯前端，1 处）

`frontend/src/views/h5/report.vue` 的 `formatReceipt(data)`（约 901–912 行）。不动后端、不加接口、不改表、不动 267 的布局与按钮。

### 3.1 目标文案（分四种分支）

金额统一 `Number(w).toFixed(2)`，如 `1.50`。

| 分支 | 当前 | 目标 |
|---|---|---|
| 单人·有价 | `工序 良品X 不良Y（状态）` | `工序 良品X 不良Y（状态）本单 +¥W` |
| 单人·未配工价 | `… · 未配工价` | 保持 `… · 未配工价`（不显示金额） |
| 多人·有价 | `已为 N 人分摊，合计良品 X（状态）` | `本人 +¥W · 已为 N 人分摊，合计良品 X（状态）` |
| 多人·未配工价 | `… · 未配工价` | 保持 `… · 未配工价` |

### 3.2 取值口径

- 单人：`w = list[0].wageAmount`。
- 多人：`w = list.find(r => Number(r.userId) === myUserId)?.wageAmount`（本人那条；分摊后的各自金额后端已算好）。
- `wageAmount == null`（未配工价）→ 走"未配工价"分支，不显示金额、不报错。
- 金额口径与 206 一致：`wage_amount` 是提交时按工价算的快照，待复核可能退回/改数。**不额外加"预估"字样**——现有（待复核/已通过）状态字已提示，避免 Toast 过长。
- 计件/计时/固定三种计价都能回显（`wage_amount` 对三类通用），文案统一叫「本单 +¥W」，不写"计件"二字。

## 四、Cursor 原子指令（前置判断 / 条件执行 / 收尾）

**一句话目标**：`formatReceipt` 在报工成功 Toast 里回显本单金额；无价仍走"未配工价"。

### 步骤1｜改 `formatReceipt`
- **前置判断**：当 `report.vue` 第 901–912 行 `formatReceipt` 可定位、且函数签名仍是 `formatReceipt(data)` → 继续；对不上 → 停下报「位置+现状」，不硬改。
- **1a 条件执行**：
  - 当 `list.length === 1` 且 `list[0].wageAmount != null` → 返回 `工序 良品X 不良Y（状态）本单 +¥${w.toFixed(2)}`。
  - 当 `list.length === 1` 且 `wageAmount == null` → 保持现有 `… · 未配工价`。
  - 当 `list.length > 1` → 取 `w = list.find(r => Number(r.userId) === myUserId)?.wageAmount`；当 `w != null` → 返回 `本人 +¥${w.toFixed(2)} · 已为 N 人分摊，合计良品 X（状态）`；当 `w == null` → 保持现有 `已为 N 人分摊… · 未配工价`。
  - 当 `list.length === 0` → 保持返回 `报工成功`。
- **1b 收尾**：当改完 → 保存；当异常 → 报「位置+失败」，不吞。

### 步骤2｜编译 + 验收
- **前置判断**：当步骤1完成 → 编译；未完成先补齐。
- **2a 条件执行**：当可运行 → 按 §四验收清单逐条勾；当任一不符 → 回步骤1修正重验。
- **2b 收尾**：当全过 → 标记完成；当不符 → 如实报「现状」，不标完成。

**一键关闭**：本指令纯前端文案回显，不改计价/结算/确认规则；不想继续 → 还原 `formatReceipt` 一处即可，不影响数据。

**失败原因要求**：失败时回显写明「位置 + 做什么失败 + 现状」，不吞错、不脱敏。
