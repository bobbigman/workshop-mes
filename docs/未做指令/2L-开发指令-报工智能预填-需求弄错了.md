- **交付流程（完整闭环）**：PC 派工界面选工序 → 系统按历史报工查候选人 → 弹"推荐派给谁"排序名单 → 班组长一键选/微调 → 点确认 → 走现有派工（执行人）逻辑。

  - 已有：`ReportService.cs` 报工（`prod_report` 含操作人/工序/良品/时长）、派工选执行人、排产评分 `calc_schedule_priority`（不混入本次）。

- **数据与契约**：推荐候选 = 该工序报权部门内人员（**遵守硬规则：派工权限=部门**），按近 30 天该人+该工序报工综合分排序；样本不足（如该工序报工 <3 次）不推荐或只列现有执行人。不改表、不改派工提交契约。
- **文档**：新增派工交互，若改业务规则同步 `docs/01` 对应章节；不改表可不改 `docs/02`。

## 行为与口径（分叉写成显式条件）

- 当【选工序，且该工序近30天有 ≥3 次报工】→ 派工界面显示"推荐派给谁"：按综合分排序候选名单（姓名+分数），默认高亮第一名，班组长可一键选或改选。
- 当【该工序报工 <3 次 / 无历史】→ 不显示推荐名单，保持现有执行人选择，不硬推。
- 当【班组长确认推荐人】→ 走现有派工逻辑，执行人=所选人。
- 当【班组长微调（改选其他人）】→ 以班组长选择为准，推荐仅作参考。
- 推荐候选**仅限该工序报权部门内人员**（硬规则：报工权限=部门，不越权推荐）。
- **绝不**：自动派工（跳过班组长确认）、推荐越权部门人员、把排产建议顺序混进派工推荐。
