# 优化指令：微信预警配置页「效果预览」与文案引导

> 状态：**待做（未开始）**
> 依据：`docs/20`（企业微信预警，已实现）；`docs/37`（上门演示脚本）；`docs/55`（能力口径红线）
> 目标：让客户老板 / 车间主管打开「微信预警」配置页即**眼前一亮**，一眼看懂"以后我手机上会收到什么提醒"，省销售口头解释
> 交付节奏：纯前端展示改动；不新增业务规则、不改数据字典、不动推送逻辑

---

## 背景（为什么改）

当前「微信预警」页是纯**运维配置页**：满屏技术字段（CorpID / Secret / AgentId / 接收人 UserId），且一进来就显示"可选功能，默认关闭""已关闭"。

老板 / 车间主管看到这个页面只会一头雾水、甚至被"已关闭"三个字吓退，达不到"这就是我要的功能"的效果。配置表单本身就该枯燥（是实施时填的），**不该硬拗惊艳**；要让人眼前一亮的，是把**"推送效果长什么样"可视化出来**。

---

## 定位与判断（重要，先读这一段，防做偏）

- **本页改动是「辅助 / 种草图」，不是签单主力。** 老板 / 车间主管不会主动打开配置页，"预览卡"的真实作用是：给车间主管自己点开时确认"哦，原来手机上能收到这个"，**不是用来当面说服老板下单的东西**。
- 让老板眼前一亮的**真实路径，优先级从高到低**：
  1. **演示当场真推一条到自己手机**，举起来给老板看——最真实，一次顶一百张预览图；
  2. **30 秒演示录屏**（真推送录下来），一次制作、反复发送，老板 / 车间主管自己点开看；
  3. **一句案例话术**：「**某张单离交期还有 2 天、还卡在第三道工序，你手机上就收到了**」——这是竞品（黑湖小工单）的签单杀手锏。
- **对标事实**：黑湖小工单、简道云都真做了"交期预警主动推送"，但卖点全是**场景效果与案例故事**，公开资料无一靠"配置页预览卡"打动老板。
- **给 Cursor 的边界**：预览卡做**轻量静态展示**即可——不做复杂动效、不做花哨大页、不占用主推演示时间；签单素材重心在**上述 1 / 2 / 3**，本页只是"锦上添花"。

---

## 本期做什么（三个改动）

### 1. 顶部加「推送效果预览」区块（核心，见 docs/37 演示第五步收尾）

- **位置**：配置页顶部、说明文字下方
- **内容**：仿企业微信消息卡片的**静态预览**，两条示例——
  - 黄（临期）：`工单号 / 产品 / 工序 / 计划交期 / 剩余 X 天`
  - 红（超期）：`工单号 / 产品 / 工序 / 计划交期 / 已超期 X 天`
- **预览旁配引导语**：「**开通后，你手机上每天到点就收到这个，不用自己盯看板。**」
- **实现**：纯前端静态 mockup（div 仿微信气泡 / 卡片样式），**不调用企业微信 API、不依赖配置状态**，未配置也直接显示

### 2. 顶部文案改引导式

- **现**：「可选功能，默认关闭」「现在不用开也能用系统…等工厂办好认证再开」
- **改**：「**看板黄红马上能看；企业微信推送到手机，开通后每天到点提醒你**」+ 保留"可选"提示，但弱化"关闭"的负面开头
- **保留**：首次说明弹窗（`docs/20` 已有）与"未配置时静默跳过"的工程行为不变

### 3. 演示路径直达

- 预览做成**可点击放大**的独立视图（或独立演示页），演示时直接给老板看那张消息卡片
- 配置表单保持现状（运维页），不因演示优化而改动提交逻辑

## 验收清单

- [ ] 打开「微信预警」页，顶部可见两张微信消息卡片预览（黄 / 红），**无需任何配置即显示**
- [ ] 预览字段口径与实际推送消息一致（工单号 / 产品 / 工序 / 交期 / 剩余或超期）
- [ ] 顶部引导文案替换完成，无"默认关闭 / 已关闭"负面开头
- [ ] 预览可点击放大，演示时直达到位
- [ ] 配置项、保存、发送测试、推送超期工单四个动作行为**完全不变**（回归 `docs/20`）
- [ ] 数据字典无改动；不新增业务规则

---

## 红线

- 本指令为**纯前端展示优化**：不新增 API、不改推送逻辑、**不开自动定时**
- 未闭环能力口径仍按 `docs/55`：**不承诺自动定时推送上线时间**
- 演示时推送画面用"推到自己手机给老板看"，不让老板当场配置（企业微信应用消息仅发本企业成员）
