# 111-优化指令：工资防错源头化（最贴黑湖版）——无价当场亮红 + 引导回工价库补配

> 状态：待落地（未做）
> 一句话目标：对齐黑湖"配价在源头工价库、报工即计价、按报工时间套版本"——**报工那一刻就有价，没价当场红字现形、一键引回工价库补配**；生成工资单再兜底告警，杜绝"报了工却不知道没算到钱"。
> 指令写法：全部步骤用「前置判断 → 条件执行 → 收尾」三件套，条件可判定、判断在动作之前；不满足前置判断就停，不硬改。

---

## 〇、黑湖机制澄清（定稿依据，docs/2G 官方口径）

黑湖的工资链路拆成**两步、清清楚楚**，不是"事后补价"：

| 环节 | 黑湖怎么做 | 结论 |
|---|---|---|
| 配价 | **源头工价库**维护工序单价（报工前配好） | 配在源头，不在报工页 |
| 计价 | 扫码报工即**按当时工价自动计价** | 报工那一刻就有价 |
| 版本 | 工价变更**按报工时间套对应版本**，历史不被覆盖不重算 | 报工即锁价 |
| 纠错 | **报表可重算**，靠源头防（防超报/留痕/版本），**不靠死拦/死冻** | 纠错留门 |

→ 因此最贴黑湖的落地方向是：**价配在源头工价库（已有功能，不动），报工端只做"计价 + 无价当场亮红 + 引导跳工价库补配"**，A0001 这类在报工/复核当场就现形，不等发工资。

## 一、背景：实测问题（工单 A0001）

- A0001（李厨·装盘·良品1）等三条，复核通过、未结算，提交时未匹配到工价 → `unit_price/wage_amount` 为 `NULL`，**全程无提示**，悄悄落库。
- 生成工资单 → 全0草稿照常生成，只弹「已生成 N 张」，没人提醒"有 N 条未匹配"。
- 根因：**定价机制已有**（`ReportService.SubmitAsync` → `PreviewWageAsync` 提交时按报工时间计价留痕），**缺的是"无价可见 + 引导补配"**。

## 二、落地方向（已拍板：最贴黑湖）

- **A段（源头）**：报工/复核/我的报工/我的工资四处，**无价 → 红色「未配工价」标识 + 「去补价」按钮**，点它跳转工价表页（`/price-rule`）补配。**不做硬拦截**（黑湖纠错留门；不误伤"故意不计价"的工序，由管理员自己判断）。

## 四、Cursor 原子指令（前置判断 / 条件执行 / 收尾）

**一句话目标**：无价当场亮红 + 引导跳工价库补配（A段）；生成工资单兜底告警（B段）。

**前置确认（无需人拍板，方向已定）**：不设硬拦截；"未配工价"一律红字可见，是否补/是否故意不计价由管理员在工价库判断。

### 步骤1｜A段：前端把"无价/单价"亮出来（核心，必做）
- **前置判断**：当 5 处前端文件（PC报工/H5报工/PC复核/H5我的报工/H5我的工资）均可定位 → 继续；任一处对不上 → 停下报「位置+现状」，不硬改。
- **1a 条件执行**：
  - 当 PC 复核页 `review/index.vue` → 表格加「单价」列：当 `unitPrice` 为空 → 红字「未配工价」+「去补价」；当有值 → 显示金额。
  - 当 PC 报工页/H5 报工/H5 我的报工 → 报工记录上：当 `unitPrice` 为空 → 红字「未配工价」；当有值 → 显示单价与金额。
  - 当 H5 我的工资 `my-wage.vue` → 当 `UnitPrice/Amount` 为空 → 该行标「未配工价」；当有值 → 正常显示。
  - 当任一处无价 → 「去补价」点击跳 `/price-rule`（仅管理员可见；工人端只标不跳）。
- **1b 收尾**：当 5 处全改完 → 保存；当有异常 → 报「位置+失败」，不吞。

### 步骤2｜B段：生成工资单兜底告警（并入 110）
- **前置判断**：当已按 110 完成"生成时未匹配告警" → 本段视为完成，跳过；当未做 → 按 110 执行（后端 `GenerateAsync` 返回 `unmatchedCount` + 前端 `onGenerate` 弹「N 条未匹配、金额0」警告）。
- **2b 收尾**：当完成 → 记录；当异常 → 报「位置+失败」，不吞。

### 步骤3｜老数据处置
- **前置判断**：当已上线旧报工（如 A0001）`unit_price` 为 NULL → 需处置；当无老数据 → 跳过。
- **3a 条件执行**：当要补老数据 → 用现有工价规则对周期内未匹配的已通过报工**重算快照**，并列出仍无价的需管理员确认；当选择不补（仅新数据生效） → 明确记录该决定。
- **3b 收尾**：当处置完 → 核对 A0001 三条；当异常 → 报「现状」，不吞。

### 步骤4｜编译 + 验收
- **前置判断**：当步骤1–3 完成 → 编译；未完成先补齐。
- **4a 条件执行**：当可运行 → 用 A0001 验收：①报工/复核/我的报工/我的工资能看到红色「未配工价」；②管理员端有「去补价」能跳 `/price-rule`；③生成工资单弹「N 条未匹配」警告；④补好工价重生成 → 金额=良品×单价、标识消失；当任一不符 → 回对应步骤修正重验。
- **4b 收尾**：当全过 → 标记完成；当不符 → 如实报「现状」，不标完成。

**一键关闭**：A段纯"展示+跳转"、B段纯"告警"，均不改计价/结算/确认规则；任何一步不想继续 → 停止并还原 5 处前端 + 110 两处改动即可，不影响已生成数据。

**失败原因要求**：任何一步失败，日志/回显写明「位置 + 做什么失败 + 现状」，不吞错、不脱敏。

**验收口径**：A0001 场景——无价在 4 处红字可见、管理员「去补价」能跳工价表页、生成工资单弹未匹配警告、补价重生成后金额=良品×单价。全过才算完成。
