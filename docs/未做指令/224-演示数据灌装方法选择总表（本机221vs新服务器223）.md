# 224 - 演示数据灌装方法选择总表（本机 221 vs 新服务器 223）

> 目的：下次要灌演示数据，先看这张表判断用哪份方法文档，别拿错。
> 依据：221（本机 fid=5，SQL 直连版）+ 223（新服务器 fid=2，纯 API 版），均 2026-10-10 实测。
> 用法：先读「一、怎么选」→ 定用哪份 → 再翻对应文档照跑。

## 一、怎么选（30 秒判断）

1. **目标环境在哪？**
   - 本机 `https://localhost:5173`（后端 `127.0.0.1:8080`）→ **用 221**（SQL 版）
   - 测试服务器 `https://103.39.222.133:11302` → **用 223**（纯 API 版）
2. **能不能直连 SQL Server？**（`sqlcmd -I -S localhost -d WorkshopMes -E` 能否通）
   - 能 → 221 全功能（**可回填时间线 + 一键重置**）
   - 不能（只有 API）→ 223，但**无时间回填、无一键重置**
3. **演示要不要「历史累积感 + 一键重置」？**
   - 要 → 必须 SQL 直连，用 221
   - 只要"当前紧张感"（超期/临期/异常/达成率梯度）→ 223 纯 API 够用

> 一句话：**本机 SQL 版能回填能重置（221）；服务器纯 API 版只能造当前紧张感（223）。按「目标环境 + 是否需要历史/重置」选，别拿错。**

## 三、关键坑（两版通用）

1. **完成量 = 各工序良品最小值**：只报首尾工序会全 0%，必须给末道（质检/组装/包装）补报。
2. **API 中文**：body 一律 UTF8 bytes 写文件再 `curl --data-binary @file`，否则存成 `?`。
3. **超期判定**：`dueDate <= 今天 且未完成 → overdue`；要凑「超期=2」，把其余单 `PUT /WorkOrder/{id}` 把 dueDate 推到明天。
4. **服务器版建异常必须 multipart**，中文用 Python `http.client + ssl._create_unverified_context()`。
