## 二、目标与明确取舍

工人在手机或 PDA 打开 `/h5/orders`，工单卡片可见“销售订单号”等已配置字段；通过筛选查到同一销售订单对应的所有现场可见工单，再点击工单进入现有报工页。

1. 这是通用自定义字段能力，按字段 ID 读取，禁止硬编码“销售订单号”名称。
2. 复用 `showInOrderList`：PC 和手机共用管理员配置的显示字段，手机以卡片键值行展示。不开第二个手机开关，不改数据库结构，不创建手机配置页。
3. 管理员仍在 PC 创建字段、配置显示、填写和修改工单；本期不增加手机建单、编辑自定义字段或打印功能。
4. 筛选可选择当前工厂所有工单自定义字段，即使未开启展示也可筛选。一次筛选一个字段。
5. 复用原状态 Tab、关键字搜索、进度/交期/工序摘要、底栏及点击报工路径；继续排除已取消工单。因此“所有相关工单”指符合当前状态和其他条件的非取消工单，已取消工单仍在 PC 查。
6. 显示开关是展示配置，不是字段级保密权限。继续遵守现有账号权限和工厂隔离，不在本期引入字段权限系统。

## 四、手机交互

### 4.1 卡片展示

- 在产品信息下方、进度信息上方，按字段 ID 升序展示开启 `showInOrderList` 的字段，格式为“字段名称：字段值”。
- 通过 `row.ext[field.id]` 读取，空值显示“—”；数字字符串 `0` 不得当成空值。
- 使用普通文本绑定，不使用 HTML 渲染字段名或值。
- 长名称、长订单号允许换行，长连续字符可折行，不使页面横向溢出。首版直接展示完整值，不依赖鼠标悬停，不增加折叠规则。
- 无显示字段时不留空白区域；点击卡片仍按工单号进入现有报工页，不将销售订单号当工单号。

### 4.2 筛选入口

- 搜索区增加“筛选”按钮，通过 Vant 底部弹层呈现控件，避免窄屏横排拥挤。
- 弹层包含：自定义字段选择、匹配方式、筛选值、“重置”“确定”。
- 文本类型支持“精确匹配/包含”，默认精确；单选类型使用选项选择且固定精确；数字类型固定精确，沿用后端字符串比较，不自行转数值。
- 单号文本输入可输入字母、横线及前导零，不使用纯数字键盘限制单号。
- 切换字段清空旧值并恢复默认匹配方式。字段空值表示不应用自定义条件；禁止有值无字段。
- 弹层使用草稿条件，点击“确定”才应用并回到第 1 页；取消/关闭弹层不改变已应用条件。
- “重置”清空草稿中的自定义筛选，点击“确定”后生效；页面显示已应用条件摘要及清除按钮，清除立即移除自定义筛选并回到第 1 页，不清除关键字与状态。
- 关键字、状态、自定义筛选按 AND 组合，原关键字搜索不自动匹配所有自定义字段。
- 无可选工单自定义字段时隐藏筛选入口；有筛选时展示“筛选结果 N 条”，Tab 仍为原全厂状态数量，不把 Tab 数量伪装成当前筛选数量。

### 4.3 分页、刷新及竞态

- 将固定只取前 100 条改为真正分页：首版每页 20 条，底部“加载更多”，加载完后显示“已全部加载”，不以增大 pageSize 代替分页。
- 使用接口 `total` 判断是否还有结果；页面正常加载时不显示“暂无工单”。失败显示可重试提示，不能伪装成空结果或全部加载完毕。
- 关键字变更、状态变更、自定义条件应用或清除都重置到第 1 页。加载更多保持整组条件，并防止重复点击造成重复请求/重复追加。
- 通过请求序号、查询版本或取消机制防止旧请求覆盖新结果；条件改变后，旧“加载更多”响应不得追加到新结果中。旧请求的 finally 也不能破坏新请求的加载状态。
- 统一处理关键字防抖与回车查询，避免回车后待执行的防抖重复请求；离开页面清理定时器。
- 从报工页返回保留当前关键字、状态、自定义条件，重新刷新第 1 页及状态数量，保证报工后的进度及时更新；不要求恢复原滚动位置和已加载页数，不把条件带到其他账号/工厂。
- 结合实际路由挂载/缓存机制处理返回刷新，避免 mounted/activated 双重请求。进入页面或返回时重取字段定义；已删除字段清理条件，改名/显示开关变更及时生效。
- 字段定义加载失败需要可见错误和重试，不得当成“未配置字段”。

## 五、接口、安全及兼容规则

复用 `GET /api/CustomField?target=work_order` 和 `GET /api/WorkOrder`，参数包含 `page`、`pageSize`、`excludeCancelled=true`，以及可选 `keyword`、`status`、`customFieldId`、`customFieldValue`、`customFieldMatch`。不新增一套手机筛选 API。

- 筛选必须在服务端分页前执行，不能只搜索本页或手机已经加载的卡片。
- 与 PC 一致：文本精确/包含，单选及数字精确；首尾空白、长度上限 256、特殊字符、非法参数行为沿用共用契约。包含查询中的 `%`、`_`、`[` 按普通字符匹配。
- 后端以登录工厂限定字段定义、工单及字段值，校验字段归属为 `work_order`，禁止串到产品/工序同 ID 数据或其他工厂数据。
- 工人和班组长只能使用已有只读配置查询和允许的报工能力，不得获得字段配置及工单新增/修改/删除权限。
- 不修改现有部门报工权限判定。能查到工单不代表有权报其全部工序。
- 原 PC 列表、录入保存、打印、扫码报工和不带筛选参数的接口调用应保持可用。
- 如必须修复共用后端，补充针对性测试并同步相关权威文档；不得只为手机正常显示而吞掉后端异常。
