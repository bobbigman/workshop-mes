# 需求分析：自动派工（黑湖对标与可行性）

> 定位：分析/对标稿（非开发指令）。回答伙伴的"能否做到自动派工、没有人派工"。
> 扒底时间：2026-10-12。来源：黑湖官方 `blacklake.cn` + 黑湖小工单官网/SEO 站（`xiaogongdan.cn`，注意该域名多为营销/SEO 站，非黑湖官方，话术打折看）。
> 关联：`docs/36`（排产评分，S3 已实现）、`docs/29`（派工到人，已完成）、`docs/1D`（对标纠偏）、`docs/16`（待办第三期）。

---

## 一、结论（一句话给伙伴）

**"完全无人自动派工"黑湖也没做到；能做到的是"半自动派工"——系统按规则自动派到具体人，人保留一键确认/改派。咱的排产评分（docs/36）已经做了一半，补齐"自动落到人"即可。**

---

## 二、黑湖到底怎么做的（扒底，别被营销话术唬住）

| 环节 | 黑湖做法 | 真实程度 |
|---|---|---|
| **自动拆单** | 拆单 Agent：图纸→结构化加工步骤→接入小工单流程"完成信息派发" | ✅ 官方（blacklake.cn 工业 Agent） |
| **自动排程（建议顺序）** | 排程/排产 Agent："订单与产能→生产计划"，秒级算机台负荷、生成甘特图、插单模拟、推荐最优顺序 | ✅ 官方；但定位是"**辅助排产员**提升效率"，是**建议不是全自动** |
| **自动派到具体人** | 官方/抖音口径一致：生产主管"**一键派工下达**"、班组长**手机点选派工**、厂长"派小李去切木板、老王去焊桌腿" | ⚠️ **仍是"人"在派**，没有无人自动派到人 |
| 营销话术 | "工单按工艺路线自动拆分工序、按分配规则下发到车间和工人" | 🔻 SEO 站话术，只到"自动拆单/下发到班组"，**没到自动派到具体人** |

**结论：黑湖 = 自动拆单（有）+ 排程给建议（有）+ 派工靠人一键（仍有）。** 真正"中枢智能体自动点兵派工"是天智等重型智能工厂的 demo 宣传，不是黑湖小工单能干的事，别拿它当对标承诺。

---

## 三、自动派工拆三层 → 咱能不能做的判断

1. **自动拆单（订单→工序任务）**：咱建工单就带工艺路线工序，**天然已有 ✅**
2. **自动排程（建议开工顺序）**：咱已实现 `ScheduleScoreService` 五维评分→`suggestSeq`（docs/36，S3 已实现、不依赖豆包）**✅ 已有**
3. **自动派到具体人（写 assignee_user_id）**：❌ 缺。黑湖也没全自动。

→ 伙伴要的"无人派工"，核心缺口在第 3 层，而第 2 层咱已经铺好。

---

## 四、可落地的"半自动派工"（推荐方案）

在既有评分 `suggestSeq` 基础上，加一个**确定性派工规则服务**（不靠大模型估）：

- **触发**：建单 / 评分完成后自动跑一次；也可手动"一键重派"。
- **规则**（按序取待派工序）：
  1. 该工序报工权限部门（红线：报工权限=部门）内；
  2. 在岗（未停用，复用 219）；
  3. 负荷最轻（当前已派/已报数量最少）的工人；
  4. 写入 `prod_work_order_operation.assignee_user_id`（字段已存在，docs/29）。
- **人可干预**：班组长/管理员一键确认、改派、取消（保留 docs/29 的 override，符合"正确性>简洁"）。
- **边界（诚实口径）**：对外讲"**自动推荐派工 + 一键确认**"，**不承诺完全无人**——毕竟派错人、特殊在岗情况还是要人兜底。

---

## 五、不做（硬边界，防做成 APS）

| 项 | 原因 |
|---|---|
| 完整 APS / 机台甘特 / 卡时 / 有限产能排程 | docs/36 §5 已明示"只做优先级评分，不做时段占用" |
| 派工强绑报工（没派工不让报） | docs/29 已否决，避免卡死自选工序报工 |
| 自动下推开工 / 改金蝶单据状态 | docs/36 §5：演示期只读+算分，写回另开 |
| 进销存 / 采购联动 | 范围外（docs/1D） |

---

## 六、要不要做（给伙伴的一句话）

值得做：**是"半自动派工"，不是"无人派工"**。能省的正是班组长最琐碎的"每天开盘一个个点"；且排产评分已实现，这一步改动小、差异大，可当卖点。唯一要按住的是——**别对客户吹"全自动无人"**，按 docs/102 指令模板写"性质+取舍+边界+验收"再开工。
