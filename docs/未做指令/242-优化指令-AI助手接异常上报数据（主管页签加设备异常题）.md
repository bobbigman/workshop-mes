## 本次范围与落点

### 后端：`backend/Services/AiToolDispatcher.cs`

1. 新增工具定义 `SearchAbnormalTool()`：
   - 名称：`search_abnormal`
   - 描述："查询异常上报记录（设备故障/物料短缺/质量异常），可按状态和类型过滤。status=0 未处理，status=1 已处理；不传查全部。abnormalType 1设备故障 2物料短缺 3质量异常。"
   - 参数：`status`(int 可选)、`abnormalType`(int 可选)、`page`(int 默认1)、`pageSize`(int 默认10，最大20)
2. 在 `ToolsForMode("support")` 的工具数组里加上它；`ModeTools["support"]` 白名单同步加 `"search_abnormal"`
3. 在 `DispatchAsync` 的 switch 里加分支 `"search_abnormal" => await SearchAbnormalAsync(root, session, ct)`
4. 新增私有方法 `SearchAbnormalAsync`：
   - 按 factoryId 过滤（`session.FactoryId`，和现有查询一致，不接受前端传 factoryId）
   - status / abnormalType 可选过滤
   - 排序：未处理按 ReportedAt 升序（**最早拖最久的排最前**，主管一眼看见最急的）；已处理按 RecoveredAt 倒序
   - 联表 Users 取上报人/处理人姓名；联表 WorkOrders 取 OrderNo
   - 返回精简 JSON：`{ total, list: [{id, typeLabel, description, reporterName, reportedAt, status, handlerName, recoveredAt, minutesOpen, orderNo, handleNote}] }`
   - `minutesOpen` = 未处理则 (now - ReportedAt).TotalMinutes 取整；已处理则 (RecoveredAt - ReportedAt).TotalMinutes 取整。让 LLM 直接报"拖了 X 分钟/小时"，不必自己算
   - 不返回 ImagePath（LLM 不需要）
5. 不动 `AiAssistantService.cs`、不动 system prompt（工具描述里说清楚即可）

## 行为与口径

- 当主管点"现在有几条设备异常还没处理？" → 后端调 `search_abnormal(status=0)`，AI 概括总数 + 列出最早 3 条（类型、描述、上报人、拖了多久）
- 当主管点"拖最久的那条设备异常是啥情况" → 同样 status=0 升序，AI 报第一条详情（谁报的、什么问题、关联哪个工单、处理人是谁）
- 当没有未处理异常 → AI 答"当前无未处理异常"，不编数据
- 当用户在 AI 里要求"帮我把 XX 异常处理掉" → AI 按 system prompt 现有"只读"口径引导去 PC 异常列表
- 当新工具在 progress/guide 模式下被调 → 后端直接拒"该功能在当前模式下不可用"（白名单机制天然保证）
