# 273-优化指令：手机更多功能与工人AI操作帮助

> 状态：待做，方案稿；2026-10-23。
> 性质：正式生产功能优化。
> 本次交付：用户要求按界面分析拟定指令，本轮仅交付文档；不实施代码、不部署。
> 目标：工人在手机工作台能找到有用的查询功能和AI操作帮助，无须在两套界面之间找入口。
> 依据：本次截图与点评、271已做结果，以及当前路由、菜单、AI控制器/服务/工具分发代码。以下为后续实施方案，尚未完成或验收。

## 取舍

| 项目 | 本稿方案 |
|---|---|
| 首页 | 保持271工作台及默认登录路径，不恢复手机默认进PC后台 |
| 更多功能 | 工作台新增清晰的“更多功能”入口，进入H5轻量功能页，只列当前账号适用的入口，不复制整套后台菜单 |
| 帮助 | 保留工作台帮助入口，进入H5帮助页，集中放“AI操作帮助、操作手册、常见问题”；不冒用浏览器自己的“问AI”按钮 |
| 管理人员 | 管理员/班组长仍可进原后台，把原灰色小字“管理后台”改成清晰的次级按钮；普通工人不增加管理后台按钮 |
| AI范围 | 首版只回答系统操作与常见问题，不查真实工单、报工、工资、异常或工艺资料，不做业务写入 |
| 实现 | H5使用Vue3+Vant；查询页面复用原页面，新增少量入口页，不重做PC报表和看板、不改表 |

## 已核实的现状与缺口

- `frontend/src/views/h5/home.vue`：已有帮助入口；“管理后台”仅非生产人员可见且样式较弱。普通工人进入工作台后缺少报表等已有查询能力的明确入口。
- 路由已允许普通工人访问生产报表 `/stat`、执行监控 `/execution-monitor`、看板 `/board` 等页面；基础资料、配置、排产、工资管理及 `/ai-assistant` 仍有管理员限制。
- `backend/Controllers/AiAssistantController.cs` 所有接口均校验管理员；`AiAssistantService` 的 `support` 模式可调用知识库和工单/报工/异常查询，`guide` 模式可读产品工艺，均不能直接当作工人纯操作帮助。
- 复用现有模型配置、连接客户端、会话所有权校验、取消/超时/失败清理及知识检索能力；新增独立的工人帮助入口和服务端工具白名单，不以隐藏页签替代权限控制。

## 行为与口径

### 1. 工作台与“更多功能”

- 工作台主操作、任务和原快捷入口保持271结果；新增“更多功能”次级按钮，不增加底栏项目，不抢占扫码主按钮的位置。
- 建议路由 `/h5/more`，展示下表中的现有查询入口，每项简短说明用途；根据角色、已有功能授权及工人视角决定显示，不显示点进去必然无权限的项目。

| 功能 | 目标 | 说明 |
|---|---|---|
| 生产报表 | `/stat` | 查看现有生产统计 |
| 执行监控 | `/execution-monitor` | 查看现有执行情况 |
| 车间看板 | `/board` | 查看现有车间进度；不新增大屏档功能入口 |
| 帮助 | `/h5/help` | AI操作帮助、操作手册及常见问题 |

- 当生产人员为“仅看我的任务”模式时，不通过新页面增加全车间工单/统计/监控/看板入口，仅保留帮助及原来已有的本人功能；不把菜单隐藏宣称为新增服务端数据隔离，本次不改原接口可见范围。
- 现有“我的报工”“我的工资”继续从原工作台入口进入；不在“更多功能”夹带PC报工管理、代报、补报、基础资料或管理员工资管理。
- 每个H5新增页有明确“返回工作台”。从更多功能打开现有PC查询页面时提供清楚的“返回工作台”入口；仅在H5来源访问时展示，复用原页面与原权限，不增加手机全局重定向。来源参数只决定导航，不授予权限。
- 管理员/班组长的“管理后台”按钮保留原目标及权限；原后台手机“报工端”能返回工作台，来回切换无需重新登录。

### 2. 帮助页面与AI操作帮助

- 建议路由 `/h5/help`；顶部“返回工作台”，正文为“AI操作帮助、操作手册、常见问题”三个清晰入口。手册和常见问题复用现有内容及页面，不新建知识库管理。
- 建议AI页面 `/h5/ai-help`，使用手机对话布局，显示固定用途“询问怎么使用系统”；提供扫码报工、查我的报工、报错数量、找不到任务等4～6条简短示例，不显示老板/主管/财务等管理员角色页签。
- 输入问题→发送→显示答复及本轮实际依据的操作说明来源；来源只能打开允许的帮助章节，不能借来源链接进入管理员业务页面或任意本地文件。
- 当AI已关闭、未配置或不可用时，明确显示状态，仍可打开手册/常见问题；不展示密钥、模型地址或连接测试按钮，不新增工人配置开关。
- 当加载、超时、取消或请求失败时，给出可理解提示并保留问题以便重试；取消/失败不能留下永久忙碌会话。支持新对话、结束本人对话，切换账号不串历史。
- 工人询问“我的工资多少、某工单完成多少、帮我通过复核”等数据/执行问题时，明确本入口只提供操作指导，引导去其可用页面查看或联系管理员；不得生成具体业务数字，不得声称已查询或已执行。

### 3. 后端契约与权限边界

- 建议新增已登录用户专用控制器，路由 `/api/worker-help`，允许当前有效账号的三个现有角色使用同一受限能力；身份/工厂从JWT取得，校验当前人员有效及所属工厂，拒绝客户端指定其他人或工厂。
- 最小接口：`GET /status` 返回启用/配置可用状态；`POST /messages` 接收 `message`、可选 `conversationId`，返回答复、本人会话ID和允许的说明来源；`DELETE /conversations/{id}` 仅删除本人本厂的帮助会话。优先复用已有响应DTO中适用的字段，但不返回业务查询结果、内部配置或凭证。
- 控制器强制指定独立 `worker-help` 模式；客户端不得指定或切换 `support/progress/guide`，管理员从该入口进入也只获相同操作帮助能力。请求携带其他模式时拒绝，不默认落入旧模式。
- 在服务和工具分发层为 `worker-help` 单独建立白名单，只允许检索已公开的用户操作说明；模型自行发起工单/报工/异常/产品工艺/工资等工具调用也必须被服务端拒绝，不调用底层业务查询。不能只靠提示词约束。
- 知识来源限定为现有手机操作手册及通用操作FAQ的已发布章节；实施时按实际检索索引的SourceId/章节标识建立服务器白名单，不按用户输入路径读文件，不检索配置、日志、内部部署/运维文档。过滤必须在摘录进入模型前完成，不能只隐藏最终来源卡。
- 会话仍按厂＋用户＋模式校验；猜测他人会话ID、使用管理员旧会话ID或跨厂会话均拒绝。不得共享管理员会话上下文、已查询数据或缓存结果。
- 保留 `/api/ai-assistant` 现有管理员校验及全部业务查询权限；不得将 `EnsureAdmin` 改成普通登录即可，不给工人放开旧数据查询、连接测试或配置权限。
- 复用现有输入长度、轮次、超时及会话清理约束，限制同人并发并支持取消；异常带上下文，模型及连接凭证不进入响应。新契约同步现有接口说明、PRD和当前操作帮助；无表变更无需修改数据字典DDL。

## 止步线

- 不新增工人AI实时数据查询、工艺问答、语音、上传、业务写入、外部机器人、个人效率排行或工资算法；后置能力不预建接口、配置开关或空按钮。
- 不改复核权限与“是否允许自审”规则；不因入口调整授予工人复核、派工、补报和后台配置权限。
- 产品编号唯一、部门报工权限、删除依赖倒序，以及既有金额追溯/重算规则保持。
- 本轮仅拟定指令；后续实施完成后据实际验证归档，不自动打包、部署或外发通知。

## 后续实施验收

- [ ] 普通工人从工作台进入更多功能，可打开允许的查询页并一键返回工作台；管理员/班组长可清楚找到管理后台并返回报工端。仅任务模式不新增全车间数据入口，底栏不增项。
- [ ] 三个角色均能从H5帮助入口问操作问题，得到带实际说明来源的回答；未启用/未配置/失败时可转看手册；360×640、常见手机及键盘弹出后输入、发送、返回和来源查看可用。
- [ ] 服务层验证工具越权：客户端改模式、模型发起业务工具调用、索引返回非白名单文档均被阻止；模型收到的上下文不包含被过滤的业务/内部资料。不能只用“模型回答说不支持”代替权限测试。
- [ ] 使用不同用户/工厂及管理员旧会话做隔离验证：不能读取、续聊或删除他人/其他模式会话；普通工人直接访问原AI管理/查询接口仍被拒绝。未登录、停用账号按原鉴权规则拒绝。
- [ ] 问工资、工单数量或请求复核时不查业务、不编造结果；失败/取消后可再提问、无串会话；完成必要后端测试、前端构建与隔离页面验证，不写真实报工。真实模型调用和真机未测时单列限制，未执行项不标通过。
