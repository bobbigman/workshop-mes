# 272-优化指令：代报工弹窗手机布局适配

> 状态：待做，方案稿；2026-10-23。
> 性质：正式生产界面优化。
> 本次交付：按用户截图和分析拟定指令，仅交付文档，本轮不实施代码、不部署。
> 目标：管理员、班组长在手机上代报时，能清楚地为每个人填写良品、不良及原因，控件不挤压、不越界、不串人。

## 取舍与依据

依据：用户本次代报工截图、界面分析，以及现有 `frontend/src/views/report/index.vue`。以下为本稿实施方案，尚未实施验收。

| 项目 | 本稿方案 |
|---|---|
| 改哪里 | 适配现有PC `/report` 的代报工弹窗，不新增H5代报入口、页面或接口 |
| 组件库 | 原页面是Element Plus，继续复用；不是新建H5页面，不为手机适配混入另一套表单 |
| 手机布局 | 窄屏全屏弹窗，标签上置、每人一卡、良品不良分别独占一行 |
| 电脑布局 | 保留适合宽屏的弹窗与操作习惯；不套用手机全屏样式 |
| 业务 | 每人填各自实际数量，不改成多人平均分摊；原权限、金额、提交与复核规则保留 |

## 已核实现状与范围

- 代报工弹窗固定 `width="720px"`，表单 `label-width="90px"`；每个人员行共用 `alloc-user`，内有180px人员选择、两个数量控件、140px不良原因和340px时间范围控件，手机发生标签断行与横向溢出。
- 不良原因当前在不良为0时禁用，大于0时提交必选；计时补报控件当前仅管理员可见。不能凭计件/计时业务猜测另加显示条件或取消已有能力。
- 现有 `proxyForm.rows`、候选人员、不良原因查询、`submitReportWithUpstreamConfirm`、`clientRequestId` 及 `timeFields` 继续复用。实施先检查已有未提交改动，避免覆盖。
- 本次只改代报工弹窗及必要的局部样式/前端状态、当前相关帮助文案；不改数据库、API契约、普通报工或多人分摊布局。样式不得通过共用 `alloc-user` 意外改变其它弹窗。

## 行为与口径

### 1. 手机容器与顺序

- 当视口宽度不大于767px时，代报工使用全屏弹窗；宽屏保持电脑弹窗。打开后改变视口也能正确适配。
- 顶部为“代报工”及关闭入口；中间正文独立滚动；底部为合计、取消、确认代报。输入法打开后能看到并滚动到当前输入，按钮不得遮挡字段，保留底部安全区。
- 手机正文顺序：工单号 → 已加载的产品/计划信息 → 工序 → 代报明细说明 → 人员卡片 → 添加工人。工单和工序标签置于输入框上方，不保留左侧90px空栏。
- 说明压缩为“记到所选工人名下，各人分别填写数量”；部门/班组限制可作为紧凑辅助说明，候选范围仍由原接口控制。未加载工单、没有可选工序/人员时明确提示，加载失败不能显示成无人员。

### 2. 每人一卡，数量分行

- 每张卡片包含：“工人1”等序号及“移除” → 全宽人员选择 → 良品数量 → 不良数量 → 有不良时的不良原因 → 管理员计时补报。
- “良品数量”“不良数量”分别作为完整标签，放在各自输入框上方；两个数量框禁止在手机上横排，不允许“不良”拆成散落的单字。
- 继续复用数量控件，支持点数字直接输入；若保留加减按钮，整组不得超出卡片。数量精度、范围和合法性沿用现有业务校验，不擅自改成只允许整数，不自动填剩余量。
- 人员卡片使用稳定的本地标识作为key，新增/移除中间人员后，姓名、数量、原因、时间必须仍属于原来的人；本地标识不进入API报文。
- 将“删”改为“移除”，位于本张卡片右上角，只移除这张尚未提交的明细；最后一张保持原有不可移除约束。“+ 加人”改为“+ 添加工人”。
- 底部显示“合计良品X · 不良Y”，取当前人员明细实时求和，仅供核对，不改变各人数量或后端计算。

### 3. 不良原因与切换

- 当某人的不良数量为0时，收起该人的不良原因，并清空对应原因值；大于0时在该人的不良数量下展开，必须选择当前工序可用原因才能提交。
- 当更换/清空工单或工序时，先使旧候选列表及其加载结果失效；以当前工单工序重新校验已选人员和原因，不合法的选择清空并明确提示，不静默换人或换原因。保留各人已填数量，供用户核对，不自动提交。
- 多次快速切换时只接受最后一次选择的加载结果；切换及加载期间不能用旧工单/工序数据提交。服务端权限校验继续保留，不能仅靠下拉框限制。

### 4. 计时与提交

- 管理员仍可按现有规则计时补报，班组长不新增该能力。手机将时间范围拆成“开始时间”“结束时间”两行，保留完整日期和时间；内部仍组合成原 `timeRange` 并通过 `timeFields` 提交，不能丢失日期、时分秒或改变时区语义。
- 不新增计时开关、默认时间或自动估算；未填写、只填写一端、结束早于开始的处理与后端现有完整性规则一致，错误要明确指出人员及时间问题，不悄悄补齐。
- 提交继续使用原代报接口与上游确认流程；保留逐人归属、部门/班组权限、防超额、幂等和事务边界。未配工价仍沿用原提示，不增加庆祝弹窗或改算工资。
- 提交中防止重复点击；失败保留原输入及原重试标识，结果未知不得换新标识自动再报。界面错误提示带可定位上下文，不吞异常。

## 止步线

- 不扩展为手机代报新业务，不新建H5代报页面，不重做PC报工管理页，不联动271工作台改版。
- 不修改代报与多人分摊的区别、工资/复核口径、部门及班组边界；产品编号唯一、部门报工权限、删除依赖倒序三条硬规则保持。
- 不改表、不改API、不升级组件库、不部署；发现已有后端业务缺陷时单独记录，不夹带重构。必要的前端校验只能对齐现有契约。
