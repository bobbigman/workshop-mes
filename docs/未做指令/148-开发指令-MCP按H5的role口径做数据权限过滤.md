## 已确认取舍（2026-10-07 用户授权“按建议处理”）

- 车间查询用钥匙 + 启用绑定账号授权，不额外要求金蝶授权码；金蝶工具保持原规则。旧 authToken 参数仅兼容旧调用，不参与扩权。
- 仅 role=1 查全厂工资；role=2/3 固定本人，财务名单和金蝶 IsFinance 不扩权。
- QuerySalary 沿用已生成工资单查询，不是工资预估；复用 SalaryQueryDto.UserId。
- 排产计算仅 role=1；员工/班组长拒绝，不查询业务数据。

## 现状与实施落点

- `RoleGuardMiddleware` 允许 role=2/3 调用 `GET /api/Report`；`ReportController.Query` 调全厂 `QueryAsync`，`/mine` 才调本人 `QueryMineAsync`。本文 MCP 报工限制采用本人接口口径，范围比现有全厂查询窄。
- `RequireBoundOrHintAsync` 能解析绑定账号，但只返回提示或 null，不把账号返回给工具；其 `QuerySalary` 特判仅允许管理员/配置名单。它不是所有工具通用的角色数据过滤器。
- `SalaryMcpTools.QuerySalary` 正式模式还调用金蝶 `RequireAuthAsync` 并检查 `IsFinance`。因此现有“管理员绑定”不保证能查工资，员工加 `UserId` 条件也仍会被提前拦截。
- `SalaryQueryDto` 已有 `UserId`；`QuerySalary` 是工资单列表。H5 `/api/Salary/mine` 调 `MineAsync` 返回本人工资预估，两者不能宣称等价。
- `ReportQueryDto` 没有 `UserId`；已有 `QueryMineAsync`，但 `ReportMineQueryDto` 的筛选项少于 MCP 现有入参。实现时保留工单号、产品编号/名称、复核状态筛选，必要时补兼容的查询参数，不静默丢弃条件。
- 允许最小范围调整 `McpWxBindService` 的工资权限检查、MCP 工具权限/返回投影以及 Service/DTO。不得用“只改工具方法体”阻止必要的权限修复。

## 工具权限矩阵

下表为已确认的执行矩阵。

| MCP 工具 | role=1 管理员 | role=2/3 生产人员/班组长 |
|---|---|---|
| `QueryWorkOrder` / `QueryWorkOrderProgress` | 本厂工单/进度 | 本厂工单/进度只读，按下述字段范围返回 |
| `QueryReport` | 本厂报工 | 仅 `FactoryId=当前厂 AND UserId=绑定账号` 的报工 |
| `QuerySalary` | 本厂已生成工资单 | 仅本人已生成工资单；无工资单返回空列表，不自动改查预估 |
| `CalcSchedulePriority` | 本厂排产计算 | 无权，返回拒绝，不查询排产业务数据 |
| `SearchSupportDocs` / `QueryProductionGuide` | 沿用现有本厂/公共说明资料范围 | 同现有资料范围只读，不扩大为所有后台文档或其他厂文件 |

### 正式模式分支

1. 钥匙校验、工厂身份仍走现有逻辑，不接受工具参数指定厂别。
2. 缺会话身份 → 沿用现有缺身份提示；未绑定、解绑、绑定账号不存在/停用 → 提示重新绑定，不返回业务数据。
3. 已绑定且启用 → 读取当前账号；role=1/2/3 按确认后的矩阵执行，未知角色拒绝，不默认当管理员。
4. 无权调用 → 返回稳定的失败结果 `code=1`、`msg=您（姓名）无权查询此数据`，使用 JSON 序列化，不拼接姓名生成 JSON；业务 list/data 不包含数据。
5. 普通员工调用 `QuerySalary` 自动固定本人，不需要“本人/全厂”入参；自然语言要求全厂不能改变服务端范围。首版不新增范围入参，因此不验收不存在的“全厂请求参数”。
6. 身份、角色与本人筛选不缓存进长期会话权限；账号停用、解绑或角色变更在下一次请求生效。

### 查询与字段约束

- **工厂与本人过滤必须在数据库查询阶段完成，再 Count、分页、汇总。禁止取全厂前 20 条后再过滤。** `total`、金额合计等也只能统计授权范围。
- 复用现有工资查询 `UserId`；报工复用/补充本人查询能力或兼容的服务端用户过滤参数，不能扩大 PC/H5 现有权限。
- 员工工单/进度仅返回定位与生产进度所需字段：工单号、产品编号/名称、状态、计划数量、交期、工序名称及其计划/完成数量、进度比例。现有响应中非敏感的定位 ID 可保留；不得带工价、工资、订单金额、客户联系方式或他人个人信息。
- 员工报工仅返回本人记录及其定位、时间、数量、复核状态等生产字段；不附带他人明细。本人已生成工资单允许返回现有本人结算字段，不以“不吐工资”误删本人金额。
- 工具不得直接序列化含额外敏感字段的业务 DTO；列表、明细、候选项、嵌套对象统一按允许字段投影。资料查询沿用现有文件范围，不能借文档检索旁路查询工资或账号信息。
- 同步工具 Description：明确本人工资单而非预估、各角色范围，以及确认后的授权码要求，避免模型继续提示员工只能被拒绝查询工资。
