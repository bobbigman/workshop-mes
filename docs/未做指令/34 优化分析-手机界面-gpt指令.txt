我看了你这套手机版的 `orders.vue / report.vue / scan.vue / TabBar.vue / theme.css`。整体方向是对的：**已经不是简单把 PC 页面压缩到手机，而是在做独立 H5 操作端**。尤其你已经有底部 TabBar、工单卡片、扫码入口、报工页，这个架构值得保留。

不过如果实际使用场景是**车间工人拿手机/PDA，站着操作、戴手套、快速报工**，我建议手机版不要追求“后台管理系统缩小版”，而应该往：

> **少看、少填、少点、按钮大、数字大、一步完成。**

你现在 `theme.css` 的手机适配主要还是“PC 后台在窄屏能用”：工具栏换行、表格横滑、弹窗全宽。
而 H5 已经有独立页面，所以我建议下一阶段**PC 和 H5 的设计思路彻底分开**。

## 一、工单页：这是最值得先改的

你现在一张工单卡里面有：

**状态 → 工单号 → 产品 → 工单进度 → 剩余数 → 工序流程 → 计划 → 交期 → 创建时间**

信息完整，但手机上略微有点“什么都展示”。工人真正需要快速判断的是：

**这是什么工单 → 做什么产品 → 还剩多少 → 做到哪道工序 → 能不能报工。**

建议卡片改成这样的视觉层级：

```text
┌─────────────────────────────┐
│ 执行中              WO26091801 │
│                               │
│ P001  电机外壳                 │
│                               │
│ 已完成  680 / 1000             │
│ █████████████░░░░  68%         │
│                               │
│ 剩余 320          交期 今天 18:00 │
│                               │
│ 下道工序：03 · CNC加工          │
│                         去报工 › │
└─────────────────────────────┘
```

### 具体建议

**1. “剩余数”不要做一个独立的小灰盒。**

你现在 `.remain-box` 单独占右侧空间，视觉上像一个 KPI 卡嵌套在工单卡里。手机上可以更简单：

**剩余 `320`**

其中 320 加粗、加大即可。

**2. 加真正的进度条。**

你现在有 `680/1000`，但没有直观进度条。车间场景下，工人扫一眼进度条比读数字快很多。

**3. 工序不要全部画圆点。**

目前每张工单都横向展示 `ops`。工序多以后，一张卡会明显变高，而且需要横滑。

建议默认只显示：

> 当前工序：03 CNC加工
> 下一工序：04 去毛刺

如果确实需要知道全过程，点进工单详情再看。

**4. 创建时间可以从卡片首页去掉。**

工人通常更关心**交期**而不是“这张工单什么时候创建”。

交期则应该强化：

* 正常：灰色
* 临期：橙色
* 超期：红色

你已经有 `due-warning / due-overdue`，这个逻辑可以继续保留。

# 二、顶部筛选：减少“后台味”

现在是：

```text
工单    [搜索工单号/产品]

全部 12  未开始 3  执行中 7  已结束 2

总计 (12)
```

我建议改成：

```text
工单                         🔍

全部 12     待生产 3     生产中 7     已完成 2
────────────────────────────────
```

搜索默认只显示一个搜索图标，点击以后展开搜索框。

这样第一页顶部能少占约 **40px 高度**。

另外：

> `总计 (12)`

基本没有必要，因为“全部 12”已经告诉用户总数了，可以删除。

# 三、报工页：应该成为整个手机版最强的页面

目前 `report.vue` 的基本流程很好：

> 工单 → 产品 → 计划/良品/不良/剩余 → 工序 → 良品数 → 不良数 → 原因 → 时长 → 提交

但是现在还是比较典型的“手机表单”。

车间报工最好做成**数字操作台**。

例如：

```text
WO20260918001
P001 · 电机外壳

CNC加工
────────────────────

计划        已完成        剩余
1000         680          320


本次良品
┌───────────────────────────┐
│            320             │
└───────────────────────────┘

      [-10]   [-1]   [+1]   [+10]


不良品                         0
──────────────────────────────

报工时长
[ 1 ] 小时      [ 30 ] 分钟


┌───────────────────────────┐
│         提 交 报 工         │
└───────────────────────────┘
```

### 这里我尤其建议改 5 个地方

**第一，良品数输入框做到 52～56px 高。**

你现在输入控件 `40px`，普通 SaaS 足够，但车间现场偏小。

手机版核心操作控件建议：

* 普通输入框：44～48px
* 数量输入：52～56px
* 主按钮：52～56px

**第二，数量是第一视觉重点。**

`goodQty` 应该成为整个页面最大的输入内容，数字字号可以做到 **24～28px**。

因为工人最重要的动作就是：

> 这次报多少。

**第三，增加快捷数量。**

非常实用：

```text
[-10] [-1]  100  [+1] [+10]

[报全部剩余 320]
```

特别是：

> **全部剩余**

这个按钮对尾数报工非常好用。

**第四，“不良品原因”不要一直占位置。**

现在即使不良数为 0，原因选择框仍然显示，只是 disabled。

建议：

```text
不良品   [ 0 ]
```

只有当：

```text
不良品 > 0
```

再展开：

```text
不良原因
[ 划伤             › ]
```

页面会干净很多。

**第五，提交按钮固定到底部。**

不要让工人填写完以后还需要找按钮。

建议：

```text
        页面内容


────────────────────────────
 [继续报工]    [提交报工]
────────────────────────────
          底部导航
```

而且考虑：

```css
env(safe-area-inset-bottom)
```

你现在 TabBar 已经处理了安全区，这是正确的。

# 四、你现在的“四个统计数字”可以重新设计

当前报工页：

```text
计划数 | 良品数 | 不良品数 | 剩余可报
```

4 个数字平分屏幕。

手机 375px 宽时，每项空间很有限。

我更推荐：

```text
计划 1000       已完成 680

剩余可报
320
```

其中：

**320 做最大。**

因为工人真正需要知道的是：

> “我现在最多还能报多少？”

而不是四个指标具有相同视觉权重。

# 五、扫码页目前太“空”

你现在扫码页实际上是：

```text
扫码报工

请用 PDA 扫描工单流转卡二维码

┌─────────────────────────┐
│       等待扫描……         │
└─────────────────────────┘
```

功能没问题，但产品感偏弱。

建议改成明显的扫描工作台：

```text
          扫码报工

       ┌────────────┐
       │  ┌──    ──┐ │
       │              │
       │     ▣ ▣      │
       │      ▣       │
       │  └──    ──┘ │
       └────────────┘

        等待扫描工单

   请扫描工单流转卡二维码


      [ 手动输入工单号 ]
```

PDA 扫码枪仍然保持隐藏/自动 focus 的输入逻辑。

但 UI 不需要让工人觉得：

> “我要点这个输入框才能扫码。”

而应该明确：

> **这个页面现在就在等你扫。**

# 六、扫码成功后最好直接进入“当前可报工序”

你目前扫码后进入 `/h5/report?order=xxx`，然后工人还需要：

> 选择工序 → 输入数量 → 提交

如果业务规则允许，我会强烈建议：

**只有一个可报工序时自动选中。**

例如扫码：

```text
WO001
 ↓
系统发现当前只有
03 CNC加工
可以报工
 ↓
直接选中 CNC加工
 ↓
光标进入良品数量
```

于是实际操作：

> 扫码 → 输入数量 → 提交

这才是车间系统手机版应该追求的速度。

如果有多个可报工序，再让用户选择。

这项虽然涉及交互逻辑，所以我把它单独列出来，不建议混在纯 UI 优化里直接改。

# 七、底部 TabBar：建议把“扫码”做成核心动作

你现在：

```text
工单             扫码
 📋               ⛶
```

是标准 50/50 导航。

但从你的系统业务来看，**扫码报工明显是高频核心动作**。

可以稍微强化：

```text
      工单            扫码
       ▤               ⛶
```

扫码图标 24～26px，工单 22px。

或者进一步：

```text
       工单          扫码报工
        ▤               ⛶
```

不过我不建议做成悬浮圆形大按钮。

你这个项目之前确定的是**飞书/钉钉式克制 SaaS 风格**，手机端也应该保持这个原则。你的主题本身已经定义了浅灰背景、白色卡片、克制蓝色、12px 容器圆角等体系，完全可以延续。

# 八、建议给 H5 单独增加尺寸变量

现在 `theme.css` 主要定义的是 PC 尺寸：

```css
--app-page-padding-x: 24px;
--app-page-padding-y: 20px;
--app-card-padding: 20px;
--app-control-height: 36px;
```

而且代码明确规定 769px 以上才把控件尺寸接进去。

这个做法是好的，**不要破坏 PC 变量**。

建议增加一套 H5 尺寸 token，例如：

```css
--h5-page-padding: 12px;
--h5-card-radius: 12px;
--h5-card-padding: 14px;
--h5-control-height: 48px;
--h5-action-height: 52px;
--h5-tabbar-height: 56px;
```

颜色仍然全部继承：

```css
var(--app-primary)
var(--app-bg)
var(--app-card)
var(--app-text-1)
var(--app-text-2)
var(--app-text-3)
var(--app-border)
```

这样以后 PC 和 H5 可以独立调尺寸，但不会出现两套颜色体系。

# 我会按这个优先级改

| 优先级    | 页面     | 最值得改                   |
| ------ | ------ | ---------------------- |
| **P0** | 报工页    | 大数字输入、快捷 ±、全部剩余、底部固定提交 |
| **P0** | 工单页    | 精简卡片、真正进度条、突出剩余/当前工序   |
| **P0** | 扫码页    | 改成明显的“等待扫描”工作台         |
| **P1** | TabBar | 加大触控区域、扫码动作稍强化         |
| **P1** | 全局     | 建立 H5 独立尺寸变量           |
| **P2** | 工单页    | 搜索折叠、去掉重复总计            |
| **P2** | 报工页    | 不良原因条件展开、统计区重新分级       |

最终我希望你的手机版形成一个非常简单的闭环：

**工单列表 → 扫码/选工单 → 自动定位工序 → 输入数量 → 一键报工。**

而不是把 PC 后台的“信息完整”搬到手机。车间移动端评价好不好用，一个很实际的标准就是：**工人能不能单手、3～5 秒完成一次常规报工。**
