# 454-优化指令-PC所有业务单据下拉框及浏览字段支持复制文字

> 状态：待做；2026-11-12。
> 本次交付：仅建立开发指令，不实施代码、不打包、不部署。
> 目标：用户在任一 PC 业务单据中，可以复制下拉框已选文字；浏览模式下工单号、状态等可见业务字段也均可复制，不因只读、禁用或单据状态而限制。
> 依据：用户明确“复制文字”“先建一个指令，所有单据上的下拉选项，都要做”；另补充用户要求：“在浏览模式下，工单号，状态，无法复制。我希望能复制，不要这个限制”。按419规范起草。

## 2. 完整流程与覆盖范围

进入单据 → 选择或查看现有值 → 点击字段旁复制图标 → 剪贴板得到完整显示文字 → 成功提示“已复制”。未保存的新单也能复制，不依赖保存接口。

### 2.2 浏览模式可见业务字段（用户补充，必须纳入）

所有上述单据的浏览/详情模式，复制范围不局限于下拉框：单据编号（含工单号）、状态、产品、数量、日期、备注、自定义字段及明细中已显示的业务文字或数字，均不得因浏览模式、readonly、disabled或业务状态而禁止复制。

已核实工单现状：`order/index.vue` 的表单使用 `:disabled="saving || browseOnly"`，工单号是 el-input，状态是 `statusLabel(editingStatus)` 渲染的span，另有“已重新打开”标签。执行时必须逐项处理这些不同渲染方式，不得只给el-select增加复制能力后宣布完成。

- 普通文字、状态标签支持鼠标选中并用Ctrl+C或浏览器原生菜单复制，不设置阻止选中/复制的样式或事件；无法可靠选取的展示控件提供字段旁复制图标。
- 工单号等浏览输入框可使用readonly保持原生选取和复制，或提供不受父表单disabled影响的复制图标；不得为实现复制把业务字段变成可编辑。
- 状态复制用户看到的中文文案，不复制内部状态码；独立“已重新打开”等标签也须可选中复制。
- 字段旁复制图标沿用本文成功/失败、HTTP兼容与无副作用规则；原生Ctrl+C/浏览器菜单保持浏览器原生行为，无须强加成功提示。
- 空字段没有可复制内容即可，不用生成占位文字；可见编号本身是业务内容，应原样复制，不受“不得复制数据库ID”的规则误伤。
- 覆盖清单补充“浏览字段 → 渲染方式 → 原生选取或复制图标 → 验证结果”，逐项验证工单号与状态，并排查其它单据同类问题。

## 3. 复制文字与交互契约

- 单选复制当前已提交选择值对应的完整显示 label；工单产品例：`P001 产品甲`。仅显示名称的字段复制名称，不擅自补编号；不复制数据库ID、placeholder、搜索词、按钮或隐藏信息。
- 多选按当前已选项的显示顺序逐项复制，每项一行；折叠标签时仍复制全部已选内容，不复制“+N”。同名不同项保留各自一行，不擅自去重。树选/级联沿用控件当前显示的标签或路径，不自行扩充未显示的父级。
- 截断只影响屏幕展示，复制必须为完整文本；保留文字内部有意义的空格、标点和换行，不把HTML标签复制出去。
- 筛选框 allow-create 的值，只有已提交为选中项后才能复制；搜索框正在输入但尚未选定的文字，不覆盖当前已选项的复制内容。
- 用明确的空值判断；合法数值0、布尔false对应的标签可复制。没有选中值时图标禁用，不写剪贴板、不提示成功。
- 只读或因业务状态禁用的字段，用户有权查看且存在显示文字时仍可复制；复制按钮不得被父 el-form 的 disabled 一并锁死。不得解除原字段的只读或禁用状态。
- 图标与下拉箭头、清空按钮分开，预留布局空间；支持鼠标及Tab聚焦后Enter/空格操作，提供可访问名称。点击不得展开、清空、切换选项、触发查询或提交表单。
- 每次点击取当时已选内容的快照；切换单据、值变化、异步选项返回后不得复制前一条单据或旧选择。复制不修改v-model，不触发业务change或dirty状态。

## 4. 分支决策与失败恢复

先检查未选值（B01）；有值时先判标签是否可解析（B02），再判解析结果是否为空（B01），最后处理正常复制及失败分支。

| 分支 | 条件 | 用户结果 | 写入与后续状态 | 验证 |
|---|---|---|---|---|
| B01 | 未选值，或标签已解析且确为空白 | 图标禁用；程序触发也不复制 | 不写剪贴板，不改表单 | V02 |
| B02 | 有绑定值但标签尚未加载或无法解析，界面无可信显示文字 | 禁止复制；提示“已选内容尚未加载，暂不能复制”；已有加载错误仍走原错误提示 | 不将ID当标签、不临时越权查资料；加载恢复后可重试 | V05 |
| B03 | 单选且显示文字可用（含0/false） | 复制完整label，成功后提示“已复制” | 只写系统剪贴板；原选择保持 | V01、V02 |
| B04 | 多选、折叠标签或级联路径 | 按第3节复制完整已选文字 | 同B03；部分标签无法解析时整次不复制，按B02提示，避免悄悄漏项 | V03、V05 |
| B05 | 字段只读或禁用但已有可见文字（包括工单号输入框、状态span/tag等非下拉展示） | 按2.2支持原生选取或图标复制 | 不解除禁用，不改变授权、字段或单据状态 | V04 |
| B06 | HTTPS/localhost可用Clipboard API，或内网HTTP无该API | 复用copyText实际尝试复制，成功后才提示成功 | 兼容复制后恢复焦点和选区，不残留临时节点 | V06 |
| B07 | 浏览器拒绝、兼容复制返回false或抛错 | 明确提示“复制失败”，附字段/位置、动作和可读原因；不得伪报成功 | 表单不变，可再次点击重试；不自动循环、不发起服务器写入 | V07 |

## 5. 实现边界与不变量

1. 优先复用现有 copyText，按需提供轻量公共组件或工具，统一图标、标签解析、提示；不要每页各写一套剪贴板逻辑，也不要全局改写第三方组件或依赖其私有DOM结构抓取标签。接入方式由执行方按现有代码选最小正确实现。
2. label来源与页面当前显示使用同一份已加载数据/格式化规则；历史单据有显示快照时沿用当前展示来源，不用最新主数据替换历史文字。不为复制新增请求、后端接口或数据库字段。
3. I01：仅系统剪贴板有副作用；复制绝不保存单据、不写业务数据、不改金额、不改报工或工资计算。
4. I02：保留搜索、清空、键盘选择、多选、allow-create、远程加载、校验、联动及权限行为；复制按钮只负责复制。
5. I03：产品编号唯一、部门报工权限及派工放行、依赖倒序删除等业务红线不变；只复制用户当前有权看到的内容。
6. I04：复制成功以写入Promise完成或兼容方法返回成功为准。不得吞异常，不在成功前提示“已复制”。本功能无数据库事务或重算，不新增幂等表、队列等设施。
