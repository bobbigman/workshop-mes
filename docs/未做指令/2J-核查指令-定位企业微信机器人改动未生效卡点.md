## 背景（已核查事实，Cursor 复核不必重挖）

- 机器人应答由两块驱动：**角色设定**（企业微信后台粘贴的文本）+ **知识库**（服务器 `Ai:SupportDocs:RootPath = D:\WorkShop\SupportDocs` 下的 md，经 `search_support_docs` 检索）。
- 已确认：16 号文档（自动派工应答口径）、17 号（行为规则）、18 号（角色设定模板）均在本地与服务器 `D:\WorkShop\SupportDocs`（截图可见，13:18/13:09/13:19）。
- 已知风险（2I 已定位）：`SupportDocumentService.cs` 的 `KeyPhrases`/`Synonyms` 词表**缺少"派工/自动派工/工时/排产/分摊"等词**，查"自动派工"可能 `no_match` → 机器人检索不到知识库，只能按角色设定兜底。
- MCP 服务正常（`search_support_docs` 可调用），此前实测查"自动派工"返回 `no_match, totalMatched=0`。

## 本次范围与落点（只查不改业务）

逐项核查以下三卡点，**每项给出可观察证据**，不凭猜：

1. **卡点A：知识库是否已更新到服务器**
   - 本地 `SupportDocs\16-自动派工应答口径.md` 是否已改成"先答再问"（第一节结论前置）；
   - 服务器 `D:\WorkShop\SupportDocs\16-自动派工应答口径.md` 修改时间 / 内容是否与本地一致；
   - 若不一致 → 说明**没重新部署**，需整目录覆盖。

2. **卡点B：检索能否命中（词表）**
   - 用 `search_support_docs` 查"能否自动派工 / 班组长不派工"；
   - 若仍 `no_match` → 是 **2I 词表未补**（改 `SupportDocumentService.cs` 词表 + 编译 + 重启服务才生效）；
   - 若 `ready` 且含 16 号 → 检索正常，问题在角色设定。

3. **卡点C：角色设定是否还残留"给选项"话术**
   - 企业微信后台【角色设定】粘贴的文本里，是否还有"您回 1 或 2"这类引导选方向的话；
   - 若有 → 机器人优先按角色设定背，需删掉该话术，只保留"先答结论 + 检索闸门"。

## 行为与口径（分叉）

- 当【A 不一致】→ 先重新部署 SupportDocs 整目录到服务器，再复测。
- 当【B no_match】→ 执行 2I 补词表（`SupportDocumentService.cs` + build + 重启），再复测。
- 当【C 有残留话术】→ 改角色设定：删"回1或2"，保留"客户只问能不能→先给结论"。
- 三卡点可能叠加，**逐项排查、逐项留证据**，不要只改一处就说完成。
