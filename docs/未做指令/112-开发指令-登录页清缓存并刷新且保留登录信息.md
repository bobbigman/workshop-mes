## 一、目标与取舍

在现有登录页 `/#/login` 增加 **“清缓存并刷新”** 按钮。用户点击后，清理本站旧页面和资源缓存，重新打开当前登录页；保留已有登录令牌、账号资料、账套信息和个人设置。

该入口是手动恢复工具。111 已实现的 API GET 强制重校验、后端 `/api` 响应 `no-store` 必须保留，不得用手动按钮替代防复发措施。

- 首版入口只放现有共用登录页，不增加 PC 菜单、H5 工作台或其它页面入口。共用登录页在窄屏自然适配，不另建移动页面。
- 无数据库改动，不增加第三方依赖，不修改报工、部门权限、工资或业务数据。
- 已授权的清缓存操作点击即执行，不增加确认弹窗；按钮旁说明用途。执行中防重复点击。
- 不保证恢复过期/撤销的 JWT，也不自动延长登录有效期。

## 三、清理与保留边界（硬约束）

| 对象 | 行为 |
|---|---|
| 浏览器 HTTP 缓存 | 通过本站响应 `Clear-Site-Data: "cache"` 请求浏览器清理，是否执行受浏览器和安全上下文限制 |
| 本系统 CacheStorage | 仅删除当前 origin 下名称以 `mes-` 开头的缓存，包括 `mes-v2`；无匹配视为无需处理 |
| 本系统 Service Worker | 仅注销同源 `/sw.js` 且 scope 与本应用根路径匹配的注册；刷新后生产模式可按原逻辑重新注册 |
| 其它系统缓存/Worker | 不用前端遍历删除其它缓存和注册；HTTP 清缓存头本身作用于响应 URL 的 origin，无法只限制到 MES 某条资源路径 |
| localStorage | 全部保留，禁止 `clear()`、禁止删除或重建登录字段和设置 |
| sessionStorage | 保留现有键；最多新增一次性的非敏感表单恢复键，使用后只删除该临时键 |
| Cookie、IndexedDB、业务数据库 | 不清理，不重建，不修改 |
| 浏览器密码管理器 | 不触碰；已保存的密码交由浏览器原有机制管理 |
| 尚未提交的表单密码 | 页面刷新会清空内存密码，不持久化、不传入恢复接口；需重新输入 |

**响应头只允许 `Clear-Site-Data: "cache"`，双引号必须保留。禁止 `"storage"`、`"cookies"`、`"*"`、`"executionContexts"`。** 不复制、导出或暂存 JWT/密码到 URL、日志、新存储键来“备份登录”。

注销 Worker 不代表当前页面或其它已打开标签页立即失去旧 Worker 控制。不能据 `unregister()` 成功就宣称旧 Worker 已停止；重新导航后验证资源确实重新取回。其它标签页可在其下一次刷新后使用新资源，不主动刷新用户其它页面。

## 四、界面契约

位置：登录按钮下方的辅助操作区域，邻近“操作手册”；使用 Element Plus 次要按钮，避免抢占“登录”主按钮。

- 按钮：**清缓存并刷新**。
- 简短说明：**页面显示异常或更新未生效时可使用，保留登录信息。**
- 有未提交密码时，显示补充提示：**刷新后需重新输入未提交的密码。** 不将密码保存到 localStorage/sessionStorage。
- 执行中：按钮 loading，文案“正在清理…”；登录与清理互斥，防止清理期间提交登录、登录处理中点击清理。
- 全部可执行步骤完成：提示“缓存清理请求已完成，正在刷新；登录信息保留”，然后刷新一次。
- 已知不支持完整清理：先给出明确提示和“刷新页面”按钮，用户点击后再刷新，避免提示被立即刷新冲掉；不得显示“所有缓存已清空”。
- 发生实际错误：保留页面、恢复可操作状态，提示失败步骤与可读原因；禁止自动反复刷新。

## 五、后台接口（新增契约）

### `POST /api/Auth/clear-browser-cache`

- 在 `AuthController` 新增 Action，明确 `[AllowAnonymous]`，无需请求体和 JWT，无管理员/许可证门槛。
- 不访问业务数据、不发新令牌、不撤销令牌、不调用退出登录服务、不设置或删除 Cookie。
- 成功 HTTP 200，返回当前项目统一格式，例如：

```json
{"code":0,"msg":"ok","data":{"httpCacheClearRequested":true}}
```

- 必须返回以下响应头：

```http
Clear-Site-Data: "cache"
Cache-Control: no-store
Content-Type: application/json; charset=utf-8
```

- `httpCacheClearRequested` 只表示服务端已发出指令，**不表示浏览器一定完成清除**。不要让后台根据内网 HTTP 请求推断浏览器是否处于 HTTPS：开发环境外层 Vite 是 HTTPS、上游后端是 HTTP。
- 请求必须经页面当前 origin 的 `/api` 代理到达后端；禁止绕过代理直连 `127.0.0.1:8080` 或其它 origin，否则清的可能是后端 origin 的缓存，而非登录页 origin。
- 该头仅在这个成功接口中发出，不能全局添加到所有响应；反向代理必须透传，实际浏览器侧验收响应头。
- 只影响发起请求的浏览器站点缓存，不应声称“清理了服务器缓存/所有客户端缓存”。

## 六、前端执行顺序与条件分支

将清理步骤集中到一个小工具（建议 `frontend/src/utils/clearBrowserCache.js`）；组件负责按钮、提示、表单恢复及重新导航，不散落多份实现。

1. **进入清理状态**：当登录或清理正在执行 → 不重复执行；否则设置 loading。
2. **匿名请求清缓存接口**：在 `src/api/auth.js` 封装，使用不挂接现有 JWT/401 退出拦截器的独立请求（例如直接 Axios 请求），设置超时并明确检查 HTTP 状态和 `{code,msg,data}`。不要调用组件内裸请求；不要为了此接口改变全局 401 处理。请求不得包含 Authorization、账号、密码、factoryCode。Cookie 不主动删除。
3. **当接口请求失败/返回 HTML/业务失败** → 提示“清缓存接口失败”并附 URL、状态、追踪号（可取得时）或上下文，停止自动刷新；既有登录存储保持原样。尤其 401 不得触发全局删除 Token。
4. **当可用 Service Worker API** → 只对确认属于本系统的注册调用 `unregister()` 并等待；没有注册无需处理。若注册已被其它操作移除，返回 false 视为当前已不存在；发生异常则明确报告，不能静默吞掉。
5. **当可用 CacheStorage API** → 枚举并仅删除 `mes-` 名称缓存、等待完成；无匹配无需处理。真实删除异常应报告当前失败步骤，不把部分清理说成全部成功。
6. **当 API 不存在、非安全上下文或浏览器不支持 HTTP 清缓存指令** → 记为能力限制，明确提示“此环境无法完整自动清理缓存，可刷新后重试；登录信息保留”。不要求用户清除站点数据，不提供会删登录信息的操作口径。安全上下文以浏览器 `window.isSecureContext` 为准；HTTPS 也不保证每种浏览器支持指令。
7. **保留非敏感表单输入**：重新导航前，只将当前账号和已选账套保存到一次性 sessionStorage 键（例如 `mes.cacheRefresh.form`）。若有同名未消费记录则覆盖此专用临时键，不动其它键；禁止存密码/Token。登录页重新加载账套后恢复账号和仍有效的账套，再删除该临时键；当账套已不存在 → 不造数据，按原选择规则处理。恢复数据需类型/长度校验，过期或异常记录明确处理，不渲染为 HTML。
8. **重新打开页面一次**：保留完整 hash（包括登录页现有 `redirect`），在页面 URL 的 hash 前增加一次性 `_mes_cache_refresh` 参数，以唯一值避开旧首页 HTTP 缓存键，然后 `location.replace`。不使用非标准 `location.reload(true)`；不把密码、JWT、账号放进 URL。不改登录回跳规则、不主动跳去工单/H5。
9. **刷新后**：清理 loading 由新页面重置；生产构建按原 `main.js` 注册最新 `/sw.js`，开发环境不额外注册。可移除 URL 中已使用的刷新参数（`history.replaceState`，不再次导航），保留原 hash/query。不根据残留临时键再次自动清缓存，防止死循环。

HTTP 清缓存没有可靠的通用 JS 成功回执。支持浏览器上的实际网络验收是必需项；只有响应头返回不能证明浏览器删除了旧响应。能力限制不能吞，产品提示不展示 Worker/CacheStorage 等实现名。

## 九、技术依据（2026-10-01 核对）

- [MDN：Clear-Site-Data](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Clear-Site-Data)：`"cache"` 请求清理响应 origin 的 HTTP 缓存；`"storage"` 则会清 localStorage/sessionStorage 等，故禁止使用。指令受安全上下文和浏览器支持限制。
- [MDN：CacheStorage.delete](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage/delete)：按缓存名删除，与浏览器 HTTP 缓存分开处理。
- [MDN：ServiceWorkerRegistration.unregister](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/unregister)：注销注册不等于立即终止现有 Worker 操作，需验证重新导航后的行为。

本指令没有把“清缓存”设计成“清站点全部数据”，不涉及保存密码、恢复失效凭证或修改用户权限。
