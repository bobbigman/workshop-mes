# 110-优化指令：工资生成时未匹配工价主动告警

> 状态：待落地（未做）
> 一句话目标：生成工资单时，若本次有报工没匹配到工价，**主动提示"有 N 条未匹配、金额为0"**，别让管理员看到清一色0、当正常就发了（黑湖源头配工价、可重算纠错的思路，咱们补在"生成"这道闸）。
> 指令写法：全部步骤用「前置判断 → 条件执行 → 收尾」三件套，条件必须**可判定**、判断在**动作之前**；不满足前置判断就停，不硬改。

---

## 一、背景：实测问题（工单 A0001）

- 报工 A0001（李厨·装盘·良品1）等三条，复核通过、未结算，但**都没匹配到工价**（`base_price_rule` 工厂1 只有装盘规则且绑死部门2/用户4，维度对不上；切菜/炒制无规则）。
- 结果：`Salary/generate` 生成的全0草稿，**照常生成**，前端只弹「已生成 N 张工资单」，**没有任何"有 N 条未匹配"的提示** → 管理员差点把0工资当正常发。
- 现有防呆只守住了两处：①明细红色「未匹配」（`frontend/src/views/salary/index.vue` 第 331–333 行）；②确认时若仍存在未匹配 → 阻断（`SalaryService.ConfirmAsync`）。
- **缺口**：生成这一环静默放行，没有主动告警。

---

## 二、改动点（已核实代码位置）

- 后端：`backend/Services/SalaryService.cs` → `GenerateAsync`（当前约第 193–288 行），返回 `new { created }`（第 281 行），需追加未匹配计数。
- 前端：`frontend/src/views/salary/index.vue` → `onGenerate`（当前第 477–499 行），`ElMessage.success('已生成 N 张工资单')`（第 489 行），需按未匹配数给警告。
- 帮助浮层：`frontend/src/help/pageHelp.js` `/salary` 段**已含**「红色未匹配…别把缺价当零工资发」，**不用改**。

---

## 三、Cursor 原子指令（前置判断 / 条件执行 / 收尾 三件套）

**一句话目标**：生成工资单时，有未匹配工价的报工 → 明确提示条数与后果；明细仍标红、确认仍阻断。

**前置确认（无需人拍板，直接执行）**

### 步骤1｜后端：改 `GenerateAsync` 返回未匹配数

- **前置判断**：当 `SalaryService.cs` 存在、且能找到 `GenerateAsync` 方法及其「逐报工计算循环」→ **继续**；当文件/方法/循环结构对不上 → **停下**，报「位置 + 现状」，不硬改。
- **1a 条件执行**：当进入逐报工循环 → 对每条 `PriceRuleMatcher.Calculate(...)` 结果：当 `calc.Matched == false` → `unmatched++`；当 `calc.Matched == true` → 跳过，不计入未匹配。
- **1b 收尾**：当循环结束 → 把返回值 `new { created }` 改为 `new { created, unmatchedCount = unmatched }`；当循环或返回处有异常 → 报「位置 + 做什么失败 + 报文」，不吞错。

### 步骤2｜前端：`onGenerate` 按未匹配数告警

- **前置判断**：当 `salary/index.vue` 的 `onGenerate` 存在、且能拿到生成接口响应 `res` → **继续**；当接口/函数对不上 → **停下**，报「位置 + 现状」，不硬改。
- **2a 条件执行**：当 `res.data?.unmatchedCount > 0` → 用 `ElMessage.warning` 提示「已生成 X 张，但有 N 条报工未匹配工价、金额为0，请先到工价表补价，别把缺价当零工资发」；当 `unmatchedCount == 0` 或字段为空 → 维持原成功提示；当接口没返回该字段（老版本）→ 按 0 处理，不崩。
- **2b 收尾**：当提示逻辑写好 → 关闭生成弹窗、刷新列表；当有异常 → 报「位置 + 失败 + 现状」。

### 步骤3｜保存并编译

- **前置判断**：当步骤1、2 均完成 → **继续**编译；当任一步未完成 → 先回对应步骤补完，不带着半截编译。
- **3a 条件执行**：当后端 → 跑 `dotnet build`；当前端 → 检查无语法/引用错误；当有编译错误 → 修到通过。
- **3b 收尾**：当全部编译通过 → 记录编译结果；当仍失败 → 报「报错信息」，不宣称通过。

### 步骤4｜验收（用 A0001 实测）

- **前置判断**：当后端/前端可运行、且能登录 PC 进「工资报表」→ **继续**；当环境不可运行 → 报「阻塞点」，不跳过。
- **4a 条件执行**：当用 A0001 所在工厂、周期 2026-10 生成 → 必须弹出「N 条未匹配、金额0」警告；当补好工价重生成 → 警告消失、金额=良品×单价；当任一不符 → 回步骤1按现状修正重验。
- **4b 收尾**：当两条都符合 → 记录验收结果；当不符 → 如实报「现状」，不标完成。

### 步骤5｜回归（防误报）

- **前置判断**：当步骤4 通过 → **继续**；当未通过 → 先修，不进入回归。
- **5a 条件执行**：当用无未匹配的正常周期生成 → 只弹成功、不误报；当有误报 → 检查 `unmatched` 计数口径。
- **5b 收尾**：当无误报 → 标记整体完成；当有误报 → 报「位置 + 计数异常原因」，不吞。

**一键关闭**：纯加"未匹配提示"，不改变生成/确认/结算规则；任何一步不想继续 → 停止并还原 `SalaryService.cs`、`salary/index.vue` 两处即可，不影响已生成数据。

**失败原因要求**：任何一步失败，日志/回显写明「位置 + 做什么失败 + 现状」，不吞错、不脱敏。

**验收口径**：A0001 场景生成工资单 → 出现「N 条未匹配、金额0」警告；补工价后重生成 → 警告消失、金额=良品×单价；正常周期不误报。三者全过才算完成。
