# 66 · 开发指令 —— 工人手机查看作业指导书（对标黑湖）

> 状态：✅ 已实现并通过部署验收（后端编译 / 前端构建 / 浏览器实测全通过）；见下方验收清单
> 背景：推广前补上"工人手机扫码看作业指导书"这个基本功。黑湖、简道云均已标配（黑湖支持 PDF/JPG/PNG 预览），本系统此前**上传与预览都没有入口**。

---

## 0. 目标（一句话）

管理员在 PC 把作业指导书/图纸（PDF/图片）挂到产品或工序上，工人手机扫码进报工页就能点开看原文件。

## 1. 现状（已查实）

- 表 `base_knowledge_file` 已存在（`docs/02` 已收录），存 `RelativePath`（相对 `KnowledgeBase:RootPath`）+ `FileType` + 挂产品/工序。
- 此前后端读取只有 `KnowledgeService.QueryProductionGuideAsync`，仅被豆包/扣子 MCP 与管理员 AI 调用，无 Controller 暴露给前端。
- 此前前端仅 `ai-assistant/index.vue` 使用知识库；H5 报工页无入口；无上传页面/接口。

## 2. 范围与取舍（已拍板）

1. **完整闭环两半都做**：PC 上传 + H5 预览。
2. **文件格式**：预览支持 `pdf` + 图片（`jpg/png/webp`）；`docx/xlsx` 手机无法直接预览，**降级为下载后本机打开**，不做转图片/在线预览。
3. **`FileType` 扩展取值**：现有 `docx/pdf/excel` 基础上增加 `image` 图片类（实际存 `jpg/png/webp`）。无 DDL，仅同步 `docs/02` 注释。
4. **AI 问工艺遇到图片**：`KnowledgeService.QueryProductionGuideAsync` 跳过图片（不翻译、不报错），图片不参与文字问答。
5. **权限**：工人（role=2）/班组长（role=3）/管理员（role=1）都能看本厂文件；严格按 `FactoryId` 隔离。
6. **只读**：无新增表、无新增列、无 DDL；仅新增接口。

## 3. API 设计（实际落地 5 个）

| 方法 | 路径 | 用途 | 权限 |
|---|---|---|---|
| GET | `/api/KnowledgeFile?refType=&refId=` | PC 管理：某产品/工序已挂文件清单 | role=1 |
| GET | `/api/KnowledgeFile/by-order/{orderId}` | H5 工人：按工单（→产品→路线→工序）列文件清单 | role 1/2/3 |
| GET | `/api/KnowledgeFile/{fileId}/raw` | 原始文件流（预览/下载，Content-Type 按类型映射） | role 1/2/3 |
| POST | `/api/KnowledgeFile` | 上传（multipart：refType/refId/version/file） | role=1 |
| DELETE | `/api/KnowledgeFile/{fileId}` | 删除登记记录（磁盘文件保留，因可能被多处引用） | role=1 |

### 安全要点（红线）

- 文件下载/上传只从库表取 `relative_path`，绝不接收用户传路径；`Path.GetFullPath` 规范化 + 校验仍在根目录内（路径逃逸防护）。
- 上传扩展名白名单（pdf/docx/xlsx/jpg/jpeg/png/webp）+ 20MB 上限；登记时校验 ref 属于本厂。
- 工人白名单：`RoleGuardMiddleware` 放行 `GET /api/KnowledgeFile/*`（role=2/3）；上传/删除/列表仅管理员。
