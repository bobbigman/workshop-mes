# 未来开发待办清单（Backlog）

> **用途：** 这是"记忆外存"。记录对标黑湖后**还没做、但别忘**的事。将来打开本文件，不用重新扒黑湖原文，就能知道"该不该做、为什么现在没做、要做成啥样、依据在哪"。
> **使用规则：**
> 1. 每做完一期，回来把该期状态改为「已完成」，并勾掉清单。
> 2. 要动手做某一期前，先读"触发条件"确认时机，再读"证据链接"对应的文档，然后**新开一份优化指令**（编号接续 16 之后，如 `17-优化指令-xxx.md`），不要直接在本文件里写代码。
> 3. 每期的"触发条件"没满足前，**不要提前做**（比如第一期没跑通，别做第二期）。

### 第四期：工人一键上报异常 🟢

- **触发条件：** 第二期（角色模型）完成。
- **为什么现在没做：** 依赖"班组长/负责人"角色（第二期）；且黑湖异常要"通知到对应负责人"，得先有负责人体系。
- **黑湖真实设计（证据 1D 纠偏 2 🟢）：**
  - 工人手机一键上报异常，**官方只有三类**：设备故障 / 物料短缺 / 质量异常（第三方站的"缺料停工/来料不良/工序报废"四类是编的，不采信）。
  - 拍照上传 + 描述问题；车间主管和管理层实时收到提醒。
  - 看板红色高亮 + 滚动播报。
- **要做的大方向：**
  1. 新增异常上报表（类型枚举=官方三类 + 备注 + 图片可选）。
  2. 通知路由：物料短缺→仓库、设备→机修、质量→质检/生产主管。
  3. 看板异常滚动播报。
  4. 处理回填（谁处理、何时恢复）。
- **指令：** `docs/28-优化指令-工人一键上报异常.md`（已拆出，待做）

## 三、明确"不做"的对标项（防止误做）

| 项 | 理由 | 证据 |
|---|---|---|
| "工序停滞预警"（系统按无报工时长猜卡住） | 黑湖**没有**这种机制，是 1C 自创的；黑湖靠人主动上报停机原因 | 1D 纠偏 4 🟢 |
| 看板"灰/蓝/绿/黄/红"五色 | 官方只有"正常/预警/延期"三态，五色是第三方站编的 | 1D 纠偏 5 🟢 |
| "3 天内到期"具体天数当官方口径 | 官方只说临期/超期两级，没给天数 | 1D 纠偏 5 🟢 |
| 异常"四类"（缺料停工/来料不良/工序报废） | 官方只有三类：设备/物料/质量 | 1D 纠偏 2 🟢 |
| 进销存、排程、OEE | 本项目当前范围外，另议 | 1D §六 |
| 阶梯计价 / 班组分成 / 绩效系数 | 简单工资见 **docs/21**（须在 **docs/22** 之后） | docs/21 §6 |
| 复核后才进工资（入账过滤） | **由 docs/22 双轨 + docs/21 结算过滤共同完成**，不再标「范围外」 | docs/22 §8、docs/21 |
