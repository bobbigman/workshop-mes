## 1. 目标与边界

支持两三家客户同时试用：同一源代码、同一标准发布包，每客户独立程序目录、进程/服务、内部端口、数据库、运行账号、JWT 密钥、附件和日志。
给每客户一个专属 HTTPS 网址及账号密码，成交后可整套迁到客户电脑独立运行。

不开发管理中心、平台账号、TenantContext、动态选库、收费、自助注册、跨客户统计或云地同步。
不得顺带升级技术栈或重写工单、报工、工资业务。人工开通和到期停用即可。

## 2. 开工前必读与核查（P0）

阅读 AGENTS.md、docs/01～06、相关 .cursor/rules/；表结构以 docs/02 为准。
核查 Program.cs、AppDbContext、DbCompat、SeedData、AuthService、JwtHelper、RoleGuardMiddleware、MCP 与授权接口、前端登录、http.js、router/index.js。
补查直接 SQL、文件保存目录、后台任务、外部系统凭据、旧发布脚本与备份脚本。

保持三条红线：产品编号唯一；工序报工权限按部门；有下级禁止删除且遵守删除依赖顺序。
本需求默认不改业务表，不添加 TenantId。确需改表时先同步 docs/02，再提供迁移及数据保护说明。

## 3. 实例配置契约（P0）

在现有配置上增加最少字段，命名可按项目规范统一，但必须保持如下语义：

| 配置 | 作用 |
|---|---|
| Instance:Code | 运维标识，日志和台账使用，不作为权限凭据；仅允许字母数字与连字符 |
| Instance:DisplayName | 登录页厂名眉标与业务页头显示的客户名称；**填中文厂名**（如「××制造」），禁止用 `WorkShop` 等英文开发代号；已上线机改此键须手工合并进服务器 appsettings，更新包不得整文件覆盖 |
| Instance:FactoryCode | 此实例唯一服务的工厂代码 |
| Instance:PublicBaseUrl | 生成外部链接，取部署配置，不直接信任请求 Host |
| ConnectionStrings:Default | 仅此客户业务库 |
| Jwt 配置 | 见下方命名约定；每实例独立强随机 Secret |
| 文件/日志目录 | 每实例独立绝对路径，或严格相对本实例发布目录 |
| 演示数据开关 | 生产/客户试用默认关闭 |
| MCP 开关 | 默认关闭，覆盖 MCP 及相关授权入口 |

### JWT 命名约定（钉死，禁止各写各的）

沿用现有 `Jwt:Secret` / `Jwt:Issuer` / `Jwt:Audience` 三字段：

| 字段 | 规则 |
|---|---|
| Secret | 每实例独立，长度 ≥ 32 的强随机串；禁止仓库默认值、禁止多实例共用 |
| Issuer | 固定格式 `mes-{Instance:Code}`，例如 `mes-client-a` |
| Audience | 固定格式 `mes-{Instance:Code}-app`，例如 `mes-client-a-app` |

启动时校验：三者非空，且 Issuer/Audience 与当前 `Instance:Code` 一致；不一致则明确失败启动。
签发与校验均使用本实例配置；甲 token 到乙因密钥或 iss/aud 不匹配必须 401。

开发配置可保留本地示例；公开试用配置不得有可通用的默认密码/密钥。
服务启动校验必要配置，缺失时明确失败，不自动使用别的实例或演示连接。
密码和密钥不放入代码仓库、部署台账、普通日志或公开文件目录。
SQL Server 运行账号仅能访问自己的业务库；建库/升级使用运维身份，应用不持有 sa 权限。

## 4. 登录与身份的最小改造（P0）

增加只读匿名实例展示接口，例如 GET /api/instance-info，只返回 displayName 等展示字段，禁止返回数据库地址、连接串、JWT 密钥及其他客户信息。
登录页显示客户名称，移除默认 admin/Admin123 预填，用户只填写账号密码。

### factoryCode 行为（钉死）

服务端 AuthService **始终**以 `Instance:FactoryCode` 解析本实例工厂：

| 请求中的 factoryCode | 处理 |
|---|---|
| 空 / 未传 | 使用 `Instance:FactoryCode`，正常登录 |
| 非空且等于配置值 | 接受（兼容旧客户端） |
| 非空且不等于配置值 | **拒绝**，不得用于任意选厂或换库 |

签发 JWT 后所有业务请求仍须验证签名、issuer、audience、有效期、角色和部门权限，并检查工厂属于本实例配置。

继续使用现有 JWT 字段，不为本需求增加多租户路由体系。
用户初始密码每客户不同，通过交付渠道提供，明确要求首次使用修改；首版可人工跟进，不为强制改密新建复杂账号状态。
关闭固定验证码手机号登录；不能仅隐藏按钮，直接调用旧接口也必须不可用。

专属入口优先使用不同主机名，例如 a.example.com、b.example.com；这些只是示例，真实域名待配置。
禁止把不同客户仅放到同域名不同路径后继续共用现有 localStorage token。按独立主机名部署可保留现有浏览器登录存储逻辑，避免无关前端重构。
API 使用同源 /api，由反向代理转发至本实例。

## 5. 初始化、演示入口与升级（P0）

核查 EnsureCreated、DbCompat、SeedData 当前调用。公开实例启动不得无条件创建演示管理员、重置密码或补入演示业务数据。
提供明确的首次初始化操作，与正常启动分离；创建工厂和管理员时显式使用本客户配置。示例数据仅在明确开启时加载。
现有业务库先备份到副本验证，不能直接删除或重建；不得从真实甲客户库克隆乙客户试用环境。

默认关闭 /mcp 和全部配对、预检、授权交换等入口，关闭其 UI 链接。
如某客户实际需要 MCP/AI，后续按独立实例显式启用并检查凭据、绑定工厂及接口权限；本次不开发跨客户共享的 MCP。
通知、金蝶连接及后台任务配置逐实例隔离；未适配的入口默认关闭。

不因部署整理全盘重构历史数据库迁移。新结构按规约用 EF Migrations 管理；历史 EnsureCreated/DbCompat 与目标版本的兼容性要在副本验证并记录。
常规程序启动不承担不受控结构升级，更新脚本明确需使用的运维权限与顺序。

## 6. 标准发布与实例布局（P0）

建议部署目录（示例）：

```
D:/MesTrials/client-a/app       程序及只属于甲的配置
D:/MesTrials/client-a/data      附件/导出临时文件
D:/MesTrials/client-a/logs      运行日志
D:/MesTrials/client-b/...       乙的对应目录
```

备份位于独立受限目录并另存到不同介质/主机；不能只有同盘一份。
不要把备份、配置和日志放入 wwwroot。

发布包来自同一源码版本；前端构建产物按现有 Program.cs 静态托管方案放入 wwwroot，避免每客户重写前端 API 地址。

### 进程形态（钉死一种）

对齐 `docs/05`：**公开试用与客户本地交付统一采用 IIS 站点 + 独立应用程序池**（需 ASP.NET Core Hosting Bundle）。

- 每客户一个 IIS 站点（或站点绑定独立主机名），指向该客户 `app` 目录；应用池独立，互不回收连带。
- 本机开发/临时联调仍可用 Kestrel；**不得**为试用同时维护「Windows 服务 + IIS + 纯 Kestrel」三套运维文档。
- 反向代理（若前置 Nginx/另一 IIS）按客户主机名转发到对应站点；配置 HTTPS、可信代理、正确原始协议及访问日志。

示例内部端口 18081、18082、18083（或由 IIS 绑定决定）；实施前检查端口占用，不能覆盖现有服务。
数据库与内部应用端口不直接向公网开放；公网只暴露所需网站入口。
服务使用确定的工作目录和配置路径，防止不同实例读取同一份 appsettings。
同机部署不自动隔离资源；记录试用服务器资源并验证并发负载，不宣称可无限开客户。
同机共用一个 SQL Server 时，须在台账注明：磁盘满、误删库、整机备份失败会影响全部试用客户。

## 8. 公网试用的必要处理

### P0

- 使用 HTTPS。
- 去掉演示密码预填，关闭固定验证码，确认种子数据不产生公开通用账号。
- 关闭或限制公开 Swagger。
- 服务端通过 ThrowHelper 保留排错上下文并对公网响应脱敏，不能把 SQL、数据库密码、token 和其他客户信息原样返回公网；不吞异常、不把失败转换为空列表或成功。
- 配置数据库权限，保证 A 应用运行凭据不能读写 B 数据库；附件目录至少按实例分目录。若暂时无法完成 OS 级目录 ACL，须在完成报告写明限制，不把进程独立等同于权限完全隔离。

### P1

- 登录尝试频率限制：优先用反向代理/IIS 层限流或失败审计日志；**不为首版新建完整账户锁定业务表**。若无代理能力，可做进程内简易计数，但须有说明与上限，避免半套安全平台。
- 前端错误可理解提示及追踪号；按需同步 docs/06 的异常呈现边界。
- 目录 ACL 与独立服务身份的加固说明写入部署清单。

## 9. 客户本地交付（P0 通测一次即可）

1. 确定保留的试用数据，约定停写窗口。
2. 停止该客户实例，确认在途业务结束，其他客户继续运行。
3. 备份其数据库、附件和必要配置，记录应用/数据库版本，验证恢复。
4. 客户电脑安装匹配版本程序及兼容 SQL Server，恢复数据（托管形态仍按 §6 用 IIS，内网可无公网证书）。
5. 修改本地数据库连接、固定局域网地址、PublicBaseUrl；生成新 JWT 密钥（及按 §3 的 iss/aud）使旧云端凭证失效。
6. 配置自动启动、防休眠、备份和恢复操作。
7. 验证电脑及手机/PDA访问，调整含公网网址的二维码和外部集成。
8. 核对数量和工资汇总后交付，原试用实例保持停用，备份按约定保留。

本地实例不访问你的试用管理服务。核心业务不依赖公网；外部 AI 等网络功能另行说明。
不做试用端与本地端双向同步。若本地已产生新业务，回滚必须先停止写入并保护新数据，不直接恢复旧备份覆盖。

## 10. 推荐实施顺序

1. **P0** 配置与登录展示；固定默认工厂与 factoryCode 规则；移除公开演示入口。
2. **P0** 初始化与标准发布模板，先部署测试实例 A（IIS）。
3. **P0** 从干净发布包部署 B，使用不同数据库、账号、密钥和网址。
4. **P0** 双实例交错操作、跨实例 token 拒绝、独立停用及备份恢复测试。
5. **P0** 从 A 备份恢复出本地测试环境，验证断开公网仍可用。
6. **P1** 更新 docs/01、03、05、06、33 的相关章节；有实际表变更才更新 docs/02。
7. 根据 P0 验收结果发放真实客户试用环境；P1 可并行收尾。

## 11. 验收清单

验收记录必须区分已通过、失败、未执行和不适用。完成报告只描述实际做过的部署与验证，不把本指令当成已交付功能。

### P0 — 独立部署与客户登录

- [ ] A/B 同时运行，程序版本一致，配置、IIS 池/站点、数据库及密钥独立。
- [ ] Jwt Issuer=`mes-{Code}`、Audience=`mes-{Code}-app`，与 Instance:Code 一致。
- [ ] 专属网址展示正确客户名称，只填写账号密码即可登录。
- [ ] 空 factoryCode 走实例配置；改请求中的非空 factoryCode 不能切换工厂或数据库。
- [ ] 甲 token 请求乙接口被拒绝；甲乙业务库含相同主键时仍不串数据。
- [ ] 同浏览器同时打开两个客户网址，登录状态互不覆盖。
- [ ] 停止/重启甲实例不影响乙；实例断库不回退其他数据库。
- [ ] 应用数据库账号不能访问另一客户库；附件至少分目录且不相互覆盖。
- [ ] 日志、导出临时文件和备份不相互覆盖，也不能从网站公开下载。

### P0 — 业务及演示入口

- [ ] 工单、报工、工资、看板、导入导出及打印按已存在功能回归。
- [ ] 产品唯一、部门报工权限、删除依赖规则保持。
- [ ] 没有默认演示密码预填，固定验证码接口不可使用。
- [ ] 未显式启用的 MCP 及配对授权入口不可访问。
- [ ] 正常重启不重设密码、不自动注入演示业务。
- [ ] HTTPS、Swagger 限制及错误脱敏验证通过。
- [ ] 至少同时操作 A/B 各一组读写，核对只修改自己的数据库。

### P0 — 运维与本地迁移

- [ ] 开通第二个实例可按模板完成，未修改第二份业务代码。
- [ ] 单实例升级先备份，失败可以恢复匹配版本程序与数据库。
- [ ] 在独立测试环境实际恢复备份，包含附件并核对关键数据。
- [ ] 迁移后断开公网仍能登录、下单、报工、查看工资。
- [ ] 云端旧 token 不能用于本地，PDA/手机局域网访问正常。
- [ ] 迁移前后工单数、报工数量、工资汇总一致。
- [ ] 旧公网网址/二维码处理与本地备份方法有说明。
- [ ] 真实域名、账号密码已通过适当渠道交付；测试报告没有真实密钥。

### P1 — 可选加强

- [ ] 登录限流或失败审计按 §8 P1 落地并有说明。
- [ ] 错误追踪号与 docs/06 呈现边界已同步。
- [ ] 目录 ACL / 独立身份加固已记录。
