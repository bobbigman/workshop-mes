# 85・开发指令 —— 新增「新手入门」引导（教用户怎么用系统）

> 状态：⏳ 待 Cursor 落地
>
> 前置：`docs/30`（管理员手册）、`docs/31`（工人手册）已存在，文案风格对齐它们；`docs/84`（移除学操作）落地后再做本功能，两者不冲突。
> 拍板/设计：**帮助菜单新增「新手入门」大白话分步导览页**，管理员线 6 步 + 工人线 3 步；可选：首次登录轻提示。
> 定位：既是新客户上手引导，也兼作**陌拜/演示时的讲解底稿**。

---

## 0. 目标（一句话）

做一个「新手入门」引导页，用大白话分步教人怎么用系统：管理员照着 6 步把厂子配起来、工人照着 3 步就会扫码报工。老板（管理员）演示时照着这页念，客户一听就懂、一看就会。

## 1. 设计（已定）

| 项 | 决定 |
|---|---|
| 入口 | 侧栏「帮助」分组下新增「新手入门」（路由如 `/onboarding`） |
| 形态 | 独立 Vue 页（样式对齐 `/help`、`/advantages`），**纯前端静态页** |
| 内容 | 两条线分区展示：**管理员/老板线（6步）** + **工人线（3步）** |
| 每步 | 大白话说明 + 「去操作」跳转入口（跳对应菜单路由）+ 完成标志一句话 |
| 数据/接口 | **不改表、不加后端接口**；跳转全用现有路由 |
| 文案 | 大白话，不写技术黑话（对齐 docs/31 风格，别出现 MES/工艺路线 这类吓人词，除非顺带解释） |
| 可选增强 | 首次登录轻提示（见 §3 步骤 4，可做可不做，默认做，做成可关闭） |

## 2. 页面内容（大白话文案）

### 管理员/老板线（6步）

1. **环境准备**：浏览器打开系统地址（内网 IP）。管理员用电脑，工人用手机或 PDA 扫码。说明用什么浏览器、怎么访问。
2. **建账号和部门**：「系统配置 → 用户/部门」。给每个工人开账号、分到部门（报工权限看部门，不是看人）。→ 去操作：`/user`、`/dept`
3. **填基础资料**：「基础数据」。按顺序：单位 → 工序 → 不良品项 → 工艺路线 → 产品 → 工价表。先有单位，才有产品；先有工序，才能排路线。→ 去操作：`/unit`、`/operation`、`/defect`、`/routing`、`/product`、`/price-rule`
4. **建工单出码**：「生产管理 → 工单」。选产品、填数量、定交期，保存后打印出带二维码的工单。→ 去操作：`/order`
5. **扫码报工**：工人手机/PDA 扫工单二维码 → 选工序 → 填良品/不良品数 → 提交。班组长在「报工复核」把关。→ 去操作：`/report`、`/review`
6. **看进度**：「车间看板 / 生产报表 / 执行监控」。一眼看到每张单到哪道工序、不良率多少、工人今天挣多少。→ 去操作：`/board`、`/stat`、`/execution-monitor`、`/salary`

### 工人线（3步）

1. **扫码打开工单**：手机或 PDA 扫工单上的二维码，工单就打开了。
2. **报工**：选自己干的工序，填良品数和不良品数（有不良要选原因），点提交。
3. **看产出/工资**：下班看看今天报了多少、挣了多少（计件/计时工资自动算）。

> 页面底部放一句：**"有问题？右上角『帮助』有完整操作手册；或找管理员。"**

## 3. 原子步骤（每步带条件）

> 约定：每步做完自查，能构建就构建；失败停下贴报错，不许绕过。

**步骤 1 —— 建页面**
- 当：`frontend/src/views/onboarding/index.vue` 不存在 → 当（是）：新建该文件，按 §2 文案写两条线分区，样式对齐 `/help`、`/advantages`。
- 当（否）：复用/覆盖已有文件，先读再改。

**步骤 2 —— 加路由**
- 当：`router/index.js` 无 `/onboarding` 路由 → 当（是）：新增 `{ path:'/onboarding', name:'Onboarding', component:()=>import('@/views/onboarding/index.vue'), meta:{ title:'新手入门' } }`。
- 当（否）：检查已有路由，复用或改名。

**步骤 3 —— 加菜单**
- 当：`SideMenu.vue` 帮助分组内无「新手入门」 → 当（是）：在「操作手册」下方加 `<el-menu-item index="/onboarding">新手入门</el-menu-item>`。
- 当（否）：无需改。

**步骤 4 —— 首次登录轻提示（可选，默认做）**
- 当：决定做 → 当（是）：在登录后主界面（如 `/order` 首页）判断该账号是否首次登录：读本地 `localStorage` 标记，无标记则弹轻提示（「新来的？先看新手入门，5分钟上手」），带「去看看」和「关闭」两个按钮；点去看看跳 `/onboarding`，点关闭或看过一次即写标记，之后不再弹。
- 当：决定不做 → 跳过本步，页面照样可用。

**步骤 5 —— 全量验证**
- 当：前端改动完成 → 当（是）：跑 `npm run build` 必须通过；有错停下贴报错。
- 当：构建通过 → 当（是）：本机启动，走 §4 验收清单。

## 4. 验收清单

- [ ] 侧栏「帮助」下出现「新手入门」，管理员/班组长/工人 都能点开（本页不限角色）
- [ ] 管理员线 6 步齐全，每步有「去操作」且能跳到对应菜单
- [ ] 工人线 3 步齐全，文案工人看得懂
- [ ] 页面无技术黑话（MES/工艺路线 等要么不出现、要么顺带解释）
- [ ] 首次登录轻提示：新账号登录弹一次，点关闭/看过不再弹（若做）
- [ ] 原「操作手册」「产品优势速览」「关于」等帮助项不受影响
- [ ] `npm run build` 通过；不改表、不加后端接口
- [ ] 与 84（移除学操作）无冲突：全站无「学操作」残留

## 5. 不做

- 不做分角色弹窗强制引导、不做视频/动画、不做进度保存（首次标记够用）、不改表、不加接口、不重做使用手册（沿用 docs/30、31）。

## 6. 说明

- 纯前端静态页，改动小、回退容易（删路由+菜单+页面即可）。
- 若客户要"视频微课"那种金蝶式情景故事，另行评估，不在本指令范围。
