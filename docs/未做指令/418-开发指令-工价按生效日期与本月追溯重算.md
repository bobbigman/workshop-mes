## 行为与口径（分叉写成显式条件，禁止让执行方脑补）

| 当 | 则 |
|---|---|
| 正常调价、不选追溯 | 新提交报工按业务日期有效价保存快照，旧报工/工资不变；补报不按提交当天取价 |
| 勾选本月追溯 | 原因必填，筛本月生效日起的现存报工；用原工艺事实和可靠历史系数预览，不只按旧PriceListId筛选 |
| 相关工资status=0 | 只更新受影响明细，再汇总全单；无关明细、数量/工时/系数与复核状态不变 |
| 相关工资status=1 | 预览明确列出撤回；确认后撤回并重算，停在草稿，不能自动确认 |
| status=2、坏快照、缺可靠依据或跨厂/权限冲突 | 整次阻断并列原因，不补造历史价格/系数、不静默跳过；未核实现有发放/关账能力不得声称已全部校验 |
| 无工资明细、跨月周结、待复核/退回报工 | 不自动生成工资单；周结只改本次范围内明细；报工保持原复核状态，不提前计入工资 |
| 普通改数/普通工资重算 | 继续用原报工计薪快照；225普通人员系数重算规则不被本功能暗改 |

| 数据或关联 | 处理方式 |
|---|---|
| 工单预估/工艺事实 | 继续保留，不拿后来修改的产品资料代替原事实；当前工价不再永久绑定本单工资 |
| 工价及生效分段 | 保存可核实历史；正常修改也不能绕过版本/审计；具体方案见417附录B |
| 报工计薪依据 | 普通调价不改；明确纠正后更新当前依据，原/新快照与金额完整留痕，禁止倒推或补造历史系数 |
| 工资明细/主表 | 只变受影响价格派生金额，沿原明细系数，汇总全单；保留前后状态和确认依据 |
| 提交与失败 | 预览不写业务库；确认重扫完整集合并检查变化；单事务全成全败；幂等键同内容重试返回原结果，异内容拒绝 |

计件、计时、固定、扣价、换算及舍入沿现有计算器。接口/并发指纹/上线历史证据与针对性算例见417附录B～D；这些是必要约束，不是强制新增三个表或通用工作流。
