# 97-开发指令-微信手机号绑定认人（钥匙定厂 + 手机号直绑认人）

> 交付对象：Cursor（写代码）。本文是开发指令，不是代码。
> 前置：必须先完成 `docs/96-开发指令-多租户MCP每厂一把Key定厂.md`（钥匙定厂）。97 只做"认人"，不重复做钥匙。
> 相关表已确认：`sys_user`（已有 `factory_id`、`account`、`phone`、`name`、`role`、`password`、`status`，唯一约束 `factory_id+account`）。
> **取舍（2026-09-30）**：当前无短信通道（入口仅微信/扣子/WorkBuddy/豆包）。**不做验证码、不建 `sys_sms_code`、不发短信**。用户报手机号 → 本厂 `sys_user.phone` 直接匹配绑定。已知代价：知道别人手机号可能冒绑；接受此代价换简单可用。

---

## 一、需求背景（人话）

96 解决了"这单活是哪个厂的"（钥匙锁厂）。但厂里**不同的人**查工单/工资，还得知道"这人是厂里哪个账号"。

本指令：**首次报手机号绑一次会话身份，之后同身份进来自动认人**，不用再输手机号。

核心一句话：**钥匙锁厂（门），手机号直绑认人（谁），绑定后免报。**

---

## 二、三条铁律（任何步骤不得违反）

1. **钥匙锁厂、手机号认人，两道锁缺一不可**：请求没带钥匙 → 门都进不来（401），手机号也白报。手机号**绝不**替代钥匙定厂。
2. **绑定必须带厂别**：绑定表存"厂 + 渠道 + 会话身份 + 账号"。厂别以当前请求钥匙定的厂为准（用户不用报厂），报的手机号必须是该厂 `sys_user` 里存在且启用的。
3. **绑定后免报**：同一个会话身份再次进来，直接反查绑定表认人，按该账号的角色权限放行。绑定表不把手机号当唯一键；手机号只是首次绑定凭证。

> 明确不做：短信、验证码表、发码工具、连错锁定。以后若接短信，另开指令再加。

---

## 三、要做的步骤（原子步骤 + 条件判断）

### 步骤 1：建绑定表 `sys_wx_bind`

```sql
CREATE TABLE sys_wx_bind (
    bind_id    BIGINT IDENTITY(1,1) PRIMARY KEY,
    factory_id BIGINT NOT NULL,               -- 厂（租户隔离），关联 sys_factory.id
    chan_type  NVARCHAR(16) NOT NULL,         -- 渠道：coze / wx_gzh / wecom / doubao / workbuddy
    wx_openid  NVARCHAR(128) NOT NULL,        -- 会话侧身份（存哈希，不存明文）
    user_id    BIGINT NOT NULL,               -- 小工单用户（sys_user.id）
    status     TINYINT NOT NULL DEFAULT 1,    -- 1=已绑定 0=已解绑
    bound_at   DATETIME2 NOT NULL DEFAULT SYSDATETIME(),
    unbound_at DATETIME2 NULL,
    remark     NVARCHAR(255) NULL
);
CREATE UNIQUE INDEX ux_wx_bind_active
    ON sys_wx_bind(factory_id, chan_type, wx_openid)
    WHERE status=1;
```

**条件判断**：
- 当表不存在 → 执行 DDL；
- 当已存在 → 跳过；
- 建完 `SELECT COUNT(*)` 返回 0 才算好。

### 步骤 2：MCP 工具「绑定」`BindWechat(phone, chanType?, sessionId?)`

行为：用户报手机号 → 本厂匹配账号 → 把"当前会话身份"写进 `sys_wx_bind`。

「当前会话身份」来源（方式 A，起步定死）：
- 优先取工具参数 `sessionId`（扣子/豆包/WorkBuddy 传入的稳定用户/会话标识）；
- 若缺省，可读请求头 `X-Mcp-Session-Id`（有则用）；
- **当两者都没有 → 返回「缺少会话身份，无法绑定」**，不猜、不造默认值。
- `chan_type` 缺省为 `coze`；也可传 `doubao` / `workbuddy` / `wx_gzh` / `wecom`。
- 入库的 `wx_openid`：**对明文 sessionId 做不可逆哈希**（如 SHA256 十六进制），日志只打前 8 位。

**条件判断**：
- 当手机号格式不对 → 返回「手机号格式不对」，不绑定；
- 当 `sys_user`（`factory_id=当前钥匙定的厂 AND phone=报的手机号`）查不到 → 返回「该手机号在本厂无账号」，不绑定；
- 当查到但 `status=0` → 返回「账号已停用」，不绑定；
- 当该 (厂,渠道,会话身份哈希) 已有 `status=1` 绑定 → 返回「已绑定账号：{姓名}，如需换账号先解绑」，不重复绑；
- 当未绑定 → 写入 → 返回「绑定成功：{姓名}」；
- 当异常 → 报「绑定失败：具体原因」，回滚。

### 步骤 3：MCP 数据查询工具「免报认人」前置

改各查询工具（工单/报工/工资/排产/知识库等）——查询前先认人：

1. 取当前请求的会话身份（同步骤 2）；
2. 查 `sys_wx_bind`（厂 + chan + 哈希身份 + status=1）→ 得 `user_id`；
3. 按该用户 `role` 控制能查什么（与现有 MCP 权限口径一致：生产人员不查工资等）；
4. SQL 仍强制带 `factory_id`（钥匙定的厂）。

**条件判断**：
- 当未绑定 → 返回「请先绑定：报您的手机号」，**不发任何业务数据**；
- 当已绑定但无权 → 返回「您（{姓名}）无权查询此数据」；
- 当已绑定且有权 → 返回该厂该人范围内的数据；
- 当钥匙没定到厂 → 抛错，不发数据。

> **例外**：`BindWechat` / `UnbindWechat` 自身不要求已绑定；`DemoSkipAuth=true` 时（开发演示）可跳过认人前置，但仍必须有钥匙定厂。

### 步骤 4：MCP 工具「解绑」`UnbindWechat(chanType?, sessionId?)`

- 当已绑定 → `status=0`，记 `unbound_at`，返回「已解绑」；
- 当未绑定 → 返回「当前未绑定」；
- 软删，不物理删行。

### 步骤 5：日志与一键关闭

1. 绑定/解绑/查询记：厂名、渠道、身份哈希前缀、user_id/姓名、路径、时间、成败。
2. 手机号全文、会话明文身份 **永不落日志**（手机号只显示 `138****1234`）。
3. 复用 `Mcp:EnableMcp` 总开关。

---

## 四、验证清单

1. **绑定**：本厂已有手机号 → 成功；外厂/不存在手机号 → 拒；停用账号 → 拒。
2. **免报**：绑定后同会话再查 → 直接认人，不用再报手机号。
3. **串厂**：五金厂钥匙报川菜馆手机号 → 拒。
4. **权限**：生产人员查工资 → 拒；查自己报工 → 放行（按现有口径）。
5. **未绑定**：查数据 → 只提示先绑定，不发业务数据。
6. **解绑**：解绑后再查 → 要求重新绑定。
7. **日志**：含厂+姓名+时间；搜不到明文手机号/明文 sessionId。
8. **一键关闭**：`Mcp:EnableMcp=false` → `/mcp` 关，网页正常。
