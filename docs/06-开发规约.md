# 开发规约 · 编码规范

> 面向开发者（C# 背景，略懂 Java）的详细编码规范。规则文件在 `.cursor/rules/`，本文是完整展开版。

---

## 1. 总则

- 技术栈固定：.NET 8 + EF Core + SQL Server + Vue3 + Element Plus/Vant/ECharts。
- 表结构、业务规则、技术方案分别以 `docs/02/01/03` 为权威，本文只做编码约束。
- 任何功能不得违反三条硬规则（见 `docs/01` 第 6 节）。
- **交付节奏：** 先 PC（管理动作），后 H5/PDA（现场动作）；首版不做两端齐全。范例：`docs/17` 批量补报。

## 2. C# 后端规范

### 2.1 命名

| 对象 | 规范 | 示例 |
|---|---|---|
| 类/方法/属性 | PascalCase | `WorkOrderService`、`CreateOrder` |
| 私有字段 | `_camelCase` | `_dbContext` |
| 控制器 | `XxxController` | `OrderController` |
| 服务接口/实现 | `IXxxService` / `XxxService` | `IReportService` |

### 2.2 分层职责

- **Controller**：只做参数绑定、鉴权、返回封装，不含业务逻辑。
- **Service**：业务校验、事务、调用数据层。
- **Data（DbContext）**：EF Core 上下文与实体配置。

### 2.3 EF Core

- 实体放 `Models/`，与 `docs/02` 表一一对应。
- 用 EF Core Migrations 管理表结构，禁止手改已上线表。
- 关联关系用导航属性；多对多（如工序-部门）用显式关联实体。

### 2.4 业务规则落地

- 产品创建：`code` 唯一校验。
- 报工：Service 内校验「当前用户部门 ∈ 工序报工权限部门」。
- 删除：统一走删除顺序校验，有下级引用即阻断。

### 2.5 统一返回

```csharp
public class ApiResult<T> {
    public int Code { get; set; } = 0;
    public string Msg { get; set; } = "ok";
    public T Data { get; set; }
}
```

## 3. Vue3 前端规范

### 3.1 目录

```
frontend/src/
├─ views/        # 页面（一个模块一个目录）
├─ api/          # 接口封装（一个模块一个文件）
├─ components/   # 复用组件

└─ utils/        # 工具
```

### 3.2 组件库分工

- PC 后台：Element Plus
- 移动报工：Vant
- 大屏：ECharts

### 3.3 编码

- 统一 `<script setup>`。
- 列表 `v-for` 必须 `:key`。
- 调后端统一走 `src/api/` 封装。
- 处理 `code !== 0` 的错误提示。

## 4. SQL Server 规范

- 表前缀：`sys_`（系统）/ `base_`（基础数据）/ `prod_`（生产）。
- 主键：`BIGINT IDENTITY(1,1) PRIMARY KEY`。
- 中文字段：`NVARCHAR`。
- 时间：`DATETIME2 DEFAULT SYSDATETIME()`。
- 索引：报工表按 `(user_id, report_time)` 建索引。

---

## 5. API 约定

- 前缀 `/api`；RESTful；统一返回 `{ code, msg, data }`。
- 鉴权 JWT；生产人员仅报工接口。
- 分页返回 `{ list, total }`。
- API 查询必须实时：前端 GET 带 `Cache-Control: no-cache` / `Pragma: no-cache`；后端 `/api` 响应统一 `Cache-Control: no-store`，覆盖鉴权失败与静态兜底，防止浏览器持续复用旧接口 HTML（docs/111）。

## 6. 扫码报工（H5）

- **摄像头模式**（默认）：用户点击「打开摄像头扫码」后请求浏览器默认摄像头（`video: true`，不请求音频）；需 HTTPS（或 localhost）。2026-09-22 真机独立检查默认设备可正常打开，原后置偏好请求阶段出现页面重建，暂移除该约束，实际选中前/后置由浏览器决定。识别成功停流并进入 `/h5/report`。
- **扫码枪 / PDA 模式**：隐藏输入框自动聚焦，`@keyup.enter` 触发；扫码后清空输入框，形成连续扫码节奏。普通手机不自动抢焦点。
- **手动输入**：只校验工单号（≤64），不按 URL 解析。
- 摄像头与 PDA 共用 `scanPayload` 解析纯工单号及本站报工链接。

## 6.5 异常处理（不吞异常）

- 禁止空 `catch`、禁止静默忽略继续跑。
- 业务校验失败 `throw BusinessException`。
- `ThrowHelper.Biz` 与 `BizUser` 的 Message 只放业务提示，不自动拼接方法名；Biz 保留 where 参数兼容调用点。定位依靠服务器日志 TraceId 和异常堆栈，源码行号依赖发布调试符号。
- SQL 出错：抛异常并带 **SQL 原文**（参数快照由 EF 拦截器写入**服务器日志**，勿全局 `EnableSensitiveDataLogging`）。
- 调用外部 API 出错：抛异常并带 **网址 + 请求报文 + 返回失败信息**（落盘前统一脱敏；AI 正文省略）。
- 扫描失败：立即抛错，不得生成默认数据继续跑。
- 其它错误：带「出错位置 + 做什么失败」。
- 统一用 `Common/ThrowHelper.cs` 抛错，不散写 `new Exception(...)`。
- **呈现边界（docs/2D §7）：** 技术异常返回前端的 `msg` 含 SQL/报文等异常链 Message（密码/Token 脱敏，不含堆栈），便于 PC/H5 现场查看；完整堆栈仍只在服务器错误日志；追踪号在响应头 `X-Trace-Id` 与服务器日志。业务校验继续返回可读业务提示。
