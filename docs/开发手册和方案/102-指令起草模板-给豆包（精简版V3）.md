## 一、什么时候才写指令

| 写 | 不写（可直接让 Cursor 改） |
|---|---|
| 改表 / 改接口契约 | 改文案、样式、改常量 |
| 有做/不做、A/B 取舍要拍板 | 范围一句说清、不改契约 |
| 先选性质：售前演示 / 内部试用 / 正式生产 | 纯商业分析、竞品调研、报价（非开发任务） |

拿不准：先写**半页取舍表**问人，别先写成长篇执行剧本。

## 二、固定结构（照抄标题，不适用条目删掉，不为填满制造任务）

```markdown
# NNN-执行/优化指令：一句话标题

> 状态：待做
> 性质：售前演示 / 内部试用 / 正式生产
> 本次交付：文档 / 代码与必要验证 / 本地验收 / 增量包 / 部署（按实际授权写清范围与终点，不必逐级执行）
> 目标：让【谁】通过【动作】得到【可观察结果】
> 依据/拍板：……（谁、哪天、选了啥）

## 取舍（已定 / 待确认）
- 有用户拍板或明确项目约定依据才标“已定”，注明依据；未定的业务选择写推荐方案并标“待确认”，不得把起草建议写成已授权决定。
- 用户决定业务取舍；执行方核实事实并决定常规实现。已有项目约定和本次授权能覆盖的事项，不重复请求确认。
- 待确认项只保留会改变用户操作、业务结果或数据契约的选择；执行方可自行核实的事实标“待核实”，不转成用户审批。
- 当待确认项影响主流程 → 先确认，再编码依赖该选择的部分；独立且已授权的工作可继续。常规实现细节不列为待确认。

| 项 | 方案及依据 | 状态 |
|---|---|---|
| 做/不做 | …… | 已定 / 待确认 |
| 复用还是另写 | ……（未看代码不写"已有接口"） | 已定 / 待核实 |
| PC / H5（涉及界面时） | ……（默认先 PC，PC=Element Plus） | 已定 / 待确认 |
| 挂载/入口时机（涉及界面时） | ……（入口页是否会立刻 router.push 离开？会 → 组件挂在跳走前用户看不到；引导/弹窗勿挂在登录成功后马上跳转的页） | 已定 / 待核实 |

## 本次范围与落点
- 交付：一条完整流程【入口 → 查看 → 操作 → 结果】
- 已有 / 缺口：只写相关能力；无代码证据标"建议落点，待核实"
- 数据与契约：固定模拟/真实数据；是否持久化、改表或接口
- 文档：改表必须同步 docs/02；改业务规则同步对应权威文档
- 轻重看依赖：改几个系统、接几种数据、增几类状态；标题写「轻量」不算轻

## 行为与口径（分叉写成显式条件，禁止让执行方脑补）
- 当【条件 A】→【用户看到/系统产生的结果 A】
- 当【条件 B】→【结果 B】；只写真实存在的分叉
- 示例：当 status===0 → 显示【重算】；当 status===1 → 显示【撤回重算】；勿在草稿上做撤回
- 涉及数据写入，尤其复制或批量修改时，按需附下表；只列本次涉及的数据，不为填表新增能力。

| 数据或关联 | 处理方式：带入可改 / 重新生成 / 清空或不复制 / 继续引用 / 本次修改 |
|---|---|
| …… | ……（明确改的是原对象还是新对象，以及是否影响历史数据） |

- 写清失败是否允许留下部分数据；需要整体成功时明确回滚边界，允许部分成功时明确结果与重试范围。重复提交的处理按实际风险说明。

## 止步线
- 后置项：明确列出本次不交付的相邻能力
- 后置项不预建接口、开关、表、隐藏按钮、框架或测试

## 验收（默认 3～5 条勾选，可观察）
- [ ] 正常流程：给定【输入/状态】，操作后得到【结果】
- [ ] 关键分叉/错误：给定【条件】，得到【提示/约束】
- [ ] 必要验证：【页面操作 / 构建 / 针对性测试 / 联调】，按风险选
- 条数：独立权限或资金风险可增加；每条能独立判断通过/失败，禁止为凑条数把多项塞进一条。
- 节奏：开发中按风险做必要的针对性验证；完整流程实现后**集中验收**。失败定点修复复验，避免重复全量回归。

## 交付终点
- 按“本次交付”报告实际结果和剩余限制；文档交付只标起草/审阅完成，不能归为功能已做；功能实现验收后归档
- 打包与部署按本次授权范围执行；授权已明确则继续完成，不重复确认，未包含则不自动扩展为上线
- 现场联调未完成单独标注，不把代码完成写成生产已验收
- 验收满足即交付，不追加与目标无关的优化
```

## 三、验证随风险走（不能一刀切）

性质说明使用场景，“本次交付”决定工作终点，数据敏感性与改动影响决定验证强度。仅起草文档时列明实施所需验证，不把未执行的验证写成通过。演示或内部试用接真实数据、真实权限、工资/结算时，仍须验证对应权限与数据风险，不能因性质标签而省略。

| 性质 | 最小必要验证 | 不附加的任务 |
|---|---|---|
| 售前演示（固定模拟） | 一轮完整页面操作 + 构建；要求隔离时查生产包无演示入口 | 后端、数据库、ERP 联调、全库回归 |
| 内部试用（真实数据/权限） | 相关流程、权限与数据影响 | 未涉及模块 |
| 正式生产（改事务/接口/持久化） | 契约、事务回滚、权限、重复操作、失败路径 | 无关全站优化，但关键可靠性不能省 |
| 涉及钱（工资/结算） | 可追溯、可重算、结果固化 | 为速度牺牲账目正确性 |

## 四、起草时最容易写重的地方

1. **愿景混进首版**：台账/统计/AI/ERP/H5 写进后置范围，首版只留实现目标必需的能力。
2. **「轻量」标题包装重需求**：字数少但依赖多仍是重活；看系统数/数据种/状态类，不看标题。
3. **挂载挂错页**：引导/弹窗挂在会立刻跳走的页 → 用户看不到；先写清入口时机。
4. **重复遥控执行**：条件在"行为"处写一次，不按"前置判断→操作→收尾"抄三遍；不给过时行号硬约束。
5. **编造现状**：未看代码不写"已有接口"；没出处不写"黑湖就是这样"；没实测不写"已验收"。
6. **验收绑死 / 边写边全量验**：不绑某人某单，不验后置能力；开发中做必要的针对性验证，完整流程完成后集中验收，避免重复全量回归。
7. **环境检查无限扩张**：只核实直接落点与必要依赖，不要求先全库搜索。
8. **为短省掉正确性**：三条硬规则、异常上下文、涉及钱的追溯/重算不能砍。
9. **错误套用经验**：固定演示和生产复杂度不同，不承诺每需求六分钟完成。

## 五、自检（发出前勾一遍）

- [ ] 有性质 + 本次交付 + 一句话目标 + 取舍表；已定有依据，未定业务选择标待确认，常规实现由执行方决定，事实待核实不转成审批
- [ ] 涉及界面时写清挂载/入口时机；不适用条目已删除
- [ ] 分叉都写成「当…则…」，且只写真实分叉
- [ ] 涉及数据写入时写清字段与关联的处理、历史数据影响及必要的失败/重复提交边界
- [ ] 涉及界面时，PC/H5 组件库没抄错
- [ ] 写了「已有 / 缺口」或标了待核实；轻重看依赖不看「轻量」标题
- [ ] 验收默认 3～5 条、可独立判断、不绑人单；必要风险可增加，未把多项硬塞一条
- [ ] 按真实数据与改动风险安排必要验证，完整流程完成后集中验收
- [ ] 止步线明确，后置项没以"预留"偷偷进首版
- [ ] 三条硬规则 / 异常上下文 / 涉及钱的正确性未被简化掉
- [ ] 正文优先一页，必要细节可附表；未为凑篇幅省略正确性，也未扩展本次授权的交付范围
