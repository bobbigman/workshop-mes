# 局域网部署 与 PDA 扫码报工 · 落地细节

> 目标形态：工厂局域网内，手机/PDA 浏览器打开网页完成扫码报工；不依赖公网、不依赖微信小程序。

---

## 1. 部署拓扑

```
┌──────────────────────────────────────────────┐
│                车间局域网 (同一网段)            │
│                                               │
│   内网服务器 (Windows Server / 高配PC)          │
│     ├─ SQL Server 数据库                       │
│     ├─ .NET 8 后端 (Kestrel/IIS, 端口 8080)     │
│     └─ Vue3 前端静态文件 (Nginx/IIS 托管)        │
│     固定 IP 例: 192.168.1.100                    │
│          ▲          ▲           ▲              │
│     手机浏览器    PDA浏览器     电脑浏览器         │
│     (扫码报工)   (扫码报工)    (后台管理)          │
└──────────────────────────────────────────────┘
```

---

## 2. 服务器环境准备

| 步骤 | 操作 |
|---|---|
| 1. 固定 IP | 服务器网卡设静态 IP（如 `192.168.1.100`），避免重启后地址漂移 |
| 2. 装运行时 | 安装 .NET 8 Runtime（ASP.NET Core Hosting Bundle，含 IIS 支持） |
| 3. 装数据库 | 安装 SQL Server（Express 免费版足够中小车间） |
| 4. 放行端口 | 防火墙放行 8080（后端）与 80（前端静态页） |
| 5. 主机名 | 可配内网 DNS，或用 IP 直连（简单场景直接用 IP） |

---

## 3. 后端部署（.NET 8）

- 发布：`dotnet publish -c Release -o ./publish`
- 托管二选一：
  - **Kestrel 自宿主**（简单）：直接跑，监听 `0.0.0.0:8080`；
  - **IIS 托管**（推荐生产）：装 Hosting Bundle 后建站点指向 publish 目录。
- 连接串写进 `appsettings.json`：`Server=192.168.1.100;Database=WorkshopMes;User Id=sa;Password=...`

---

## 4. 前端部署（Vue3）

- 构建：`npm run build` → 生成 `dist/` 静态文件。
- 托管：Nginx 或 IIS 指向 `dist/`，监听 80 端口。
- 前端调后端：API 基地址写内网 IP（如 `http://192.168.1.100:8080/api`）。
- 工人入口：手机/PDA 浏览器访问 `http://192.168.1.100`，安卓可「添加到主屏幕」生成图标，体验接近 App。

## 5. 二维码设计（关键决策）

二维码存什么，取决于扫码设备：

### 方案 A：存「工单号」（推荐，配 PDA；网页摄像头也可识别）
- 二维码内容就是纯工单号，如 `GD20260912001`。
- PDA 硬件扫码头扫完后 = 把这串文本"键盘敲进"输入框并自动回车（H5「扫码枪模式」）。
- 手机在 H5 扫码页打开摄像头后，也可直接识别纯工单号（**网页调摄像头仍需 HTTPS**，见第 6 节）。
- **优点**：最稳、兼容 PDA；不依赖打印时的前端基址。

### 方案 B：存「带工单号的网址」（系统相机扫码打开网页，或网页摄像头识别）
- 二维码内容为完整 URL，如 `https://192.168.1.100/#/h5/report?order=GD20260912001`（注意真实路由是 `/h5/report`，不是旧示例 `/report`）。
- **路径 1**：手机系统相机 / 外部扫码 App 扫码 → 打开该网址进入报工页（页面本身可用 HTTP，但若再想在网页里开摄像头仍要 HTTPS）。
- **路径 2**：已打开本系统 H5 扫码页 → 网页内摄像头识别该 URL，校验同源后提取 `order` 进入报工页。
- **代价**：链接需与现网入口一致；网页内调摄像头仍需 HTTPS。

> 建议：现场有 PDA 时优先方案 A；普通手机为主且已配 HTTPS 时，方案 A/B 均可被网页摄像头识别。打印「报工页链接」时，前端基址填手机实际可访问的 HTTPS 地址。

## 6. 手机摄像头扫码的 HTTPS 限制（⚠️ 必须知道）

浏览器安全策略：**网页调摄像头（getUserMedia）必须 HTTPS 或 localhost**。

两条流程不要混：

| 流程 | 是否必须 HTTPS |
|---|---|
| 系统相机扫「报工页链接」→ 浏览器打开网页 | 打开网页可用 HTTP；但若该页再调摄像头则仍要 HTTPS |
| H5 扫码页内「打开摄像头扫码」（含识别纯工单号） | **必须** HTTPS（或 localhost） |

落地要求：

1. 内网服务器提供 HTTPS；证书 SAN 覆盖实际访问的域名或 IP，手机信任证书链。
2. 严格受管设备可用内部 CA，在手机安装并信任根证书后逐台验证目标浏览器。
3. 前端静态页与 `/api` 共用同一 HTTPS 入口，避免混合内容。
4. 仅改成 `https://` 前缀或点开证书警告，不能代替真机验收。
5. **PDA 硬件扫码头不调摄像头**，可继续用 HTTP。

## 7. PDA 扫码头对接要点

PDA 的扫码头默认是「**键盘模拟（HID）**」模式，扫到条码/二维码后：

1. 把内容当键盘输入"打"出来；
2. 结尾自动补一个**回车（Enter）**。

前端配合（H5 扫码页切到「扫码枪模式」）：

```js
<input ref="scanInput" v-model="scanText" @keyup.enter="onScan" aria-label="扫描工单号">

function onScan() {
  // 解析纯工单号或本站报工链接后：
  router.push({ path: '/h5/report', query: { order: orderNo } })
  scanText.value = ''
}
```

**要点**：
- **仅扫码枪模式**下输入框自动聚焦；摄像头模式不抢焦点，避免手机弹出软键盘。
- 扫描后清空输入框，等待下一单。
- 若 PDA 扫码头默认不带回车，可在 PDA 设置里开启「扫描后追加 Enter」。

## 8. 常见坑与应对

| 坑 | 应对 |
|---|---|
| 服务器重启 IP 变了 | 固定静态 IP + 路由器 DHCP 绑定 MAC |
| WiFi 信号弱断连 | AP 覆盖到位；报工页做轻量、提交幂等 |
| 手机摄像头被浏览器拒绝 | 用 PDA 硬件扫码头，或配内网 HTTPS |
| 扫描慢/重复提交 | 前端回车防抖 + 后端按工单号幂等处理 |
| 单机数据丢失 | SQL Server 定时备份 + 异地/U盘备份 |
| 中文乱码 | 数据库用 NVARCHAR，连接串加编码处理 |

## 8.1 PC 内置 AI 助手（可选，默认关闭）

> 依据：docs/26、50。本期改掉 docs/48「默认不在系统内调用大模型」——仅增加**管理员 PC 直连 DeepSeek**；微信/扣子/原 MCP **不改**。不要求为 PC 入口开放公网入站或新建 cpolar。

### 配置（`appsettings.json` 的 `Ai` 段 + 环境变量）

| 项 | 说明 |
|---|---|
| `Ai:Enabled` | 默认 `false`。关闭时主系统照常启动，页面显示已关闭 |
| `Ai:ApiKey` | **必须**用环境变量 `Ai__ApiKey`；仓库示例为空，禁止提交真实密钥 |
| `Ai:Model` | 部署时填写并做连接测试（官方样例曾用 `deepseek-flash`，以当时文档为准） |
| `Ai:BaseUrl` | 默认 `https://api.deepseek.com`，仅服务器改 |
| `Ai:BusinessTimeZone` | 默认 `Asia/Shanghai`（Windows 自动映射中国标准时间） |

步骤：配好密钥与模型 → 设 `Enabled=true` → **重启后端** → 管理员进「AI 助手」→ 点「连接测试」。

### 智能客服资料（可选，默认关闭）

智能客服（support 模式）靠读服务器上一批 `.md`/`.txt` 操作说明回答「如何操作」，靠查工单/报工数据回答「为什么是这个数」。资料未配置不影响查进度/问工艺。

| 项 | 说明 |
|---|---|
| `Ai:SupportDocs:Enabled` | 默认 `false`。关闭时智能客服仍可查数据，但答不了「如何操作」 |
| `Ai:SupportDocs:RootPath` | 操作说明目录的**绝对路径**（如 `D:\WorkshopMes\SupportDocs`），UTF-8 `.md/.txt`，可含一层普通子目录 |

- **复制资料**：把仓库 `SupportDocs/` 样例目录整包拷到服务器，改 `RootPath` 指向它；按需增删 `.md/.txt`，别放部署密码/连接串/默认密码。
- **版本核对**：每个文件头写 `title/version/systemVersion/updatedAt`（YAML front matter），来源卡会显示章节与版本；缺版本会提示「未标注版本」，不猜。
- **更新生效**：改/加/删文件后**下一次提问**即重新建索引生效，无需重启（按文件路径+长度+修改时间做指纹，自动失效重建）。
- **故障排查**：状态页显示 `Ready/Disabled/NotConfigured/EmptyDirectory/Failed`；编码必须是 UTF-8（否则该文件跳过并告警）；单文件/总量/文件数超限会明确提示；符号链接/目录联接不会越出根目录。
- **出网范围**：与查进度/问工艺一致，服务器需访问模型服务；资料不离开服务器（只在本地被检索拼给模型回答）。
- **关闭方法**：`Ai:SupportDocs:Enabled=false`（或清空 `RootPath`）→ 重启 → 智能客服只答数据、不再答操作步骤；要彻底关掉整个 AI 用 `Ai:Enabled=false`。

### 出网与回退

- 服务器需要能访问模型服务（出网）；PC 浏览器只访问内网 API。
- 回退：`Ai:Enabled=false` → 重启服务 → 确认下单/报工可用。未完成请求与内存会话不保留。

## 8.1 错误日志目录与排查（docs/2D、24）

| 项 | 说明 |
|---|---|
| 配置 | `ErrorLogging:Directory` 生产用**绝对路径**，每实例独立（如 `D:\MesTrials\client-a\logs\`），勿放在 wwwroot/发布覆盖目录 |
| 权限 | 应用池身份需对该目录**读写删**；启动会探测写删，失败则进程不伪装启动成功 |
| 文件 | `mes-error-yyyyMMdd.log` / `mes-error-yyyyMMdd_NNN.log`（UTC 日切，超 50MiB 续卷） |
| 保留 | UTC 日桶近 14 天；应用内每小时清理 + 启动补清；**不**用「保留 N 个文件」 |
| 时区 | 日桶按 UTC；中国时间差 8 小时，查「昨天白天」的故障可能落在相邻 UTC 日文件 |
| 按 TraceId 查 | 在对应日志文件中搜索响应头 `X-Trace-Id`（JSON 字段 `TraceId` 或 `@tr`） |
| 磁盘满/无权限 | 写入失败走独立诊断（勿指望业务异常被掩盖）；检查磁盘、ACL、杀毒锁定 |
| 升级 | 发布覆盖 `app` 时保留独立 `logs` 目录，勿删历史日志做验证 |

## 9. 小结

> 局域网 H5 + PDA 硬件扫码头，是这套车间系统**最快落地、最省手续、最稳**的形态：不碰微信、不碰小程序；用 PDA 时可不配 HTTPS，用手机网页摄像头则必须内网 HTTPS，后端 .NET 内网部署即可。
