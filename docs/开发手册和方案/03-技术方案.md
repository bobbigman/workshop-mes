# 技术方案与架构设计

> 目标：基于 C# / .NET 8 + SQL Server 的车间管理系统，前端 Vue3，局域网 H5 + PDA 扫码报工，贴合开发者现有技术栈。

---

## 1. 技术栈选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **.NET 8 Web API + EF Core** | 开发者熟悉 C#，零学习成本 |
| 数据库 | **SQL Server** | 开发者熟悉，与 .NET 天然集成 |
| PC 后台前端 | **Vue3 + Element Plus** | 表格/表单组件成熟，适合后台 |
| 移动端（报工） | **Vue3 + Vant（H5）** | 局域网浏览器访问，PDA/手机扫码 |
| 大屏看板 | **ECharts** | 生产进度/产量/不良率可视化 |
| 二维码 | 内容 = 工单号（PDA 扫码头）或带参 URL（手机摄像头） | 见部署文档 |
| 打印 | HTML 模板 + 浏览器打印 | 流转卡、80×60 母版 |
| 鉴权 | JWT + BCrypt | 登录态、密码加密 |

---

## 2. 部署形态（局域网 H5）

- 内网服务器跑 `.NET 后端 + SQL Server + Vue3 静态页`，固定 IP。
- 工人手机/PDA 浏览器访问内网地址即可报工。
- **扫码优先用 PDA 硬件扫码头（键盘模拟，无需摄像头）**；普通手机可用网页摄像头扫码（需内网 HTTPS，见 `docs/05`、`docs/2E`）。
- 详见 `05-局域网部署与PDA扫码.md`。

## 3. 系统架构（前后端分离）

```
┌─────────────────────────────────────────────┐
│  表现层  Vue3(PC后台)  /  H5(手机/PDA报工)  /  大屏看板 │
├─────────────────────────────────────────────┤
│  HTTP API (RESTful JSON)  +  JWT 鉴权         │
├─────────────────────────────────────────────┤
│  应用层  .NET 8 Web API (Controllers/Services)│
│    ├ 系统配置  ├ 基础数据  ├ 生产管理           │
│    ├ 报表      ├ 看板      ├ 自定义字段/导入    │
│    ├ AI 助手（可选，默认关闭；调 DeepSeek 工具调用）│
├─────────────────────────────────────────────┤
│  数据层  EF Core  →  SQL Server               │
│    (自定义字段: sys_custom_field* 键值表)      │
│    (AI 会话：进程内存，无新业务表)              │
└─────────────────────────────────────────────┘
```

数据流（AI，启用时）：`PC 页面 → /api/ai-assistant → DeepSeek 工具调用 → 本机白名单业务工具 → 答案+来源卡片`。不经公网 MCP 绕回；微信/扣子/原 MCP 入口并行保留。

## 5. 关键设计决策

### 5.1 多租户
- 保留 `factory_id` 字段贯穿所有表，MVP 固定单工厂，后续平滑扩展。
- 工厂级授权档 `sys_factory.license_tier`（`trial` / `enterprise` / `flagship`）：一套代码按档开放功能子集，升级改档即可、数据不重录（见 docs/88）。轻量云授权（可选 `LicenseCloud` + 独立 `license-server`）：按 `factory_code` 校验有效期，本地缓存 + 断网宽限，超期有效档降 `trial`，不锁报工/看板（见 docs/89）。体验账套另用 `trial_expires_at_utc`：后台 `TrialAccountCleanupService` 到期清场（资料+附件）并禁登录；与授权降档不混同（见 docs/90）。

### 5.2 自定义字段（灵活性核心）
- 采用「定义表 + 值表」方案（见数据字典），新增字段无需改表结构、无需发版。
- 工单字段可选 `show_in_order_list`：控制 PC 工单列表动态列；列表查询可按字段 ID + 值筛选（分页前），与打印 `show_custom_field_ids` 独立。

### 5.3 工序报工权限
- 报工前校验：当前用户所在部门 ∈ 该工序的报工权限部门，否则拒绝。

### 5.4 二维码与扫码
- PDA 扫码头：二维码存工单号，H5「扫码枪模式」输入框接收（键盘模拟 + 回车）。
- 手机网页摄像头：页面内调摄像头识别纯工单号或本站 `/#/h5/report?order=` 链接（需内网 HTTPS）；识别后进入报工页，不自动提交。
- 系统相机扫链接：也可直接打开报工页 URL（与网页内调摄像头是两条路径）。

### 5.5 删除顺序
- 业务层强制校验依赖，删除按倒序；有下级的对象禁止直接删除。

### 5.6 报表
- 报工记录表按 `user_id + report_time` 建索引，满足日/月聚合查询。

### 5.7 PC 内置 AI 助手（可选）
- 配置段 `Ai`，默认 `Enabled=false`；密钥环境变量 `Ai__ApiKey`，不进仓库/浏览器。
- 仅管理员；查进度/问工艺/智能客服三个模式只读工具；交期筛选用业务时区半开区间，不复用工单页 `DueStateHelper`。
- 智能客服（support）新增：`SupportDocumentService` 读服务器 `.md/.txt` 操作说明（路径越界/符号链接防护、指纹失效重建）；`AiReportEvidenceService` 查报工证据（只投影白名单字段，不读工资/单价）；工具 `search_support_docs / get_work_order_report_evidence`；无模型翻页接口 `POST /api/ai-assistant/report-evidence/search`；客服文档内容只是证据、不改变权限。详见 docs/25、51。
- 旧工单列表与旧知识查询（MCP）行为不变；AI 另走澄清与归属校验。详见 docs/26、50。

### 5.8 服务器错误日志与追踪
- Serilog 文件落盘：UTF-8 JSON Lines，Warning+，UTC 日切 + 大小续卷；配置段 `ErrorLogging`（绝对目录、实例隔离）。
- 请求入口建服务端 `TraceId`，响应头 `X-Trace-Id`；CORS 暴露该头。
- EF `SqlCommandErrorInterceptor`：命令失败快照 SQL + 参数（脱敏）；外部 HTTP（DeepSeek / 企业微信）记录脱敏网址/请求/响应；AI 正文继续省略。
- `ErrorLogCleanupService`：按文件名 UTC 日桶保留近 14 天，启动补清 + 每小时清理；不按文件数删近期分卷。
- 技术异常前端仅安全提示 + 追踪号；完整堆栈/SQL/密钥只在服务器日志。方案见 docs/2D，执行见 docs/24。

## 6. 安全与性能

- 密码 BCrypt 加密；JWT 控制登录态；生产人员角色仅开放报工相关接口。
- 列表统一分页；工单/报工表按 `factory_id` 建索引。
- 大屏数据定时刷新（如 10s），避免实时查库压力。
- 局域网环境：摄像头扫码需 HTTPS（自签证书），PDA 硬件扫码头无需。

## 7. 对开发者（C# 背景）的落地提示

- 后端 100% 熟悉栈，重点是把《数据字典》的表用 EF Core 建好实体即可。
- 前端只需补 Vue3 的「模板语法 + v-model + 调 API」这三块，其余用 Element Plus / Vant / ECharts 现成组件。
- 先打通「后端出接口 → 前端表格展示」这一条线，后续功能都是复制此模式。
