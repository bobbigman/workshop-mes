# 车间管理系统 · 产品需求规格说明书（PRD）

> 版本 v1.0 ｜ 编制：系统分析师 ｜ 依据：黑湖小工单教学视频（151 张截图 + 249 段语音文字）

---

## 1. 产品定位

一套面向**中小工厂 / 车间的轻量级 MES（生产执行系统）**，把车间里"纸上写工单、口头报数、月底对账"的老办法，替换成：

> **电脑下单出二维码 → 工人手机扫码报工 → 老板大屏看进度**

核心特征：上手快、功能聚焦、手机优先、现场友好。

---

## 2. 目标用户与角色

| 角色 | 登录端 | 权限范围 |
|---|---|---|
| 管理员（role=1） | 电脑端 + 手机端 | 全部权限，可创建其他账号 |
| 班组长（role=3） | 电脑端（复核）+ 可报工 | 报工、复核本组报工、只读工单/报表/看板；不可改基础数据 |
| 生产人员（role=2，工人） | 电脑端可查询 + 手机端报工 | 可查工单、报工记录、生产报表、看板；报工仍按部门授权。不能改基础数据 |

### 权限规则
- 三角色：`1` 管理员 / `2` 生产人员 / `3` 班组长（见 docs/22）。
- **工序报工权限按「部门」授权**，不是按人。用户可属多部门；报工时按「用户所属部门集合 ∩ 工序权限部门集合 ≠ ∅」放行，管理员不受限。班组长报工同样校验部门。
- **报工复核双轨：** 提交后进度实时更新；班组长/管理员复核通过后才进入生产报表入账（日后工资同口径）。
- **工厂授权档** `license_tier`（入门/企业/旗舰）与角色正交：同一套代码按厂开放功能子集，升档改字段即可、数据不重录（见 docs/88）。可选轻量云激活 + 宽限期：到期/超宽限时有效档降为入门，不锁报工与车间看板（见 docs/89）。SaaS **体验账套**另有体验期（默认 7 天可配）：到期自动清空该厂业务资料与附件并禁用登录，转正式前须及时升档（见 docs/90）。

## 4. 详细需求

### 4.1 登录
- 电脑端：输入 **工厂代码 + 账号 + 密码**（首次）；绑定手机号后可直接手机号登录。
- 手机端：微信扫码关注公众号 → 进入手机端 → **手机号 + 验证码**登录。
- 规则：密码至少 6 位；不限制大小写、数字、符号，用户输什么就是什么。

### 4.2 用户管理
- 创建用户：账号（可填手机号）、手机号、姓名、角色（单选：轻量管理员/轻量生产人员）。
- 初始密码至少 6 位；创建后可按需修改密码（同样只校验长度）。

### 4.3 部门管理
- 创建部门：部门编码（必填）、部门名称（必填）、成员（多选人员）。

### 4.4 单位管理
- 创建单位：单位名称（如"只"）。

### 4.5 不良品项管理
- 创建不良品项：名称（如"粘锅"）。

### 4.6 工序管理
- 创建工序：工序编号、工序名称、**报工权限（多选部门）**、**不良品项（多选）**。
- 规则：报工权限限定部门；不良品项决定该工序报工时可选的不良原因。
- PC 管理员可复制工序：带入名称、权限部门、不良品项，清空编号；先编辑后保存，附件和独立工价规则不复制。

### 4.7 工艺路线管理
- 创建路线：路线编号、路线名称、工序明细（可增行、按顺序排列、**拖动排序**）。
- PC 管理员可复制路线：清空编号，带入名称和有序步骤；复用已有工序，可增减及上下移动排序，不修改来源路线。同一路线不重复引用同一道工序，避免工单任务重复。

### 4.8 产品定义
- 创建产品：产品编号（**唯一，不可重复**）、产品名称（可重复）、单位、工艺路线、扩展属性（供应商/单价等）。
- PC 管理员可勾选「重点产品」（可多个），综合风险简报中的相关风险单优先列出并点名；无风险的重点产品不凭标记生成风险。新建/复制默认不勾选；旧客户端未传标记时更新保留原值（docs/252；251后续复用）。
- 小批量建档采用复制已有产品、修改差异，不新增工艺模板管理。PC 管理员复制时清空编号，带入名称、单位、供应商、产品单价，默认沿用原路线；附件与独立工价规则不复制。
- 新建/复制产品时可在表单内“复制工艺并修改”：填写新路线编号，增减及排序工序；产品与新路线整体保存或整体回滚，取消不落库，原对象与历史工单不变。所有关联必须属于本厂。

### 4.9 工单（下单）
- 企微综合风险查询（docs/252）：正式模式仅本厂有效绑定管理员；演示仍须钥匙定厂。今日查所有当前超期、未来3天内（含今日及第3天）临期、超过3个自然日未有效报工的未完成工序；本周交期截至本周日并保留当前超期/滞留。工序已完成不算滞留，无报工自工单创建日计，退回报工不刷新；仅状态0/1，现场进度含待复核/已通过，按工序Min计算。返回原因与建议供模型组织，重点产品优先；不纳入不良超标/未处理异常，不替代单张查进度与列表工具。平台挂载与群内联调另验收。
- 创建工单：选产品、填数量、填其他信息（含自定义字段）。
- 创建后：打印带二维码的流转卡。
- PC 管理员复制工单先打开新建表单，带入产品、数量与本厂工单自定义字段；单号、交期重新填写（单号留空自动生成）。保存后状态未开始、创建人为当前操作人，工序计划按所选产品当前路线及新数量生成；报工、进度、派工、异常不复制。
- 新建工单及工序计划、自定义值整体成功或回滚；保存中禁止重复点击和取消，失败保留输入。提交已成功但响应丢失时，应先查列表确认，不能盲目重试创建。

### 4.10 打印流转卡 / 打印母版
- 支持母版选择（**30×40 / 80×60**）、二维码内容（**工单号** 或 **报工页链接**）、字段勾选（产品编号/名称/数量/工序）。
- 工单页「打印设置」保存工厂级配置；行「打印」预览真实二维码标签后浏览器打印。
- 不做可视化拖拽设计器、Excel 模板打印（见 `docs/13`）。

### 4.11 自定义字段
- 为工单/产品/工序动态添加字段；字段含名称、类型（单选/文本/数字等）、选项列表。
- PC 管理员可删除未使用字段，确认后连同选项删除；已有字段值记录时禁止删除并提示，保留历史业务数据。仅允许操作本厂字段。
- **工单字段「在工单列表显示」**（可选）：开启后 PC 工单列表出现该列（按字段 ID 升序）；可按任一工单自定义字段精确/包含筛选（单选、数字仅精确；与列表显示开关独立）。不支持空值筛选、多字段组合筛、个人列配置。与打印勾选相互独立。

### 4.12 报工
- 报工方式：扫码报工（手机摄像头 / PDA 扫码枪 / 手动输入工单号）、手机搜索/点选工单报工、**电脑报工**、**企微对话报工**（内部试用，docs/241）。
- **企微对话报工**（MES 专用接口，不用工人 JWT）：企微后台解析结构化报文后调预览 → 工人回「确认」再落库；认人复用 `sys_wx_bind`（企微 userid）；底层复用报工校验（部门权限/防超额/前道）。有不良原因等复杂报工回退 149 发卡进 H5 表单；PC/JWT 报工原样不动。
- **企微 MCP 报工**（docs/242，内部试用）：平台只支持 MCP 时，调用 `preview_work_report` → 本人确认 → `confirm_work_report`，复用上述服务。默认关闭；须平台可信请求头身份、管理员核验员工映射及有效绑定，不能只靠自报手机号或查询演示免绑定写入。只接单人单工序良品件数，确认凭证绑定厂/身份/员工；修改或取消使旧预览失效，重复确认只记一次。语音转写归平台，现场联调未完成不视为上线。
- **企微报工候选**（docs/243）：不知道单号时先查 `query_my_report_tasks`；按“工单＋工序”优先列本人/班组尚可报工派工，没有合适派工时列本人权限内未完成工序，不以派工为报工前提。每页最多5项，可换批、按产品/单号缩小范围；工序剩余按全部人员未退回良品计算，不能自动当个人完成量。用户选序号＋报数量后，由后台本人最新列表凭证定位工单/工序再预览确认；旧列表、越界、跨身份或对象变化拒绝。沿用242身份核验，不开放演示免绑定，查询不写流水。
- **企微报工错误与接入检查**（docs/244）：报工MCP边界将未启用、身份/绑定、业务校验错误转为明确非成功结果；技术错误记录脱敏异常链和追踪号，确认结果未知必须查账/原凭证重试。`check_work_report_readiness` 只读返回启用、工厂、身份、映射、绑定的状态，不泄露身份值，不修改配置/绑定/报工。检查通过不代替平台身份可信性和现场验收。
- **姓名优先找人与短期登录授权**（docs/245、246）：无可信企微userid时，跨本实例有效员工按姓名精确匹配；重名/未找到时问手机号后6位，再不唯一问完整11位。完整号对应多工厂时，列实际匹配工厂供用户选序号，不预设厂名或默认入口厂；同厂重号多账号联系管理员。选择凭证10分钟单次使用，授权同时绑定入口与目标工厂，候选/预览/确认按已验证目标工厂办理，其他MCP工具仍按原钥匙范围。唯一定位后发送验证页链接，复用现有登录并要求网页内本人密码确认，8位一次性码换30分钟报工凭证；候选/预览/确认携带该凭证，仍校验启用开关、当前人员与部门权限，不修改企微绑定。授权码5分钟、5次错误作废，密码错误5次限制5分钟，重启失效；姓名、手机号和旧免密链接均不能单独授予机器人写入权限。
- **H5免密入口发放与首次关联**（docs/249）：已有本人个人码、免密链接和有效H5会话照旧使用，不新增密码/8位码。机器人新取个人链接仅限可信平台身份、管理员核验映射、当前工厂有效员工绑定一致的本人；聊天姓名/手机号/一句确认不能获取他人登录权限。无身份/未关联提供不含凭证的普通H5首页与本人扫码指引，首次由管理员核验关联；平台不传稳定身份时不宣称已能自动认人。原聊天直接写入授权独立，不修改数据表或报工权限。
- **H5简化报工**（docs/250，覆盖247默认语音入口）：工作台/我的任务直接点任务，携任务ID到当前授权工单详情确定工序；任务变化不默认选其他项。移除默认语音区域和旧语音参数自动带数，良品用Vant大号数字键盘输入，提交/继续报工先回显当前工单、工序、良品及不良再确认；取消不提交。保留个人码免密、扫码、复杂表单与原接口权限/幂等/上游校验，不自动把剩余量当本次完成量。
- **手机扫码页**（`/h5/scan`）：默认「打开摄像头扫码」（需 HTTPS）；可切「扫码枪模式」或「手动输入工单号」。识别成功后进入报工页，不自动提交报工。摄像头与 PDA 均支持纯工单号及本站报工链接二维码。
- **手机工单列表**（`/h5/orders`）：状态 Tab「全部 / 未开始 / 执行中 / 已结束」并显示各状态张数；卡片展示**工单进度、剩余数、工序圆点链**；顶栏可搜工单号/产品；点卡片进入报工页；入口「我的报工」只读查本人当日/历史报工（状态含待复核/已通过/已退回）。
- **电脑报工**（`/#/report`）：「+ 报工」输入工单号加载 → 选工序填数提交；工单列表也可点「报工」跳转过来。管理员不受部门报工权限限制。管理员/班组长可「代报工」：选工序后按人填各自数量，记到工人名下（班组长限本组，见 docs/22）；管理员代报直接已通过。
- 电脑端工单列表 Tab 同样显示数量：「全部 N / 未开始 N / 执行中 N / 已结束 N / 已取消 N」（「全部」不含已取消）；表内展示进度与剩余数。
- 报工表单：良品数、不良品数、不良品原因（关联该工序不良品项）、**报工时长**（小时+分钟，选填）。
- **计时工资（docs/240，内部试用）**：普通计时自报须先开工，开工记录独立保存；提交时自动算分钟，支持手改，单次不超过24小时。切换工单/工序自动收尾旧记录但不自动报工；管理员在PC待补报入口处理。计件岗开工可选，原选填时长保留。
- **计时补报与多人**：管理员可填起止时间补报，计时良品数可为0；按实际结束时间归工资周期。多人按人独立计时、数量沿原分摊规则；缺开工记录可由管理员在同张PC表单补填，任一人失败整批不落库。工资明细固化计价方式与分钟数；历史金额与报工时长不重写。
- 报工页展示当前工序**进度摘要**：计划数 / 已报良品 / 已报不良（随所选工序变化）。
- 提交方式：「继续报工」（留在本工单连报）、「提交」（关对话框 / 回扫码页）；带客户端请求标识，同请求重试不重复落库。
- **多人共同报工**（H5 与电脑【+ 报工】）：勾选参与人后按人头自动平分，或按各人时长占比拆分；未填时长按已填均值兜底；余数归报工人；各人独立记帐。与【代报工】不能同时提交。
- 提交后工序进度实时更新；完成判定按工序计划数。
- **防超额报工**：累计良品数 + 本次良品数不得超过该工序计划数（无任务行时按工单下单数兜底）；超限拦截并提示，不良品不占上限。
- **一键补报未完工序**（仅管理员）：对尚未报满的工序一次补同一良品数，可按工序拆人写入报工；**不做**末道自动倒冲。复用 PC 报工表单，手机工作台通过“管理操作”菜单提供入口，沿用纵向布局（指令275、278）；班组长不因此获得补报权限。
- 手机默认入口（271）：无明确直达目标时，手机/PDA各角色登录进入工作台；工单/任务等H5安全回跳优先，电脑保留角色默认入口。仅任务视角仍隐藏工单入口，不改变数据权限。
- **手机工作台分层（278）**：紧凑顶栏、蓝色扫码主卡、今日良品与预计计件收入（原工资授权可见）、任务数量摘要、彩色八宫格。任务仍称“已派任务”，详情在任务页。常用功能每排四列，完整视角依次为工单、我的工资、上报异常、生产报表、执行监控、车间看板、帮助；管理员/班组长另显示管理操作。仅任务视角隐藏工单及三项全车间查询，配置未成功时同样隐藏。管理操作直接位于首页，按管理员/班组长原权限提供代报与补报。底栏、统计口径、金额和授权不变。
- 手机底栏：工作台 | 任务 | 我的报工；管理员/班组长且有授权时增加复核。扫码在工作台主按钮，异常上报和帮助在工作台次级入口；报工表单保持独立提交栏。
- **工人一键上报异常**（H5）：选类型（设备故障/物料短缺/质量异常）+ 描述 + 可选拍照；看板红标与滚动播报；管理员/班组长在 PC「异常处理」标记恢复。不做系统猜停滞、试用期不接企业微信。

### 4.13 报表
- 报工数据查询（按工单编号/产品编号/产品名称）。
- 生产报表（今日/本月/上月）、工资报表（计件/计时/固定 + 不良扣款；**不含绩效**；只结算已复核通过的报工，见 docs/21/22）。

### 4.14 车间看板
- 大屏展示生产进度，配置可后期修改。
- 交期三态：工单设「计划交期」，看板按「正常 / 预警(临期≤3天) / 延期(超期)」三色区分，超期置顶；统计「临期工单」「超期工单」数量（见 docs/15）。
- **待处理异常**：工人上报后看板显示待处理数与滚动播报；处理恢复后消除（见 docs/28）。
- **微信预警推送**（可选，默认关闭）：管理员在「微信预警」页配置告警群机器人 Webhook 后手动开启即可收群提醒（免备案、免可信 IP）；页面与正常发送入口仅群机器人Webhook；旧会话规则停用、历史保留。试用期不推送，正式期再开；服务器需能出站访问企微接口（见 docs/1B、docs/131、docs/141）。
- **进度口径（与工单列表、执行监控统一）**：现场进度仅含 `review_status=0/1`；工单完成数取各工序良品最小值；`progressPercent` 为各正计划工序 `done/plan` 最小值（工序达成进度），不得称为成品产出率。零计划不参与百分比；无任务行优先按产品工艺路线兜底展示；正式报表/工资仍仅已通过。

### 4.14a 执行监控（PC）
- 入口：**生产管理 → 执行监控**（`/#/execution-monitor`）。管理员/班组长/生产人员均可只读查看本厂数据。
- 展示：状态统计卡、关键词/状态/交期筛选、工序进度链、待处理异常、超期工单、工单明细、待复核与未派工待办（按角色）。
- 筛选：状态卡按关键词+交期全集统计并忽略当前状态筛选；异常区与待办区不随工单筛选；超期区随关键词/交期。
- 操作：跳转现有工单详情（派工）、报工、异常处理、复核页；约每 10 秒自动刷新。详细规则见 `docs/2F`、`docs/19`。

### 4.15 批量导入
- 用户/不良品项/工序/工艺路线/产品定义均支持：下载母版 Excel → 填数据 → 上传导入。

### 4.16 AI 助手（PC，管理员）
- 入口：电脑端菜单「AI 助手」；仅管理员（role=1）。
- 三个模式：**查进度**（工单交期/状态/进度）、**问工艺**（基于本厂知识库文件）、**智能客服**（操作指引 + 数据解释，只读）。
- 智能客服：操作类问「如何补报」「为什么产品不能删除」查服务器上的操作说明；数据类问「完成数为什么是 80」查工单/报工真实数据并给出公式与明细；回答必须引用来源/证据编号，伪造来源被拒绝。
- 只读：不创建/改数/报工；工厂身份取自登录 JWT，不由模型传入；工具白名单 + 服务端参数校验，客服文档内容不能扩大权限（不能读工资/执行 SQL）。
- API Key 在服务器配置；页面仅显示启用状态与连接测试。会话存服务端内存，刷新或重启后作废。
- 会话缓存满额时自动回收最久未使用的闲置会话，不要求用户手动清理；正在生成回答的会话不回收。仅容量被正在处理的请求占满时提示稍后重试。首次提问失败/取消不留无主会话；已有上下文被回收时明确提示点击“新对话”重新开始。详见[262整改指令](../已做指令/262-整改指令-AI会话自动回收与失败清理.md)。
- 需要服务器出网访问模型服务；不宣传「数据不出厂」。详细口径见 docs/2B、26、50；智能客服见 docs/2C、25、51。

## 5. 核心业务流程

**下单流**：选产品 → 填数量/自定义字段 → 创建工单 → 打印二维码流转卡 → 张贴现场。

**报工流**：工人手机登录工作台 → 点本人/班组任务，或从可见的工单入口按状态查找并点选工单报工；或打开扫码页用摄像头/扫码枪/手动输入定位工单 → 填良品/不良品数 + 原因（可填时长）→ 提交/继续报工 → 进度实时可见。电脑端可在「报工」页「+ 报工」或工单列表点「报工」完成同样填报。

**看数流**：管理员搜报工记录 / 看生产报表（日/月）/ 工资报表 / 车间大屏。

## 6. 三条贯穿全文的硬规则

1. **产品编号唯一**，名称可重复。
2. **工序报工权限 = 部门**（非个人）。
3. **删除顺序（依赖倒序）**：
   工单 → 产品定义 → 工艺路线 → 工序 → 不良品项 → 单位 → 部门。

## 7. 非功能需求

- 手机端优先，现场扫码响应快（页面加载 ≤ 2s）。
- 数据可追溯：报工记录保留操作人、时间、工序。
- 权限隔离：生产人员可以查询工单、报工、报表、看板；没有报工部门权限时仍可登录查询，不能提交报工，也不能改基础数据。
- 可扩展：自定义字段与批量导入减少二次开发。


## 企微事件消息（docs/129）

正式授权沿用交期预警档，默认关闭；PC「微信预警」可配置群机器人 Webhook（群消息）及报工成功/工单开始/工单结束/异常上报规则。群消息走 Webhook、不走 access_token。异常可按设备故障/物料短缺/质量异常分规则，群内 @ 用该规则 to_user，未填则只发群、不继承默认成员；支持企微UserId与@all。设置默认成员只用于测试和交期，交期临期+超期每天汇总一条、当日不重推。持久待发与业务同事务，每分钟计划任务投递。报工按实际新增记录、不良率为该条不良数/(良品数+不良数)，阈值严格大于。状态比较事务前后最终结果：0→1 开始，0/1→2 结束，0→2 只结束，2→1 撤回不提醒。接收消息不增加 MES 报工权限。消息失败可查，群消息无部分失败；结果未知先核实。交期与事件共享每日额度，测试消息不计额度。所有入口按机器人key共享每分钟20次发送尝试上限，明确失败也计入分钟限流；事件超限延后，测试/交期提示稍后重试。关闭或试用时各入口均不外发；未知结果不自动重发。


### H5本人工资单（docs/241）

我的工资页保留今日／本周／本月预估，下方可查本人本厂已确认的月结、周结工资单；草稿及撤回工资单不可查看。计价金额、扣款读取明细快照，应发工资读取主表 total_amount，不表示已付款。支持逐条报工明细、系数、计时和历史未知计价提示。


### 定时综合生产简报（251）
启用微信预警且授权允许的工厂，通过既有每日计划任务，在交期预警之后再发一条综合简报：复用252的超期、临期、工序滞留和重点产品排序，取前3张，AI组织原因与建议，失败回退规则文本；无风险也发范围限定的平安报。综合简报与交期各自按日去重、共用每日额度，额度不足明确跳过；不良超标、未处理异常不在本期。代码完成不等于服务器定时配置或企微现场验收完成。

> docs/266（2026-10-22）修订：工价在报工提交/补报时保存完整快照（规则ID、计价方式、单价、不良扣价）。生成、改数及撤回/草稿重算沿用报工快照，调价不追历史。历史快照缺失时阻止生成/重算并提示报工ID，不按当前价补算。人员系数仍按 docs/225 允许在重算时更新；已生成明细在重算前保持原金额。

### 手机更多功能与AI操作帮助（273）

工作台保留现场主流程，直接提供生产报表、执行监控、车间看板及帮助入口，不再显示更多功能按钮；仅任务视角不新增全车间查询入口，不改变既有接口权限。管理员/班组长保留清晰的后台切换按钮。

手机AI操作帮助供当前有效的三个角色使用，仅检索随版本发布的手机手册及通用FAQ，不查业务数据、不做写入。独立worker-help模式、工具白名单和本人本厂会话校验由后端强制执行；原管理员AI助手权限不变。未启用或未配置时手册仍可用。
