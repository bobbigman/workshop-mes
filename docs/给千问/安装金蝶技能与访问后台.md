# 给千问：安装金蝶技能，并用两种方式进金蝶后台

> 状态：给千问照做
> 目标：在这台 Windows 上装好金蝶技能；查单据走 MCP，查库表 / SQL / BOS 走 WebAPI。
> 依据：Qwen Code 文档（技能目录 `~/.qwen/skills/`，MCP 写在 `~/.qwen/settings.json`）；本机技能 `k3-webapi-sql`、`k3-bos-metadata`、`laohu-kingdee-mcp`。

## 取舍（已定）

| 项 | 怎么做 |
|---|---|
| 技能从哪来 | 复制本机已有文件夹，不从网上另装一套 |
| 查单据、列表、库存 | 老胡专有方案 kingdee-mcp（测试、正式各一个服务） |
| 查中间表、存储过程、BOS 设定、自定义 SQL | WebAPI（技能 `k3-webapi-sql`；读表单 XML 再用 `k3-bos-metadata`） |
| 登录 | 从当前项目本机登录文件读；密码不写进技能、不写进 git、不贴进对话 |
| 默认 | 只读。用户没明确说「请你执行 / 改数」时，不写库、不审核、不删除 |

不要用要 AppID 的 `kingdee-k3cloud-mcp`。

## 止步线

- 不把密码、账套口令写进任何 markdown 或提交。
- 登录失败立刻停，把错误原文和本次网址、账套、用户名给人看；不要连试、不要改连另一套账套。
- 用户要正式环境而正式连不上：停。不要改用测试库冒充正式。
- 整份 BOS XML 写到临时文件看完删除，不要贴进对话。

## 一、安装技能（复制文件夹）

这三项是本机自定义技能，GitHub 上没有，用文件夹安装。

源目录（已在这台电脑上）：

- `C:\Users\bob\.cursor\skills\k3-webapi-sql`
- `C:\Users\bob\.cursor\skills\k3-bos-metadata`
- `C:\Users\bob\.cursor\skills\laohu-kingdee-mcp`

目标：用户级技能，所有项目都能用。Windows 上 `~` 是 `C:\Users\bob`，所以是 `C:\Users\bob\.qwen\skills\`。

在 PowerShell 执行：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.qwen\skills" | Out-Null
$src = "$env:USERPROFILE\.cursor\skills"
$dst = "$env:USERPROFILE\.qwen\skills"
foreach ($name in @("k3-webapi-sql", "k3-bos-metadata", "laohu-kingdee-mcp")) {
  Copy-Item -Recurse -Force (Join-Path $src $name) (Join-Path $dst $name)
}
Get-ChildItem "$env:USERPROFILE\.qwen\skills" -Directory | Select-Object -ExpandProperty Name
```

每个目录里必须有 `SKILL.md`，第一行是 `---`，里面有 `name` 和 `description`。

然后新开一个 Qwen Code 会话（已开着的要退出再进），输入 `/skills`，应能看到这三个名字。

当 `/skills` 里没有 → 核对路径是不是 `C:\Users\bob\.qwen\skills\<名字>\SKILL.md`，不要放进项目里的 `.cursor\skills`。

## 三、WebAPI（查 SQL / 中间表 / BOS）

先读技能 `k3-webapi-sql`，再读 `k3-bos-metadata`。不要另写查询程序，不要猜字段。

1. 在**当前仓库**找登录和入口（不要抄别的项目的绝对路径）：
   - `CsPublicOA.CreateK3CloudApiClient`
   - `DbServiceTests.GetDynamicObject`，或包在 `CsData.GetDynamicObjects` 里
   - 登录：`stru_k3login.cs`、`K3Login.Local.cs` 一类（常被 gitignore）。测试看 `struct_K3Test` / `Test*`，正式看 `struct_K3Normal` / `Normal*`
2. DLL 以当前项目 csproj 的 Debug `OutputPath`、`HintPath` 为准，解析出本项目的 `K3Cloud\bin`。这里要有本项目编出的 `ahu.*.dll`。不要用本机共用目录 `D:\K3Cloud\bin`。只有金蝶 DLL、没有本项目 DLL，就是找错了。
3. 改过 `stru_k3login.cs` 后先重新编译，确认 `ahu.*.dll` 比源码新。
4. PowerShell 加载这些 DLL，`AssemblyResolve` 指向该 `K3Cloud\bin`，然后：

```text
登录 = CreateK3CloudApiClient(ref Struct_K3LoginInfo, 该环境的 RunMode)
结果 = DbServiceTests.GetDynamicObject(client, sql, ref error)
```

RunMode 数字以当前源码为准，不要假设正式一定是 11 或 3。

5. 当前项目若已有 `docs/QueryK3Sql.ps1` 或 `tools/Inspect-ReportSync.ps1` 这类现成入口，优先用它。`-Account` / 环境参数按脚本自己的 test、normal 来，查正式要显式指定正式。
6. 只跑 `SELECT`。结果可写到仓库根 `_k3_query.txt`，看完删除，不要提交。一次查询加日期或 `TOP`。
7. 用户没说「请你执行」：改数 SQL 只给人看，自己不跑 `UPDATE` / `INSERT` / `DELETE`。用户明确要求写库时，先 `SELECT * INTO 备份表`，确认备份表名不存在，备份成功后再改。

登录失败（含「登录过于频繁」「无法连接到远程服务器」「登陆失败了」）：立刻停。把异常原文给人看。里面通常已有网址、账套、用户名、密码；原文给人即可，不要再写进文件。

BOS：不要让用户从设计器导出。整份 XML 在 `T_META_OBJECTTYPE.FKERNELXML`。FormId 以库为准。超大 XML 用 `ExecuteScalar` 写入 `_k3_bos.xml`，看完删除。

## 四、MCP（查单据）

先读技能 `laohu-kingdee-mcp`。包名 `kingdee-mcp`，认证是账号密码 `ValidateUser`。

### 1. 装 Python 包

本机已有解释器：`C:\Users\bob\AppData\Local\Programs\Python\Python312\python.exe`。找不到再用 `where.exe python`。

```powershell
& "C:\Users\bob\AppData\Local\Programs\Python\Python312\python.exe" -m pip install kingdee-mcp
& "C:\Users\bob\AppData\Local\Programs\Python\Python312\python.exe" -c "import kingdee_mcp; print('ok')"
```

报 `No module named 'kingdee_mcp'`：对**同一个** python.exe 再执行一次 pip。

### 2. 写入 Qwen 的 MCP 配置

文件：`C:\Users\bob\.qwen\settings.json`（用户级，所有项目可用）。已有别的配置时只合并 `mcpServers`，不要整份覆盖。

四项从当前项目登录文件读。若本机 Cursor 已配好，也可从 `C:\Users\bob\.cursor\mcp.json` 里现成的 `kingdee-test`、`kingdee-prod` 抄 `command` / `args` / `env`，抄的时候不要把值打到对话里。

某套为空或项目还没有正式环境：只配有的那套。不要建空的 `kingdee-prod`。

`command` 用 python.exe 绝对路径。`args` 固定为 `["-m", "kingdee_mcp.server"]`。网址以 `/k3cloud/` 结尾。

```json
{
  "mcpServers": {
    "kingdee-test": {
      "command": "C:\\Users\\bob\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
      "args": ["-m", "kingdee_mcp.server"],
      "env": {
        "KINGDEE_SERVER_URL": "<测试 ServerURL>",
        "KINGDEE_ACCT_ID": "<测试账套>",
        "KINGDEE_USERNAME": "<测试用户名>",
        "KINGDEE_PASSWORD": "<测试密码>"
      }
    },
    "kingdee-prod": {
      "command": "C:\\Users\\bob\\AppData\\Local\\Programs\\Python\\Python312\\python.exe",
      "args": ["-m", "kingdee_mcp.server"],
      "env": {
        "KINGDEE_SERVER_URL": "<正式 ServerURL>",
        "KINGDEE_ACCT_ID": "<正式账套>",
        "KINGDEE_USERNAME": "<正式用户名>",
        "KINGDEE_PASSWORD": "<正式密码>"
      }
    }
  }
}
```

密码里若有 `$`：Qwen 读 `settings.json` 时会把 `$变量名` 当成环境变量展开。这种密码不要明文写进该文件，改成先设 Windows 用户环境变量，配置里只写 `"KINGDEE_PASSWORD": "$KINGDEE_TEST_PASSWORD"` 这种引用。

写完后退出 Qwen Code 再开。输入 `/mcp`，应看到 `kingdee-test`（以及已配置的 `kingdee-prod`）。

### 3. 怎么查

- 用户说测试、摸数、联调 → `kingdee-test`
- 用户说生产、正式、线上 → 只有 `kingdee-prod` 已配置且登录成功才查
- 先看当前会话里该服务的工具说明，再按真实参数调用。单据查询常见入口是按 `form_id` 过滤；`limit` 最大 100。
- 默认不调用保存、提交、审核、下推、删除。
- 中间表（如自定义映射表）不是单据 `form_id`，改走第三节 WebAPI。
