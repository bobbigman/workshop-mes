## 一、待办 1（P0）：报工负数漏洞 —— 必修



* **文件**：`backend/Services/ReportService.cs` → `SubmitAsync`

* **现象**：`POST /Report` 传 `goodQty=-1` / `defectQty=-1` 均返回 `code=0` 且真实写入；负数写入后 `GET /WorkOrder` 报 `报工汇总数量非法`，列表瘫痪。

* **根因**：`SubmitAsync` 校验块（约 122–128 行）有「不良原因 / 时长非负 / 时长≤24h」，**漏了良品 / 不良品数非负**；`UpdateAsync`（193 行）已有同款校验 → 对齐补齐即可。

* **改法**：在 `SubmitAsync` 校验块开头（`if (dto.DefectQty > 0 ...)` 之前）插入：



```
if (dto.GoodQty < 0 || dto.DefectQty < 0)

&#x20;   throw ThrowHelper.Biz(nameof(SubmitAsync), "良品/不良品数不能为负");
```



* **验收**：负数报工 → `code=1「良品/不良品数不能为负」`；正常报工 / 超剩余 / 不良原因 / 时长三条不回归。

## 二、待办 2（P1）：新建工单 500（删单后必现）—— 必修



* **文件**：`backend/Services/WorkOrderService.cs` → `NextOrderNoAsync`（659–672 行）

* **现象**：当天删除过工单后，`POST /WorkOrder` 稳定 `code=500 操作失败`（复现现场已保留，当前 F001 必现）。

* **根因**：单号 = `prefix + (当天 Count + 1)`，用**数量推断序号**；删除（真删）后 Count 变小 → 与存量单号重复 → 撞唯一索引 `IX_prod_work_order_factory_id_order_no`。日志铁证：`重复键值 (1, GD20260927008)`。

* **改法（方案 A 优先）**：改用「当天 `Max` 尾号 + 1」取号（查询 `OrderNo` 以 `prefix` 开头的最大尾号），避免序号回退；注意 `Count` 为 `int`、超 999 也会溢出。方案 B：生成后查重，冲突则序号 +1 重试。

* **验收**：当天「删 1 单 → 连续建 3 单」均 `code=0` 且不撞号；「建→删→建」10 次无 500；自定义单号去重不回归。
