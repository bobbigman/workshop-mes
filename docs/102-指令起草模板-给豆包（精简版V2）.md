# 102｜指令起草模板（给豆包，精简版 V2）

> 2026-10-02。用途：起草可直接审阅、实施和验收的开发指令。豆包负责起草，执行方对照代码把关后实施；文档本身不代表用户授权开工。
> 依据：AGENTS.md、docs/06、相关权威文档与 [142 开发复盘](142-开发复盘-轻量指令与验收避坑.md)。[V1](102-指令起草模板-给豆包（精简版）.md) 保留供对照；以后起草优先使用 V2。
> 原则：**一句目标、一条完整流程、明确止步线、集中验收，通过即交付。** 轻量看依赖与范围，不看标题是否写了“轻量”。

## 一、先判断是否需要指令

有产品取舍或改表、接口、业务契约，先写短指令与验收清单；文案、样式、对齐已有规则等范围清楚的修改可直接开工。跨多个文件本身不构成必须写指令的理由。

先选清性质：**售前演示 / 内部试用 / 正式生产**。内部试用若使用真实业务数据，也要保留相应正确性要求。商业分析、竞品调研、报价和后续路线图不自动成为开发任务。

已有用户定案直接沿用；缺少信息时标明待核实。普通实现细节由执行方判断，不逐项请求确认；影响产品目标或契约且尚无定案的取舍，集中列出必要问题。

## 二、可直接复制的指令模板

```markdown
# NNN-开发指令：一句话标题

> 状态：待实施 / 待核实取舍（据实选一个）
> 性质：售前演示 / 内部试用 / 正式生产
> 目标：让【谁】通过【动作】得到【可观察结果】。
> 依据：用户已定案内容 + 相关权威文档；未核实事实明确标注。

## 本次范围与落点
- 交付：一条完整流程【入口 → 查看 → 操作 → 结果】。
- 复用：已确认的页面/服务/依赖；默认先 PC，PC 用 Element Plus。
- 已有 / 缺口：只写相关能力；没有代码证据的路径标“建议落点，待核实”。
- 数据与契约：固定模拟 / 真实数据；是否持久化、调用外部接口、改表或接口。
- 文档：改表同步 docs/02；改业务规则或接口同步对应权威文档，无变化则省略。

## 行为与口径
- 当【条件 A】→【用户看到或系统产生的结果 A】。
- 当【条件 B】→【结果 B】；只写真实存在的分叉。
- 计算、空值、重复操作、失败处理：仅写本次涉及且会影响正确性的规则。

## 止步线
- 后置：明确列出本次不交付的相邻能力。
- 后置项不预建接口、开关、表、隐藏按钮、框架或测试。

## 验收与验证
- [ ] 正常流程：给定【输入/状态】，操作后得到【结果】。
- [ ] 关键分叉或错误：给定【条件】，得到【提示/约束】。
- [ ] 重复操作、恢复或隔离：只选本次实际涉及的风险。
- 必要验证：【页面操作 / 构建 / 针对性测试 / 联调】，按实际风险选择。
- 完整流程实现后集中验证；失败才定点修复复验，相关规则要求的检查仍须完成。

## 交付终点
- 附入口、实际验收结果和剩余限制；实现验收后归档。
- 需要现场联调但尚未完成时单独标注，不把代码完成写成生产已验收。
- 本次验收满足即交付，不追加与目标无关的优化。
```

不适用的条目删掉，不为填满模板制造任务。验收通常 3～5 项；有独立关键风险可增加，不为凑条数把多项检查塞入一条。目标约 40～80 行，生产契约需要的细节可以更长。

## 三、验证随风险走，不能一刀切

| 性质 / 改动 | 最小必要验证 | 不附加的任务 |
|---|---|---|
| 独立固定演示，无真实接口与持久化 | 一轮完整页面操作；前端构建；若要求隔离，检查生产包未包含演示入口 | 后端、数据库、ERP 联调、全库回归、新测试工程 |
| 内部试用，使用真实数据或权限 | 相关流程、权限与数据影响；适用构建和针对性测试 | 未涉及模块、尚未开发的正式能力 |
| 正式生产，改事务、接口或持久化 | 对应契约、事务提交/回滚、租户权限、重复操作与失败路径；必要联调 | 无关全站优化；但不能省掉关键可靠性检查 |
| 工资、结算等涉及钱 | 可追溯、可重算、结果固化及相关规则验证 | 为追求速度牺牲账目正确性 |

不统一要求“只测一轮”，也不默认要求“全库回归”。必要检查通过后，有新改动、实际失败或未解决风险才扩大或重复验证。

## 四、起草时最容易写重的地方

- **愿景混进首版**：把台账、统计、AI、ERP、H5 等写在后置范围；首版只保留实现目标必需的能力。
- **演示接生产架构**：固定样板优先复用现有开发环境与独立入口；真实部署或正式菜单确有需求再写进范围。
- **为将来做通用化**：不默认建计算引擎、版本管理、导入导出或组件库。
- **重复遥控执行**：条件在行为处写一次，不再按“前置判断→操作→收尾”抄三遍；不给过时行号硬约束。
- **编造现状**：未看代码不写“已有接口”；未提供出处不写“黑湖就是这样”；没有实测不写“已验收”。
- **环境检查无限扩张**：只核实直接落点与必要依赖；不要求先全库搜索或搭新工具链。
- **验收无法结束**：不绑某人某单，不验后置能力，不把配图、商业资料和无关优化作为代码交付条件。
- **错误套用六分钟经验**：固定演示和生产功能复杂度不同；不承诺每个需求六分钟完成。

## 五、一个轻量写法示例

目标：售前人员看到裁切缺料 50 个，一键模拟补齐后复验通过。

落点：复用现有 Vue3 + Element Plus，独立演示入口，固定 100 件、三道工序，状态只存页面内存。

行为：需求 210、可用 160、在途 100 → 缺口 50；在途不抵扣。补齐增加当前缺口，齐套后按钮禁用；重置和刷新恢复初始数据。

止步线：不接生产菜单、库存、金蝶、数据库、H5，不做台账、统计或通用计算引擎。

验收：初始数量正确；缺料提示正确；补齐复验通过且不重复累加；重置与刷新恢复。集中操作一轮并做默认构建，确认演示不进入生产包。

这个示例适用于固定模拟演示；真实开工拦截、库存占用或消息投递必须另写生产契约与可靠性要求。

## 六、发出前自检

- [ ] 性质、目标和完整流程明确，已有用户定案没有重新变成问题。
- [ ] 只保留目标必需的改动；未核实路径、现状与对标事实已标注。
- [ ] 条件、数据口径和关键风险写清；三条硬规则、异常上下文与钱的追溯未被简化掉。
- [ ] 止步线明确，后置项没有以“预留”方式偷偷进入首版。
- [ ] 验收可观察，验证与风险匹配，现场联调与代码验证状态分开。
- [ ] 有交付终点，无重复剧本、无无关回归、无耗时承诺。

技术栈沿用 .NET 8 + EF Core + SQL Server + Vue3；PC=Element Plus，H5=Vant，默认先 PC。执行方仍按相关规则审指令、核实现状，不因模板精简而跳过必要约束。
