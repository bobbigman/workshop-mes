# 车间小工单 · 演示数据模拟

维护日期：2026-10-25。项目内技能源文件；存放在 docs 供复用，不表示已安装到个人技能目录。
姊妹技能：[workshop-data-import](../workshop-data-import/SKILL.md) 负责**资料导入**（产品/工价/基础资料），本技能只负责**演示数据的报工与工资**，二者边界不重叠。

## 范围与依据

把一组能看的"工人 + 每日报工 + 工资"写进目标演示账套，让前端工资报表/H5 能展示每人日工资 ≈ 目标值（默认 200 元）。
只做模拟演示，**不做**：资料导入、正式生产单、工资发放/确认、部署。

动手前读本项目根目录 AGENTS.md、docs/开发手册和方案/33-接口对接说明.md；涉及表结构读 docs/02-数据字典.md。
接口现状与实测契约见 [references/current-contract.md](references/current-contract.md)。每次使用再核对实际代码及目标服务器版本，不能把本机已实现当成线上已部署。

## 授权边界

- 涉及写库（建用户/价目表/工单/报工/工资单），必须先有覆盖目标账套和范围的用户授权。已有明确授权即可执行，不重复确认。
- 优先在**演示/测试账套**执行；若在正式账套模拟，须明确告知用户会写入真实业务表，且报工不可简单删除（有复核、工资、变更日志引用）。
- 不把模拟数据当初始化必经步骤；模拟用专属价目表/工单会保留在账套里，演示完如需清理须单独授权并按依赖倒序删除。
- Bearer 令牌仅用于请求，不写入脚本常量、技能、报告或 Git；脚本运行时通过 `--token` 传入，CONFIG.TOKEN 留空。

## 一键脚本

`scripts/sim_demo_data.py`（python3 标准库，无需第三方包），幂等可重跑：

```bash
python scripts/sim_demo_data.py --token "Bearer <管理员令牌>" --period 2026-10
python scripts/sim_demo_data.py --base https://127.0.0.1:8080 --token "Bearer <令牌>" --period 2026-11
```

顶部 CONFIG 段按目标账套调整：BASE_URL、PRODUCT_ID/PRODUCT_NO、WO_NO/WO_QTY、8 工序单价（PLANS）、10 名工人账号/部门/良品数量（WORKERS）、工资期间。

脚本六步，全部幂等（已存在即复用、不叠加）：
1. 建 10 个工人用户（POST /api/User 返回无 id，需 GET 回查）
2. 建 8 张**专属价目表**（绑 PRODUCT_ID；创建传完整 details 会自动启用）
3. 建工单（自动锁价到专属表）
4. admin 代报 10 人 8 工序（`confirmUpstream:true` 放行跨工序软确认）
5. 生成指定期间工资（已有则跳过）
6. 回查工资单/报工汇总

## 设计要点（为什么这么建）

- **专属价目表优先于通用表**：库里若已有 8 张按客户 Excel 建的通用价目表（带伞型/尺寸等属性条件），给演示产品建**专属价目表**（表级绑产品、无条件基础价行）可绕开产品属性的规格校验，取价必定命中，且正好演示"专属表优先"。
- **单价×数量≈目标日工资**：每人只做一道工序，单价（元/把）× 良品数 ≈ 200。按 8 工序单价 0.18~0.45 把数量配在 445~1112 之间，10 人日工资全部落在 200.00~200.25。
- **部门与工序报工权限匹配**：工人 deptIds 必须挂到对应工序的报工权限部门（23合片/24缝伞/25拉边/26小裁/27顶带/28珠尾/29品检/30包装），否则代报会被权限校验挡下。

## 验收与交付

- 回查 `GET /api/Salary?periodType=1&periodValue=<期间>`，确认每名模拟工人应发金额 ≈ 目标值；`GET /api/Report?orderId=<工单>` 核对每人良品数 × 单价 = 工资。
- 前端展示路径：PC 管理员 **#/salary 工资报表**；H5 工人端用 simXX / 密码 登录看"我的工资"。
- 交付时说明：用了哪张产品/哪些价目表/什么单价方案、写入了哪些表、是否需演示后清理。
