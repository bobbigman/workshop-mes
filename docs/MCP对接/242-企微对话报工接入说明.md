# 242｜企微对话报工 MCP 接入说明

状态：本地实现；尚未部署、未做企微语音真机联调。只支持本人、单工单、单工序、良品件数。MES 不收音频，平台须先将语音转成文字。

## 默认入口（248）

用户只说“帮我报工/语音报工”，优先提供H5免密入口或扫描本人个人登录码；不默认调用网页登录授权。已有个人码可直接扫码登录，之后选择任务或扫工单码。需要入口才调用get_report_link_by_identity（249，identity可空）：个人链接须可信平台身份、管理员VerifiedUsers映射、有效WxBind员工一致；姓名或手机号不能代替核验。未关联返回use_existing_login_or_personal_code和不含凭证的publicEntryUrl，已有H5登录可直接进入，或使用本人原链接/个人码；不得把普通首页称为已按某姓名登录。首次由管理员核验，不能要求聊天密码/8位码作为默认补救；保持原钥匙工厂范围，不跨厂取码。H5当前按250简化为点任务、用页面数字键盘输入数量、核对提交，247默认语音区域已收起，不等于企微聊天语音。机器人无二维码图片工具，缺码请管理员提供。

仅用户明确选择聊天直接报工时，使用下述245/246身份核验。需在企微刷新工具并粘贴发布SupportDocs/18的新角色设定，再用新会话验收；修改本地文件不会自动发布企微人设。

## 临时域名无userid时的聊天替代路径（245）

此路径不要求平台转发用户身份头。新增 `identify_report_worker(displayName?, phone?)` 与 `verify_report_identity(lookupToken, verificationCode)`：

1. 机器人已有当前企微用户名则先精确查姓名；不知道名字、重名或无匹配，问手机号后6位，再不唯一问完整11位。跨本实例有效员工精确匹配，不默认MCP钥匙工厂。完整手机号仍匹配多厂则返回select_factory，展示factories真实列表让用户选序号，再以factorySelectionToken和factoryNumber重调identify_report_worker；不接受模型自填工厂ID。同厂重号多账号交管理员核对。授权绑定入口与目标工厂，后续候选、预览、确认按已验证目标厂执行，不改变其他MCP工具范围（246）。返回state指导下一步；code=0只表示定位请求完成，不代表授权。
2. 唯一定位返回姓名、工厂、lookupToken、authorizationUrl。机器人原样发链接，保留lookupToken。用户在网页复用现有登录，所登录账号必须是所定位的本人及工厂；授权页再次核验该账号密码，避免旧免密链接直接换取写入资格。密码只在网页输入，不发送给机器人，不存缓存。
3. 用户点“是我本人，确认本次授权”后，页面显示8位验证码。机器人收到验证码后调用verify_report_identity，返回30分钟reportAccessToken。验证码只在JWT保护的网页产生，MCP不能轮询获取；5分钟有效、单次兑换、5次错误作废。定位链接10分钟，确认后延至验证码5分钟期；密码按账号最多5次失败，换定位链接不能绕过5分钟限制。
4. 后续 `query_my_report_tasks`、`preview_work_report`、`confirm_work_report`、`check_work_report_readiness` 都带可选 `reportAccessToken`。接入检查显示authenticationMode=verified_login，不再因缺userid/映射而误判；Enabled仍须管理员启用。原可信平台头路径保留，有效登录凭证不要求写入WxBinds。
5. 模型只保留凭证用于工具调用，不向用户展示或朗读；无效凭证不降级为别人的平台身份。换人、超时或重启需重新验证，旧列表/确认不可跨凭证复用。接口每次重查当前用户有效状态、角色/类型，报工仍用原部门/数量/前道校验。

新增网页登录接口：`POST /api/ReportIdentity/inspect {lookupToken}` 与 `/approve {lookupToken,password}`，两者均须正常JWT，身份来自JWT而非请求体员工ID。页面 `/#/h5/report-authorize?t=...` 由现有路由保护；未登录先登录并返回此页。授权仅改变内存票据，不写员工绑定或报工。HTTPS基址仍取Mcp:AuthBaseUrl（空时回退Instance:PublicBaseUrl）；临时域名变化须更新基址，不能填localhost。

需刷新并选中六个工具：找人、验证码验证、接入检查、候选、预览、确认。同步SupportDocs/18新增身份步骤并发布，新会话测试。机器人不得直接把手机号或聊天昵称用作写入凭证。此路径的真实登录、临时域名访问、企微完整对话尚待现场验证。

## 工具与身份

- `preview_work_report(orderNo, operationName, goodQty)`：返回 `{code,msg,data}`，成功 data 含 `confirmToken`、`previewText`、`userName`、数量和期限。只预览，不生成流水。
- `confirm_work_report(confirmToken, cancel=false)`：用户明确确认后提交；返回实际报工结果。`cancel=true` 时可不传 token，只作废当前预览，返回 `cancelled=true` 不代表报工成功。
- `query_my_report_tasks(keyword?, page=1)`（docs/243）：本人/班组派工优先，无符合条件派工则回退本人有权限的未完成工序。data 返回 source、page、hasMore、items（最多5项）、candidateListToken、expireMinutes、hint及业务排除原因；关键词支持产品名/编号/单号。source=assigned 的末页不会误切为全厂任务；查询错误不能作为空派工处理。
- `check_work_report_readiness()`（docs/244）：无需开启报工即可只读检查开关、MCP工厂、身份头、核验映射及有效绑定。返回 `ready` 和 `checks`（passed/blocked/not_checked）、下一步；不展示userid、哈希、员工ID，不修改任何配置/绑定或流水。`code=0` 只是检查成功，`ready=false` 仍不能报工；程序可检查项全通过也不能证明平台身份头不可伪造。
- 也可调用 `preview_work_report(goodQty=50, candidateListToken="工具返回值", candidateNumber=1)`，无需用户记单号。凭证绑定本人当前列表，序号按本页1～5解释；换批/重查旧列表和旧待确认预览失效。预览重新核对原工单/工序ID及实际数量，旧的单号＋工序调用保持兼容。
- 自动注册复用 Program 的 `WithToolsFromAssembly()`。无企微userid时按245增加找人与验证码验证，共六个工具；原四个工具仍兼容旧调用。
- 工厂仍由 MCP 钥匙确定。身份只读平台请求头 `X-Mcp-Session-Id`，其值必须为真实、稳定的企微用户身份，与 `chan_type=wecom` 的已有绑定一致；没有身份参数供模型填写。此头代表用户身份，不是 MCP 协议的连接/session id。不得全厂共填一个值。

## 启用条件及配置（原可信平台身份头方式，管理员）

以下VerifiedUsers映射和身份头要求适用于原平台认人方式。245网页登录短期授权方式不需要企微userid头或VerifiedUsers映射，但必须完成本人网页登录及密码验证，工具携带有效短期凭证；两种方式都不自动打开Enabled。

在可信平台/网关能够保证该请求头由平台身份注入、不能被聊天内容或模型控制后，管理员核验“企微身份→MES员工”，再手工合并配置（不要覆盖服务器 appsettings）。当前项目没有证据证明平台已满足该条件；不能传或不能保证真实性时保持关闭，回退表单。本次不开发平台网关。

```json
{
  "Mcp": {
    "WecomReport": {
      "Enabled": false,
      "VerifiedUsers": {
        "实际工厂ID": {
          "实际企微身份UTF8的SHA256小写十六进制": 123
        }
      }
    }
  }
}
```

`123` 仅示意 MES 用户ID，须换真实已核验员工。厂ID来自钥匙上下文。配置缺省等于关闭；核验后才设置 Enabled=true。核验表须与实际有效绑定同时匹配，解绑、停用、改绑后不能用旧凭证提交。仅手机号自绑不构成核验，不使用 `Mcp:DemoSkipAuth` 放行。已有普通 HTTP 的 `WecomReport:ApiToken` 不用于 MCP 入口。

仓库另提供 `backend/config-examples/wecom-report.disabled.json`，内容默认关闭、映射为空；它不是自动加载的appsettings，不要直接复制覆盖服务器配置。管理员只合并需要的字段；不掌握真实平台身份或员工对应关系时，不猜值、不启用。

## 看到“暂时无法回答”时的具体排查（244）

2026-10-18实际日志证明：候选工具已被调用，但因开关未启用抛了业务异常。已修为报工MCP边界返回非零 `code`、具体 `msg` 和追踪号；技术故障另记录脱敏异常链。此修复须更新运行中的后端才生效，修改本地代码不改变旧进程。

1. 更新运行后端（部署授权另行执行），在平台刷新并选中四个工具。
2. 机器人角色设定不能留空：将 SupportDocs/18 的最新规则同步到控制台，清除知识集的旧“不报工”绝对口径，保存/发布后新开对话。
3. 对机器人说“检查报工接入条件”，调用只读接入检查。未启用、缺身份、未核验等依据blocked项逐个处理；检查结果不是启用操作。
4. 若身份项blocked，平台须按用户注入可信稳定身份头；模型参数或全厂固定值不能替代。若映射/绑定blocked，由管理员核实实际企微身份与员工，再完善配置及有效绑定。程序不能仅凭收到请求头证明该头可信。
5. 人员映射核验完成后才能由管理员启用，再测试“帮我报工→候选→选序号和数量→预览→确认→查账”。

预期业务回复例：“当前对话报工尚未启用，可以先用报工表单；请管理员完成身份核验后启用。”不再将明确业务拒绝改成“暂时无法回答”。技术故障的追踪号仅供管理员；确认/取消返回 `resultUnknown=true` 时不自动重建，不假称未入账或取消成功。

待确认默认5分钟，沿用 `WecomReport:ConfirmExpireMinutes`（1～30）。新预览替换同一身份/员工的旧预览；修改但信息不全时先 cancel=true，用户取消同样调用。短期缓存只适用于单进程实例；重启后凭证失效。重复确认短时回放结果，不应重新预览再提交；结果未知应保留原凭证重试/查账，过期后先查本人记录再重新报数。多实例分布式确认不在本次范围，不能把不同请求随机分配到不同实例。

## 机器人规则与现场验证

将 `SupportDocs/18-企业微信机器人角色设定模板.md` 的规则同步到实际机器人配置，更新实际知识集，清除“只读不写、不报工”的旧绝对口径。语音报“功”须按语境澄清/识别为报工，不能编数量。办理不先反复搜索帮助，咨询才检索。

不知道单号的对话示例：用户“帮我报工”→查候选→“1. 雨伞A / GD001 / 包装 / 工序剩余200件；您选哪项、完成多少？”→用户“第一项，50件”→带列表凭证和序号调用预览→回显完整工单工序数量→用户“确认”→原确认工具提交。只有一项也不自行认定用户选择，不把剩余200自动填成完成量。候选仅验证最小1件可通过现行预览，实际50件仍须再次校验；不能承诺剩余量均可立即报工。

现场集中验证：语音转写准确；身份头按员工变化且不可伪造；首次未核验拒绝；预览无入库；本人确认数量准确；其他员工不能确认；重复确认不重复入账；改数/取消旧凭证失效；部门权限/超额/前道拒绝；有不良等复杂情况发链接。只有工具明确成功且返回实际记录才回复成功。

本地检查：`dotnet run --project tests/WecomReportChecks/WecomReportChecks.csproj -p:SkipVersionBump=true`。检查使用替身与内存缓存，不连接账套，不能证明生产落库、SQL事务回滚或平台语音链路通过。

## 249：管理员首次关联与已有免密的区别

- 已有个人码/免密链接照旧使用。用户已在H5登录时，打开普通`/#/h5/home`入口直接沿用该浏览器本人会话；会话过期可扫描管理员给本人的个人码，无新增8位码步骤。
- 管理员在原电脑用户管理中核对员工及工厂，取得/发放该员工个人登录码。不要将个人码发给其他人；撤销个人码按既有重新生成规则处理，既有JWT有效期策略不在本次修改范围。
- 如果企微能提供真实、稳定、用户或模型无法伪造的X-Mcp-Session-Id：管理员核对实际企微身份与MES员工，确认现有WxBind后，在原Mcp:WecomReport:VerifiedUsers:<入口厂ID>:<HashSession(实际身份)>配置对应员工ID；单凭bind_wechat的手机号自绑仍不够。入口厂、映射、绑定、有效内部/临时可登录员工必须一致，后续取本人链接不再让工人输入密码或验证码。无须为了H5入口打开聊天报工Enabled。
- 当前临时域名不传用户身份时，不能靠协议连接ID、聊天昵称、所有人共用固定头补齐。此时使用H5已登录会话或管理员本人个人码，不能宣称已完成企微自动认人。没有新开发关联管理页或自动同步通讯录。
- get_report_link_by_identity仍保留identity可选参数，仅核对当前已认证本人的姓名/账号/完整手机号，不以它搜索并授予其他人免密权限；不接受模型指定员工ID或工厂ID。返回失败不泄露他人账号资料，不新发码。
- 发布人设用249-企微本人入口与首次关联角色设定可粘贴.txt，同时刷新插件工具；旧215/248中“自报姓名/手机号即可发个人链接”的口径以本条为准。
