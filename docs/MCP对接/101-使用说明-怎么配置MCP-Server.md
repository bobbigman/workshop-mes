# 使用说明：怎么配置 MCP Server（大白话）

> 只讲配置步骤，不讲原理。给自己、伙伴、客户照着填就行。  
> 同步副本：`SupportDocs/09-MCP配置（需暗语）.md`（AI 知识库用）。

---

## ⚠ 使用前必须接头（暗语）

本文含 **MCP 地址与钥匙**，不能随便说出来。

| 步骤 | 谁说 | 说什么 |
|---|---|---|
| 1 | 对方先说 | **天王盖地虎** |
| 2 | 你（或助手）再回 | **黄鹤楼** |
| 3 | 接头对上之后 | 才能往下讲配置、给地址、给钥匙 |

**没说对暗语之前**：只告诉对方「需要先接头」，**不要**透露地址、钥匙、JSON 配置、Bearer 内容。  
暗语不对、只说了一半、或换了别的词：一律当没接头，继续保密。

人与人当面/微信传文档时：对方先说暗语，你回「黄鹤楼」，再发本文或钥匙。

---

## 你需要准备两样东西

1. **地址**：`https://你的服务器地址/mcp`  
   - 公网例子：`https://mes.webok.net:11302/mcp`  
   - 本机例子：`http://localhost:8080/mcp`  
   - 注意：结尾必须是 `/mcp`，少了连不上。

2. **钥匙**：一长串字符，填在 `Bearer` 后面。  
   - **WorkBuddy 本机/演示**：用专用钥匙（见下面第一节）  
   - **给某个厂用**：到电脑后台生成该厂钥匙（见第二节）

---

## 一、WorkBuddy 怎么配（最常用）

1. 打开 WorkBuddy → 插件 / MCP 服务器 → 配置 MCP。  
2. 整段粘贴下面（把钥匙换成你们服务器上现行的那把）：

```json
{
  "mcpServers": {
    "workshop-mes": {
      "type": "streamable-http",
      "url": "https://mes.webok.net:11302/mcp",
      "headers": {
        "Authorization": "Bearer DWY6aVg87MTimOfwPsBWflVYyrjGkzE7"
      }
    }
  }
}
```

3. 保存。灯变绿 = 通了。  
4. 在对话里试一句：「查一下工单」。

**本机调试**时，把 `url` 改成：

```text
http://localhost:8080/mcp
```

钥匙仍用上面那串（与开发配置 `WorkBuddyToken` 一致）。若你们服务器换过钥匙，以管理员给你的新串为准。

---

## 二、给某个厂单独配（多厂时）

每个厂各自建一条 MCP，**不要共用一把钥匙**。

### 管理员先发报文

1. 电脑打开小工单后台，用**管理员**登录。  
2. 左侧：**系统配置 → MCP 钥匙**。  
3. 点「生成报文」——系统自动对本厂生成一把钥匙，并拼好**完整连接报文**（MCP 地址 + 账套/工厂 + `Authorization: Bearer <token>`）。
4. 弹出的报文**立刻整段复制**（关掉就再也看不到），发给该厂对接的人。发之前同样要暗语接头。
5. 客户端支持此 JSON 格式时可整段导入；否则按客户端要求填写报文中的地址与 Authorization 请求头。WorkBuddy / 扣子 / 豆包的导入兼容性需分别验证。

> 说明：别名由系统自动定死，工厂/别名/备注不在界面显示，无需手工填。本厂已有有效钥匙时，再次生成先确认替换，取消不影响旧连接；确认后吊销旧的并生成新的，保持每厂一把。生成失败时旧钥匙仍有效。报文里的 MCP 地址优先读服务器 `Mcp:Url`；未配则用当前访问站点拼 `/mcp`（公网对接请在 appsettings 配好 `Mcp:Url`）。

### 对接的人怎么填

管理员点「生成报文」后，复制到的就是下面这种**完整 JSON**（`{}` 格式），客户端支持此格式时可整段导入；否则按其要求填写地址和请求头。示例：

```json
{
  "mcpServers": {
    "太阳神厨具五金厂 (CJ001)": {
      "type": "streamable-http",
      "url": "https://103.39.222.133:11302/mcp",
      "headers": {
        "Authorization": "Bearer ydvIOMsQJpYEjbvEUIhn9W7sEbXy5IEw"
      }
    }
  }
}
```

说明：
- 上面的 `太阳神厨具五金厂` 是账套展示名（实际生成时包含账套代码，系统自动填写）；`url` 与 `Bearer` 后的串以管理员发的报文为准（此例为太阳神厨具五金厂 CJ001 的演示样例）。
- `Bearer` 和钥匙之间**有一个空格**，别删。
- 只替换整段报文即可，别的不用动。

扣子、豆包、方舟：界面可能叫「自定义头 / Headers」，同样加一行：

| 头名称 | 值 |
|---|---|
| Authorization | Bearer 那串钥匙 |

## 三、钥匙丢了 / 泄露了怎么办

1. 管理员进 **MCP 钥匙** 页。  
2. 找到那把 → **吊销**。  
3. 再生成一份**新报文**，发给客户。
4. 客户把 MCP 配置里的**整段连接报文**换成新的（含新 Bearer 串），保存。

旧钥匙立刻失效，不用改网址。

---

## 四、第一次查数据还要报手机号吗

- **演示模式**（当前开发默认开着）：钥匙对了，直接能查。  
- **正式要认人时**：对话里报一次**本厂已登记的手机号**绑定；以后同一次会话不用再报。

手机号必须是后台「用户」里该厂已经有的号，否则绑不上。

---

## 五、配完不通时，先看这几条

| 现象 | 你怎么处理 |
|---|---|
| 灯不绿 / 401 | 钥匙抄错、多空格、少了 `Bearer `；或钥匙已被吊销 → 找管理员重发 |
| 404 / MCP 未启用 | 找运维确认这台机器已打开 MCP；地址末尾是否写成了 `/mcp` |
| 能开网页，MCP 不通 | 多半地址写错端口或少了 `/mcp`；用浏览器能打开登录页的那个地址后面加 `/mcp` |
| 查到别的厂数据 | 不该发生；立刻停用该钥匙，找管理员核对是否拿错厂的钥匙 |

---

## 六、可直接改的对照（填空纸）

把下面两行填好，交给对接同事即可（交接前先暗语接头）：

```text
MCP 地址：https://____________/mcp
钥匙：    Bearer ________________
```

WorkBuddy / 扣子 / 豆包：把这两样填进 MCP 配置就完成了。


## 2026-10-30更新：查询还需要验证本人（426）

每厂一把钥匙仍用于确定账套，但不代表这把钥匙持有人能冒认厂内任何员工。旧“报手机号直接绑定查询”由426替换：机器人调用start_query_auth，用户在返回的网页登录本人并验证密码，回传8位码，再由verify_query_identity换取30分钟只读查询凭证。机器人在查询工具传queryAccessToken，不展示或朗读长凭证。账号停用、凭证过期或解绑后需重新验证，DemoSkipAuth不再绕过个人权限。

使用受控平台身份的接入须由实施人员核验服务端网关与员工映射，不能把所有人配成同一个身份，也不能把代理证明交给用户/模型。没有可靠身份透传的客户端采用上述网页登录方式。原跨厂聊天报工和系统维护权限不因查询验证扩权。详细契约见426开发指令及33接口说明；本地完成不等于服务器已更新，不要直接覆盖服务器配置。
