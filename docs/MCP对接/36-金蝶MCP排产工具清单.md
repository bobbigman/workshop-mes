# 金蝶 MCP · 排产评分最小工具清单

> 版本：v1.2（2026-09-16）｜ 定位：**范围 + 行业默认拍板；实现另开**  
> 对照样表：`其它截图/排产示例.xlsx`（优先级评分试算）  
> 前提：老胡小工单已有 MCP（工单/报工/工资，见 `docs/34`）；本清单只补**金蝶侧**缺的维。  
> 原则：MCP 只负责「取数 / 触发算分」；加权、排名、权重配置放在**确定性服务**里，不让大模型估分。  
> **已拍板：** 主数据 = MES 工单；关联键 = 金蝶生产订单同号；其余见 §8 行业默认方案。

---

## 1. 一句话边界

```
MES MCP  ──► 工单号、产品、数量、交期、进度（已有：query_work_order）
金蝶 MCP ──► 客户等级、订单金额、齐套、物料规格（本清单）
评分服务 ──► 五维打分 × 权重 → 总分 / 排名 / 建议开工顺序（本机，非 MCP 协议本身）
导出     ──► 输出像「排产示例.xlsx」的表
```

金蝶 MCP **不能单独**完成排产；它只补样表里 MES 没有的维。

## 2. 样表列 ↔ 数据来源

| 样表列 | 谁出数 | 说明 |
|---|---|---|
| 任务单号 / 产品 / 数量 / 要求完工日 | **MES（已有）** | `prod_work_order.order_no` / 产品 / `qty` / `due_date`；MCP 工具 `query_work_order` |
| 交期紧迫度 0–100 | **评分服务**（用 MES 的 `due_date` 算） | MES 只提供日期，不算分 |
| 客户等级 0–100 | **金蝶** | 客户主数据 / 客户分类 → 映射成分数 |
| 订单金额 0–100 | **金蝶** | 销售订单/生产订单关联金额 → 归一化成 0–100 |
| 换型相似度 0–100 | **评分服务** + 金蝶规格属性 | 金蝶出规格；相似度按「与上一张已排单」规则算 |
| 齐套性 0–100 | **金蝶** | BOM + 库存 / 齐套检查结果 |
| 加权总分 / 优先级排名 / 建议开工顺序 | **评分服务** | 确定性公式；MCP 可包一层 `calc` 工具触发 |
| 备注 | 规则生成或人工 | 如「齐套低→建议顺延」由规则拼，不靠模型编 |

**关联键（MES ↔ 金蝶）：** 需有一条可对齐的键（如 MES 工单号 = 金蝶生产订单号，或 MES 自定义字段存金蝶单号）。没有关联键，金蝶侧客户/金额/齐套对不上单。

## 3. 金蝶 MCP 最小工具清单（P0 共 4 个 + P1 共 1 个）

> 命名用英文 snake_case；中文说明给人对齐。

### 3.1 不做 / 非必须（MES 已有）

| 工具名 | 结论 |
|---|---|
| `list_open_mos` | **金蝶侧非必须。** 前四列由 MES `query_work_order` 提供。仅当要对齐全蝶生产订单清单做对账时，可作可选只读工具，不进 P0。 |

### 3.2 金蝶侧要做的

| # | 工具名 | 作用 | 关键入参 | 对应样表列 | 优先级 |
|---|---|---|---|---|---|
| 1 | `get_customer_grade` | 取客户等级（或分类） | 客户编码 / 金蝶订单号 / MES 工单关联键 | 客户等级 | P0 |
| 2 | `get_order_amount` | 取订单金额 | 销售订单号 / 生产订单号 / 关联键 | 订单金额 | P0 |
| 3 | `check_kit_completeness` | 齐套检查 | 生产订单号 / 关联键 | 齐套性 | P0（排产红线） |
| 4 | `calc_schedule_priority` | **触发**评分（内部调本机评分服务；先拉 MES 工单，再补金蝶维） | 筛选条件或工单号列表；可选权重覆盖 | 加权总分、排名、建议开工顺序、备注 | P0 |
| 5 | `get_material_attrs` | 取物料规格属性（换型用） | 物料编码 | 换型相似度（原料） | P1 |

> `calc_schedule_priority` 建议挂在 **MES 进程**（能直接查本库工单），金蝶三维通过金蝶 MCP/客户端调用补齐；不必放进金蝶进程。

### 工具输出约定（统一）

每个工具返回 JSON 字符串，结构与现有 MES MCP 一致风格：

```json
{ "code": 0, "msg": "ok", "data": { } }
```

失败：`code != 0`，`msg` 带「出错位置 + 正在做什么失败」；调金蝶 API 失败时带上 **网址 + 请求报文 + 返回信息**（对齐项目异常规约）。

### `calc_schedule_priority` 的 data 形态（对齐样表）

```json
{
  "list": [
    {
      "moNo": "MO202609001",
      "product": "BFK-200",
      "qty": 320,
      "dueDate": "2026-09-20",
      "scoreDue": 95,
      "scoreCustomer": 80,
      "scoreAmount": 60,
      "scoreChangeover": 70,
      "scoreKit": 90,
      "total": 82.5,
      "rank": 1,
      "suggestSeq": 1,
      "remark": "大客户急单，料已齐"
    }
  ],
  "weights": { "due": 0.3, "customer": 0.2, "amount": 0.15, "changeover": 0.15, "kit": 0.2 }
}
```

> 权重默认值来自「排产参数配置」；工具允许临时覆盖，便于试算（对齐样表说明第 ④ 条）。

## 4. 必须另有、但不算「金蝶业务工具」的两块

| 块 | 放哪 | 为什么 |
|---|---|---|
| **排产参数配置**（五维权重、交期天数→分数换算、齐套低于阈值强制顺延） | 本机配置表 / 配置页 | 样表第 ④ 条；属配置 |

| 工具名 | 作用 |
|---|---|
| `export_schedule_xlsx` | 把 `calc_schedule_priority` 的结果导出成「排产示例」同结构的 xlsx |

## 5. 明确不做（防做成 APS）

| 项 | 原因 |
|---|---|
| 金蝶侧再实现一套 `list_open_mos` 当主列表 | MES 已有；重复且易双源不一致 |
| 有限产能排程 / 机台甘特 / 卡时 | 样表只做优先级评分，不做时段占用 |
| 自动下推开工、改金蝶单据状态 | 演示期只读 + 算分；写回另开指令 |
| 让模型根据自然语言「估」五维分数 | 分数必须由规则/服务算出，可解释、可重算 |
| 进销存全模块 MCP 化 | 只暴露齐套检查所需的最小查询 |
| 替换 `docs/27` 派工 | 派工是「人派人」；本清单是「建议开工顺序」，可衔接、不互相替代 |

## 8. 拍板结论（行业默认方案，2026-09-16）

> 立场：离散制造、MES 管现场进度、金蝶管订单/物料/库存；排产评分是**轻量优先级试算**，不是 APS。  
> 下列为**推荐默认**；现场有特殊习惯再改映射表/权重，不改主链路。

### 8.1 关联键（你已定 + 补全）

| 项 | 结论 |
|---|---|
| 主键 | **MES `order_no` = 金蝶生产订单编号（`PRD_MO.FBillNo`）**，一对一、同号 |
| 建单约定 | 下发/同步时保证同号；本系统建单若早于金蝶，须回写同一单号或禁止两边各编各的 |
| 客户、金额从哪来 | 生产订单 → **销售订单** → 客户 / 金额（金蝶常规链路；生产订单上若带客户字段可作兜底） |
| 齐套查哪 | 以该 **生产订单号** 做齐套（见 8.3） |
| 对不上怎么办 | 评分行标「无金蝶关联」，客户/金额/齐套三维记空并 **总分不参与排名**（或仅按交期临时分，但备注强制写「未关联金蝶」）——避免瞎填 |

### 8.2 客户等级 → 分数

| 项 | 结论 |
|---|---|
| 金蝶取数 | 客户主数据上的 **客户分类 / 客户等级**（常见 `FCustTypeId` 一类；具体字段以账套为准） |
| 映射方式 | **本机对照表**（不要假设金蝶分类代码就是 0–100） |
| 行业默认映射 | A / 战略 = **100**；B / 重要 = **70**；C / 普通 = **40**；未分级 = **50** |
| 谁维护 | 对照表在本机「排产参数配置」维护；金蝶只出分类编码 |

### 8.3 订单金额 → 分数

| 项 | 结论 |
|---|---|
| 金蝶取数 | 关联 **销售订单价税合计**（优先）；无销售订单则用生产订单相关金额字段兜底 |
| 归一化（行业常用） | **在当前待排产集合内做分位**：金额最高=100、最低=0，中间线性插值；集合只有 1 单则给 60（中性） |
| 为何不用绝对金额档 | 各厂订单量级差太大，绝对档（如「>50 万=80」）难通用；分位法开箱即用 |

### 8.4 齐套口径（排产红线）

| 项 | 方案 |
|---|---|
| 查什么 | 金蝶对该 **生产订单** 的齐套/库存可发量（行业：BOM 子项需求 vs 仓库可用量；优先用星空自带齐套分析/库存查询，不自研 MRP） |
| 得分 | **齐套率 × 100**（可开工数量口径：关键子项都满足才算齐；允许「按齐套率」部分齐套打分） |
| 强制顺延阈值 | **齐套分 &lt; 60 → 不进入建议开工顺序**（或排到队尾且备注「缺料，不可硬排」）——对齐样表说明第 ③ 条 |
| 缺料信息 | 备注拼「缺料：子项编码…」（有则写，便于催货） |

### 8.5 换型相似度

| 项 | 方案 |
|---|---|
| 比较对象 | 候选单 vs **当前建议序列中的上一张单** 的物料 |
| 规则（由宽到严打分） | 同物料编码 = **100**；同规格型号/同产品族 = **80**；同颜色或同模具组 = **60**；仅同大类 = **40**；其它 = **20** |
| 规格从哪来 | 金蝶物料属性（`get_material_attrs`）；本机产品无规格时以金蝶为准 |
| 第一张单 | 无「上一张」，换型分给 **60**（中性，不奖不罚） |

### 8.6 交期紧迫度（MES `due_date`）

| 剩余天数 D（完工日 − 今天） | 分数 |
|---|---|
| D ≤ 0（已超期） | **100** |
| 1～3 | **90** |
| 4～7 | **70** |
| 8～14 | **50** |
| &gt; 14 | **30** |
| 未设交期 | **40**（中性偏低，促使补交期） |

> 与现有看板「临期≤3 天」一致：3 天内仍属高紧迫，但不替代连续评分。

### 8.7 权重默认值（可调）

| 维度 | 默认权重 | 理由 |
|---|---|---|
| 交期紧迫度 | **0.30** | 交期仍是排产第一声音 |
| 齐套性 | **0.25** | 排了开不了工等于零；且另有 &lt;60 硬规则 |
| 客户等级 | **0.20** | 大客户插单常见 |
| 换型相似度 | **0.15** | 减换型损失，但次于交期/齐套 |
| 订单金额 | **0.10** | 有用，不宜压过交期与齐套 |
| **合计** | **1.00** | |

公式：`总分 = Σ(维度分 × 权重)`；排名按总分降序；齐套&lt;60 的单 **不占 suggestSeq 正序**（队尾或剔除出「可开工」列表，样表可仍显示分数供催料）。

### 8.8 部署

| 项 | 结论 |
|---|---|
| 评分服务 / `calc_schedule_priority` / 导出 | **挂 MES 本机进程**（工单在本库） |
| 金蝶三维工具 | **可同进程内金蝶客户端封装**，或独立金蝶 MCP；演示期同进程更少隧道 |
| 方舟 | MES MCP 一个地址即可；金蝶工具由 MES 进程转发调用，对方舟仍是一个 MCP |

### 8.9 仍允许现场改、但不动主链路的

- 客户等级对照表分值、齐套阈值（60）、交期天数档、五维权重 → 全部进「排产参数配置」  
- 不改：关联键=生产订单同号、齐套低不硬排、分数由服务算死
